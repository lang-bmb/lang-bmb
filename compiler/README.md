# bmb 컴파일러

M1(ADR-0016) 최소 관통 경로: 파싱 → 이름·타입·소유권·명세·효과 검사 → 증명 게이트(Z3) → LLVM IR → 실행 파일.
의미론과 인코딩은 ADR-0017·0018.

```
cargo run -- check a.bmb b.bmb   # 진단을 JSONL로 출력. 오류가 있으면 종료 코드 1
cargo run -- verify a.bmb        # 검사 + 증명. 정의별 상태 줄 포함. --emit-smt DIR로 질의 저장
cargo run -- build a.bmb -o app  # 모든 의무가 증명된 경우에만 실행 파일 생성
cargo run -- emit-llvm a.bmb -o a.ll  # IR. 증명되지 않은 의무는 런타임 검사(trap)로 남음
cargo run -- emit-llvm --all-checks a.bmb -o a.ll  # 증명 없이 IR. 모든 의무가 런타임 검사로 남음(계약을 믿지 않으므로 증명되지 않는 변이체도 정직하게 실행, 2A-10)
cargo run -- codes               # 진단 코드 목록(JSONL)
cargo run -- fix a.bmb           # 기계적 수정(replacement)을 적용·재검사 반복. 기본은 보고만(JSONL), --write로 제자리 수정, --print로 고친 텍스트 출력
cargo run -- verify --cache .bmb-cache a.bmb  # 증명 캐시: 해법기 입력이 같은 증명된 의무는 다시 풀지 않음(2D-01). 바뀌지 않은 정의는 인코딩·IR 생성도 건너뜀(2D-10)
cargo run -- stability a.bmb     # Z3 시드 0..5로 증명해 판정이 시드에 따라 바뀌는 정의를 보고(1B-19)
cargo run -- uses a.bmb          # 증명되지 않는 정의마다 최소 #[uses(..)] 목록을 찾아 보고. --write면 파일 수정(2D-05). --cache DIR은 verify와 같은 캐시(2D-15)
cargo run -- lint a.bmb          # 계약 조정 린트: 불가능한 pre, 증명에 쓰이지 않는 pre, 호출자가 쓰지 않는 post, 변이가 살아남는 약한 명세(경고 W09xx, 2D-08·2D-09). --cache DIR은 verify와 같은 캐시(2D-15)
cargo run -- mutate --def u::f a.bmb  # W0904 변이 전부(상한 없음, 증명 안 함)를 프로그램으로: 행마다 바뀐 단위의 정규형(BSB 생성기용, 2A-10)
cargo run -- doctor              # 고정된 Z3·LLVM 버전 확인(scripts/toolchain.env)
../scripts/setup.sh              # 고정 버전 설치(새 클라우드 세션은 시작 훅이 자동 실행)
../scripts/check.sh              # 검증 게이트: fmt·clippy·빌드·백로그·문서, 그다음 테스트 실행 파일과 벤치 검사를 동시에(INF-08, scripts/gate_jobs.py). 종료 코드로 판단
cargo run -- map all a.bmb        # 표준 맵 L0~L2(JSONL, ADR-0020; 타입·`impl` 함수·`types` 간선은 ADR-0026 §6)
cargo run -- query slice u::f -- a.bmb  # 읽기 질의: units surface edges slice find contracts status impact duplicates effects tests
cargo run -- query --cache .bmb-cache status -- ws  # map·query도 --cache DIR을 받는다(증명하는 L1·surface·status만 영향, 출력은 같은 바이트, INF-08)
cargo run -- import ws a.bmb     # 작업 공간 ws/src/에 단위당 정규형 파일 하나
cargo run -- apply ws ops.json   # 쓰기 트랜잭션(unit/put/remove/remove_unit/rename/expect, 아래 "정체성"). 구조·타입 오류면 전체 거부
cargo run -- mcp ws              # MCP 서버(stdio): query map verify build tx_begin/put/commit 등
cargo run -- mcp --write-tool ws # 위에 `write`(단위·정의·삭제·커밋·증명을 한 호출로, 2D-24)를 더한다. 동결 과제 집합은 끄고 쓴다
BMB_SOUND_ITERS=60 cargo test --release --test soundness  # 건전성 퍼징(1B-17): 증명·반례·빌드를 독립 해석기와 대조
BMB_SOUND_ITERS=40 cargo test --release --test soundness_owned  # 소유 자료 퍼징(2O-05): 연결 리스트·Box·Vec 필드의 이동·교체·참조 match, 증명·반례·빌드·valgrind 해제를 해석기와 대조
BMB_FMT_FUZZ_ITERS=2000 cargo test --release --test fmt_fuzz  # 정규형·해시 퍼징(1D-22): 배치·주석·파일 분할에 정규형·해시 불변, fmt 멱등, fmt 전후 상태 줄·IR 동일(앞 BMB_FMT_FUZZ_PROVE개만 증명). 이름 하나(정의·단위·타입·필드·변형·매개변수·지역·레이블)를 바꿔도 모든 `id` 불변, 리터럴 편집은 그 정의의 `id`를 바꿈(T1-10, 파일당 이름 수는 BMB_FMT_FUZZ_RENAMES)
BMB_MCP_FUZZ_SESSIONS=500 cargo test --release --test mcp_fuzz  # MCP 세션 퍼징(1D-23): 임의 도구 호출 순서에서 응답 형식·트랜잭션 모형·커밋만 작업 공간을 바꿈·커밋 뒤 검사 통과와 정규형
cargo test                       # 회귀 코퍼스(tests/check, tests/verify)와 게이트·보조 사실 테스트
BMB_BLESS=1 cargo test           # 기대 진단(.jsonl) 갱신
```

표준 출력이 닫히면(`bmb hash ws | head -1`) 모든 명령은 패닉 없이 종료 코드 141로 끝난다(SIGPIPE로 끝난 프로세스와 같음, 백로그 1D-24, `tests/cli.rs`).


## 구현하며 정한 표면 규칙

ADR-0016의 부분집합을 구체화한 것이다. 모두 "선택을 필수로"(ADR-0013)와 정규형 하나(원칙 8)에서 나왔다.

| 규칙 | 내용 |
| --- | --- |
| 구성 단위 | 최상위에는 `#[summary("..")] mod 이름 { .. }`만 온다. 요약 필수. 다른 단위는 전체 경로(`unit::f`)로 부른다. `pub` 없음. `use a::b::f;`(단일 이름)는 E0214로 받아 `bmb fix`가 쓰임을 전체 경로로 바꾸고 줄을 지운다(glob·묶음·별칭은 E0214 안내만) |
| 함수 | 반환 타입 필수(`-> ()` 포함). 실행 함수는 `#[effects(pure)]` 또는 `#[effects(io)]` 필수. `spec fn`은 효과 속성 없음. `proof fn`은 반환 타입도 효과 속성도 쓰지 않는다(E0256, 아래 증명 함수 항목) |
| 절 순서 | `requires`, `ensures`, `decreases` 순서 고정 |
| 계약 | `requires`·`ensures`의 각 절은 이름 붙은 술어(`spec fn .. -> bool`) 호출. 본문이 `true`인 술어는 거부 |
| 결과 이름 | `ensures`에서 결과를 쓰려면 `-> (r: T)`로 이름을 붙인다 |
| 참조 | `&[T]`·`&mut [T]`는 매개변수에만. 인자로는 `&arr`·`&mut arr` 또는 받은 참조 매개변수를 그대로 넘긴다. `&mut` 인자는 같은 호출의 다른 인자와 겹칠 수 없다. 단, 값으로 넘기는 스칼라 인자가 그 배열을 읽기만 하면 허용(`f(&mut a, a.len())`, ADR-0024) |
| 이름 | 한 함수 안에서 같은 이름을 두 번 묶을 수 없다(블록이 달라도) |
| 리터럴 | 접미사(`5i64`, `0xffu32`) 없음(E0104, 접미사만 지우는 수정). 타입은 문맥에서 정해진다. 10진수와 `0x`·`0o`·`0b`, `_` 구분자(ADR-0048 §3, 2N-02). 진법 밖의 숫자(`0b102`)·숫자 없는 접두(`0x`)는 E0108. 정규형은 쓴 진법을 유지하고(구문 트리가 `Radix`를 가진다) 그 진법의 숫자를 소문자로, 구분자와 앞의 0 없이 쓴다(`0xFF_00` → `0xff00`, `0b0000_0101` → `0b101`, `1_000` → `1000`). 구분자는 공백처럼 배치일 뿐이라 정규형 하나(ADR-0019)를 지킨다. 배열 길이·반복 횟수(`[T; N]`, `[v; N]`)는 개수라 10진수로 쓴다 |
| 제어 | `return`(2K-01a), `break`·`continue`·레이블(2K-01b), `loop`(2K-01c), 범위 `for`(2K-01d), `?`(2K-01e), `match`가 있다. 블록의 마지막 식이 값. 모든 `while`·`loop`에 `decreases` 필수(`for`는 자동), 재귀 함수(상호 재귀 포함)에 `decreases` 필수 |
| 명세 전용 | `forall`, `==>`, `old(..)`, `#[trigger]`는 명세 문맥에서만. `old`는 `ensures`·루프 불변식·`assert`·`proof` 블록에서 `&mut` 매개변수에만(함수 진입 시점 값) |
| 유령 문맥 | `proof fn`의 몸과 실행 코드의 `proof { .. }` 블록(문장 자리, 루프 몸 포함, 값 없음). 오는 것: `proof fn` 호출(문장으로), `assert`, `if`·`match`(경우 나누기), 명세 식의 `let`. 실행 함수 호출·대입·`let mut`·`&mut`·루프·`proof` 블록 중첩은 E0257, `proof fn`을 유령 문맥 밖(실행 코드, 명세)에서 부르면 E0258(실행 코드면 `proof { f(..); }`로 감싸는 수정). 블록의 `let`은 그 블록 안에서만 보인다. 정규형에서 `proof` 블록은 쓴 자리의 문장이다(순서가 의미: 그 뒤로 사실이 성립) |
| 중첩 한도 | 구문 중첩(괄호·단항·블록·`if`·`else if`·`while`·`==>`·이항 연산과 후위 연산의 사슬·타입·단위)은 256단계까지. 넘으면 E0107. JSON 입력(트랜잭션, MCP)의 배열·객체 중첩도 256까지. CLI와 MCP 서버는 큰 스택(`STACK_BYTES`)의 스레드에서 돈다(백로그 1A-11) |
| 주석 | `//`만. 맵에는 들어가지 않는다. 구조화 근거(ADR-0006)는 M1 이후 |

- 데이터 타입 표면(ADR-0026, 2B 진행 중): 파서와 정규형은 `struct`·`enum`·`impl T`·`Option<T>`·`Result<T, E>`·수신자 `self: &T`·구조체 생성·필드 읽기·`*p`·`match`를 읽고 쓴다(2B-03). 정규형은 단위 안에서 하위 단위 → 타입(이름순, 각 타입의 `impl`이 바로 뒤, 그 안 함수 이름순) → 함수이고, `match`는 갈래마다 한 줄이며, 구조체 생성을 담은 조건은 괄호로 감싼다. 구조체 생성은 `T {` 다음에 `이름 :`이 올 때만이라 `while k < n { .. }`의 블록과 섞이지 않는다. 검사기는 타입 선언, 이름, 시그니처, `impl` 함수와 `T::f` 호출을 받는다(2B-04a: 재귀 타입 E0421, 내장 이름 `Option`·`Result`·`Some`·`None`·`Ok`·`Err` 예약 E0309, `impl`은 타입과 같은 단위에 하나 E0308, 첫 매개변수가 그 타입이면 이름은 `self` E0310, 타입 인자·빈 타입 E0420, 모르는 타입 E0305). 값·필드·`match`도 검사한다(2B-04b·c: 구조체 생성 E0422, 모르는 필드·변형 E0306·E0307, 망라성·선언 순서 E0426, 페이로드 개수 E0427, 실행 코드의 데이터 타입 `==` E0425). 데이터 타입의 Rust 습관은 E0220~E0233이고 기계적인 것은 `replacement`가 있다(2B-04d: `if let`과 `_ =>`는 선언 순서의 `match` 전체로). 증명(2B-05, ADR-0027): 구조체는 필드 분해, 열거형(`Option`·`Result` 포함)은 인스턴스마다 SMT 데이터타입, `match`는 판별자 경로 조건(실행 코드의 열거형 값, 즉 매개변수·호출 결과·루프 뒤 값은 변형마다 그 페이로드 잎의 범위 사실을 그 변형일 때로 갖는다: `match` 갈래가 주는 사실과 같다, 1B-50. 없으면 `Option<Vec<u8>>` 결과의 페이로드 슬라이스를 받는 `spec fn`이 길이의 범위 가드 때문에 펼쳐지지 않았다), 구조체 슬라이스는 잎마다 배열이다. 반례는 Rust 표기(`Point { x: 1, y: 2 }`, `Some(-1)`). 명세 `==`는 Rust의 `==`다(2V-05): 구조체는 필드별, 배열은 길이 안의 원소만(고정 길이 16 이하는 원소별로 펼치고, 그 밖은 범위 수량자), 배열 페이로드를 가진 열거형은 같은 변형과 같은 페이로드. 명세에 배열 리터럴·반복(빈 배열 포함)과 `forall` 안의 재귀 호출(묶인 변수마다 측도 의무)을 쓸 수 있다. 증명기가 받지 않는 구성은 없다(E0814 은퇴). 코드 생성(2B-06): 구조체·열거형은 이름 붙은 LLVM 구조체 타입으로 메모리에 있고(열거형은 태그 `i64`와 페이로드 영역, 변형마다 보기 타입), 포인터로 다닌다. Rust가 복사하는 곳(인자, 생성 식 필드, 페이로드, `let`, `=`, `match` 바인딩)에서 복사하고(`memmove`, 크기는 LLVM 배치의 상수식), 데이터 결과는 호출자가 준 메모리(`ret.out`)로 돌려준다. `&T`·`&mut T`는 그 자리의 주소다. 데이터 타입 배열(2B-14, 2V-04b): 지역·필드·페이로드·결과·슬라이스에 `[T; N]`. 원소는 스칼라, 구조체·열거형(배열 필드 포함), 고정 배열(중첩 `[[T; M]; N]`)이고 `Vec`만 안 된다(E0402, ADR-0047 제안). 장소는 `g[i][j] = v`, `b.rows[i].cells[j] = v`처럼 변수·필드·원소의 경로다. 값 매개변수와 결과로도 쓴다(2V-04a: 매개변수는 호출된 쪽이 복사, 결과는 `ret.out`). 스칼라 배열의 결과도 같다. 증명은 구조체 슬라이스와 같은 잎마다 배열이고 길이는 `N`, 리터럴은 원소마다 `store`, 반복은 잎마다 상수 배열이다. 원소 안의 고정 배열은 한 단계 깊은 잎 배열(`(Array Int (Array Int T))`)이고 그 길이는 상수다(`elem_leaves`·`elem_template`). 코드 생성은 메모리의 `[N x %T]`이고, 리터럴은 원소를 모두 계산해 복사해 둔 뒤 채우며(`a = [a[1], a[0]]`), 반복은 채우기 루프, `let`·`=`는 배열 통째 복사다.
- 정수 변환(ADR-0028, 2C-02, 2N-01b): `T::try_from(x).unwrap()`(`T`는 정수 타입)은 값을 그대로 두고, 대상의 범위가 원본의 범위를 담지 못하면(`i64`→`u64`는 `x >= 0`, `i32`→`i16`은 `-32768 <= x <= 32767` 등, `check::conv_obligation`) 범위 의무 E0815를 증명기에 낸다. 담으면(`u64`↔`usize`, `u8`→어느 것이나, `i16`→`i32`) 의무가 없다. `T::try_from(x).ok()`는 `Option<T>`이고 의무가 없다(범위 안이면 `Some`). 코드 생성은 증명된 변환에 명령을 내지 않고, 증명되지 않은 변환에는 대상 범위 검사(비교 하나, `Gen::in_range_of`)와 트랩을 남긴다. 습관: `x as T`는 E0205(정수 대상이면 `T::try_from(x).unwrap()`로 교체하고 같은 의미로 계속 검사), 그냥 `T::try_from(x)`·`.unwrap()`/`.ok()` 밖의 메서드·정수가 아닌 원본은 E0412(`bool`은 `if b { 1 } else { 0 }`로 교체), `T::from`·`.into()`·`.try_into()`는 E0212, `.expect(..)`는 E0213, 명세 안의 변환은 E0513(명세는 정수 타입이 섞인다, ADR-0022). 내장 `print_u64`가 `u64`를 부호 없이 출력한다.
- 조기 반환(ADR-0049 §1·§3·§4, 2K-01a): `return e`·`return`은 문장과 식 자리(`None => return d,`)에 오는 타입 `!`(`TypeKind::Never`)의 식이다. `!`은 어떤 기대 타입에도 맞고(`expect_ty`), 갈래 하나가 `!`인 `if`·`match`는 다른 갈래의 타입을, 끝나지 않는 문장으로 끝나는 꼬리 없는 블록은 `!`을 가진다. 명세 안의 `return`은 E0503. 문장 자리의 `if`·`match`는 닫는 `}`에서 끝난다(Rust: `if c { return; } *x = 1;`은 두 문장). 증명: 반환 지점의 경로 조건 아래에서 사후 조건이 의무이고(`Enc::post_check`, 함수 끝과 같은 함수) 그 경로가 끝난다(`Enc::dead`). 합류(`branch`, `&&`·`||`의 오른쪽)는 끝난 쪽을 빼고 남은 쪽의 조건과 사실로 이어 가며, 루프 몸이 끝나면 불변식 유지·감소 의무가 없다. 이동 검사: `return`이 지나는 모든 소유 지역·매개변수(필드 경로 포함)를 그 출구에서 해제하고(`MoveInfo::exits`), 합류는 끝난 경로를 빼며(`Mv::join`), 같은 블록의 뒤 문장은 보지 않는다. 코드 생성: 둘레 영역의 소유 임시값과 출구 해제 뒤 반환(`Gen::emit_return`, 함수 끝과 공유)하고, 뒤의 코드는 도달할 수 없는 블록에 둔다(값은 `CVal::Never`). E0203 은퇴. 구현 중 기존 건전성 결함 둘을 고쳤다: 루프 머리의 havoc이 몸 안 `match` 갈래의 대입과 `&mut` 참조 `match`의 바인딩 쓰기를 빠뜨렸다(`assigned_in_expr`, 회귀 `tests/verify/fail/loops`의 `arm_assigns`·`binding_writes`).
- 루프 탈출(ADR-0049 §1·§3·§4, 2K-01b·c): `break`·`continue`·`break 'l`·`continue 'l`, 레이블 `'l: while`·`'l: loop`(렉서는 `'l`을 `break`/`continue` 뒤와 `:` 앞(주석을 건너)에서만 레이블로 읽고, 다른 곳의 `'a`는 수명 E0208), `loop [invariant ..,] [decreases ..,] { .. }`(값은 `break e`의 값, `break`가 없으면 `!`). 셋 다 타입 `!`의 식. 루프 밖 E0250, 없는 레이블 E0317, `while`의 값 있는 `break` E0251, `loop`의 `decreases` 없음 E0506, 명세 안 E0503. `loop`의 기대 타입이 모든 `break` 값의 타입. 증명(`Enc::loop_core`, `while`과 공유): 반복 하나의 `break` 지점마다 그 반복의 경로 조건과 상태를 모으고(`VLoop`), 출구는 "조건 거짓 ∨ 각 `break`의 경로 조건"(한 반복 안의 경로라 배타적)과 그 조건에 따른 상태·값의 `ite`다. `continue`는 그 지점에서 대상 루프의 불변식 유지·감소 의무를 진다(`back_to_head`, 몸 끝과 공유). 이동 검사: 루프 안에서 선언되어 아직 소유인 지역을 탈출 간선에서 해제하고(`MoveInfo::exits`), 출구에서 `break` 상태들을, 머리에서 `continue` 상태들을 합류점 규칙(E0414)으로 맞춘다(`MvLoop`, `loop_backs`). 코드 생성: `continue`는 머리로, `break`는 값을 결과 자리에 두고 끝으로 분기하며, 루프 안 영역의 임시값과 출구 해제를 먼저 한다(`GLoop`, `Gen::jump`).
- 범위 `for`(ADR-0049 §2, 2K-01d): `['l:] for i in lo..hi [invariant ..,] { .. }`와 `lo..=hi`. `i`의 타입은 두 끝의 정수 타입(리터럴은 다른 끝의 타입, 둘 다 리터럴이면 `i64`), 두 끝은 들어갈 때 한 번 계산한다. `i`는 루프 안에서만 보이고 대입할 수 없다(E0408, 루프 뒤 E0301, 둘 다 안내 있음). 반복자(`for x in v.iter()`, `for x in &v`) E0252, `decreases` E0253, 정수가 아닌 끝 E0401, 명세 안 E0503. 증명은 펼친 꼴 `let mut i = lo; while i < hi invariant lo <= i && (i <= hi || i == lo), P decreases hi - i { body; i = i + 1; }`(`..=`는 증가 앞에 `if i == hi { break; }`, `continue`는 그 앞에 증가)의 인코딩과 질의가 바이트 단위로 같다(`Enc::loop_core`의 `ForStep`, `end_iteration`, 시험 `for_queries_are_the_while_expansion`). 코드 생성: 머리 비교(`i64`는 부호, 그 밖은 부호 없음), `continue`가 가는 증가 블록, `..=`는 `i == hi`에서 끝으로 나가 타입의 최댓값에서도 넘치지 않는다. E0204 은퇴.
- `?`(ADR-0049 §1·§3·§4·§5, 2K-01e): `x?`는 `x: Option<T>`이고 함수 결과가 `Option<U>`이면 `None`을, `x: Result<T, E>`이고 결과가 `Result<U, E>`(같은 `E`)이면 `Err(e)`를 돌려주고, 그 밖에서 값은 `T`다. 다른 오류 타입·`Option`과 `Result`의 혼용·그 밖의 결과 타입 E0241(암묵적 변환 없음), 열거형이 아닌 피연산자·참조 E0401, 명세 안 E0503. 피연산자는 이동한다(이동 타입이면 `consumed`, 쓰고 난 뒤 E0413). 증명은 펼친 `match x { None => return None, Some(v) => v }`(`Ok(v) => v, Err(e) => return Err(e)`, 갈래는 선언 순서)의 인코딩과 질의가 바이트 단위로 같다(시험 `try_queries_are_the_match_expansion`). 이동 검사는 `?` 지점을 반환 간선으로 보고 그때 소유인 지역을 해제한다(`MoveInfo::exits`). 코드 생성: 태그 비교, 나가는 갈래는 결과 타입의 `None`/`Err`에 오류를 옮겨 담고 `return`과 같은 해제 뒤 반환(`Gen::try_expr`). E0206 은퇴.
- 정수 타입(ADR-0048 §1, 2N-01): `i8`·`i16`·`i32`·`i64`·`isize`, `u8`·`u16`·`u32`·`u64`·`usize`(`isize`·`usize`는 64비트). 검사기는 `TypeKind::Int(IntTy)` 하나로 다루고(폭·부호·한도는 `IntTy`의 메서드), 섞인 폭은 E0401(변환 안내), 범위 밖 리터럴 E0406·부호 없는 부정 E0411(둘 다 안내). 증명은 모두 `Int`에 그 타입의 범위 사실과 넘침 의무(E0803, `T::MIN % -1` 포함), 되감기는 2의 보수 사상이다. 코드 생성은 레지스터에서 `i64`(부호 있는 타입은 부호 확장, 부호 없는 것은 0 확장한 수학적 값), 메모리(배열·`Vec`·필드)에서 제 폭(`i16`·`i32` 등)이고 읽을 때 확장한다(`elem_kind`·`load_mem`). 64비트보다 좁은 타입의 `+`·`-`·`*`는 64비트에서 정확하므로 그대로 계산하고 증명되지 않았으면 타입 범위를 검사한다(`Gen::narrow_arith`), 정수 메서드는 결과를 그 범위로 되감거나 자르거나 검사한다(`Gen::narrow_method`). `Vec` 길이 한도는 원소 크기로 나눈 `isize::MAX`. 128비트는 E0402(열린 질문 1).
- 비트 연산(ADR-0048 §2·§4·§5, 2N-02): `&`·`|`·`^`·`!`·`<<`·`>>`. 우선순위는 Rust: 비교 < `|` < `^` < `&` < 시프트 < `+`(`a & b == c`는 `(a & b) == c`). 파서는 붙어 있는 `<` `<`·`>` `>` 두 토큰을 시프트로 읽는다(어휘는 떼어 두어 `Vec<Vec<i64>>`가 그대로 닫힌다). `&`·`|`·`^`는 같은 정수 타입 둘(섞인 폭은 E0401, 변환 안내) 또는 `bool` 둘(양쪽을 모두 계산, Rust와 같음)이고, `!`는 `bool`에서 논리 부정, 정수에서 비트 반전이다(그 밖은 E0401, 안내 있음). 시프트는 정수만 밀고(E0401) 양은 어느 정수 타입이나 된다(Rust와 같음; 리터럴 양은 `u32`), 값의 타입은 미는 값의 타입이다. 시프트 양이 `0..w`(`w`는 폭) 밖일 수 있으면 넘침 의무 E0803(Rust 디버그 빌드의 panic 조건; 부호 있는 양은 음수도 막는다, 범위 안의 리터럴 양은 의무 없음). `<<`는 폭 밖의 비트를 버리고 `>>`는 부호 있는 타입에서 산술 시프트다. 명세에서 섞인 폭의 비트 연산은 둘을 담는 타입의 폭이고(그런 타입이 없으면 E0401), 명세 시프트의 양이 `0..w` 밖이면 값은 정해지지 않는다(의무는 실행 코드의 것). 증명(혼합 인코딩): 정수는 `Int`로 남고 비트 연산 항만 피연산자 폭의 bitvector를 거친다(`verify::bv_term`: `(bv2nat (bvand x y))`, 부호 있는 타입은 부호 비트를 뒤집은 `bv2nat`에서 `2^(w-1)`을 빼는 2의 보수). 실행 코드는 피연산자마다 bitvector 상수를 선언하고 그 값을 준다(`(= (bv2nat x) a)`, 음수는 `a + 2^w`: `Enc::operand_bv`; `int2bv`보다 모형을 수십 배 빨리 찾는다), 명세는 `((_ int2bv w) a)`. 선형으로 쓸 수 있는 꼴은 선형이다(`verify::linear_bit`): 상수 양 `<<`는 곱셈을 폭으로 되감은 것, `>>`는 바닥 나눗셈(`div`), `a & (2^k - 1)`은 `a mod 2^k`, `!a`는 `-a - 1`(부호 없는 것은 `MAX - a`). bitvector 항에는 결과 범위 사실을 피연산자 범위 아래에서 함께 준다(`bit_facts`: 범위, `&`는 피연산자 이하, `|`는 이상, 부호 있는 타입은 부호별로, `^`의 부호, `>>`의 크기). 의무는 먼저 bitvector 항을 정수 상수로 추상한 질의(`abstract_bits`: 같은 항은 같은 상수, 묶인 변수를 담은 항은 그대로, 정량 정의가 있으면 그 지상 인스턴스로)로 풀고 증명되면 끝, 아니면 정확한 질의로 간다(약한 질의의 증명은 증명이다). 추상 질의에는 표기만 다른 같은 연산의 합동 사실이 붙는다(`bit_congruences`, 1B-49): 실행 코드의 피연산자 상수(값이 주어진 `|'bv@k|`), 명세의 `((_ int2bv w) v)`, 수 리터럴을 폭과 값으로 읽어 같은 나무가 되는 두 항에 "다른 잎의 값이 같으면 두 항이 같다"를 준다. 어느 모형에서나 참이라(`bv2nat`은 한 폭에서 단사, `bv2nat`과 같은 값은 범위 안) 추상 질의는 여전히 정확한 질의보다 약하다. 이것이 없으면 코드의 `x ^ k`와 명세의 `x ^ k`가 서로 모르는 두 상수가 되어 정확한 질의(`int2bv`)로만 이어졌고, 32비트 `^` 하나가 rlimit 5,000,000에서 끝나지 않았다(`lib/crc32.bmb`의 `bit_step` 10,003,176 → 2,481). 시험 `bit_congruences_relate_notations_and_hold`(사실이 표본 값마다 Z3로 참), 코퍼스 `tests/verify/pass/bits`의 `mix`·`mask_xor`. 64비트 가변 시프트의 정의가 필요 없는 증명의 비용이 줄었다(`tests/run/bits`의 `ones`의 정의 전체 757860 → 8988). `--emit-smt`에는 추상 질의가 의무의 첫 시도이고 정확한 질의가 `; exact query of obligation k`로 뒤따른다(`scripts/solver_stability.py`는 첫 시도를 잰다). 항이 Rust의 연산과 같고 사실이 참임은 `tests/lemmas.rs`가 항을 계산해 확인한다(8비트는 모든 쌍, 넓은 타입은 경계·2의 거듭제곱 근처·의사 난수 값). 코드 생성(§5): 레지스터의 확장된 값에 `and`·`or`·`xor`는 그대로 확장된 값을 내므로 검사가 없고, `!`는 부호 있는 타입에서 `xor -1`, 부호 없는 것은 `xor MAX`, `>>`는 `ashr`/`lshr`(64비트에서 정확), 좁은 타입의 `<<`는 `shl` 뒤 제 폭으로 `trunc`하고 다시 확장한다. 증명되지 않은 시프트 양은 `icmp ult amount, w`로 검사하고 트랩한다(`Gen::shift`, 시험 `an_unproved_shift_traps_exactly_from_the_width`). W0904 변이에 `&`↔`|`, `^`→`|`, `<<`↔`>>`.
- 비트 메서드(ADR-0048 §2, 2N-03): 정수 타입의 `rotate_left`·`rotate_right`·`wrapping_shl`·`wrapping_shr`(양은 `u32`이고 폭으로 나눈 나머지만큼, 의무 없음), `count_ones`·`count_zeros`·`leading_zeros`·`trailing_zeros`(`u32`), `swap_bytes`. Rust의 시그니처다: 인자 개수 E0405, `u32`가 아닌 양 E0401, 정수가 아닌 수신자 E0404(모두 안내). 증명(`verify::bit_method`): 상수 양은 선형 꼴(감싸는 시프트는 `<<`·`>>`의 꼴, 회전은 두 조각의 합), 그 밖은 이름 붙은 bitvector 함수(`bmb_rotl32`·`bmb_ctpop64` 등, `subproof::helper_def`, 질의가 쓰는 것만 정의가 들어간다) 하나를 `bv2nat`로 감싼 항이고, 실행 코드는 결과 사실(타입 범위, 개수는 `0..=w`이고 0일 때만 극단)을 가정한다. 이름 붙은 함수라 코드와 명세의 같은 메서드가 추상 질의의 합동 사실로 이어진다. 항이 Rust 메서드와 같고 사실이 참임은 `tests/lemmas.rs`의 `bit_method_terms_are_rusts_methods`. 코드 생성(`Gen::bit_method`): 제 폭으로 자른 값에 LLVM `fshl`/`fshr`(양은 폭의 나머지)·`ctpop`·`ctlz`/`cttz`(0에서 폭)·`bswap`, 다시 확장. 감싸는 시프트는 양을 `w - 1`로 마스크하고 `<<`·`>>`와 같은 명령(`Gen::shift_inst`). 모든 정수 타입에서 rustc와 같은 값임을 `tests/codegen.rs`의 `bit_methods_compute_rusts_results`가 확인한다(경계·무늬 값과 폭 안팎의 양). `to_be_bytes` 등 바이트 배열 메서드는 2N-09.
- `assert(e) by (bit_vector);` 하위 증명(ADR-0048 §4, 2N-03, `src/subproof.rs`): `e`를 따로 된 질의(`QF_BV`)에서 증명하고 그 뒤로 바깥 증명이 가정한다(E0818: 반례는 자유 변수의 값, 고칠 길 안내). 실행 코드·`proof` 블록·`proof fn` 몸 어디서나 같고, 명세 안은 E0503. 질의는 `e`의 자유 변수만 보고 각각 제 타입의 모든 값을 돈다(경로 사실 없음, Verus 규칙: 필요한 사실은 `p ==> q`로). 번역은 인코더가 `e`로 만든 항(자유 변수마다 새 기호)을 정수 부분항마다 구간을 담는 폭의 2의 보수 bitvector로 옮긴 것이라 바깥 질의가 가정하는 사실과 정확히 같다(`bit_vector_translations_are_exact`). 바깥은 `(=> (and 자유 변수의 범위 .. 펼친 인자의 범위 ..) e)`를 가정한다. 단언이 부르는 spec fn은 `#[uses]`에 있고 재귀·제네릭이 아니며 정수·`bool`만 다루면 펼친다(인자는 `define-fun`으로 한 번 이름 붙임, 타입 밖일 수 있는 인자는 하위 증명의 가정이자 바깥 사실의 전제). 번역할 수 없는 것(드러나지 않거나 재귀인 spec fn, 부호 있는 `/`·`%`, 변수로 나누기)은 E0818과 사유이고, 드러나지 않은 spec fn은 `#[uses]` 안내라 `bmb uses`가 채운다(`a_bit_vector_sub_proof_gets_the_spec_fns_it_unfolds`). 항이 아닌 것(원소, 필드, 수량자, `old`, 참조 뒤의 값, 데이터 값)은 검사기의 E0515, 다른 증명기 이름과 Verus의 `by { .. }`는 E0516(이름이면 `by (..)`를 지우는 수정). 정규형은 `assert(e) by (bit_vector);`. 증명 캐시·`--emit-smt`(`; obligation k: E0818 .. (sub-proof)`)·증분 키는 다른 의무와 같다. 추상 질의의 합동 사실(1B-49)은 잎의 값이 다르게 쓰인 같은 모양의 항도 잇는다(`t[i] ^ (c >> 8)`와 `byte(i, 0) ^ (c >> 8)`, 모양당 64개까지). 건전성 퍼저 `tests/soundness_bitvector.rs`: `u8`·`i8` 두 변수의 무작위 단언(명세 산술, 비트 연산, 시프트, `!`, 메서드, `if`, 인자가 타입 밖일 수 있는 spec fn)을 65,536점 모두에서 해석기로 계산해, 증명된 단언은 가드 아래 모든 점에서 참이고 반례는 가드 안의 거짓인 점임을 확인한다. 쓰는 곳: `lib/crc32.bmb`의 표 보조 정리 `table_lemma`(rlimit 104,291), `tests/run/bit_methods`의 `next_power`.
- 정수 상수(2N-06): 정수 타입의 `MIN`·`MAX`(Rust 연관 상수). 실행 코드와 명세 모두에서 그 타입의 값이고(`check::int_const`), 없는 상수(`i64::MID`)는 E0305.
- 검사·포화 산술(ADR-0028 §3, 2C-03): 정수 메서드 `saturating_add/sub/mul`은 수학적 결과를 타입 범위로 자른 값이고, `checked_add/sub/mul/div/rem`은 `Option<T>`다(결과가 범위 안이면 `Some`, 나눗셈은 0으로 나누기와 `i64::MIN / -1`·`i64::MIN % -1`이 `None`). 둘 다 의무가 없고 명세에서도 쓴다. 증명은 `wrapping_*`과 한 함수(`verify::int_method`)로 인코딩하고 `checked_div/rem`의 값에는 `/`·`%`의 나눗셈 사실을 붙인다. 코드 생성: 포화 `add`·`sub`는 `llvm.{s,u}{add,sub}.sat.i64`, `mul`은 `*.with.overflow`와 `select`, 검사는 넘침 표지가 `Option`의 태그이고 `div`·`rem`은 표지가 거짓이면 1로 나눠 트랩하지 않는다. `pow`·`abs`·`overflowing_*`는 E0404.
- `Vec<T>`(ADR-0031, 2G-02, 검사기만): 원소는 스칼라 또는 배열 없는 구조체·열거형(E0402, `Vec<Vec<T>>`과 이동 원소는 2O-03b). 2O-03부터 구조체 필드·열거형 페이로드·`Option<Vec<T>>`·`Box<Vec<T>>`에 담긴다. 매개변수는 `Vec<T>`(이동)·`&Vec<T>`·`&mut Vec<T>`, 반환은 `Vec<T>`. `Vec::new()`·`Vec::with_capacity(n)`(원소 타입은 기대 타입에서), `push`·`pop`(`Option<T>`)·`len`·`truncate`·`clone`, `v[i]` 읽기·대입, 슬라이스 매개변수에는 인자 자리의 `v.as_slice()`·`v.as_mut_slice()`. 변경 메서드는 `let mut` 지역이나 `&mut Vec<T>`에서만(E0408), 명세에서는 `len`·인덱스·`as_slice`만(E0503), spec fn은 `Vec`을 받거나 돌려주지 않는다(E0402). 습관: `&v`를 슬라이스 자리에 E0218(`v.as_slice()`로 교체), `drop`·`mem::take`류 E0219, `Vec ==` E0514, `is_empty`·`first`·`get`·`iter` 등 E0404(안내). 이동 검사(`src/moves.rs`): 값 쓰임(`let`, 대입 오른쪽, 인자, 블록 값)이 이동이고 이동 뒤 사용은 E0413, `*v`에서 꺼내기도 E0413. 합류점(`if`·`match` 갈래, `&&`·`||`·`==>` 오른쪽, 루프 머리와 몸 끝)에서 "아마 이동"은 E0414. 같은 호출에서 `&mut v`·`v.as_mut_slice()`와 `v`의 이동·참조는 E0410. 이 검사가 해제 지점(블록 끝에 남은 소유 지역, 소유 값을 바꾸는 대입)을 정해 코드 생성(2G-04)에 넘긴다. 증명(2G-03, ADR-0031 §3): 인코더는 `Vec<T>`을 슬라이스 값(원소 배열과 길이의 쌍), `&Vec<T>`·`&mut Vec<T>`을 슬라이스 참조로 본다(`Tables::slice_view`). 그래서 인덱스 의무, 길이 상한 사실, 루프·호출 뒤 다시 정하기, 명세 인자, 반례가 슬라이스 경로 그대로다. 길이를 바꾸는 것만 새로 있다: `push`는 `len < LEN_MAX(T)` 의무 E0816과 `store`·`len + 1`, `pop`은 `len = 0`이면 `None`, `truncate(n)`은 `min`, `Vec::new()`은 길이 0, `with_capacity(n)`은 `n ≤ LEN_MAX(T)` 의무 E0816. `&mut Vec<T>` 인자 호출 뒤에는 길이도 새 상수다(callee의 `ensures`만 가정). 코드 생성(2G-04, ADR-0031 §4): `Vec`은 메모리의 머리 `%bmb.vec = {ptr, len, cap}`이고 구조체처럼 주소로 다니며, 머리 복사가 곧 이동이다(값 인자는 머리 사본, 결과는 `ret.out`). 인덱스는 쓸 때마다 버퍼와 길이를 읽고(검사는 증명되지 않을 때만), `push`는 `len == cap`이면 `@bmb_vec_grow`(용량 두 배, 최소 4, `realloc`), `pop`은 `Option` 임시값, `truncate`는 `umin`, `clone`은 새 버퍼와 `memcpy`다. 크기가 `isize`를 넘거나 할당이 실패하면 `abort`. E0816은 다른 의무처럼 증명되면 `; proved E0816`, 아니면 검사와 트랩. 해제: `moves.rs`가 정한 블록 끝(소유로 남은 지역·값 매개변수)과 소유 값을 바꾸는 대입, 그리고 이동되지 않고 읽힌 임시 `Vec`은 그 영역(문장, 블록 값, `match` 갈래, `&&`·`||` 오른쪽, 루프 조건) 끝에서 해제한다. 해제되는 버퍼를 가리키는 데이터 값은 먼저 복사한다. 해제는 2O-01부터 타입별 drop glue(`Box` 항목)다. 런타임은 힙을 쓰는(`Vec`·`Box`를 담는) 프로그램에만 IR로 들어간다(libc `malloc`·`free`·`abort`, `Vec`이면 `realloc`).
- `Box<T>`(ADR-0047, 2O-01): `T`는 값 타입(스칼라, 구조체·열거형, 배열, `Box`. `Box<()>`·참조는 E0402, `Box<Vec<T>>`는 2O-03). `Box::new(v)`(상자 타입은 기대 타입, 없으면 `v`의 타입), 읽기 `*b`·`b.f`(필드는 `&`와 모든 `Box`를 거쳐 투영), 쓰기 `*b = v`·`b.f = v`·`(*b)[i] = v`(`let mut` 지역이나 `&mut Box<T>`에서만, E0408), 인자 `&*b`·`&mut *b`. `Box`는 구조체 필드·열거형 페이로드·`Option`·`Result`에 담긴다. `Box` 이름은 예약(E0309). 이동 분류는 구조적이다(`check::is_move`): `Vec`·`Box`와 그것을 필드·페이로드·타입 인자로 담는 구조체·열거형은 이동하고, 나머지는 복사다(`Copy` 경계는 이동 타입을 받지 않음, E0428). 아직 없는 것: 재귀 타입(E0421 유지, 2O-02), 이동 원소의 배열·`Vec`(E0402, 2O-03), 필드나 `*b`에서 꺼내는 이동(E0413, 2O-03). 습관: `Rc`·`RefCell`·`Cell`·`Arc` E0238, 코드의 `Box ==` E0425(수정 안내 `*a == *b`). 이동 검사(`moves.rs`)는 `Vec` 규칙을 모든 이동 타입으로 넓혔다: 블록·`if`·`match` 갈래의 값은 언제나 이동(Rust처럼 `{ v }.len()`도), 이동 페이로드를 묶는 `match`는 피검사 값을 이동하고(`MoveInfo::consumed`) 갈래 끝에 남은 바인딩을 기록한다(`arm_drops`), 소유 필드·`*b`에 대입하면 옛 값을 해제한다(`replaces`). 증명(ADR-0047 §3): `Box<T>`는 어디서나(필드, 페이로드, 타입 인자 포함) 값 `T`다(`Tables::slice_view`), `Box::new(v)`는 `v`. 코드 생성(§4): `Box`는 `malloc`한 주소를 담은 칸(`ptr`)이고 데이터 값처럼 주소로 다닌다(칸 복사가 이동). `*b`·`b.f`는 주소를 읽어 들어간다(`&mut Box<T>` 매개변수의 `*r`은 칸 자체). 해제는 타입별 drop glue `@"bmb_drop.<type>"`(모듈 단위로, 이동 타입마다): `Vec`은 버퍼, `Box`는 값의 glue 뒤 `free`, 구조체는 필드 순서, 열거형은 변형의 페이로드 순서. 해제 지점은 `Vec`과 같고(블록 끝, 대입, 버린 식 문장), 읽기만 한 임시값(`mk().x`, `*mk()`, `&mk()` 인자, 이동하지 않는 `match`의 피검사 값)은 영역 끝에서 해제한다. 이동하는 `match`는 갈래 시작에서 묶지 않은 이동 페이로드를, 끝에서 남은 바인딩을 해제한다. 할당 실패는 `abort`(`@bmb_box_alloc`). 시험 `run_corpus_frees_every_allocation_once`는 힙을 쓰는 실행 코퍼스를 `-O0`으로 빌드해 valgrind(없으면 AddressSanitizer)로 누수·이중 해제·해제 뒤 접근이 없음을 본다.
- 재귀 타입(ADR-0047, 2O-02): 자기를 `Box` 아래에만 담는 열거형·구조체(`enum Expr { Num(i64), Add(Box<Expr>, Box<Expr>) }`, `struct Node { v: i64, next: Option<Box<Node>> }`), 상호 재귀 포함. 값으로 직접 담으면 E0421(수정 안내 `Box`), 유한한 값이 없으면 E0421(최소 고정점 `check_type_cycles`: 재귀를 끝내는 변형이나 `Option`이 필요), 제네릭 타입은 자기 매개변수 그대로만 자기를 담는다(다른 인자·다른 타입을 거치면 E0421: 인스턴스가 끝나지 않음), 재귀 타입은 아직 배열을 담지 않는다(E0402). 읽기는 참조 `match`(ADR-0055): `match e`(`e: &E`)·`match &n.next`의 바인딩은 페이로드를 가리키는 참조(`&P`)이고 `*n`·`&**a`로 읽는다. 참조 뒤나 필드에서 소유 페이로드를 값으로 묶으면 E0413(기계 수정: 참조 `match`). `&mut` 참조 `match`(2O-04b, `match e`·`match &mut b.label`)의 바인딩은 `&mut P`로 페이로드 자리를 쓰고(`*n = v`, `double(&mut **a)`), 갈래 안에서 피검사 변수를 쓰면 E0410이다. 증명은 갈래 끝에 바인딩의 새 값으로 변형 값을 다시 만들어 피검사 자리에 쓰고(`match_arms`의 `back`), 코드 생성은 바인딩을 페이로드 주소로 두며 스칼라는 레지스터 슬롯에 읽었다가 갈래 끝에 되쓴다. 검사기는 `&mut` 인자 자리의 하위 식 타입도 기록한다(`place_of`: `&mut **a`의 상자 풀기). 종료: `decreases`는 정수 또는 재귀 열거형 값(`check::measure_type`, 구조체면 그 재귀 필드를 쓰라는 안내). 증명(ADR-0047 §3): `Box`가 투명하므로 재귀 열거형은 그대로 재귀 SMT 데이터타입이고, 순환하는 열거형은 함께 선언한다(`verify::datatypes`, Tarjan 성분). 구조적 감소는 크기 함수 없이 결정 가능한 조건이다(`Enc::decrease_goal`): 호출의 측도 항이 호출자 측도에서 선택자 사슬이고 각 선택자가 그 생성자의 값에 적용되면(엄격한 하위 항) 증명되고, 아니면 실패한다(반례). 기본값(`default_val`)은 만드는 중인 열거형을 다시 요구하지 않는 첫 변형. 코드 생성: `Box`가 배치를 끊으므로 바뀐 것은 재귀 drop glue뿐이다(타입마다 한 번, 서로 부름).
- 소유 필드와 부분 이동(ADR-0047 §2, 2O-03): 필드 자리의 `Vec` 메서드·인덱스(`s.buf.push(x)`, `s.buf[i] = v`, `s.buf.len()`)는 그 자리를 직접 쓴다(`let mut` 지역이나 `&mut` 매개변수 아래, `Checker::writable`). 지역 구조체의 필드는 따로 꺼낼 수 있다: `moves.rs`가 이동 상태를 필드 경로(`c.a.data`)로 두고, 꺼낸 필드를 다시 쓰면 E0413, 꺼낸 뒤 구조체 전체를 쓰면 E0433, 합류점에서 한쪽만 꺼내면 E0414, 꺼낸 필드에 다시 대입하면 소유로 돌아온다. 지역 구조체의 필드에 대한 `match`(`match l.e`)도 그 필드만 꺼내는 부분 이동이다(2O-06, 참조 뒤·`Box` 안의 필드는 E0413). 블록 끝에는 남은 소유 필드만 해제하고(`drops`의 경로, 코드 생성 `drop_path`), 부분 이동된 자리에 통째로 대입하면 남은 필드를 해제한다(`partial_replaces`). 참조 뒤나 `Box` 안의 필드에서 꺼내기는 E0413(`mem::replace`는 2O-04). 증명은 바뀌지 않는다: 필드의 `Vec`은 슬라이스 값의 잎(`s.buf.e`, `s.buf.len`)이고 필드 자리의 `push`도 같은 인코딩이다. 코드 생성: `Vec` 머리는 데이터 타입 정의보다 먼저 선언하고, 열거형 페이로드 크기 계산에서 24바이트다.
- 중첩 컨테이너와 이동 원소(ADR-0047 §1·§3·§4, 2O-03b): `Vec` 원소는 스칼라, 배열 없는 구조체·열거형(이동 필드 포함), 그리고 그것의 `Vec`·`Box`(`Vec<Vec<T>>`, `Vec<Row>`, `Vec<Box<T>>`, `Checker::vec_elem_ok`), 슬라이스 매개변수 `&[Vec<T>]`. 원소 자리의 메서드·인덱스(`g[i].push(x)`, `g[i][j] = v`, `rows[i].cells.len()`). 원소에서 값으로 꺼내기는 E0413(`pop`이나 읽기로), 원소 대입은 옛 원소를 해제, 이동 원소의 `clone`은 아직 E0404. `Vec`을 거친 재귀 타입은 E0421(2O-03c), 이동 원소의 고정 배열은 아직 E0402. 증명: 안쪽 `Vec`은 원소 잎 배열이 한 단계 깊어지고 길이가 원소마다의 배열 잎이 된다(`elem_leaves`·`elem_template`, 고정 길이는 상수, 가변 길이는 배열이라 `select_val`·`store_val`이 함께 고른다), 새 원소 배열을 만들 때 안쪽 길이의 범위 사실(`inner_len_facts`), 빈 `Vec`의 기본값. 반례는 중첩 표기(`[[] (len 0), [0, 0] (len 2)] (len 2)`). 코드 생성: 원소 자리는 데이터 원소처럼 주소, `Vec` glue는 원소마다 glue를 부른 뒤 버퍼를 풀고, `truncate`는 잘린 원소를 해제한다.
- `std::mem::replace`·`swap`과 이동하는 타입 매개변수(ADR-0047 §2, 2O-04): `std::mem::replace(&mut p, v)`는 `p`의 옛 값이고 `p`는 `v`를 담는다, `std::mem::swap(&mut a, &mut b)`는 두 자리의 값을 바꾼다(첫 인자는 `&mut 자리` 또는 `&mut T` 매개변수 그대로, 명세에서는 E0503, 같은 변수의 두 자리는 E0410, `mem::replace`는 E0214로 `std::mem::replace`, `std::mem::take`는 E0219 유지). 증명은 자리 쓰기(`set_at`)이고 코드 생성은 옛 값을 사본에 옮긴 뒤 새 값을 쓰므로 해제가 없다(`Gen::mem_call`, 스칼라 슬롯·배열 지역 포함 `any_place`). `&mut` 뒤에서 소유 값을 꺼내면 E0239(기계 수정: `Vec`이면 `std::mem::replace(&mut r.f, Vec::new())`, `Option`이면 `None`), 공유 참조 뒤는 E0413. 타입 매개변수의 `Copy` 경계는 이제 선택이다(E0402 해제): `Copy` 없는 매개변수의 값은 이동하고(`check::is_move_in`, `moves.rs`가 함수의 그런 매개변수를 받음), `Copy` 경계는 이동 타입 인자를 거부하며(E0428), 그런 매개변수의 배열은 아직 E0402(2O-03c). 인스턴스의 해제는 단형화된 타입의 glue다.
- `Vec`을 거친 재귀와 이동 원소 배열(ADR-0047 §1·§3, 2O-03c): 열거형이 낀 순환은 `Vec`을 거쳐도 된다(`enum Tree { Leaf(i64), Many(Vec<Tree>) }`): 증명에서 페이로드의 원소 배열이 그 데이터타입인 중첩 데이터타입이고, 구조적 감소의 사슬은 원소 단계 `(select (|T::V.0.e| x) i)`를 받으며 `0 <= i < len`을 함께 요구한다(`Enc::decrease_goal`, `select_app`). 구조체만으로 된 순환은 아래 2O-03d. Z3 4.15.4가 서곡 뒤에 선언된 중첩 데이터타입에서 만족 질의를 끝내지 않아(rlimit도 무시, `dev-docs/measurements/z3-nested-datatypes`) 모든 질의에서 데이터타입 선언을 서곡 앞에 둔다(`needed_decls`). 반례는 모델의 `let`을 풀어 보인다(`unlet`). 이동 원소(`Box`, 소유 필드 구조체, `Copy` 없는 매개변수)의 고정 배열을 받는다(`[v; N]` 반복은 E0402, 원소에서 꺼내기 E0413, `std::mem::replace(&mut a[i], ..)`로 교체): 배열 glue는 원소 순서로 해제하고, 배열 지역의 해제(`drop_path`의 `Slot::Arr`)와 읽기만 한 임시 배열의 해제가 있다. `Vec` 원소의 고정 배열은 여전히 E0402(`Vec<Vec<T>>`를 쓴다).
- 구조체만으로 된 재귀(ADR-0056, 2O-03d): `struct Node { v: i64, kids: Vec<Node> }`처럼 열거형 없이 자기를 담는 구조체(`check::struct_cycle`)는 증명에서 `Int` 손잡이다(정렬 이름은 구조체의 것, `define-sort`, 데이터타입보다 먼저). 필드는 선택자 함수(열거형 페이로드와 같은 이름 규칙, `variants`가 생성자 하나로 돌려준다), 구조체 식과 필드 쓰기(`n.kids[0].v = x`, `n.kids.push(c)`: `Step::DtField`)는 새 상수와 선택자 등식(`Enc::mk_struct`), 필드의 범위·길이 사실은 의무의 경로 조건과 목표에 나오는 선택자 적용마다 지상으로(`Prog::struct_facts`; 값 정의 `decls`는 훑지 않는다: 뒤에서나 다른 경로에서 만든 값의 사실이 그 필드를 검사하는 의무를 미리 가정하게 되는 건전성 결함을 소유 퍼저가 찾았다, `tests/verify/fail/rec_structs`의 `built`): 생성자 함수와 한정자가 없다. 빈 `Vec`의 기본 원소는 선언된 상수 `'arb`(`elem_default`). `decreases n`을 받고(`measure_type`) 구조적 감소는 2O-03c의 사슬(구조체 생성자는 판별자 없음, `Prog::struct_ctors`). 명세에서 이 구조체의 값을 만들면 E0432, 재귀 타입이 `Vec`을 담으면 명세 `==`는 E0431(`Checker::recursive_with_vec`: 2O-03c의 열거형 `==`가 인코더를 끝나지 않게 하던 결함도 막는다). 반례는 입력을 한 단계 필드로 보인다(`Node { v: 0, kids: [Node { .. }] (len 1) }`). 데이터타입·정해지지 않은 정렬을 먼저 시도해 쟀다(`dev-docs/measurements/z3-nested-datatypes`). 코드 생성은 그대로(보통 구조체, 서로 부르는 drop glue).
- 제네릭(ADR-0046, 2T-01): 함수·구조체·열거형·고유 `impl`에 타입 매개변수 `<T: Copy>`. `Copy` 경계는 2O-04부터 선택이다(없으면 값이 이동한다, 아래 `std::mem` 항목). 내장 경계 `Eq`·`Ord`(2T-02): `T: Eq`이면 코드에서 `==`·`!=`, `T: Ord`이면 `<`·`<=`·`>`·`>=`까지(`Ord`는 `Eq`를 포함). 정수 타입과 `bool`이 둘 다 가진다(`false < true`). 데이터 타입은 아직 아니다(ADR-0046 열린 질문 4). 증명에서 `Ord` 매개변수는 정렬 위의 비해석 전순서 `|'T.le|`(반사·반대칭·추이·전체 공리), 인스턴스에서는 그 타입의 순서다(`bool`은 함의). 사용자 trait은 아래 항목. 호출은 타입 인자를 쓴다: `f::<i64>(x)`, `Cell::<u64>::new(v)`(`impl`의 것은 타입 뒤, 함수의 것은 이름 뒤). 생략하면 E0237이 인자 타입과 기대 결과 타입에서 추론해 써 넣는다(추론할 수 없으면 안내만). 개수는 E0429, 타입 인자는 값 타입(E0403)이고 경계를 채운다(E0428, `Vec`은 `Copy`가 아님). 구조체 생성·변형 값에는 타입 인자를 쓰지 않는다: 기대 타입이나 필드·페이로드 값에서 정하고, 없으면 E0424. `where` 절(함수·`impl`·구조체·열거형)은 Rust 습관 E0240이고, 기계 수정이 경계를 각 타입 매개변수 옆으로 옮긴다(정규형, 2T-03. 매개변수가 아닌 타입의 경계는 안내만). 정의 해시(`fmt::qualified_text`)는 제네릭 `impl`의 매개변수와 경계, trait impl·trait 메서드의 trait과 타입을 함께 담는다(`impl` 경계를 바꾸면 그 함수의 증분 키가 바뀐다). 재귀 호출이 자기 매개변수를 더 큰 타입으로 감싸면(`f::<[T; 2]>` in `f<T>`) E0430. `T` 값의 `==`는 명세에서 언제나, 코드에서는 `T: Eq`가 있을 때(없으면 E0428). 증명(ADR-0046 §4): 제네릭 정의는 한 번 증명하고 매개변수는 비해석 정렬(`(declare-sort |'T| 0)`, 빈 배열의 바탕 값 `|'T.default|`)이다. 제네릭 `spec fn`은 쓰이는 인스턴스(`same<i64>`, `same<T>`)마다 선언·정의되고(`verify::prepare`가 정의·인스턴스 본문·제네릭 실행 함수 계약을 따라 모은다), `#[uses(f)]`는 `f`의 모든 인스턴스를 드러낸다. 호출자는 호출의 타입 인자를 대입한 계약을 쓴다(`Enc::tsub`). 반례에서 정렬의 값은 `T#0`, `T#1`. 코드 생성(§5): 단형화. 실행 함수가 부르는 인스턴스(`@"g::id<i64>"`)를 차례로 낮추고, 증분 IR 캐시(2T-04): 인스턴스는 자기 키(기반 정의의 IR 키 + 인스턴스 텍스트 + 타입 인자가 가리키는 데이터 타입 선언)로 저장되고, 모든 조각은 부르는 인스턴스와 쓰는 인스턴스 타입(`incremental::IrDeps`, 타입은 `ty_str`으로 저장하고 `check::parse_ty`로 읽음)을 함께 저장해 적중해도 그 인스턴스들을 낮추도록 큐에 넣는다. 맵: L1 서명에 타입 매개변수, L2 호출 간선에 `type_args`.
- 스칼라 참조(ADR-0054, 2T-08): 매개변수 `x: &i64`·`x: &mut bool` 등(정수 타입·`bool`). 본문은 `*x`로 읽고 `*x = v`로 쓰며, 계약의 이전 값은 `*old(x)`. 코드 생성은 호출자의 슬롯을 가리키는 포인터를 지역 슬롯처럼 쓰고(`Slot::Scalar`), 인자가 지역·스칼라 참조 매개변수면 그 슬롯을, 필드·원소면 값을 담은 임시를 넘기고 `&mut`이면 호출 뒤 되쓴다(`Gen::scalar_ref`). 증명은 기존 `&mut` 인자 처리 그대로. 제네릭 `&T`의 스칼라 인스턴스도 같은 길이다.
- trait(ADR-0046 §1·§2, 2T-07a): `trait Shape { #[effects(pure)] fn area(self: &Self) -> i64; }`(메서드는 시그니처만, `;`로 끝남, `Self`는 구현 타입), `impl Shape for Sq { .. }`·`impl<T: Copy + Shape> Shape for Wrap<T> { .. }`(impl의 함수는 `Self` 대신 구현 타입을 쓴다. `Self`는 E0305가 그 타입으로 고친다), 경계 `T: Shape`(다른 단위의 trait은 `unit::Shape`), 호출 `Shape::area(&x)`. `Self`는 쓰지 않고 인자 타입과 기대 결과 타입에서 정한다(정할 수 없으면 E0237, trait 경로의 타입 인자는 E0429, 메서드 자신의 타입 인자는 `Shape::pick::<U>(..)`). `Self`가 구체 타입이면 그 impl의 함수를 부르고 그 계약을 쓴다. 매개변수(`T: Shape`의 `T`)면 trait의 서명만 안다(결과는 임의 값). trait 계약(2T-07b): trait 메서드는 `requires`·`ensures`를 가지고(이름 붙은 술어, `self`·매개변수·결과 이름, `*old(x)`·`old(self)`), trait의 `spec fn m(self: &Self) -> T;`는 impl마다 정의한다(`spec fn m(self: &Sq) -> T { .. }`). 경계 호출(`Self`가 매개변수)은 trait 계약을 쓰고(전제 E0801, 결과 가정), trait의 spec 메서드는 그 정렬 위의 비해석 함수 `unit::Tr::m<T>`다. 구체 `Self`면 impl의 함수·spec 정의다. impl 함수는 정제 의무 E0817을 진다(`Enc::refines`, 위치 순으로 매개변수를 맞춤): trait의 전제가 impl의 각 전제를 함의하고, trait 전제와 impl 결과(새 결과 값, `&mut` 뒤의 새 값)가 trait의 각 결과를 함의한다. `#[uses(Tr::m)]`는 trait spec 메서드의 모든 impl 정의를 드러낸다(`check::uses_target`, `Prog::revealed`). trait 메서드의 `decreases`는 E0207(경계 호출은 측도를 갖지 않는다). 명세 정수는 무한 정수라(ADR-0022) 비해석 spec 메서드의 결과는 `i64` 범위를 가정하지 않는다: 결과를 원래 인자로 말하는 술어(`spec fn scored<T: Copy + Score>(x: &T, r: i64) -> bool { r == Score::value(x) }`)를 쓴다. 검사: blanket impl `impl<T> Tr for T` E0235, `dyn Trait` E0236, 같은 타입일 수 있는 두 impl E0311(타입 매개변수는 무엇과도 겹친다고 본다), trait 단위도 타입 단위도 아닌 곳의 impl E0312, 빠지거나 trait에 없는 메서드 E0315, `Self = T`로 바꾼 trait 서명과 다르거나 trait의 `pure`를 `io`로 구현 E0316, 경계 불충족·impl 없는 구체 타입 E0428, impl 타입에 없는 impl 매개변수 E0420, `Copy`·`Eq`·`Ord` 이름의 trait E0309. 구현 타입은 `Copy` 값 타입이다(ADR-0047 전까지). 기본 본문(2T-07c): trait 메서드는 본문을 가질 수 있다(`fn twice(self: &Self) -> (r: i64) ensures .. { Shape::area(self).saturating_mul(2) }`, `spec fn label(self: &Self) -> i64 { 7 }`). 기본 본문은 `Self`를 정렬로 한 번, 그 메서드 자신의 계약과 다른 메서드의 trait 계약으로 증명한다(정의 `unit::Shape::twice`, `check::defs_of`에 포함). 그 메서드를 정의하지 않은 impl의 호출은 기본 본문을 그 타입으로 부르고(`check::dispatch`가 trait 메서드 경로와 `Self`를 돌려준다, 코드 생성은 인스턴스 `unit::Shape::twice<unit::Sq>`), 정의한 impl은 보통처럼 정제 의무를 진다. spec 기본 본문은 그것을 쓰는 구체 `Self` 인스턴스에서만 `#[uses(Tr::m)]`로 드러난다(경계 `T`에서는 아니다: 그 impl이 재정의할 수 있다). 경계 `Self` 호출을 거치는 재귀(프로그램이 닿는 인스턴스 그래프의 순환, `check::trait_cycles`)는 측도를 확인할 수 없어 E0207이다(`impl<T: Shape> Shape for Wrap<T>`가 `T`의 것을 부르는 구조적 위임은 순환이 아니다). 경로: trait 메서드 `unit::Shape::area`, impl 함수 `<unit::Sq as unit::Shape>::area`(`check::defs_of`가 모든 정의를 이 경로로 내놓는다). 증명: impl 함수는 보통 정의로(제네릭 impl은 매개변수를 정렬로) 한 번 증명하고, trait 호출은 `check::dispatch`로 impl 함수와 타입 인자를 찾아 그 계약을 쓴다. 코드 생성: 같은 `dispatch`로 impl 함수(제네릭 impl은 인스턴스)를 정적으로 부른다. 증분 키: trait 메서드를 이름으로 부르는 정의는 그 메서드의 모든 impl 함수의 표면을 읽는다. 정규형: 단위 안에서 하위 단위 → trait(이름순) → 다른 단위 타입의 trait impl → 타입(각 타입 뒤에 고유 impl, 그 타입의 trait impl) → 함수. 맵: L0·L1에 trait(`def_kind: "trait"`, 한 줄 정규형)과 impl 함수, L2 호출 간선은 구체 `Self`면 impl 함수, 아니면 trait 메서드.
- 증명 함수(ADR-0062, T1-18): `proof fn f(..) requires .., ensures .., decreases .., { .. }`는 사용자가 쓰는 보조 정리다. 매개변수는 값과 `&T`(`&mut`은 E0257, `Vec`은 `spec fn`처럼 E0402), 반환 타입은 쓰지 않고(파서가 `()`로 둔다, 쓰면 E0256과 지우는 수정), 효과 속성도 없다(E0256). 계약 절은 실행 함수와 같은 이름 붙은 술어(E0501)이고, 재귀(상호 재귀 포함)면 `decreases`가 필수다(E0507, 검사기의 호출 간선에 `proof fn`끼리의 호출이 든다). 귀납은 `decreases`가 있는 재귀 호출이다(구조적 귀납은 재귀 열거형 측도, ADR-0047 §3). 검사기는 유령 문맥을 `Mode::Ghost`로 읽는다: `if`·`match`·블록은 유령 문장을 담고, 조건·피검사 값·인자·`let`의 값·`assert`는 명세(`Mode::Spec`, `old` 허용)이며, 호출은 피호출자 종류로 가른다(`Checker::call`). 이동 검사는 `proof` 블록을 읽기만 하는 코드로 본다(`Mv::ghost`: 아무것도 이동하지 않는다). 증명(`verify.rs`, `Enc::ghost`): `proof fn`의 몸을 실행 함수처럼 기호 실행해 `ensures`를 의무로 낸다(`post_check`, E0802). 유령 식은 `spec`으로 번역하므로 넘침·인덱스 의무가 없고 산술은 수학적 정수다(ADR-0017). `if`·`match`는 `branch`·`match_arms`로 나뉘고 한쪽에서 증명한 사실은 그 조건 아래 남는다(`ghost_expr`). 호출은 실행 함수 호출과 같은 `Enc::call`이다: `requires`를 증명하고(E0801), 같은 재귀 성분이면 측도 감소를 증명하고(E0809), `ensures`를 가정한다. 유령 산술의 인자는 매개변수 타입 밖일 수 있으므로 인자가 타입의 사실(정수 잎의 범위, 길이 범위, 정수 배열 원소의 범위: `Enc::type_facts`)을 만족함이 의무다(E0819, 경로 조건에 같은 사실이 이미 있으면 생략). `proof fn` 자신은 매개변수에 바로 그 사실만 가정한다(열거형 페이로드의 범위는 한 단계뿐이라 빠진다: 페이로드로 내려가는 귀납이 그 페이로드의 페이로드를 증명할 수 없다. 필요하면 `requires`에 쓴다). 실행 코드의 `proof` 블록은 그 자리의 상태에서 같은 번역을 하고, 증명한 사실은 블록 뒤로 경로 조건에 남으며 블록의 `let`은 블록과 함께 끝난다(`Enc::proof_block`). 루프 havoc은 `proof` 블록을 보지 않는다(대입이 없다). 코드 생성은 `proof fn`(실행 함수만 낮춘다)과 `proof` 블록(`Stmt::Proof`는 명령 없음)을 지운다: 유령 코드를 뺀 프로그램과 IR이 바이트 단위로 같다(`tests/codegen.rs`의 `ghost_code_leaves_no_trace_in_the_ir`). 맵: L0·L1의 `def_kind: "proof fn"`(L1 `effects`는 `"proof"`), L2의 `proof_calls` 간선(`proof` 블록이나 다른 보조 정리에서 부름, 귀납이면 자기 자신), `proof fn` 몸의 `spec fn` 이름은 `contract` 간선, `impact`는 보조 정리의 계약 변경을 부르는 쪽의 `calls`로 본다, `tests`는 보조 정리를 세지 않는다. 증분 키: 보조 정리는 실행 피호출자처럼 호출자 해시(계약)로 들어간다(계약 방화벽: 몸을 바꾸면 그 보조 정리만 다시 인코딩, `tests/incremental.rs`의 `lemma_edits_follow_the_contract_firewall`). 쓰는 곳: `tests/run/max_list`(BVB `vc-vv0039`의 재귀 계약을 한정 기호 계약으로, 루프 안 보조 정리로 합의 넘침 없음), `tests/run/numlist`(자릿수 한도를 경우별 술어 대신 `pow10`과 귀납으로), `lib/utf8.bmb`(이음 명세 `parses`와 보조 정리 둘). 남은 것: `impl`·trait 안의 `proof fn`(파서가 받지 않는다), `assert forall .. by { }`(ADR-0062 채택 시 확인: 수요가 나오면 새 ADR), `bmb fix`의 보조 정리 제안(T1-24).
- 바이트(ADR-0044, 2S-02): `u8`은 `u64` 규칙에 범위 0..=255인 정수다. 레지스터에서는 `i64`, 메모리(배열·슬라이스·`Vec`·필드)에서는 1바이트이고, 덧셈·곱셈은 64비트로 계산한 뒤 `<= 255`가 의무다(E0803). `u8`로의 변환은 `0 <= x <= 255` 의무(E0815, 코드 생성은 부호 없는 비교 하나), `u8`에서 넓히기는 의무 없음. `b'a'`는 `u8`, `b"..."`는 `&[u8]`이고 호출 인자 자리에서만 쓴다(E0409). 증명에서 바이트 문자열은 길이와 원소가 모두 알려진 상수 배열, IR에서는 함수의 private 상수(그 함수의 IR 조각에 함께 있어 증분 캐시와 맞는다). 내장 `print_bytes(s: &[u8])`는 `fwrite`로 바이트를 그대로 쓴다(`printf`와 같은 버퍼라 순서가 섞이지 않는다). 습관: 식의 `"..."` E0234(`b"..."`로, 비ASCII는 `\xHH`), `'a'` E0101(`b'a'`로), `char`→`u8`, `str`→`[u8]`, `String`→`Vec<u8>`(E0402 교체). 라이브러리 `lib/bytes.bmb`(BMB로 쓰고 증명, 쓰는 프로그램이 함께 넘긴다): `eq`·`starts_with`(결과가 정확히 명세됨), `find`(`Some(i)`는 실제 위치), `extend`(덧붙인 내용까지), `push_u64`·`push_i64`(길이와 앞부분 보존), `parse_u64`(`Some(v)`는 숫자들의 10진 값 `dec`). 다른 라이브러리(T4): `lib/utf8.bmb`(`valid_up_to`·`is_valid`, Unicode 표 3-7, 명세는 잘 짜인 시퀀스들의 이음 `parses`이고 루프는 보조 정리 `parses_extend`로, `is_valid`는 스캔의 결정성 `parse_goes_on`으로 증명, T1-18), `lib/crc32.bmb`(`checksum`·`update`·`update_with`: 결과가 비트 단위 정의 `run`과 같음. 바이트마다 zlib의 256항목 표 `table()` 하나를 찾고, 표 단계가 비트 단계와 같음은 `by (bit_vector)` 보조 정리 `table_lemma`, 2N-03), `lib/sha256.bmb`(`digest`: FIPS 180-4의 채우기·일정·라운드·상수를 명세로 쓴 다이제스트 `hashed`와 같음. 명세와 코드의 `ROTR`은 `rotate_right`), `lib/base64.bmb`(`encode`는 명세 `enc_at`과 같고 정규형이며 되읽힘, `decode`는 정규형만 받고 `dec_byte`와 같음, `round`가 `decode(encode(s)) == Some(s)`). 라이브러리마다 혼자 전부 증명되고(`libraries_are_proved`), `tests/lib_run`의 프로그램은 `lib/`의 모든 파일과 함께 빌드된다.

## 진단

- 한 줄에 객체 하나: `code`, `severity`(`W`로 시작하는 코드는 `warning`, 나머지는 `error`. `W` 코드는 `bmb lint`만 낸다), `message`, `file`, `line`, `col`, `end_line`, `end_col`, 선택적 `fix`(`message`, 기계적으로 고칠 수 있으면 `replacement`).
- 위치 순으로 정렬되고 중복이 제거된다. 같은 입력이면 같은 바이트가 나온다.
- 코드는 `src/diag.rs`의 `CODES`가 유일한 목록이다. 번호는 바꾸거나 재사용하지 않는다.
- `bmb fix`(백로그 2D-04)는 `replacement`가 있는 진단을 모두 적용하고 다시 검사하기를 적용할 것이 없을 때까지 반복한다(최대 16회, 같은 텍스트가 다시 나오면 멈춤). 한 회차에는 (파일, 시작, 끝, 코드, 텍스트) 순으로 보며 이미 고른 것과 겹치지 않는 것만 적용한다(같은 위치의 삽입 둘도 겹침). 출력은 적용한 수정마다 `{"round","file","line","col","code","replacement"}`(위치는 그 회차 전 텍스트 기준), 남은 진단, 요약 행 `{"summary":true,"rounds","applied","changed","remaining","ok"}`. 검사를 통과한 프로그램이면 셀 수 있는 `while`의 정규형 수정 W0907(ADR-0057)도 같은 규칙으로 적용한다. 증명은 돌리지 않는다. 기본은 파일을 바꾸지 않고, `--write`가 바뀐 파일만 제자리에 쓴다. 공백은 정리하지 않으므로 정규형이 필요하면 `bmb fmt`를 이어 쓴다. 오류가 남으면 종료 코드 1
- E02xx는 Rust 습관(타입 생략, 매크로, `return`, `as`, `?` 등)을 따로 묶는다. Rust 습관 오류율 측정(DESIGN.md §4.1)이 이 범주를 센다.

## 증명 게이트

- 실행 함수마다 기호 실행으로 증명 의무를 만든다: 넘침, 0 나눗셈, `i64::MIN % -1`, 인덱스 범위, 호출 전제, 사후 조건, 루프 불변식(진입·유지), `decreases`(루프·재귀·재귀 `spec fn`), `assert`.
- 호출은 callee의 `requires`를 증명하고 `ensures`만 가정한다. `spec fn`은 `#[uses(..)]`에 이름(다른 단위는 `unit::name`)이 있을 때만 정의가 펼쳐지고, 펼침은 전이되지 않는다.
- 의무마다 깨끗한 해법기 상태에서 푼다. `unsat`만 성공이고, `sat`은 반례, `unknown`·자원 초과·해법기 부재는 원인과 함께 실패다.
- 질의는 그 텍스트(가정, 목표, 펼친 정의, 기저 인스턴스)가 언급하는 `spec fn`만 선언한다(백로그 2D-14, `verify::needed_decls`). 무관한 `spec fn`을 더하거나 바꿔도 다른 정의의 질의 텍스트는 바이트 단위로 같다. 측정: 코퍼스(`tests/**`, m1·m1b 시드) 전체에서 `verify` 출력이 이전과 바이트 단위로 같고(판정·`rlimit` 모두), m1b 시드의 `--emit-smt` 스크립트는 1,987,446 → 746,728바이트, `spec fn` 선언 21,294 → 707줄.
- 해법기 프로세스 하나가 여러 정의를 맡는다. 의무마다 `(reset)` 후 옵션을 포함한 기반 전체를 다시 보내므로 결과는 프로세스마다 새로 띄운 것과 같다. 시작 60초가 지난 프로세스는 다음 정의에서 새로 띄워, 정의마다 벽시계 안전장치(300초)를 온전히 받는다(백로그 1D-18).
- 맵·질의는 증명 결과를 담는 것(L1 행: `map L1`·`map all`·`surface`, 그리고 `status`)만 증명을 돌린다. 나머지는 해법기 없이 같은 결과를 낸다(백로그 1D-17, `tests/no_prove.rs`).
- `surface DEF`는 DEF 하나만 증명한다(백로그 3A-04, `verify::verify_only`). 정의의 상태는 자기 의무로만 정해지므로(질의는 자기 원문과 남의 계약·`#[uses]`로만 만들고, 의무마다 해법기를 초기화한다) 전체 증명의 L1 행과 같은 바이트다. 증분 키도 DEF가 닿는 것만 계산하고(`incremental::Session::new_for`), 캐시 파일 줄의 해시는 읽는 줄만 확인한다(저장할 때는 전부). `tests/mcp_cache.rs`가 정의마다 캐시 없음·콜드·웜에서 `map L1` 행과 비교한다. 실패한 정의도 실패 의무 수가 같다(`verify_defs`처럼 첫 실패에서 멈추지 않는다).
- 진단 코드 E08xx. `bmb verify`의 마지막 줄들은 `{"def":..,"status":"verified"|"failed","obligations":n,"failed":k}`.

## `#[uses]` 자동 채우기

`bmb uses [--write] [--cache DIR] <file.bmb|DIR>...`(백로그 2D-05, `src/uses_fill.rs`). 요청할 때만 돌고 `check`·`verify`는 그대로다.

- 증명되지 않는 실행 함수와 `proof fn`(ADR-0062: 그 증명도 `#[uses]`를 읽는다, `a_lemma_gets_the_predicates_its_proof_needs`)마다 후보 = 현재 `#[uses]` 항목 ∪ 그 정의의 진단 `fix`가 "이름으로만 본다"고 알린 술어(1D-13). 후보로 증명되지 않으면 새로 펼친 본문이 언급하는 술어를 더해 다시 시도한다(최대 8단계). 증명되면 항목을 정렬 순서로 하나씩 빼 보고 여전히 증명되면 뺀 채로 둔다. 결과는 한 항목만 빼서는 더 줄일 수 없는 목록이다(전역 최소는 보장하지 않음).
- 시도마다 속성 텍스트를 고쳐 쓰고 프로그램 전체를 다시 검사·증명한다. 정의의 의무는 자신의 `#[uses]`에만 달려 있으므로(펼침은 전이되지 않고 피호출자는 계약으로만 본다, ADR-0017 §4) 실패한 정의들은 한 번의 검증에서 함께 한 단계씩 나아간다. 검증들은 증분 캐시(2D-15, `incremental::Session::in_memory`와 `rekey`)를 함께 써서 앞선 검증 뒤로 키가 바뀌지 않은 정의는 다시 인코딩하지 않고, 증명 캐시가 바뀐 정의의 바뀌지 않은 의무를 다시 풀지 않게 한다. `--cache DIR`이면 두 캐시를 `DIR`에서 읽고 끝에 써 넣는다(`verify --cache`와 같은 파일). 결과는 캐시와 무관하다(`tests/uses_fill.rs`). 정의당 검증은 최대 32회다. 끝으로 찾은 목록을 모두 넣고 한 번 더 검증해 증명되지 않는 정의는 되돌린다.
- 출력(JSONL): 상태 줄이 있는 정의마다 `{"def","uses","status","verifications"}`. `status`는 `proved`(목록을 바꿔 증명됨), `unchanged`(이미 증명됨), `not_found`(힌트로 만든 어떤 목록으로도 증명되지 않음, 파일은 그대로). `proved` 줄에는 진단과 같은 위치 키(`file`,`line`,`col`,`end_line`,`end_col`)와 `fix.replacement`(속성 하나를 바꾸거나 `fn` 앞에 넣는 텍스트)가 붙는다. 마지막 줄은 `{"summary":true,"defs","proved","unchanged","not_found","verifications","changed"}`. `not_found`가 있으면 종료 코드 1.
- 한계: 진단이 이름을 대지 않는 술어(어떤 의무의 질의에도 나타나지 않는 것)는 찾지 못한다. `spec fn`의 종료 의무는 `#[uses]`를 읽지 않으므로 실패하면 `not_found`다.

W0901인 함수는 뺀다. 게이트 시험 `proofs_are_not_vacuous`가 증명 코퍼스·실행 프로그램·벤치 씨앗과 기준선에 대해 없음을 확인한다 |
| W0906 | `forall`의 유일한 트리거 항과 몸의 다른 항이 같은 배열을 읽거나 같은 함수를 부르는데 인자가 다르고 묶인 변수를 쓴다(`#[trigger] out[k + 1] == out[k] + ..`). 인스턴스가 트리거에 다시 걸리는 항을 만든다(매칭 루프, 백로그 1B-45) | 구문만 본다(증명 없음). 계약·본문·불변식·`assert`의 모든 `forall`(중첩 포함)에서 트리거 항이 하나일 때, 트리거 밖의 색인·호출 항을 머리와 인자 텍스트로 비교한다. 교체는 그 항을 `#[trigger]`로 표시하는 것(두 항이 다중 패턴 하나가 된다). 트리거가 여럿(다중 패턴)이면 보고하지 않는다 |
| W0907 | 셀 수 있는 `while`: `let mut i: T = lo;` 바로 뒤의 `while i < hi .. { ..; i = i + 1; }`의 정규형은 `for i in lo..hi`다(ADR-0049 §2, ADR-0057, 백로그 2K-04) | 구문만 본다(증명 없음). 마지막 문장만 `i`를 바꾸고, 몸이 `hi`가 읽는 변수를 바꾸지 않고(`hi`는 변수·상수·필드·산술·`len()`), 이 루프로 가는 `continue`가 없고, 루프 뒤에서 `i`를 쓰지 않을 때(두 끝이 리터럴이면 `T`가 `i64`일 때만). 교체는 원문을 이어 붙인 `for`(불변식과 주석은 그대로, `decreases`와 증가 문장은 빠짐). 범위 `for`가 이 펼친 꼴로 인코딩되므로 증명이 그대로 통과한다. `bmb fix`가 검사를 통과한 프로그램에 적용한다 |

- 절마다 따로 판정한다. 따로 보고된 두 절을 함께 뺄 수 있다는 뜻은 아니다.
- 재검증은 비싸므로 W0902·W0903 각각 32회(`MAX_PRE_TRIALS`, `MAX_POST_TRIALS`)까지만 한다. 넘는 절은 (경로, 절 순서)로 정해진 순서에서 뒤쪽부터 건너뛰고 요약의 `skipped`에 센다. 메모리 안 증명 캐시가 바뀌지 않은 의무를 다시 풀지 않게 한다.
- 변이는 실행당 64개(`MAX_MUTANTS`)까지 증명한다. 순서는 함수를 경로순으로 돌아가며 하나씩(라운드 로빈), 함수 안에서는 본문의 전위 순회 순서다. 넘는 변이는 요약의 `mutants_skipped`에 센다. 요약의 `mutants`는 증명한 변이 수, `surviving`은 살아남은 변이 수(W0904 수)이고, 변이 증명은 `verifications`에 세지 않는다.
- W0904는 정보성이다. 변이가 모든 입력에서 원래 본문과 같은지(동치 변이)는 판정하지 않는다. 예: `if x < 0 { 0 - x } else { x }`의 `x < 0` → `x <= 0`은 `x == 0`에서 두 갈래가 모두 0이라 동치인데도 보고된다. 전제 아래 죽은 코드 안의 변이도 거르지 않는다. `ensures`가 없는 함수는 모든 변이가 살아남으므로 변이하지 않는다.
- `*`는 `+`로만 바꾼다. `+`는 이미 `-`로 바뀌므로 가장 흔한 연산자에 변이를 하나 더 두면 `MAX_MUTANTS` 예산을 차지한다. 인덱스 변이는 대개 범위 증명으로 죽는데, 그것도 다른 죽음과 같다.
- 측정(`tests/run/search.bmb`): 변이 48개 중 9개가 살아남았다(2D-16 전 33개 중 7개). 예: `alg::digit_sum`의 `n / 10` → `n / 11`, `n % 10` → `n / 10`(2D-16), `alg::lower_bound_of`의 `(hi - lo) / 2` → `(hi - lo) / 3`. 마지막 것은 이분 탐색이 계속 맞으므로 실제로 명세가 구별할 필요가 없는 변경이다. 인덱스 변이 6개(`a[mid]`, `a[i]`, `a[best]`)는 모두 죽었다.
- 비용(2D-15): 제한 재검증(`verify::verify_defs`)은 처음 실패한 의무에서 멈춘다. 린트는 "완전히 증명되는가"만 묻기 때문이다. `--cache DIR`이면 첫 전체 검증이 증분 캐시를 쓰고 증명 캐시는 `DIR/proofs`에서 읽고 써 넣는다. 릴리스 빌드 CPU 시간(해법기 포함, 2D-16 전 변이 집합): `search.bmb` 11.7초 → 4.7초(따뜻한 `--cache` 3.8초), m1b 시드 40.3초 → 30.6초(따뜻한 `--cache` 29.8초). m1b에서 남는 비용은 대부분 죽는 변이의 실패 의무(실패는 캐시하지 않는다)와 W0901 충족 가능성 질의 중 `rlimit`까지 가는 수량자 질의 몇 개다.
- 결정론: 고정 시드·`rlimit`, 경로·절·변이 순서. 같은 입력이면 같은 바이트다.
- 요약 행: `{"summary":true,"defs","reports","verifications","skipped","mutants","surviving","mutants_skipped"}`(뒤 세 키는 2D-09에서 추가).
- 한계: W0903은 현재 프로그램의 호출자만 본다(공개 API로 쓸 post도 보고될 수 있어 정보성이다). 기준 검증에서 실패한 함수나 호출자가 실패한 함수는 판정하지 않는다.
- `bmb mutate --def PATH [--def PATH].. <file.bmb>..`(백로그 2A-10, `lint::mutate_sources`): W0904와 같은 변이 지점(같은 순서)마다 변이를 하나 적용한 프로그램을 만든다. 상한도 증명도 없다. 행은 `{"def","site","line","col","before","after","unit","text"}`(`text`는 바뀐 최상위 단위의 정규형, 다른 단위는 그대로)이고 마지막 줄은 `{"summary":true,"mutants"}`. 실행 함수가 아닌 경로나 검사 오류면 종료 코드 1. BSB 변이체 생성기(`bench/m1/bsb_gen.py`)가 쓴다.

## 정체성과 이름 (ADR-0059, 백로그 T1-10)

`bmb hash`는 정의(함수, `spec fn`, `impl` 함수, trait 기본 본문)와 타입 선언마다 `{"def","id","body","iface"}` 행을 낸다. 맵 L1 행(타입·trait 포함)은 `iface` 뒤에 `id`를 더한다. 셋 다 이름 없는 정규형(`fmt::Printer::identity`, `src/identity.rs`)의 SHA-256이다.

- 다른 정의는 그 `id`로(`#<hex>`), trait 메서드와 열거형 변형은 `#<id>#k`로 적는다. 묶는 이름(매개변수, 결과 이름, 지역, 레이블, 타입 매개변수, `forall` 변수, 패턴 이름)은 묶인 순서의 위치(`_0`, `_1`, ..), 필드·변형은 선언 위치다. 속성·효과·계약·`decreases`·트리거는 그대로, `#[uses]`의 대상은 `id`로 적고, 단위 요약은 들어가지 않는다. 내장(`Vec`, `Option`, `std::mem::replace`, 정수 타입)은 이름 그대로다. 타입 인자는 경로 끝에서 센 마디 위치로 적는다.
- 명목 타입: 구조가 같은 두 타입도 trait 호출의 디스패치가 다르므로, 타입의 텍스트는 그 타입의 trait `impl`을, trait의 텍스트는 모든 `impl`을 담는다(`impl #trait for <타입> { #trait#k = #fn, .. }`). trait, 그 `impl` 함수, 구현 타입은 한 재귀 성분이 된다.
- 재귀 성분(참조 그래프의 강연결 성분, 함수·타입·trait 함께): 구성원은 `#self.k`로 적는다. 순서는 성분을 지운 텍스트의 해시에서 시작해, 다른 구성원을 직전 해시로 적은 텍스트로 다시 해시하기를 분할이 더 쪼개지지 않을 때까지 하고(색 정제), 남는 동률만 경로로 정한다. 성분 해시는 구성원 해시를 그 순서로 이은 것의 해시이고, 구성원의 `id`는 `<성분>.k`, 하나짜리 성분은 자기 해시다. trait 메서드 순서는 메서드 텍스트와 그 메서드를 정의하는 `impl` 함수들의 해시로 정하고, 남는 동률은 이름으로 정한다(시그니처·계약·구현이 모두 같은 두 메서드).
- `body`는 자기 텍스트(같은 성분 구성원은 `#self.k`)의 해시, `iface`는 본문을 뺀 것(`spec fn`은 `body`). 참조하는 정의의 `id`가 바뀌면 참조자의 `id`·`body`도 바뀐다(내용 주소). 계약이 부르는 `spec fn`의 본문이 바뀌면 `iface`도 바뀐다.
- 커밋의 `changed`는 정의 자신의 텍스트가 바뀐 것이다(다른 정의를 경로로 적은 한정 해시, `fmt::qualified_hashes`). 본문 편집은 그 정의만 보고한다. 전이적인 영향은 `impact`가 답한다.
- 트랜잭션 `rename`(`{"op":"rename","def":"a::f","to":"g"}`, `workspace::rename`): 함수·`spec fn`·`impl` 함수·타입·trait의 선언과 그것을 가리키는 모든 참조(짧은 이름과 전체 경로의 호출, 타입, 구조체 리터럴, 변형, 패턴, `#[uses]`, 경계, `impl` 머리)를 고친다. 검사를 통과하는 프로그램에만 쓴다. 바꾼 뒤 모든 `id`의 다중 집합이 그대로여야 한다: 새 이름이 다른 참조를 가로채면(같은 시그니처로 내장 `print_i64`를 덮는 경우) 그 정의를 들어 거부한다. 같은 단위의 이름과 겹치면 검사가 거부한다(E0302). trait 메서드는 아직 받지 않는다.
- 트랜잭션 `expect`(`{"op":"expect","def":"a::g","id":"sha256:.."}`): 트랜잭션이 시작한 작업 공간에서 그 정의의 `id`가 다르면 커밋 전체를 거부한다(낙관적 동시성). 다른 정의의 이름 바꾸기는 `id`를 바꾸지 않으므로 충돌이 아니다. 피호출자의 본문 편집은 호출자의 `id`를 바꾸므로 충돌이다(`tests/workspace.rs`).
- MCP에는 노출하지 않았다. 동결 과제 집합의 도구 목록은 그대로이고(ADR-0021), 새 판과 함께 연다(백로그 T1-20).
- 가독성: 맵 출력은 `id`를 빼고 해시 값을 가리면 이전 컴파일러의 출력과 바이트 단위로 같다(코퍼스 85개 파일, `dev-docs/experiments/rename-ripple/readability.py`).

## 증분 빌드

`--cache DIR`(MCP는 `.bmb-cache/`)은 증명 캐시(`DIR/proofs`) 옆에 정의별 결과(`DIR/defs`)를 둔다(백로그 2D-10, ADR-0032, `src/incremental.rs`). 키가 그대로인 정의는 기호 실행 인코딩도 IR 생성도 하지 않는다. 출력(진단, 상태 줄, IR, 맵)은 캐시 유무·콜드·웜과 무관하게 같은 바이트다(`tests/incremental.rs`).

- 증명 키: 컴파일러 정체성(`build.rs`가 `src/**`·`toolchain.env`로 만든 SHA-256), Z3 버전, 질의 머리(옵션·`rlimit`·전주곡), 정의의 한정 정규형(`T::f` 호출은 전체 경로로. 원문은 아니다: 아래 노드 위치), 부르는 실행 함수의 계약 해시, 펼치거나 같은 재귀 성분인 `spec fn`의 본문 해시, 재귀 성분 구성원, 그리고 정의의 텍스트에서 피호출자 계약과 `spec fn` 텍스트를 따라 닿는 `spec fn`마다 그 SMT 선언(2D-14, ADR-0033), 그 텍스트들이 이름으로 쓰는 데이터 타입과 그 필드·페이로드 타입의 선언(2B-05a). `impact` 질의의 간선(`calls`·`uses`·`names`)을 모두 포함하고, 선언은 그보다 넓게(피호출자 계약이 부르는 `spec fn`까지) 잡는다.
- IR 키: 정의의 원문(실행 시 검사의 위치)·한정 정규형, 부르는 실행 함수의 호출자 해시, 그 정의 안에서 쓸 수 있는 증명된 의무(1B-31: 실패가 있는 호출 성분은 검사를 유지하므로 그 성분의 IR은 다시 만든다).
- 완전히 증명된 정의만 증명 결과를 저장한다. 실패는 늘 다시 돈다. 재사용된 정의의 의무는 증명 캐시 적중으로 센다.
- 파일 줄마다 SHA-256이 붙고, 맞지 않는 줄·다른 형식 버전·다른 컴파일러의 파일은 무시하고 다시 만든다.
- `bmb verify --emit-smt`는 모든 스크립트가 필요하므로 재사용을 끈다(증명 캐시는 쓴다).
- `spec fn`을 더하거나 빼도, 그것에 닿지 않는 정의는 다시 인코딩하지 않는다(`tests/incremental.rs`의 `adding_an_unrelated_spec_fn_reencodes_nothing`: 스크립트도 바이트 단위로 같다). 시그니처 변경은 그 선언에 닿는 정의만 다시 인코딩한다.
- 증명된 의무는 바이트 오프셋이 아니라 정의의 구문 노드 위치(`incremental::node_spans`: 이름, 매개변수, 결과, 계약, 본문을 깊이 우선으로)로 저장하고, 적중하면 지금 원문의 위치로 옮긴다(ADR-0059 §4). 그래서 정의 안의 공백·주석·배치 변경은 다시 인코딩하지 않는다(`layout_inside_a_definition_reencodes_nothing`, 감사 포함). IR은 다시 만든다(IR 키는 원문을 쥔다). 파일 형식은 `bmb incremental cache v2`다.
- 이름: 증명 키의 행(경로, 한정 정규형, 피호출자의 한정 표면, `spec fn` 선언, 타입 행)은 이름을 담는다. 질의 텍스트가 이름을 담기 때문이다(기호 `|u::f|`·`|x@0|`·`|u::g.result@0|`·필드 선택자, 이름순으로 지역을 도는 병합). 이 행들은 질의가 담는 이름의 범례이고, 질의 기호가 이름 없이 지어질 때(백로그 T1-10e) 이름 없는 키로 바뀐다. 그때까지 이름 바꾸기는 그 이름을 쓰는 정의를 다시 인코딩한다(측정 `dev-docs/experiments/rename-ripple/`).
- 부르는 실행 함수는 호출자 해시로 키에 들어간다: 계약 해시에서 `#[uses]`를 뺀 것(`fmt::caller_text`, ADR-0043). `#[uses]`는 그 함수 자신의 질의에서만 본문을 펼치므로, 피호출자의 `#[uses]`만 바뀌면 그 함수만 다시 인코딩한다(`verify_stats_name_the_reencoded_definitions`, 감사 모드는 `edits_that_shift_spans_or_change_context_keep_outputs_exact`). `bmb hash`·맵의 `iface`는 그대로다(`#[uses]`의 대상 `id`를 담는다).
- `--stats FILE`(`verify`·`emit-llvm`·`build`)은 캐시가 한 일을 JSON 한 줄로 쓴다: `{"encoded":[..],"reused":[..],"lowered":[..],"ir_reused":[..],"proof_cache_hits","proof_cache_misses"}`(정의 경로는 정렬, `verify`는 IR 목록이 빈다). 표준 출력은 그대로다. BCB(2A-14)가 커밋당 재증명 집합을 잰다.

## MCP 서버의 전단 캐시

`bmb mcp`는 호출 사이에 전단 결과를 메모리에 둔다(백로그 3A-03, `FrontCache` in `src/lib.rs`). 호출마다 `src/*.bmb`는 다시 읽는다(다른 쓰는 쪽·직접 편집도 보인다). 이름·위치·원문이 지난 호출과 같은 파일은 다시 렉싱·파싱하지 않고 구문 트리와 진단을 다시 쓴다(스팬이 파일 위치를 담으므로 위치가 바뀐 파일은 다시 파싱). 무엇이든 바뀌면 검사기는 프로그램 전체에 다시 돈다(표가 전역이다). 맵 색인(`map::Index`: 단위, 정의, 간선, 역간선)은 바뀐 뒤 첫 맵 요청에서 다시 만들고, 정의 해시는 처음 쓸 때 계산한다. 아무것도 바뀌지 않으면 모두 다시 쓴다. 정의 단위 질의는 색인의 범위 조회(나가는 간선은 정렬된 간선 집합의 구간, 들어오는 간선은 역간선 표)만 한다. 응답은 호출마다 새 서버를 띄운 것과 같은 바이트다(`tests/mcp_cache.rs`: 질의·맵·`verify`·`build`와 커밋, 다른 서버의 커밋, 직접 편집, 구문 오류, 파일 위치 이동이 섞인 세션). 측정은 `bench/m3/results/2026-10-24-front-cache.md`.

## 코드 생성

- 증명된 의무는 검사 없이 LLVM에 사실로 전달된다: 넘침 없음 → `nsw`/`nuw`, 범위 안 → 검사 없는 `getelementptr inbounds`, 0 아닌 제수 → 검사 없는 `sdiv`/`udiv`. 각 줄에 `; proved Exxxx` 주석이 붙는다.
- 증명되지 않은 의무는 `llvm.trap`으로 가는 검사로 남는다(`; unproved: ..`). `bmb build`는 그런 프로그램을 거부한다.
- `&mut` 슬라이스 매개변수는 `noalias`, `&` 슬라이스는 `readonly`(ADR-0015).
- 닫힌 세계(백로그 2D-07): 모듈 하나가 프로그램 전체이므로 모든 함수(BMB `main`, `bmb_print_i64`·`bmb_print_u64` 포함)가 `internal`이고, C 진입점 `@main`만 외부에 보인다. LLVM이 자유롭게 인라인하고 쓰지 않는 함수를 지운다. 기준선 벤치 7개에서 실행 파일에 BMB 함수 기호가 0개가 되었고(전에는 2~4개) 크기가 100~180바이트 줄었다. 실행 시간 차이는 측정 잡음(±10%) 안이었다.

## 맵 스키마에 추가된 키

ADR-0020 §1의 하위 호환 규칙(키 추가 허용)에 따라 추가한 키다.

| 키 | 위치 | 뜻 |
| --- | --- | --- |
| `rlimit_max` | L1 행, `status` 질의 행 | 가장 비싼 의무 하나의 해법기 자원 사용량. 고정 `rlimit`(scripts/toolchain.env)에 가까울수록 증명이 깨지기 쉽다(백로그 1B-15) |

`bmb verify`의 상태 줄에는 `rlimit`(정의 전체 합)과 `rlimit_max`가 붙는다.

## 추가된 질의

ADR-0020 §5의 7개 질의 외에 추가한 질의다. 기존 질의와 행 형식은 바뀌지 않는다.

| 질의 | 결과 |
| --- | --- |
| `impact DEF [body\|iface]` | DEF의 본문(`body`) 또는 계약·시그니처(`iface`, 기본값)를 바꾸면 다시 증명할 정의마다 `{"path","reason"}` 행, 그리고 요약 행 `{"summary":true,"changed","change","reprove","defs"}`. `reason`: `changed`(자신), `calls`(호출자: 계약이 바뀜), `uses`(`#[uses]`로 펼침), `names`(시그니처가 바뀐 `spec fn`을 이름으로 씀). 증명은 피호출자를 계약으로만, `spec fn`을 `#[uses]`로만 보므로(ADR-0017 §4) 영향은 한 단계에서 멈춘다(백로그 2D-02). DEF가 구조체·열거형이면(2B-07, ADR-0026 §6) 그 타입이나 그것을 담은 타입을 이름으로 쓰는 정의가 `types`이고, 그중 표면(실행 함수의 시그니처·계약, `spec fn` 전체)에 쓰는 정의에서 한 단계 더 `calls`·`uses`·`names`로 퍼진다 |
| `duplicates` | 정체성(`id`, ADR-0059 §6)이 같은 정의 묶음마다 `{"hash","defs"}` 행(`hash`는 그 `id`, 정의가 둘 이상인 묶음만, `id`순, `defs`는 경로순), 그리고 요약 행 `{"summary":true,"groups","duplicate_defs","defs"}`. 정체성에는 이름이 없으므로 이름·단위·매개변수·지역·레이블·필드 이름만 다른 알파 동치 정의, 같은 정의를 부르는 정의, 재귀·상호 재귀 정의의 복제가 묶인다(DESIGN.md §7.2, 백로그 2D-06·T1-10, 코퍼스 `tests/duplicates/`) |

| `effects [DEF]` | 효과 뷰(DESIGN.md §7.2, 백로그 2D-11). DEF가 있으면 DEF에서 실행 호출(`calls` 간선)로 닿는 `io` 정의(DEF 자신과 내장 `print_i64`·`print_u64` 포함)마다 `{"def":DEF,"effect":"io","path"}` 행(`path`는 DEF에서 그 정의까지의 최단 호출 경로, 도달한 정의의 경로순), 그리고 요약 행 `{"summary":true,"def","io_reached","defs"}`. DEF가 없으면 내장 `io` 연산에 닿는 정의마다 `{"def","effect":"io","path"}` 행(가장 가까운 연산까지의 최단 경로, 정의 경로순), 그리고 요약 행 `{"summary":true,"io_reaching","io_defs","defs"}`. 최단 경로가 여럿이면 정의 경로를 차례로 비교해 가장 작은 것을 고른다(호출 순서·정의 순서와 무관). 맵 간선만 쓰고 증명하지 않는다(1D-17의 증명 불필요 집합). 효과 검사(E0603)가 `pure`의 `io` 호출을 막으므로 `io`에 닿는 정의는 모두 `io`로 선언되어 있다. `io`로 선언했지만 어떤 연산에도 닿지 않는 정의는 DEF 없는 결과에 나오지 않는다(`io_defs`와 행 수의 차이) |
| `tests` | 남은 테스트 면적(백로그 2D-21, ADR-0003, DESIGN.md 원칙 4). 테스트가 여전히 필요한 실행 정의마다 `{"path","test_reasons","sites","lines"}` 행(경로순), 그리고 요약 행 `{"summary":true,"exec_defs","test_needed_defs","io_defs","unproved_defs","test_sites","test_lines"}`. M1의 이유는 둘이다: `io`(실행 호출이 내장 `io` 연산에 닿음: 출력의 순서·내용은 계약이 말하지 않는다), `unproved`(실패한 의무가 있어 계약 자체가 서지 않음). `sites`는 그 정의가 직접 부르는 내장 `io` 연산 수(테스트가 겨냥할 곳), `lines`는 정규형 줄 수다. `spec fn`과 `io`로 선언만 하고 어떤 연산에도 닿지 않는 정의는 세지 않는다. 증명 상태를 쓰므로 증명한다(`status`와 같다). G8(2H-06)의 BMB 쪽 값이다. 효과가 늘면(ADR-0030 제안: `panic`·`nondet`·신뢰 등급) 이유가 는다 |

MCP `query` 도구의 설명문은 바꾸지 않았다. 실제 모델 측정(1E-10)이 끝날 때까지 에이전트가 보는 문구를 그대로 둔다. 도구는 `impact`·`duplicates`·`effects`도 받는다.
