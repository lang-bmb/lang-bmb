# 라이브러리 속도·크기 (2026-11-02)

- 환경: Intel(R) Xeon(R) Processor @ 2.80GHz (4 cores), Linux-6.18.44-fc-v185-x86_64-with-glibc2.39
- 도구: rustc 1.97.0 (2d8144b78 2026-07-07); Ubuntu clang version 18.1.3 (1ubuntu1); bmb `build`(clang -O2)
- 방법: 변형별 15회 교차 실행의 중앙값(벽시계). 출력 일치 확인 후 측정. 크기는 strip한 실행 파일.
- 비교 대상: utf8은 Rust 표준 라이브러리 `std::str::from_utf8`, sha256은 같은 알고리즘의 안전한 Rust(표준 라이브러리만)와 `sha2` 크레이트 0.11.1(`cargo build --release --locked`, opt-level 2). 이 CPU의 SHA-NI: 없음(크레이트의 소프트웨어 구현).
- 비율 < 1 이면 BMB가 빠르다.

| 벤치 | 비교 대상 | BMB ms | 대상 ms | BMB/대상 | BMB 바이트 | 대상 바이트 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| utf8 | `std::str::from_utf8` | 1392.5 | 1599.9 | 0.87 | 14512 | 343768 |
| sha256 | 같은 알고리즘의 Rust | 988.8 | 977.5 | 1.011 | 14512 | 345952 |
| sha256 | `sha2` 크레이트 | 988.8 | 785.0 | 1.26 | 14512 | 356136 |

- 부하: 실행 중 T0-12 측정(모델 대기 위주, 판정의 증명이 가끔)이 같은 머신에서 돌았다(1분 부하 평균 1.1~1.3). 같은 날 부하 평균 약 5에서 잰 첫 실행은 버렸다(sha256 BMB 1,128ms, 같은 알고리즘의 Rust 대비 1.25배: 순서를 바꿔 가며 돌려도 부하가 변형마다 다르게 걸린다).
- 읽기: BMB의 SHA-256은 같은 알고리즘의 안전한 Rust와 같은 수준이고(1.01배, 2026-10-28의 1.02배), `sha2` 크레이트의 소프트웨어 구현이 BMB보다 1.26배 빠르다. 크레이트는 라운드를 펼치고 일정 계산을 라운드와 겹쳐 쓴다. BMB 코드는 FIPS 명세와 같은 모양의 작은 함수로 나눠 증명한 것이고(`lib/sha256.bmb`), 그 꼴을 바꾸면 증명도 다시 짜야 한다. 크기는 BMB 14,512바이트 대 크레이트 356,136바이트(strip).
