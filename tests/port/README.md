# Differential test cases of the port

Read by `scripts/difftest.py run tests/port/cases.json`. Each case runs the stage0 side (`a`) and the port side (`b`) on the same input and compares stdout, stderr, the exit code and the files left behind, byte for byte. The gate job "port difftest" runs them every time.

| File | Contents |
| --- | --- |
| `cases.json` | The cases and the list of builds |
| `sha256_files.bmb` | The `std::sha256` value of each file given as an argument, in the line format of `sha256sum` |
| `json_roundtrip.bmb` | Reads each line of standard input with `std::json` and writes it back without whitespace |
| `json_ref.rs` | The same job with stage0's `json.rs` (compiled as is through `#[path]`) |
| `json_edge.txt` | Edge inputs for JSON (escapes, numbers, nesting, rejected forms) |
| `unicode_ref.rs` | Classifies every code point outside ASCII with Rust's `char::is_alphabetic`, `is_numeric` and `is_whitespace`, as ranges |
| `unicode_classes.bmb` | The same job with the port's tables (`selfhost/unicode.bmb`) |
| `smt_terms_ref.rs` | Calls the term builders of stage0's proof encoder (`compiler/src/verify.rs`) over a fixed grid of arguments and prints one JSONL row per call. An example of the compiler's crate (`compiler/Cargo.toml`), built by `cargo build --example smt_terms_ref`; `compiler/tests/fmt.rs` reads its rows too |
| `smt_terms.bmb` | The same job with the port's builders (`selfhost/encode_terms.bmb`) over the same grid |
| `lexer/` | Edge inputs for the lexer (the extension is `.txt`, so that text that is not a BMB program does not get mixed into other corpora) |
| `parser/` | Edge inputs for the parser (`.txt` for the same reason) |
| `lower/` | Edge inputs for the stage that lowers function values and constants (`.txt` for the same reason) |

| `types/` | Edge inputs for the checker's second pass (checking bodies) (`.txt` for the same reason) |

For the cases of the port (`selfhost/`), `a` is `{bmb}` (stage0) and `b` is `{build:stage1}` (`selfhost/*.bmb` through `bmb build`). At present: `codes`, `codes-md`, `tokens` (every tracked `.bmb`, one file at a time), `tokens-together` (several files at once), `tokens-edges` (the files of `lexer/`, one at a time), `parse` (every tracked `.bmb`, one file at a time, with `dump parse`), `parse-together` (several files at once: the order of units and units of the same name), `parse-edges` (`parser/`), `std` (every tracked `.bmb`, one file at a time, with `dump std`: the normal form of the program with the named library units added), `std-together` (several files at once), `lower` (every tracked `.bmb`, one file at a time, with `dump lower`: the normal form of the program with function values and constants lowered, the generated names, the places passed, the values of constants), `lower-together`, `lower-edges` (`lower/`). `decls`, `decls-together`, `decls-edges` (`dump decls`: the declarations collected by the checker's first pass). `types` (the tracked `.bmb` files, one at a time, with `dump types`: diagnostics, the normal form of the resolved program, the tables computed by body checking), `types-together`, `types-edges` (`types/`). `check` (the tracked `.bmb` files and the files of `types/`, one at a time, with `check`: the JSONL of diagnostics and the exit code). `moves` (the tracked `.bmb` files and the files of `types/`, one at a time, with `dump moves`: for each function, the places where owned values are dropped), `moves-together`. `hash` (the tracked `.bmb` files and the files of `types/`, one at a time, with `hash`: the identity hashes of definitions and type declarations), `hash-together`. `fmt` (the same files, one at a time, with `fmt`: the normal form of the checked program, method calls written by path in method syntax), `fmt-check` (`fmt --check`: the exit code and standard error), `fmt-together`. `texts` (the same files, one at a time, with `dump texts`: the qualified text and qualified hashes read by the incremental key), `texts-together`. `lowered` (the same files, one at a time, with `dump lowered`: the lowered tables read by code generation, where text is bytes and `char` is `u32`: signatures, data types, local variables, the types of expressions, the positions that are text, and for each type its type with references stripped and its fields and variants), `lowered-together`. `layout` (the same files, one at a time, with `dump layout`: if checking passes, for each type its LLVM type, size, alignment and predicates, what the module head depends on, the LLVM type definitions), `layout-together`. `smt-decls` (the same files and the files of `smt/`, one at a time, with `dump smt-decls`: if checking passes, what the proof encoder derives from the checked tables before it reads a body, with no solver: the instances of generic spec fns the program reaches and the types they mention, for each function of the encoder's tables the sorts of its parameters and result, the SMT functions of a spec fn and the declarations of its type parameters, the datatype declarations in their order, which parameters and results are text, each definition's default proof context), `smt-decls-together`. `smt` (the same files and the files of `smt/`, one at a time, with `dump smt`: if checking passes, what the proof encoder builds of each definition, with no solver and nothing canonicalised: the declarations of the spec fns; for each definition and instance its kind, unit and substitution, its `#[uses]`, its proof context, the spec fns of its contract, the definitions it reveals, which parameters and result hold an array and the field positions of its struct parameters; for a spec fn that is not generic its definition as the queries take it (the macro form, the marker and the quantified form), its parts for ground instances and the struct facts of the text; for a proof fn the declarations and facts of its parameters on entry; for a recursive spec fn its termination obligations with code, position, message, assumptions, goal and struct facts. A definition whose body the port does not encode yet, an executable or proof function, has `encoded: false` in its row on both sides: the next pieces of the encoder add its rows to the same dump, so there is no allow list), `smt-together`. `smt-terms` (no input: `a` is `{build:smt_terms_ref}`, an example of the compiler's crate that calls stage0's own functions, and `b` is `{build:smt_terms}`, `smt_terms.bmb` built with the units of `selfhost/` but its driver. Both call the term builders of the proof encoder that need no encoder state, each over a grid of arguments written out in both files, and print one JSONL row per call with the builder, its arguments and its result: the readers of numerals and of term text, the integer, bit-vector and `f64` builders at every integer type and operation, the bit and integer methods, the bytes of an integer in both orders, the lemma templates, the builders of text, the reader of s-expressions, and the values of expressions (`Val`) with their array, default and flattening helpers and assignment to a place, the ones that read the tables at each parameter type of a program both files carry. These functions are reached by no dump of a program, and the grid is test material, so it is outside the compiler: stage0 only makes the builders public). `emit` (the tracked `.bmb` files and the files of `emit/`, `types/` and `gen/`, one at a time, with `emit-llvm --all-checks`: the port side goes through `scripts/port_emit.py run`. For inputs on the allow list `emit/ported.txt`, the port's IR, standard output and exit code are compared with stage0's byte for byte; for inputs outside the list, only whether the port ends with "not ported" is checked. If the list and the port's behaviour disagree (it fails to emit an input on the list, or emits an input outside it), the case fails). `emit-together` (`selfhost/*.bmb` at once: the IR the port emits from itself is byte-identical to stage0's, the condition that closes the port of code generation). `emit-run` (the files of `tests/run` and `emit/`, one at a time: for an input that is on the allow list and has a `main`, the IR from both sides is built with clang and run, and the standard output and exit code are compared; if there is an `.out` next to it, they must equal that too).

The files of `lexer/`:

| File | Contents |
| --- | --- |
| `tokens.txt` | Well-formed text with every kind of token (no errors): the three radixes and the extreme values of 128 bits, escapes, labels, `///` groups |
| `floats.txt` | 1,494 float literals (no errors): the shortest text of random bit patterns, powers of 2, subnormals, the exact midpoint of two adjacent `f64` values and its two neighbours, the boundary of the largest finite value, long digit strings |
| `err-numbers.txt` | Diagnostics for number literals (E0104·E0105·E0108·E0109·E0406) |
| `err-text.txt`·`err-bytes.txt`·`err-unterminated.txt` | Escapes of string, character and byte literals, and unterminated literals (E0101·E0102) |
| `err-quotes.txt` | Labels, lifetimes (E0208), character literals of several characters |
| `err-names.txt` | Characters outside ASCII: letters and digits inside a name (reported once per name) and other characters, Unicode whitespace |
| `err-comments.txt` | Block comments (E0106) |
| `mix-NN.txt` | 40 lines each of randomly joined token fragments (fixed seed). One in three has only error-free fragments |

If a file has even one error, `dump tokens` emits diagnostics instead of tokens. So the error-free files compare the values of tokens, and the rest compare the text, position and order of diagnostics.

If there is even one syntax error, `dump parse` emits diagnostics instead of the normal form. So the error-free files (most of the corpus, `order.txt`, and the `deep-` files within the limit) compare the syntax tree and the normal form, and the rest compare the text, position and order of diagnostics and the recovery. The warnings for input aliases (W0912~W0914) do not appear in `dump parse`: that text is compared when `lint` is ported.
