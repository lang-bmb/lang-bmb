# Differential test cases of the port

Read by `scripts/difftest.py run tests/port/cases.json`. Each case runs the stage0 side (`a`) and the port side (`b`) on the same input and compares stdout, stderr, the exit code and the files left behind, byte for byte. The gate runs every case every time. The cases too long for it are in `nightly/cases.json` and run every night instead (below).

The gate builds the programs the cases compare once and concurrently (`difftest.py build tests/port/cases.json target/port-build`, with the debug compiler, which is the compiler under test; each build of a BMB program reads a copy of its own of the port's proof cache) and runs the cases as concurrent jobs "port difftest 1/N" to "port difftest N/N", each `difftest.py run tests/port/cases.json --built target/port-build --shard I/N` (N is `port_shards` in `scripts/check.sh`). The parts are disjoint and together hold every case: the cases in decreasing recorded seconds go one by one to the part with the least so far; a case `costs.json` does not list counts as the mean. `scripts/test_difftest.py` fails when a case is in no job or in two. A build that fails does not stop the gate in its build step: the jobs that need the program fail with its error. The script checks that went with the cases and the formatting of the port (`bmb fmt --check selfhost/*.bmb`) are the job "port checks".

if there is an `.out` next to it, they must equal that too). `build-emit` (the files of `emit/`, `prove/`, `tests/verify/pass` and `tests/verify/fail`, one at a time, with `emit-llvm --stats` and no `--all-checks`, the port side through `scripts/port_emit.py run`: the program is proved first, and the runtime check of an obligation is dropped only when its proof is usable, that is when no definition connected to its own by calls has a failure and its definition does not rest on trusted facts (proved, failed and undecided obligations, the passes with and without trusted facts of `prove/trust.bmb`); both sides print the same diagnostics and status rows, write the same IR (`; proved Exxxx` where a check is dropped) and the same stats with the count of the checks kept, and exit with the same code), `build-fake-unknown` and `build-fake-retry` (the files of `prove/` and three of `tests/verify/pass` with the stand-in `prove/fake/z3`: every query undecided, so every check is kept, and undecided twice, then proved, so the checks of the obligations the retries prove are dropped; the stand-in's record of every line it was sent is compared too), `build-runs` (`build/runs.sh` over the files of `emit/` and two of `tests/run`: `build` without a cache, then cold and warm over one cache; a program built is run, and the programs built through the cache are the same bytes; a program that is not fully proved or has no `main` is refused), `build-edits` (`build/edits.sh`: the programs of `incr/` in turn over one cache with `emit-llvm --cache`, the IR of each run and the cache file after it, then `--audit` and `build`: which definitions are lowered again after each edit and which take their IR from the cache), `build-cross` (`build/cross.sh`: the IR side of the cache file between the two builds, which read nothing of each other's file, and the file under the other build's name, where every proof and fragment of IR is reused, with and without `--audit`) and `build-ends` (`build/ends.sh`: a module, a stats file or an executable's `.ll` that cannot be written, caches that cannot be written, a program that does not check, flags without their value or given to the other command, `--all-checks` with `--cache`, and the tools `build` runs: no `llc`, one of another version and one whose version cannot be read, no `clang` and one that fails).

## The nightly set

`nightly/cases.json` holds the comparisons too long for the per-push gate, in the same format and run by the same `scripts/difftest.py`. CI runs them every night (`.github/workflows/nightly.yml`, job `port`) as three jobs on runners of their own, each a part `--shard I/3` balanced by the seconds in `nightly/costs.json`; `scripts/test_gate_scripts.py` fails when the workflow no longer runs every case of the set in exactly one part. Locally one command runs them all, or the parts and cases its arguments name: `scripts/port_nightly.sh [--shard I/N] [--case NAME]..`. It builds the optimized compiler, which is the compiler under test here, proves the port into a cache of its own (`target/nightly-proof`, as the gate's port proof does), builds what the cases compare (`target/nightly-build`) and runs the cases; the lines of the run are left in `target/nightly.jsonl` and, for a case that differs, the difference and the bytes around it in `target/nightly-excerpts/CASE` (CI keeps both when a part fails).

The cases over the whole port compare outputs of gigabytes (`"digest": true`): each side's standard output and error are hashed as they are written and its files as soon as it ends, in blocks of 64 KiB, and its directory is removed before the other side starts, so neither output is held in memory or kept on disk beside the other. A difference is located to the block and line where it starts, with the SHA-256 and size of each side; the excerpt holds the first bytes of each side and side b's first block that differs.

Measured once with the optimized compiler on 4 cores and 15 GB (2026-11-25; the cases over the whole port ran beside the others, so alone they are faster). Every case was the same on both sides. Memory is the peak of the largest single process of a side (the compiler or the solver).

| Case | Seconds, both sides | Rust compiler | Port | Peak memory |
| --- | --- | --- | --- | --- |
| `verify-port` | 4030 | 1995 | 2032 | 4.1 GB |
| `verify-port-warm` | 1007 | 553 | 450 | 4.1 GB |
| `verify-port-def` | 15 | 10 | 5 | 591 MB |
| `smt-queries-port` | 1081 | 611 | 470 | 9.9 GB |
| `build-port` | 986 | 581 | 405 | 4.7 GB |
| `incr-port` | 54 | 32 | 22 | 625 MB |
| the 27 cases over single files, together | 4043 | 1979 | 2060 | 344 MB |

The whole set is 11216 seconds (3.1 hours) of cases after about 8 minutes of setup (the port's proof and the builds); each of the three parts is 60 to 67 minutes of cases. `smt-queries-port` is the case nearest a limit: the Rust compiler holds 10.2 GB while it writes the dump and the port 8.8 GB, one after the other, on a runner of 16 GB.

`incr-files` has an hour per run: one query of `gen/g35.txt` is ended by the 300-second wall-clock safeguard, that program's result is never stored, and the case's script verifies it five times, about five minutes each. That query spends no resource units in the output, so its status row is the same from run to run (two runs of the Rust compiler gave the same bytes). The table above was measured without that program: the case over `gen/g35.txt` alone took 1523 seconds on the Rust compiler and 1525 on the port (2026-11-26, the two sides at once), the same on both sides, and `nightly/costs.json` adds them to the case's seconds.
