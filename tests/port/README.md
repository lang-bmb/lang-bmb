# Differential test cases of the port

Read by `scripts/difftest.py run tests/port/cases.json`. Each case runs the stage0 side (`a`) and the port side (`b`) on the same input and compares stdout, stderr, the exit code and the files left behind, byte for byte. The gate job "port difftest" runs them every time.

declarations, the obligations that hold by their own text, whether the end of the body is unreachable, the path condition there, the entry values of the parameters, the texts known valid, the validity functions defined and the reach points with their path conditions (the end of the body and the exit of each loop, recorded as the vacuity check records them); and for each obligation of either an `obl` row with code, position, message, assumptions, goal, struct facts, the value a counterexample adds and, for a sub-proof `assert .. by`, its own query (logic, declarations, hypotheses, goal, free variables, guards) or why its assertion has no translation with the spec fns it does not reveal. The assumptions of an `obl` row are written as the number it shares with the row before it (`shared`, counted from the start; 0 in the first row of a definition) and the rest: the path condition grows at its end, so the lists repeat, and written in full the dump of the port itself was 868 MB against 343 MB this way. Nothing is lost: the full list of a row is the first `shared` assumptions of the row before and its own. Everything else is as the encoder holds it before a query is assembled. Every executable and proof function has these rows; `encoded: false` is left for an `#[external_body]` function alone, for which the encoder builds nothing (it has no obligations; its contract is read where it is called)), `smt-together`, `smt-port` (`selfhost/*.bmb` at once: the dump of the port itself, every definition of it with its obligations). `smt-queries` (the same files and the files of `smt/`, one at a time, with `dump smt-queries`: if checking passes, per definition a `queries` row with the script and the legend `bmb verify --emit-smt` writes of it before the solver's first answer, with no solver. Per obligation that is the query with bit operations abstracted and their congruences (when it has any, over the ground instances of the revealed definitions when there are any), the probe (when its base differs from the full one) and the full query: the options, the datatype and spec fn declarations the query needs in order of first use, the definitions it reaches in the forms of that query, the local declarations, the assumptions, the negated goal, the instances of the validity functions and the struct facts; or the query of a sub-proof. All of it is in canonical symbols, numbered per query, and the legend names each. What follows an answer is not in the dump: the ground-instance retries, the bounded search, the `f64` model check, and the trusted pass of a program with escapes, of which the dump is the first pass. Then per definition a `reach` row with every form each reach point of the vacuity check may be asked in: the probe in the forms of a satisfiability check, the exact bit-vector form, the form with recursive definitions as recursive functions, and the full query; which are sent after the first depends on the answers. `compiler/tests/cli.rs` shows that the `queries` rows are the bytes `--emit-smt` writes), `smt-queries-together` (seven units of the port that form a program with three of the library, at once: `needed_decls` over a program with more spec fns and datatypes than one file has. The dump of the whole port is 3.7 GB, 27,000 queries that each repeat their base, and takes stage0's optimized build seven minutes and 9 GB of memory, so it is no case: the two sides were compared once by hand, with the same SHA-256). `smt-terms` (no input: `a` is `{build:smt_terms_ref}`, an example of the compiler's crate that calls stage0's own functions, and `b` is `{build:smt_terms}`, `smt_terms.bmb` built with the units of `selfhost/` but its driver. Both call the term builders of the proof encoder that need no encoder state, each over a grid of arguments written out in both files, and print one JSONL row per call with the builder, its arguments and its result: the readers of numerals and of term text, the integer, bit-vector and `f64` builders at every integer type and operation, the bit and integer methods, the bytes of an integer in both orders, the lemma templates, the builders of text, the reader of s-expressions, and the values of expressions (`Val`) with their array, default and flattening helpers and assignment to a place, the ones that read the tables at each parameter type of a program both files carry; then the translations of sub-proofs over a grid of terms and variables of every sort (`bit_vector`, `bit_vector_int` and `bit_vector_sat` with no spec fn to unfold: numerals up to the ends of 128 bits and the arithmetic that leaves them, each operator at each width with and without a known interval and past the widest bit-vector, division by powers of two, other constants, zero and terms, the bit-vector and `f64` operations, and the terms each refuses), the definitions of the bit helpers, the readers of model values (`model_int`, `render_value`), the text of a sub-proof's counterexample from a model's values (`sub_values`) scripts in canonical symbols with their legends (`canonical_script` over comments, string literals, a `(reset)` among white space, symbols and strings left open), the canonical text of one query (`canonical`) and the solver's answers named back in the program's symbols (`back`: bare and quoted canonical symbols, values of an uninterpreted sort, names that need their bars again, numbers past the symbols). Most of these functions are reached by no dump of a program, and the grid is test material, so it is outside the compiler: stage0 only makes the builders public). `emit` (the tracked `.bmb` files and the files of `emit/`, `types/` and `gen/`, one at a time, with `emit-llvm --all-checks`: the port side goes through `scripts/port_emit.py run`. For inputs on the allow list `emit/ported.txt`, the port's IR, standard output and exit code are compared with stage0's byte for byte; for inputs outside the list, only whether the port ends with "not ported" is checked. If the list and the port's behaviour disagree (it fails to emit an input on the list, or emits an input outside it), the case fails). `emit-together` (`selfhost/*.bmb` at once: the IR the port emits from itself is byte-identical to stage0's, the condition that closes the port of code generation). `emit-run` (the files of `tests/run` and `emit/`, one at a time: for an input that is on the allow list and has a `main`, the IR from both sides is built with clang and run, and the standard output and exit code are compared; if there is an `.out` next to it, they must equal that too).

If a file has even one error, `dump tokens` emits diagnostics instead of tokens. So the error-free files compare the values of tokens, and the rest compare the text, position and order of diagnostics.

If there is even one syntax error, `dump parse` emits diagnostics instead of the normal form. So the error-free files (most of the corpus, `order.txt`, and the `deep-` files within the limit) compare the syntax tree and the normal form, and the rest compare the text, position and order of diagnostics and the recovery. The warnings for input aliases (W0912~W0914) do not appear in `dump parse`: that text is compared when `lint` is ported.
