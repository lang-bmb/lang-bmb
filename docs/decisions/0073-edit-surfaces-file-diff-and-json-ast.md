# ADR-0073: The comparison surfaces of H-EDIT: the file diff is `git apply --recount`, the JSON AST is the syntax tree + JSON Patch

- Status: Accepted (Accepted (autonomous), AUTONOMY.md §4: optional flags of the MCP server, one CLI command and new measurement editions. The default output and the frozen sets are unchanged)
- Date: 2026-10-31
- Related: DESIGN.md §9 R2, principles 1·6, ADR-0009 (transactions), ADR-0011 (layout is the tool's), ADR-0019 (normal form), ADR-0021 (freeze), ADR-0070 (same condition), backlog T1-06·2D-24, ROADMAP hypotheses H-EDIT·H-GRAIN

## Context

- H-EDIT (editing with a structural address + text content has a higher first-attempt success rate than file diff or JSON AST editing) and H-GRAIN (the definition level uses fewer total tokens than the file or statement level) are compared by solving the same tasks through three surfaces. The definition-level surface (`write`, 2D-24) and its editions (`bench/*-write`) exist. The file diff and JSON AST surfaces did not exist in the compiler: there was no way to export or import the syntax tree as JSON, and no way to apply a diff.
- For the comparison to be able to refute the hypothesis, the competing surfaces must be built fairly, in the canonical way of each format (C3). Everything except the edit representation must be the same: the read tools (`query`·`map`), the commit rule (whole rejection on a structure or type error), commit and proof in one call, the rest of the frozen tasks and prompt.

## Decision

1. **Common.** On both surfaces, as with `write`, one call commits and proves the whole workspace and returns the commit line and the proof results. The commit follows the transaction rules as they are (`workspace::plan_files`: check all the new files, write nothing on an error, store the normal form). File layout belongs to the tool (ADR-0011), so `src/UNIT.bmb` must contain only the one top-level unit `UNIT`. They are visible only with optional flags (`--file-tools`, `--ast-tools`), and without the flags the tool list and responses are the same bytes.
2. **File diff (`read_file`, `edit_file`).** A unified diff is applied by the rules of `git apply --recount`. The line counts of a hunk header are not trusted and are recounted from the hunk. The line number is where to look first; if several places match, the nearest one, and with no number exactly one place must match. Context and deletion lines must match exactly, including whitespace (no fuzz). If they do not match, it says which line is missing (and says so if only whitespace differs). Files are created and deleted with `/dev/null`. A file whose text the normal form changed is reported as `reformatted` (a signal to read it again before the next diff).
3. **JSON AST (`read_ast`, `edit_ast`).** The document is the compiler's syntax tree (`ast.rs`) rendered as JSON (`src/ast_json.rs`, CLI `bmb ast`). The top level is an object keyed by unit name, and the definitions, types, traits, impls and sub-units of a unit are also keyed by name, so a JSON Pointer points to a definition like a path (`/calc/fns/twice/body/tail`). Other nodes have `kind` and the field names of `ast.rs`; names, paths and operators are strings, empty parts are omitted, and there are no positions. Edits are RFC 6902 JSON Patch (atomic). The imported tree is printed in normal form and parsed again, and committed only if it is the same tree. The position of diagnostics and proof results is `at`, the pointer of the innermost node that contains that position (also for the `verify` of this surface). What the normal form discards and the recovery forms of the parser are not in the tree.
4. **Editions and scripts.** `bench/edit/gen.py` makes `*-diff`·`*-ast` from m1b·BVB·BRB (BMB arm). They differ from the original editions only in the write surface: `set.json` (flags, hidden transaction tools, `script`), the tool section and "How to work" of the prompt, and the AST edition also shows the examples as trees. The scripted agents (reference and weak solutions) write through the surface of the edition (`script` of `set.json`, `bench/m1/surface.py`: a unified diff against the transaction's result files, a JSON Patch between trees). The gate checks that generation matches and that on the m1b·BVB editions the reference solutions pass and the weak solutions are rejected. The BRB editions are pilot variants, like `-write`.

## Rationale

- **Cause layer (JUDGMENT §3):** having no surface to measure is a gap in the tool layer. If the harness applies the diff or turns JSON into text (alternative i), the meaning of the surface (error wording, positions, atomicity) goes into measurement assets and runs apart from the compiler's diagnostics and normal form.
- **Canonical way (S1):** the rule for applying a unified diff is `git apply` (no fuzz, position search). `--recount` was chosen because the line count is a value computed deterministically from the hunk (principle 6: do not make the agent count what a tool can count). For partial edits of a JSON document RFC 6902/6901 is the canonical way. The shape of the tree follows the conventions of ESTree (a kind tag on every node) and syn-serde (empty parts omitted), and the field names use the compiler's syntax tree as is, so as not to make a new language.
- **Fairness (C3):** the two competing surfaces are strong editions of each format: they forgive line count errors, return diagnostics in the address of that surface (file line, tree pointer), and point to definitions by name. If the definition-level surface is still better the hypothesis is supported, and otherwise it is refuted.
- **Alternatives:** (a) The harness takes the diff or JSON and turns it into `tx_put`: the surface meaning goes into measurement assets and the diagnostics do not fit. (b) A strict diff (down to line counts): the surface carries a computation burden unrelated to the hypothesis. (c) JSON at the definition level only (a tree in place of the code of `write`): statement-level editing (the third level of H-GRAIN) goes away. JSON Patch allows both the definition level and the node level. (d) Point to nodes by array position only: discards the canonical address (path) that points to a definition by name. (e) This decision.

## Consequences

- Six frozen editions (`bench/m1b-diff`·`bvb-diff`·`brb-diff`·`m1b-ast`·`bvb-ast`·`brb-ast`). The formal measurement is backlog `T1-41`.
- The tree is larger than the text (m1b seed: text 26,051 bytes, `bmb ast` 102,643 bytes). This is a cost of the surface and is what is being measured.
- The `commits` and E02xx/commit of the harness count only `tx_commit`, so they are empty on the one-call write surfaces (`write`·`edit_file`·`edit_ast`) (`T1-40`).
- Revert: remove the flags, the command and the editions. The default and the existing frozen sets do not rely on this decision.
