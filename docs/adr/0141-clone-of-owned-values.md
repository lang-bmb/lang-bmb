# ADR-0141: `clone` of values that own memory

- Status: Accepted (approved by the maintainer 2026-11-15 "recommendation accepted, autonomous execution/verification approved": a surface change during the freeze, an exception under decision 4 of ADR-0100)
- Date: 2026-11-15
- Related: ADR-0031 §1 (`clone` of `Vec`), ADR-0047 §1·§4 (move types, drop glue), ADR-0050 (`String`), ADR-0051 (method calls), ADR-0091 §2 (`Child`), ADR-0100 (freeze), the decision criterion of the seventeenth plan in `dev-docs/BACKLOG.md`, backlog 4D-27·4D-28

## Context

- `clone` existed only on `Vec` (copy type elements) and `String`. Structs, enums, `Box` and a `Vec` of move elements were E0404, and the guidance was "make a copy by pushing new values in a loop".
- The port (`4D-03b`) paid that price: the 86 deep copies of the syntax tree `ast::clone_*` (about 890 lines) were generated by machine from the type declarations, and have to be generated again when a type changes. The body of the checker (`4D-03d`~) uses even more copies of the type and signature tables (hundreds of `.clone()` sites in `check.rs` of stage0).
- The decision criterion (maintainer instruction 2026-11-15) is "does the agent writing the port want to write that code". Hand-written copy functions per type do not meet it. It also deviates from the Rust habit (`x.clone()`).
- A soundness defect was found during the investigation (4D-27): `Vec<T>.clone()` inside a generic function (no `Copy` on `T`) was accepted, and when instantiated with `T = String` it copied only the buffer and freed the elements twice (valgrind `Invalid free`).

## Decision

1. **`x.clone()` exists on any type whose value owns memory.** Structs and enums that are move types (ADR-0047 §1) (including `Option`·`Result`), `Box<T>`, arrays, and a `Vec` whose elements are a move type. The result is the value type of the receiver (`T` for a `&T`·`&mut T` receiver), the same value as the original, and owns its own memory. Nothing is marked on the declaration: the same as copy and move being determined by structure (ADR-0047 §1).
2. **A copy that is not made is E0404.** (a) A type that holds in its name a type parameter without a `Copy` bound: the value may own memory, but the type is not known at the place where the copy is written. `Vec<T>` is the same (the fix of 4D-27). With a `Copy` bound it works. (b) A type that holds `std::process::Child`: one owner per resource. (c) Copy types: they are copied by value, so the guidance is "remove the `.clone()`" (as before).
3. **The type's own `clone` comes first.** If there is a `clone` in its own `impl` or a `clone` method of a trait it implements, the call is that one (the order of method resolution as it is, ADR-0051).
4. **The effect is `alloc`, inside a specification it is E0503, and the receiver is read (not moved).** In the proof the result is the same value as the original (the same encoding as the `clone` of `Vec`: no new obligation and no new axiom). The type invariant holds as it is because it is the same value.
5. **Code generation is per-type glue.** `@"bmb_clone.<type>"(ptr %dst, ptr %src)` builds the copy in `%dst`: it copies the bytes and then rebuilds the parts that own memory (the buffer and elements of a `Vec`, the value of a `Box`, the fields of a struct, the payload of an enum variant). It is emitted only for the types the program clones and the types they hold (the IR of a program without clones is unchanged). Allocation failure is `abort`, like other allocations.

## Rationale

| Option | Verdict |
| --- | --- |
| **A builtin `clone` determined by structure (accepted)** | Declarations do not grow and the call form is Rust's as it is. The meaning in the proof already exists (the same value), and code generation has the same shape as drop glue. The 86 copy functions of the port disappear |
| `#[derive(Clone)]` and a `Clone` trait | The same marking as Rust, but `derive` was decided against (E0220) and copy and move are also determined by structure. Going as far as a trait bound (`T: Clone`) would make it usable in generic code too, but dictionary passing for a builtin trait needs a different mechanism from `Copy`·`Eq`·`Ord`. It is opened when the need is measured (the place of decision 2a) |
| Leave it and generate the copy functions with a generator | It does not change the language. But the generated output is remade every time a type changes, and every copy function spends proof time (86 of them). It goes against the decision criterion |
| Open wildcard arms too | Not done. The rule of writing every arm (ADR-0026) makes the compiler point at the missing place when variants are added, and the cost to the port (empty arms) is line count, not a maintenance risk |

## Consequences

- stage0: `check.rs` (`builtin_clone`·`clone_method`·`clone_blocked`), `codegen.rs` (`clone_glue`). The version change is a MINOR of 0.x (ADR-0138: the accepted programs increase).
- Surface fingerprint (`dev-docs/health/surface.json`): the entries of the corpus whose result changed are written as exceptions (reasons 4D-27·4D-28).
- Tests: `tests/run/clone_values` (struct, recursive enum, `Box`, `Vec` of move elements, `Option`, array, own `clone`, `Copy` parameter, valgrind clean), `tests/check/err/clones`, conformance `05/clone_owned_values`·`05/clone_not_built`.
- Port: `ast::clone_*` is deleted and `.clone()` is written. When the checker comes to the port (`4D-03e`), the same rule is carried over. The glue of code generation is carried over in `4D-05`.
