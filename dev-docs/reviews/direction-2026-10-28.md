# 방향성 논의: 인간용 구성의 재검토와 가설 우선 트랙

> 2026-10-28 · 기준 커밋 `30166f99` · **상태: 논의 중(결정 아님).** §8의 질문에 대한 답을 받아 ADR로 남긴다.
> 판단은 `dev-docs/JUDGMENT.md`(ADR-0045)로 하고, 권장안은 그 §10 형식을 따른다.
> 이 환경에서 원문을 열지 못한 외부 수치는 "원문 미확인"으로 표시한다(arxiv.org 차단, ADR-0040과 같은 규칙).

## 1. 논의를 여는 이유

**측정이 언어를 따라가지 못한다.**

- v2 리셋 뒤 4일, 커밋 237개 동안 언어 페이즈 일곱을 닫았다.
- 그러나 모델이 있어야 재는 것은 데이터가 0이다.
  - 미션 목표: G2(1회 정확성), G3(명세 품질), G5(증명 대 테스트), G8(테스트 코드)
  - ADR-0040의 가설 아홉 중 여섯: H-SPEC, H-ORACLE, H-GAME, H-FAMILIAR, H-SCALE, H-REUSE
- 모델 실행은 "사용자 머신 + 유료 API" 한 경로에만 묶여 있다. 그래서 1E-10이 10-24부터 🚫다.
- 진입점(`bench/run_models.py`, INF-14)과 예산 상한은 이미 있다. 빠진 것은 실행뿐이다.
- 지금 genesis §3.5의 첫 교훈("차별점 가설은 그 위에 쌓기 전에 최소 실험으로 측정한다")을 어기고 있다.
- 귀속 층은 프로세스다(JUDGMENT §3).

**사람이 던진 질문.**

- AI는 BMB에서 더 이상 텍스트 파일을 읽고 쓰지 않는다. 도구로 정의를 더하고, 빼고, 고친다.
- 그렇다면 다음 구성은 여전히 필요한가: 파일 분할, 네임스페이스, 전역·지역 변수, 상속, 합성, 인터페이스.
- 이것들은 인간의 컨텍스트와 이해의 한계 때문에 생긴 것 아닌가.
- AI에게도 컨텍스트 한계는 있다. 그러나 읽기·쓰기·저장·맵 도출을 도구가 맡는다면 어떻게 되는가.
- 저장 파일이 최소화되고 난독화된다면, 그것은 AI에게 무슨 의미인가.

BMB는 이 질문의 절반을 이미 결정했다.

- 파일은 투영이다. 구성 단위는 선언으로 정한다(원칙 1·6·7, ADR-0011).
- 읽기·쓰기는 도구로만 한다.

남은 절반, 곧 "그 위에서 언어의 구성 자체를 어디까지 바꿀 수 있나"는 열려 있다(DESIGN §9 R2·R3). 이 문서는 그 절반을 가설로 바꾸고, 가설을 재는 트랙을 제안한다.

## 2. 분석 틀: 구성은 누구의 한계를 위한 것인가

| 기호 | 존재 이유 | 도구가 대신할 수 있나 |
| --- | --- | --- |
| H | 인간의 인지 한계(기억, 주의, 탐색, 타이핑) | 대신한다. 투영과 질의로 바꾼다 |
| C | 컨텍스트 한계(인간과 모델 공통): 한 번에 볼 수 있는 양 | 대부분 대신한다. 맵·슬라이스가 일차 수단이고, 언어는 경계(계약)를 준다 |
| S | 의미의 필요: 상태, 값 공유, 다형, 모듈 단위 검증, 분리 컴파일 | 대신하지 못한다. 언어에 남기고 증명 쪽으로 강화한다 |
| K | 협업: 동시 편집, 소유, 안정된 인터페이스 | 형태가 바뀐다. 여러 에이전트의 동시 편집이 새 형태다 |

**이름은 H가 아니다.** 모델에게 식별자는 의미를 실어 나르는 주 통로다.

- 의미를 보존한 채 식별자만 바꾸거나 지워도 LLM의 코드 이해가 크게 떨어진다. 요약은 줄 단위 서술로 무너지고, 프로그램 구조에만 기대야 할 실행 예측 과제에서도 영향이 보인다([When Names Disappear](https://arxiv.org/html/2510.03178v1), 2025. Gao 외 2023을 인용. 수치는 원문 미확인).
- 그러므로 "이름은 인간용이니 지워도 된다"는 틀린 추론이다.
- 이름에서 떼어 낼 수 있는 것은 **정체성**(무엇을 가리키는가)이다. **의미**(무엇을 하는가)는 떼어 낼 수 없다.

## 3. 구성별 재검토

| 구성 | 존재 이유 | BMB 현재 | 도구를 전제하면 | 가설 |
| --- | --- | --- | --- | --- |
| 파일 | H(탐색 단위), K(diff·병합 단위, 소유) | 투영, 의미 없음(ADR-0011). 저장과 git은 여전히 텍스트 파일 | 읽기·쓰기 단위는 이미 정의다. 남은 것은 동시 편집이다. 텍스트 3-way 병합은 같은 파일 안의 무관한 정의도 충돌시킨다 | H-PAR |

| 이름(식별자) | 정체성 + 의미 통로 | 정체성은 전체 경로다. 참조 대상의 이름이 해시 입력에 들어간다(ADR-0019 §2) | 정체성은 해시로, 이름은 메타데이터로 나눌 수 있다(Unison 선례). 의미 통로는 남긴다 | H-ID, H-NAME |
| 난독화 | — | — | 이름의 의미 통로를 끊는다. 계약(이름 붙은 술어)이 그 의미를 대신 실어 나를 수 있는지가 BMB만의 질문이다 | H-NAME |
| 네임스페이스·모듈 | H(정리), S(충돌 방지), C(목차) | 선언된 `mod`, 요약 필수, `pub` 없음, 전체 경로 | 정체성이 해시면 충돌 방지는 의미가 아니다. 남는 것은 C, 곧 1만 정의를 탐색할 목차(L0)다. 사람이 선언한 단위와 호출 그래프에서 도출한 군집 중 어느 쪽이 나은지 잴 수 있다 | H-UNIT |

| 지역 변수 | S(중간 상태와 루프 상태의 이름), 모델의 추론 보조 | 타입 명시, 셰도잉 금지 | 없앨 수 없다. 불변식·`old`·반례가 지역 이름으로 말한다. 질문은 "지역"의 크기다. 슬라이스 예산(원칙 5)이 정의를 작게 묶으면 지역·전역 구분은 "한 슬라이스 안·밖"이 된다 | H-GRAIN |

| 합성·인터페이스(trait) | S(다형, 모듈 단위 검증) | trait 계약과 정제 의무(2T) | 오히려 강화할 대상이다. 계약은 슬라이스의 경계이고(본문 대신 계약만 읽는다) 증명 캐시의 키다. 인터페이스는 인간 편의가 아니라 **증명과 컨텍스트의 경계**다 | H-SLICE |
| 주석 | H | 자유 `//`. 구조화 근거는 2E | 계약과 해시에 묶인 근거로 옮긴다(ADR-0006). 유지 | — |

**정리.** 도구를 전제하면 사라지는 것은 H뿐이다. BMB는 그것을 이미 대부분 지웠다(파일의 의미, import, 전역 가변, 상속, 매크로, 셰도잉). 다음 걸음은 셋이다.

1. **정체성과 이름을 나눈다(H-ID).** 이름은 의미 통로로 남기고, 참조는 해시로 한다.
2. **협업 단위를 옮긴다(H-PAR).** 동시 편집의 단위를 파일에서 정의로 바꾼다.
3. **보호 수단을 옮긴다(H-ENCAP).** 접근 제한 대신 증명된 불변식으로 지킨다.

## 4. 구조적 주소, 친숙한 내용

모델이 보는 언어는 저장된 바이트가 아니라 도구가 내놓는 투영이다. 저장은 미니파이든 바이너리든 상관없다. 그러나 투영을 낯선 형태로 바꾸면 안 된다는 근거가 셋 있다.

- 같은 모델에게 코드를 JSON 안에 담아 내게 하면 품질이 떨어진다([aider, 2024](https://aider.chat/2024/08/14/code-in-json.html), 다섯 번 평균). Claude 3.5 Sonnet은 60.5%에서 54.1%로, DeepSeek-Coder V2는 60.6%에서 51.1%로 떨어졌다.
- 학습 데이터가 적은 언어에서 LLM 성능은 24~39%p 낮다(ICPC 2025, genesis §4).
- 이름을 지우면 이해가 무너진다(§2).

권장 방향은 이렇다.

- 읽기·쓰기의 **주소**(무엇을 고치는가)는 구조적으로 정한다: 정의 경로·해시, 트랜잭션 연산.
- **내용**(무엇으로 고치는가)은 친숙한 Rust 꼴 텍스트로 둔다.

BMB의 트랜잭션(ADR-0009)이 이미 이 꼴이다. 이것을 가설로 확인하자는 것이다(H-EDIT). DESIGN §9 R2에 대한 답의 후보이기도 하다.

**미니파이·난독화가 AI에게 갖는 의미:**

- **공백을 지우는 미니파이는 정규형이 있는 한 얻는 것이 적다.** 얼마나 적은지는 토큰 수로 결정론적으로 잰다(H-VIEW).
- **이름을 지우는 난독화는 의미 통로를 끊는다.** 따라서 일반 언어에서는 해롭다.
- **BMB에서는 계약이 그 통로를 대신할 수 있다.** 오도하는 이름(`is_sorted`가 정렬을 확인하지 않음)을 만나면, 테스트에 기대는 에이전트는 속는다. 증명 게이트는 계약으로 판정하므로 속지 않을 수 있다. 이것은 BMB만 주장할 수 있는 이득이고, 잴 수 있다(H-NAME).

## 5. 이미 잰 것: 이름 바꾸기의 파급 (H-ID)

`dev-docs/experiments/rename-ripple/`에 실험이 있다.

- **방법:** 실행 프로그램 46개와 `lib/bytes.bmb`에서, 파일 안에서 이름이 유일한 정의의 이름만 하나씩 바꾼다. 그리고 해시가 바뀐 다른 정의(그 정의의 L2 참조자)를 센다.

| 항목 | 값 |
| --- | ---: |
| 이름을 바꾼 정의(검사 통과) | 412 |
| 다른 정의의 해시까지 바꾼 이름 바꾸기 | 356 (86%) |
| 본문 해시가 바뀐 참조자(합) | 611 |
| 계약 해시가 바뀐 참조자(합) | 377 |

- 해시 참조를 쓰고 이름을 메타데이터로 두면 위 참조자 수는 모두 0이다.
- **영향:** 이름 바꾸기나 이동(3C 보존형 리팩터링)마다 무관한 증명 캐시 키가 바뀐다. 동시 편집에서는 참조자가 모두 충돌 후보가 된다.
- **재지 않은 것:**
  - 이득 쪽: 맵·진단·diff는 이름으로 읽혀야 한다.
  - Unison이 치른 비용: 텍스트 기반 도구·git과의 마찰. Unison은 정의를 구현의 해시로 저장하고, 이름은 메타데이터로 두며, 의존을 해시로 참조한다. 이름 충돌은 병합 시 해시로 한정된 이름으로 드러난다([Unison 투어](https://unison-lang.org/docs/tour), [저장소](https://github.com/unisonweb/unison)). 이 주장들은 대부분 Unison 자신의 문서에서 왔다.

이 측정은 판정이 아니라 판정의 근거 하나다. H-ID는 이득과 비용을 함께 재야 닫힌다.

## 6. 가설 등록부

**상태 표기**

- **미측정:** 아직 데이터가 없다.
- **결정론 근거:** 모델 없이 잰 근거가 있다.
- **파일럿:** 동결 절차 밖의 예비 데이터가 있다. 주장에 쓰지 않는다.
- **확정·반증:** 동결 절차로 판정했다.

진척이 없어 판정을 못 한 것은 그대로 미측정으로 둔다. 판정을 추정하지 않는다(C3).

| H-PAR | 정의 단위 트랜잭션(해시 전제조건, 낙관적 동시성)은 파일 단위 텍스트 병합보다 동시 편집 충돌이 적고, 충돌 없이 깨진 병합이 0이다 | 정의 단위 충돌률이 텍스트 병합 충돌률 이상이다. 또는 깨진 병합이 하나라도 있다 | BCB 편집 이력을 N개 에이전트에 나눠 동시에 적용하는 재생(`git merge-file` 대 트랜잭션) | 아니오 |
| H-SLICE | 계약 경계 덕분에 한 정의를 고치는 데 필요한 읽기 양(슬라이스)이 코드베이스 크기와 무관하고, 파일 기반 읽기보다 작다 | 슬라이스 크기가 정의 수에 따라 늘어난다 | BNB 1k·3k·10k에서 슬라이스와 파일 읽기의 크기(H-SCALE의 결정론 부분) | 아니오 |
| H-VIEW | 같은 정보를 담은 투영 중 정규형 Rust 꼴이 성공률 대비 토큰이 가장 좋다. 미니파이는 토큰을 거의 줄이지 못한다 | 다른 투영이 같은 성공률에서 토큰이 10% 이상 적거나, 같은 토큰에서 성공률이 높다 | 토큰 수는 토큰 계산 API, 성공률은 m1 과제의 투영 쌍둥이 | 토큰은 계산만, 성공률은 예 |
| H-NAME | BMB에서는 계약이 이름의 의미 통로를 대신한다. 이름을 무의미하게 또는 오도하게 바꿔도 1회 성공률의 하락이 Rust+테스트 쌍둥이의 하락보다 작다 | 하락폭이 같거나 더 크다 | m1·BVB·BRB 과제의 난독화 쌍둥이(알파 개명판, 오도하는 이름판), 같은 모델 | 예 |
| H-UNIT | 탐색 목차는 사람이 선언한 단위보다 호출 그래프에서 도출한 군집이 탐색 정확도가 같거나 높다. 그렇다면 단위 선언은 도출물이 될 수 있다 | 도출 군집에서 BNB 탐색 P·R이 낮다 | BNB 1만 정의, L0를 두 판으로 | 예 |
| H-GRAIN | 편집 단위가 정의(슬라이스 예산 안)일 때 총 토큰이 파일 단위·문장 단위보다 적고 성공률은 같거나 높다 | 다른 단위가 더 적은 토큰으로 같은 성공률을 낸다 | m1b 편집 과제를 세 가지 단위의 도구로 | 예 |
| H-EDIT | 구조적 주소 + 텍스트 내용의 편집이 파일 diff 편집이나 JSON AST 편집보다 1회 성공률이 높다(R2) | 다른 표면의 성공률이 같거나 높다 | m1 편집 과제, 세 가지 도구 표면 | 예 |
| H-ENCAP | 자료 불변식을 타입 불변식 증명으로 지키면, 에이전트가 자료 구조 내부를 고쳐도 불변식 위반이 바이너리에 들어가지 않는다(0). Rust의 private + 테스트는 0보다 크다 | BMB에서 불변식 위반 결함이 게이트를 통과한다 | BRB 확장 과제(자료 구조 수정) | 예(언어 기능 타입 불변식이 먼저 필요) |

## 7. 트랙 재설정

### 7.1 권장안: 측정 경로 (JUDGMENT §10)

1. **문제:** 모델이 필요한 가설 여섯과 미션 목표 넷이 데이터 0인 채로 언어만 커진다.
2. **원인과 귀속 층:** 프로세스. 모델 실행 경로가 하나(사용자 머신)뿐이고 그 경로가 막혔다. 언어·컴파일러의 결함이 아니다.
3. **정석 해:** 평가 파이프라인 자동화다. 고정 모델 ID, 동결 과제·프롬프트, 예산 상한, 결과 커밋을 갖춘다. 공개 코딩 벤치(aider 벤치, SWE-bench 하네스)가 이렇게 운영된다.
4. **후보 비교:**

   | 후보 | 내용 | 평가 |
   | --- | --- | --- |
   | A. 현행 | 사용자 머신에서 실행 | C1~C4는 통과한다. 그러나 4일째 데이터가 없다(S5 실패) |
   | B. 자동 경로 | 이 클라우드 환경이나 GitHub Actions에 API 키를 시크릿으로 두고, `bench/run_models.py --budget`으로 실행 | C1~C4 통과, S1 정석, S5 증거가 지속적으로 생긴다 |
   | C. 파일럿 | 이 환경의 Claude Code CLI(`claude -p`)를 피험 에이전트로 쓴다 | 하네스의 프롬프트·도구 조건을 정확히 재현하지 못한다(자체 시스템 프롬프트와 도구). ADR-0021 동결 절차의 측정으로 인정할 수 없다 |

5. **권장과 결정적 기준:** B. 결정적 기준은 S1(정석)과 S5(증거)다. C는 B가 늦어질 때 방향 판단용 파일럿으로만 쓴다. 결과에 "파일럿"을 표시하고 문서의 주장에는 쓰지 않는다.
6. **영향(정보):** 어댑터(`bench/m1/anthropic_agent.py`)와 진입점(`bench/run_models.py`)이 있다. 필요한 것은 시크릿 설정, 예산 값, 결과 커밋 절차다.
7. **필요한 승인:** 유료 API 사용(AUTONOMY §4 "외부"). 시크릿은 사람이 설정해야 한다.

| T4 라이브러리 | 쓸모 있는 증명된 라이브러리로 실용성을 증명한다 | 공인 시험 벡터가 있는 것부터: SHA-256(FIPS 180-4, NIST CAVP), base64(RFC 4648), UTF-8 검증, CRC-32, JSON 파서(JSONTestSuite). 각각 전부 증명 + 공인 벡터 통과 + Rust 크레이트 대비 속도·크기 표. 4B(표준 라이브러리 핵심)와 겹친다 | 라이브러리마다 증명·벡터·비교 표 커밋 |
| T5 자립 | 4단계 그대로 | T2·T4 뒤 | ROADMAP 4단계 |

**순서와 규칙**

- T0가 첫째다. 다른 트랙을 막지는 않는다. 다만 주장은 T0 데이터가 있어야 문서에 들어간다(C3).
- T2의 새 페이즈는 T3·T4의 구체 수요가 있을 때 연다. 단, JUDGMENT §7의 "정석 Rust 프로그램을 쓸 수 없다"는 수요와 상관없이 결함이다.
- 수요의 예:
  - SHA-256 → 2N 비트 연산
  - JSON 파서 → 2U 문자열
  - Benchmarks Game:
    - 지금 언어로 쓸 수 있는 것: binary-trees(`Box`), fannkuch-redux(정수·배열)
    - `f64`가 필요한 것: n-body, spectral-norm, mandelbrot
    - 해시 맵이 필요한 것: k-nucleotide
- 페이즈 종료 감사에 "가설 등록부 변화"를 넣는다.
