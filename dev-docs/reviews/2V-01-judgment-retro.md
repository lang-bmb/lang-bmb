## R1. 코퍼스 `k*k` → `3*k`

1. **문제:** 2G-05에서 루프 길이 건전성 버그를 고치자 `tests/verify/pass/vecs.bmb`의 `first_squares`가 증명은 되지만 의무 하나가 rlimit 3,793,469(한도의 76%)가 되었다. 지표 V5(최대 의무/한도 ≤ 0.2)를 넘지 않게 코퍼스를 `3*k`로 바꿨다(`e352cfd`).
2. **원인과 층:** 의무 `i < n ≤ 1000 ⇒ i*i`가 `i64` 범위 안. 무관한 문맥(`squares`)을 빼도 937,263이고 z3의 비선형 엔진이 비용이다. 단조성 사실 `0 ≤ i < n ⇒ i*i ≤ n*n` 하나를 더하면 4,142다. **컴파일러 층**(인코딩이 곱셈 사실을 주지 않음). 코퍼스를 바꾼 것은 지표를 맞추려 해를 바꾼 **프로세스 오용**(JUDGMENT §9)이다.
3. **정석 해:** 검증 도구는 비선형 산술을 보조 정리로 다룬다(Verus `vstd::arithmetic::mul` 보조 정리, Dafny 표준 라이브러리 `Std.Arithmetic` 보조 정리). BMB는 원칙 6(기계적인 것은 도구가)에 따라 1B-42의 나눗셈 사실처럼 인코더가 곱셈마다 자동으로 넣는다.
4. **후보:** (가) 곱마다 부호·단조성 사실(피연산자의 경로 조건 상한 항으로 인스턴스화) (나) 사용자가 보조 정리를 부르게 함 (다) z3 옵션 조정(`nl.grobner false`는 233k, 다른 의무를 악화시킬 수 있음). (나)는 원칙 6에 어긋난다. (다)는 원인을 남긴다.
5. **권장:** (가). 결정적 기준 S1·S2. 사실은 `tests/lemmas.rs`로 정리임을 증명한다. `first_squares`를 원래대로 되돌린다.
6. **영향(정보):** `verify.rs` 인코더, 코퍼스 기대 출력의 rlimit.
7. **승인:** 자율(인코딩, 1B-42와 같은 부류).

## R2. `primes`의 `i*i` → `2i`

1. **문제:** `tests/run/primes.bmb`의 체를 `i*i`부터 표시하면 `pr::primes`가 기저 인스턴스 재시도로만 증명되고(rlimit_max 5,000,286), `tests/incremental.rs::outputs_are_identical_with_and_without_the_cache`가 `audit_mismatches: ["pr::primes"]`로 실패한다. 체를 `2i`부터 표시하도록 바꿔 피했다(`e352cfd`).
2. **원인과 층:** 두 가지다. (a) 재시도로 증명된 정의를 증분 캐시가 다시 쓸 때 기록과 재계산이 다르다(감사가 상태·rlimit·증명 집합을 비교, `incremental.rs::proof_audit`). 결정론(C2)에 걸린 **컴파일러 결함**이다. (b) `i*i < n`의 비선형 비용은 R1과 같은 부류다.
3. **정석 해:** 캐시 키·기록이 재시도 경로까지 포함해 같은 질의 텍스트에 같은 결과를 주게 한다(ADR-0032의 불변식 그대로).
4. **후보:** (가) 재시도 결과의 기록·감사 비교를 고친다 (나) 재시도된 정의는 캐시하지 않는다. (나)는 원인을 남기고 증분 빌드의 이득을 줄인다.
5. **권장:** (가), 그리고 R1의 곱셈 사실로 재시도 자체가 필요 없게 한다. 원래 알고리즘(`i*i`부터, `i * i < n`)으로 되돌린다. 결정적 기준 C2·S2.
6. **재현:** `tests/run/primes.bmb`에서 `let mut j: usize = i + i;`를 `i * i`로, 바깥 조건을 `i * i < n`으로 바꾸고 `cargo test --test incremental outputs_are_identical`.
7. **승인:** 자율.

## R3. 배열 반환·데이터 배열 값 매개변수·배열을 담은 원소·중첩 배열

1. **문제:** 다음이 E0402로 거부된다. 함수가 배열을 반환("a function cannot return an array in milestone 1"), 구조체·열거형 배열을 값으로 받기("passed as `&[T]`", 2B-14), 배열을 담은 구조체의 배열(2B-14), 중첩 배열 `[[T; M]; N]`(1B-35).
2. **원인과 층:** 모두 Rust에서 정석인 형태이고 원장 항목이 아니다. 증명기의 잎 분해(`leaves`의 "array inside an array element")와 코드 생성의 집합값 전달이 구현되지 않았을 뿐이다. **컴파일러 층**.
3. **정석 해:** 값 의미의 집합 전달(rustc: 결과는 `sret`, 인자는 복사), 중첩 배열은 SMT에서 `(Array Int (Array Int T))` 또는 잎마다 배열의 배열.
4. **권장:** 네 가지를 모두 받는다. 증명 인코딩은 중첩 배열을 일반화한 잎 분해로, 코드 생성은 기존 `ret.out`·복사 경로로. 결정적 기준 S1·S2.
5. **승인:** 자율(제한 해제는 언어 범위 확대지만 ADR-0026·0031 범위 안의 "아직 구현 안 됨"이다. 새 표면이 없다).

## R4. E0814 잔여

1. **문제:** 증명기가 거부하는 구성: 명세의 배열 리터럴·반복, `forall` 안의 재귀 호출, 배열 페이로드를 가진 열거형(과 그것을 담은 구조체)의 명세 `==`.
2. **원인과 층:** 인코딩 미구현. **컴파일러 층**(JUDGMENT §8: E0814는 줄여야 할 결함 목록).
3. **권장:** 각각 인코딩한다(배열 리터럴은 실행 코드와 같은 `store` 연쇄, 재귀 호출은 `decreases` 검사를 수량자 본문에 적용, 배열 페이로드 `==`는 원소별 외연 동등). E0814는 범주로 남기되 코퍼스에서 발생 0을 목표로 한다.
4. **승인:** 자율.

## R5. 사용자 제네릭과 trait

1. **문제:** ADR-0026은 사용자 제네릭·trait를 "제네릭 페이즈로 미룸"이라 했지만 로드맵에 그 페이즈가 없다. 그 결과 정렬된 맵을 표준 라이브러리로 쓰려면 키·값 타입마다 복제하거나(`selfhost-gap.md` §5.3-2), 맵을 내장해야 한다는 우회가 권장안에 들어갔다(R12).
2. **원인과 층:** 정석 해법(제네릭 컨테이너, 제네릭 알고리즘)을 표현할 수 없다. **언어 층**.
3. **정석 해:** Rust의 제네릭 + trait 경계 + 단형화. 검증 쪽 선례: Verus는 제네릭 함수와 trait를 지원하고, 제네릭 정의를 단형화하지 않고 한 번 증명한다(타입을 SMT 항으로 넘기는 균일 표현).
4. **후보:** (가) 제네릭 + trait 경계, 증명은 정의마다 한 번, 코드는 단형화 (나) 맵·집합만 내장 (다) 단형 라이브러리 복제. (나)는 사용자 정의 컨테이너를 막고 내장과 사용자 정의의 규칙이 갈린다(S3). (다)는 우회다.
5. **권장:** (가). 원칙 5(슬라이스 자급)와의 관계: 제네릭 정의의 계약은 경계 trait의 계약까지 포함하면 자급한다. 겹침 없는 명시적 impl(원장 "다형성")은 그대로 유지한다.
6. **승인:** 필요(언어 범위, ADR-0026 일부 대체).

## R6. 재귀 타입(`Box<T>`)

1. **문제:** ADR-0026이 재귀 타입을 금지했다("힙은 2G"). 2G(ADR-0031)는 `Vec`만 넣었고 재귀 타입은 여전히 E0421이다. 구문 트리·JSON·S-식 같은 정석 표현이 아레나 우회를 강요받는다(`selfhost-gap.md` §4.1 "상").
2. **원인과 층:** **언어 층**. SMT 데이터타입은 재귀를 지원하므로(ADR-0027의 인코딩 그대로) 원리적 장벽이 없다.
3. **정석 해:** Rust `Box<T>`(소유, 이동, drop) + 재귀 `enum`. 검증: Verus·Dafny 모두 재귀 데이터타입과 `decreases`(구조적 크기)를 쓴다.
4. **권장:** `Box<T>`와 재귀 열거형·구조체를 넣는다. 종료는 구조적 크기를 `decreases`에 쓸 수 있게 한다. 이동 검사는 ADR-0031 §2를 `Box`로 넓힌다.
5. **승인:** 필요.

## R7. `Vec`을 담는 구조체, `Vec<Vec<T>>`

1. **문제:** ADR-0031 §1이 범위 밖으로 두었다. 문맥 구조체(`Checker`·`Gen`처럼 `Vec` 여러 개)를 쓸 수 없어 매개변수 펼치기 우회가 권고되었다(`selfhost-gap.md` §4.1, 함수당 5~15개).
2. **원인과 층:** 소유 필드의 이동·해제 규칙이 없다. **언어·컴파일러 층**.
3. **정석 해:** Rust의 소유 필드, 부분 이동 금지(또는 Rust 규칙 그대로), 재귀 drop glue.
4. **권장:** 소유 타입(`Vec`, `Box`, 그것을 담은 데이터 타입)을 일반화한다: 값은 이동, 해제는 drop glue. R6과 같은 ADR로 묶는 것을 권한다(소유 타입 일반화).
5. **승인:** 필요.

## R8. 비트 연산과 16진 리터럴

1. **문제:** `&`·`|`·`^`·`<<`·`>>`와 `0x` 리터럴이 없다. 셀프호스팅 분석은 SHA-256을 탈출구(`external_body`)로 두자고 권했다.
2. **원인과 층:** 정수를 `Int`로 인코딩한 결정(ADR-0017)에서 비트 연산이 비선형이 된다는 **컴파일러 층**의 어려움이 언어 기능 부재로 남았다(JUDGMENT §7: 인코딩이 어려운 것은 기능을 빼는 이유가 아니다).
3. **정석 해:** Rust 연산자 그대로. 검증: Verus는 비트 연산을 `by (bit_vector)` 단언으로 bitvector 이론에 보내고, Dafny는 `bv` 타입을 쓴다. Int↔BV 변환(`int2bv`·`bv2int`)으로 해당 식만 bitvector로 증명하는 혼합 인코딩이 선례다.
4. **권장:** 연산자와 16진 리터럴을 넣고, 비트 연산을 포함한 의무를 bitvector로 옮기는 혼합 인코딩을 설계한다. SHA-256은 증명된 BMB 코드가 된다.
5. **승인:** 필요(언어 범위, ADR-0017 보완).

## R9. 조기 탈출과 `for`

1. **문제:** `return`·`break`·`continue`·`?`가 없고(E0206 등), 셀 수 있는 루프도 `while` + `decreases`다. 셀프호스팅 분석에서 `?`·`return`·`break` 518곳이 "상" 비용이다.
2. **원인과 층:** 원장(DESIGN §4.1)은 `?`의 암묵적 `From` 변환만 금지한다. 조기 탈출 자체를 금지하는 원장 항목이 없다. **언어 층**. `for`는 원장 "표현: 정규형 하나"의 대상이지만 어느 형태가 정규형인지가 열려 있다(2R-04f).
3. **정석 해:** Rust 그대로(`?`는 같은 오류 타입일 때만). Verus·Dafny 모두 조기 반환과 `break`를 지원하고 VC 생성은 표준 기법이다.
4. **권장:** 조기 탈출 네 가지를 넣는다. 셀 수 있는 루프는 `for i in lo..hi`를 정규형으로 하고 `decreases`를 자동으로 준다(원칙 6). `while`은 그 밖의 루프에 남는다.
5. **승인:** 필요(2R-06과 함께 결정. 2R-04f 결과를 입력으로).

## R10. `String`·`&str`

1. **문제:** ADR-0044가 `String`·`&str`·`char`를 거부하고 `Vec<u8>`·`&[u8]`로 대체했다. 근거는 UTF-8 불변식을 증명에 들이는 비용이었다.
2. **원인과 층:** 비용은 기준이 아니다(JUDGMENT §5). 문자열은 Rust에서 정석이고 LLM의 사전 지식이 가장 많은 영역이다(S4, Rust 습관 오류율). **언어 층**.
3. **정석 해:** Rust `String`/`&str`(UTF-8 불변식, 바이트 접근은 `as_bytes`). 검증: Verus는 `String`을 `Seq<char>` 보기로 명세한다.
4. **권장:** `String`·`&str`를 UTF-8 불변식을 가진 타입으로 넣는다(생성 지점에서 불변식 증명 또는 검사, 보기는 바이트 열). `Vec<u8>`·`b"..."`·`lib/bytes.bmb`는 그대로 둔다. `char`는 Rust처럼 유니코드 스칼라 값.
5. **승인:** 필요(ADR-0044 일부 대체).

## R11. 메서드 구문

1. **문제:** 사용자 함수는 `T::f(&x)`만 허용하고(ADR-0026), 내장은 `v.len()`, `v.push(x)`, `x.wrapping_add(y)`, `u8::try_from(x).unwrap()`처럼 메서드 구문이다. 같은 일에 두 규칙이다(S3).
2. **원인과 층:** 금지 근거는 원칙 5(호출 대상이 텍스트에 없으면 슬라이스가 자급하지 않는다)였다. 그러나 BMB는 모든 지역 타입을 명시하고 auto-ref·auto-deref·Deref 강제를 금지하므로(원장 "호출 해석"), 수신자 타입과 호출 대상은 슬라이스 안의 시그니처로 결정론적으로 정해진다. 내장 메서드가 이미 그렇게 동작한다. **언어 층(일관성)**.
3. **정석 해:** Rust의 고유 impl 메서드 구문(`x.f(..)`), 수신자 자동 참조 없이.
4. **권장:** 메서드 구문을 정본으로 통일하고 `T::f(&x)`는 기계 수정으로 바꾼다. 맵 L2는 해석된 대상을 기록한다(지금도 내장에 대해 하는 일).
5. **승인:** 필요(ADR-0026 일부 대체, 2R-06과 함께).

## R12. 직전 W5a 제안의 우회 권장

- "정렬된 맵을 단형 `bytes→u64`·`u64→u64`로", "아레나·`Vec` 필드 없이 렉서를 쓸 수 있는지 확인"은 언어 결함(R5·R6·R7)을 우회로 덮는 권장이었다. 철회한다.
- 4B-03(표준 라이브러리 초안)은 R5·R6·R7·R10의 결정 위에서 다시 쓴다: 제네릭 `BTreeMap<K, V>`·`BTreeSet<T>`, `String`, 정렬, 서식.

## R13. 2B-13 구조체 생성 필드 순서

- Rust는 적힌 순서로 평가하고 어떤 순서로든 쓸 수 있다. 정규형 하나(원칙 8)와 Rust 관례(clippy `inconsistent_struct_constructor`가 선언 순서를 권함)를 함께 만족하는 것은 (가) 선언 순서 요구 + 기계 수정이다. 기존 권고를 유지한다(S1·S3).

## R14. 남은 "milestone 1" 제외 항목

- 파서와 검사기가 "not supported in milestone 1"로 거부하는 Rust 정석 형태가 더 있다: `const`·`static` 항목(안내는 "`spec fn`으로"), `type` 별칭, `use`, 클로저, 튜플 타입·튜플 구조체·구조체형 변형(ADR-0026이 원칙 8 "형태 하나"를 근거로 듦).
- 튜플류는 원장 근거(원칙 8)가 적혀 있어 대조가 필요하다. 나머지는 원장 근거가 없다. 2V-13에서 항목마다 §10 형식으로 권장한다.

## 1. 다음 일정에 주는 함의

- 컴파일러 층(R1~R4)은 승인 없이 바로 고친다. 고친 뒤 되돌린 코퍼스가 원래 형태로 증명되는지가 완료 기준이다.
- 언어 층(R5~R11)은 ADR 초안(2V-06~2V-11)을 쓰고 한 번에 승인을 받는다(2V-12). 구현 순서는 셀프호스팅 임계 경로를 따른다: 제네릭 → 소유 타입(`Box`·재귀·`Vec` 필드) → 조기 탈출·`for` → `String` → 비트 연산 → 메서드 구문.
- 표준 라이브러리(4B)와 포팅(4D)은 이 결정들 뒤에 둔다. 셀프호스팅 격차의 "상" 비용 항목은 우회 비용이 아니라 이 페이즈의 범위가 된다.
