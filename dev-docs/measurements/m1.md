# M1 측정 보고서 (초안)

> 상태: **초안.** 실제 모델 수치(백로그 1E-10)가 아직 없다. 모델 실행과 무관한 부분(절차, 편향, 성능 기준선, 증명 게이트 신뢰성, 언어 마찰)만 먼저 쓴다. 결과 파일이 커밋되면 §3을 채우고 1E-06으로 확정한다.
> 근거: ADR-0021(절차), `bench/m1/`(과제·하네스), `bench/baseline/`(성능), 백로그 1B-17~1B-19, 1E-11.

## 1. 가설과 절차

M1의 가설은 "에이전트가 파일 없이, 테스트 없이, 증명된 코드를 쓴다"이다(genesis §5).

- 에이전트는 MCP 도구(`bmb mcp`)만 쓴다. 파일·셸 접근은 없다.
- 과제당 세션은 한 번이고 재시도하지 않는다. 한도는 도구 호출 40회다.
- 작성 과제의 성공 = 작업 공간 전체 증명 + 요구 시그니처 + **명세 강도 검사**(숨긴 기준 계약을 에이전트의 계약이 함의함을 증명). "증명은 되지만 아무것도 말하지 않는 명세"는 실패다.
- 탐색 과제의 정답은 맵에서 결정론적으로 계산하고, 정밀도·재현율이 모두 1이어야 성공이다.
- 과제·시드·프롬프트는 `bench/m1/MANIFEST`의 SHA-256으로 동결되어 있다. 다르면 하네스가 실행을 거부한다.

## 2. 과제 집합과 편향

| 항목 | 값 |
| --- | --- |
| 과제 수 | 15(작성 10, 탐색 5) |
| 시작 작업 공간 | 정의 23개 |
| 도메인 | 정수·배열 알고리즘(ADR-0016 범위) |
| 기준 해법 | 15/15 성공(CI, `--agent oracle`) |
| 약한 명세 대조군 | 1/1 실패(CI, `--agent weak`): 명세 강도 검사가 약한 명세를 거른다 |

결과를 읽을 때 고려할 편향:

1. **범위:** 정수·배열만 다룬다. 구조체·열거형·힙이 없어서 실제 코드베이스의 어려움 대부분이 빠져 있다.
2. **규모:** 과제 15개, 정의 23개다. 성공률 1개 차이가 7~10%p다. 원칙 7(질의 범위 비례)은 이 규모로 검증할 수 없다(3단계 대상).
3. **작성자:** 과제는 컴파일러를 만든 같은 에이전트가 썼다. 과제가 컴파일러가 잘 지원하는 형태로 치우쳤을 수 있다. 과제를 쓰다 언어를 고친 사례(§5)가 그 증거다. 동결은 과제를 쓴 뒤 컴파일러를 맞추는 것을 막지만, 그 이전의 치우침은 막지 못한다.
4. **단일 실행:** 과제당 1회이므로 모델의 실행 간 분산을 재지 않는다.

## 4. 성능 기준선

`bench/baseline/results/2026-10-24.md`의 요약이다. 벤치 7개, 변형별 9회 교차 실행의 중앙값이다.

| 벤치 | BMB/안전 Rust | BMB/unchecked Rust |
| --- | ---: | ---: |
| sieve | 0.986 | 1.016 |
| isort | 0.869 | 0.907 |
| kadane | 1.019 | 1.079 |
| gcdsum | 0.998 | 0.994 |
| hist | 1.009 | 0.988 |
| gather | 0.987 | 0.951 |
| vadd | 0.975 | 0.725 |

- BMB는 안전 Rust와 대략 ±5% 안에서 대등하다.
- 안전 Rust와 unchecked Rust도 잡음 수준으로 같다. **증명으로 범위 검사를 지우는 속도 이득은 이 벤치들에서 관찰되지 않았다.** 간접 인덱스(hist, gather) 벤치를 일부러 추가했어도 마찬가지였다(백로그 1E-08).
- 증명의 이득은 속도보다 실패 경로 부재(넘침·범위 초과가 없음이 증명됨)에 있다고 본다.

## 5. 증명 게이트의 신뢰성

에이전트에게 "증명되었다"는 판정은 테스트를 대신한다. 따라서 판정이 틀리면 측정 전체가 무의미해진다. 실제 모델 측정과 별개로 다음을 확인했다.

| 확인 | 방법 | 결과 |
| --- | --- | --- |
| 건전성 | 임의 정수 함수·계약을 증명하고, 증명된 함수를 전제를 만족하는 입력에서 독립 해석기로 실행(`compiler/tests/soundness.rs`, 1B-17) | 60배치에서 함수 480개, 증명된 109개를 전제 만족 입력 383개로 실행. 위반 0건 |
| 반례 | 확정 반례마다 입력이 전제를 만족하고 함수를 실제로 깨뜨리는지 해석기로 확인(1B-18) | 반례 620개, 거짓 반례 0건 |
| 루프·배열 건전성 | `&mut` 배열·`while`·불변식·`old`가 있는 함수로 같은 확인(`soundness_loops.rs`, 1B-21). 불변식은 매 루프 머리에서 확인 | 60배치에서 함수 360개, 증명된 162개를 입력 964개로 실행. 위반 0건. 반례 131개 전제 만족 |
| 코드 생성 | 검사 제거 빌드와 전체 검사 빌드의 출력이 해석기와 일치 | 3,664회 실행, 불일치 0건 |
| 안정성 | 코퍼스 전체를 Z3 시드 3~5개로 증명(`bmb stability`, 1B-19) | 판정이 시드에 따라 바뀐 정의 0개. `rlimit`은 시드에 따라 최대 2.2배 변함(비선형 산술이 있는 정의) |

## 6. 언어 마찰 (1E-11)

과제·벤치·코퍼스를 쓰면서 드러난 마찰이다. 실제 모델이 같은 곳에서 막히는지 §3에서 대조한다.

| 마찰 | 처리 |
| --- | --- |
| 명세에서 정수 타입을 섞을 수 없었다(`usize` 길이와 `i64` 값 비교) | ADR-0022로 명세에서 정수 타입 혼합을 허용 |
| 루프 불변식에서 `old(a)`를 쓸 수 없었다 | 불변식의 `old` 허용 |
| `#[uses]` 누락이 반복되었다. 술어가 불투명해 증명이 실패하고, 원인이 바로 보이지 않았다 | 실패 진단의 `fix`에 펼치지 않은 술어 목록을 제안(1D-13) |
| 정수 변환이 없다(`as` 금지, E0205). `usize` 결과를 출력하려면 세는 루프를 손으로 써야 했다(`tests/run/search.bmb`의 `show_size`) | 해소(ADR-0028, 2C-02): `i64::try_from(n).unwrap()`과 `print_u64`. `search.bmb`의 세는 루프 두 개를 지웠고 출력이 같다 |
| 비선형 산술은 증명 비용이 크다. `pow`(밑 ≤ 10, 지수 ≤ 15)의 한 의무가 `rlimit` 500만 중 410만을 썼다 | 비선형 진단과 우회 안내(1B-16). 코퍼스에서는 제외 |
| 음수 리터럴의 메서드 호출 `-4.wrapping_mul(y)`은 Rust처럼 `-(4.wrapping_mul(y))`이다. 건전성 퍼저의 생성기가 이 우선순위를 틀렸다 | Rust와 같은 의미라 유지. 에이전트도 틀릴 수 있는 지점으로 기록 |
| 틀린 명세(코퍼스의 `gcd` 사후 조건)는 반례 `a = 1, b = 2`로 바로 드러났다 | 긍정 사례: 반례가 명세 오류를 짚음 |
| 원소 합 루프는 원소 범위와 누적 불변식만으로는 증명되지 않는다. 슬라이스 길이에 상한이 없어 길이가 약 10^16이면 누적값이 넘칠 수 있기 때문이다. 판정은 옳지만, Rust 작성자는 보통 이 조건(`a.len() <= N`)을 떠올리지 않는다 | 건전성 퍼저의 합 템플릿에 길이 상한을 추가. 에이전트가 같은 곳에서 막히는지 §3에서 확인 |
| 리터럴만으로 된 식(`(66 + 14) < y`, `if c { 5 } else { y }`)이 `i64`로 정해져 `u64` 코드가 타입 오류가 났다(Rust는 문맥에서 추론) | 수정(백로그 1A-12). 부호 없는 산술 퍼저가 발견 |
| `f(&mut a, a.len())`가 별칭 오류였다. 명세의 `-x`(u64)·큰 리터럴도 거부되었다 | 완화(ADR-0024, 사람 승인) |
| 이름 재사용 금지(E0303)가 벤치 기준 해법 작성 중 3번 걸렸다(수량자 변수, 결과 이름 `r`과 같은 `let r`). Rust에서는 섀도잉이 흔하다 | 문법 재평가(2R-02) 입력 |
| 반례 표시 버그: 길이 4 미만 배열 뒤의 매개변수에 배열 원소 값이 표시되었다(`x = 7`이어야 할 곳에 `x = 8`) | 수정(백로그 1B-22). 반례를 믿고 고치는 에이전트를 오도할 수 있었다 |
| 2B: 구조체·열거형 원소의 지역 배열 `[Point; N]`을 만들 수 없다(E0402 "array elements must be scalars"). 그래서 `&[Point]`를 받는 함수를 실행 코드에서 부를 길이 없다(증명·코드 생성은 슬라이스를 다룬다) | 2B-14(검사기 허용 + 배열 값의 증명·코드 생성) |
| 2B: 구조체의 배열 필드 원소 대입 `s.w[i] = v`가 거부된다(E0408 "only `name[i]` can be assigned"). 전체 대입 `s.w = [..]`만 된다 | 2B-15(장소 규칙 확장. 증명기·코드 생성은 장소 단계로 이미 처리) |
| 2B: `ensures`에서 `old(self)`의 타입이 `&mut T`라 값을 받는 술어에 넘기려면 `*old(self)`를 써야 했다(E0401, 수정 제안 없음) | 2B-16(`&T`를 `T` 자리에 줄 때 `*e` 기계적 수정) |
| 2B: 갈래 바인딩도 함수 전체에서 이름이 하나여야 해서(E0303) 같은 함수의 `match` 두 개에 `Some(v)`를 쓰지 못하고 이름을 바꿨다(`tests/run/shapes`·`values`) | 문법 재평가(2R-02·2R-06) 입력. 셰도잉 금지 규칙 그대로 |
| 2B: 구조체 생성 식의 필드 순서. 정규형이 선언 순서로 정렬하면 효과 있는 필드 식의 평가 순서가 바뀐다 | 2B-13(승인 대기, 규칙 결정) |
| 2B: 양화된 `spec fn` 정의 뒤의 거짓 주장은 반례 대신 `rlimit` 한도(약 500만)까지 돌고 실패한다(정수에서도 같음, `structs` 실패 코퍼스) | 유지(판정은 옳다: 증명되지 않음). 실패가 느린 점은 2D 도구 후보로 기록 |
| 2C: `u64` 문맥의 리터럴 수신자 `3.saturating_sub(5)`가 `i64`라 타입 오류(E0401)였다 | 유지. Rust도 모호한 정수 리터럴의 메서드 호출을 거부한다(E0689). 타입 있는 지역 변수로 씀 |
| 2C: `checked_*`·`.ok()` 결과를 쓸 때마다 `match`가 필요하고, 갈래 바인딩 이름이 함수 안에서 하나여야 해(E0303) 퍼저 생성기가 고유 이름(`v0`, `v1`, ..)을 만들어야 했다 | 2B의 같은 행과 함께 문법 재평가(2R-02·2R-06) 입력 |
| 2C: `b as i64`(`bool`)는 `bmb fix`가 두 번에 고친다(E0205가 `i64::try_from(b).unwrap()`으로, 다음 회차 E0412가 `if b { 1 } else { 0 }`으로) | 유지. 회차 반복으로 수렴(`conversion_habits_are_fixed_into_a_checked_program`) |
| 2C: 코퍼스를 쓰며 `saturating_add`의 결과가 수학적 합 이하라고 잘못 적었다. 반례 `x = -9223372036854775527, y = -282`(아래로 잘림)가 바로 짚었다 | 긍정 사례: 반례가 명세 오류를 짚음 |
| 2G: 루프 불변식에 `Vec` 길이를 다시 써야 한다(`v.len() == i`). 루프가 바꾸는 `Vec`은 길이까지 다시 정해지기 때문이다(그러지 않으면 건전하지 않았다, 2G-05) | 유지(판정은 옳다). 프레임 조건 자동 채움 후보(DESIGN.md §8.2) |
| 2G: 핸들 패턴에서 "기존 원소 보존"만 쓴 계약으로는 두 번째 `add`의 사전 조건과 원소 값이 증명되지 않았다. 정확한 성장(`len + 1`, 새 원소)이 필요했다(`tests/verify/pass/vecs`의 `added`) | ADR-0031 §5가 예상한 마찰. 프레임 조건 자동 채움 후보 |
| 2G: `old(v).as_slice().len()`처럼 슬라이스 값을 식에서 쓸 수 없다(E0409, 인자 자리만). 술어로 옮겨야 했다 | 유지(정규형 하나). 2R-02 입력 |
| 2G: 체의 `while i * i < n`에서 `*` 넘침 의무 하나가 `rlimit` 500만을 다 쓰고 기초 인스턴스 재시도로만 증명되었다. 증분 감사가 이 흔들림을 잡았다 | `2i`부터 표시하는 선형 형태로 다시 씀(126k). 비선형 진단(1B-16)은 있음 |
| 2T: trait의 spec 메서드 결과에 `is(r, Score::value(self))`처럼 `i64` 매개변수 술어를 쓰면 정의 공리의 범위 가드가 열리지 않아 루프 불변식이 미결정이었다(명세 정수는 무한 정수, 비해석 함수의 결과에 범위가 없다) | 유지(의미가 옳다, ADR-0022). 결과를 원래 인자로 말하는 술어(`scored::<T>(x, r)`)로 쓴다. README·`tests/run/trait_contracts`에 형태를 남김 |
| 2T: `Shape::twice(&Big { s: 5 })`에서 `Self`를 추론하지 못했다(E0237) | 고침: 구조체 생성 식의 참조도 `Self` 추론에 쓴다(`Checker::place_peek`), `tests/run/trait_defaults` |
| 2T: 정수 타입에 `&self` 수신자 trait을 impl할 수 없었다(`self: &i64`가 E0402) | ADR-0054(자율 채택)로 스칼라 참조 매개변수 허용(2T-08) |
