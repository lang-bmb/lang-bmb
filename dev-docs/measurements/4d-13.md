# 4D-13: 출력 버퍼의 길이 의무 (2026-11-11)

`port-shape` 실험의 두 팔이 모두 `out.push` 앞에 길이 가드를 두었다(`results.md` 마찰 표). 원인을 찾고 후보를 쟀다. 결론은 언어의 증명 규칙을 바꾸는 권장안이라 승인 안건이다(변경은 하지 않았다).

## 1. 문제

- `v.push(x)`에는 증명 의무 `len < LEN_MAX(T)`가 붙는다(E0816, ADR-0031 표). 트리를 걸으며 버퍼에 쓰는 함수는 이 의무를 계약으로 풀 수 없다: 출력 길이의 상한을 말하려면 트리 크기의 명세 함수와 그 합의 보조 정리가 필요하고, 아레나는 자식 공유를 허용해 상한이 없다.
- 그래서 실험의 두 팔은 `if out.len() < 4611686018427387904 { out.push(b) }`를 썼다. 바이트마다 비교 하나가 실행되고, 닿을 수 없는 길이에서 출력이 조용히 잘린다.
- 재현: `dev-docs/experiments/port-shape/tree.bmb`의 `put`에서 가드를 빼면 E0816 하나로 실패한다.
- 포트의 서식기(C3)와 코드 생성(C8)이 같은 꼴이다. 지금 코드에서도 길이 상한 상수를 적은 줄이 표준 라이브러리에 27줄(`push` 자리 80곳), 실행 코퍼스에 7줄 있다.

## 2. 원인과 귀속 층

언어(증명 규칙)다. 런타임은 이미 이 조건을 지킨다: `bmb_vec_grow`와 `bmb_vec_alloc`은 바이트 크기가 `isize`에 들지 않거나 할당이 실패하면 `abort`한다(`compiler/src/codegen.rs`의 `VEC_RUNTIME`, ADR-0031 §4). `push`가 돌아왔다면 `len + 1 <= cap <= LEN_MAX(T)`다. 의무는 런타임이 지키는 것을 프로그램에 다시 증명시킨다.

## 3. 정석 해와 출처

Rust의 `Vec::push`는 용량 초과를 호출자에게 묻지 않고 끝낸다(용량 초과는 panic, 할당 실패는 abort). 할당 실패가 `alloc` 효과의 종료이고 증명 의무가 아닌 것(ADR-0031)과 같은 등급으로 용량 초과를 둔다.

## 4. 후보 비교

| 후보 | 내용 | 측정·판정 |
| --- | --- | --- |
| **(다) `push`의 길이 의무를 없앤다** | `push` 뒤에 `len < LEN_MAX(T)`를 사실로 준다. 넘는 경우는 성장 경로의 `abort`(지금 있는 검사) | 임시 빌드로 잼: 가드를 뺀 `tree.bmb`가 전부 증명(의무 238 → 236). 표준 라이브러리 11단위는 218개 정의 모두 그대로 증명, 의무 1,750 → 1,697(−53), `rlimit` 20,192,306 → 19,750,746(−2.2%). 제약 C1(건전성): 길이 상한 사실(ADR-0017 §3)은 런타임 검사가 지킨다 |
| (가) 크기의 명세 함수와 보조 정리 | 트리마다 출력 길이의 상한을 증명 | 포트의 걷기 함수마다 크기 함수와 귀납 보조 정리가 든다. 아레나처럼 상한이 없는 구조에는 못 쓴다. 재지 않음(두 세션 모두 시도하지 않고 가드를 택함) |
| (나) 가드를 가진 표준 라이브러리 함수 | 가드를 한 곳에 | 바이트마다 비교가 남고 조용한 잘림이 남는다. 증상을 한 곳으로 모을 뿐이다 |
| (라) 지금대로 | 쓰는 쪽이 가드나 용량 논증을 쓴다 | 아레나 팔의 계약 30절 중 8절이 용량 논증이었다 |

## 5. 권장과 결정적 기준

**(다).** 갈린 기준은 원인의 층이다(JUDGMENT §3): 의무가 런타임이 이미 하는 검사와 겹친다. 정석과도 같다(S1).

`Vec::with_capacity(n)`의 의무는 그대로 둔다: `n`은 프로그램이 주는 값이고 넘는 값은 프로그램의 오류다(Rust도 거기서 끝난다). 같이 볼 것은 `String`의 `push`·`push_str`와 `extend_from_slice`가 같은 의무를 갖는지다. 갖는다면 같은 규칙으로 옮긴다.

## 6. 영향(정보)

- ADR-0031의 표(`v.push(x)` 행)와 E0816의 범위가 바뀐다. 새 ADR이 필요하다.
- 받아들이는 프로그램이 늘어난다(가드 없는 `push`가 증명된다). 동결 선언 전에 정해야 한다.
- 코퍼스의 E0816 실패 사례(`tests/verify/fail/`)와 게이트 검출력 변이체 가운데 `push` 의무를 겨눈 것을 고친다. 표준 라이브러리의 용량 논증은 지워도 되지만 지우지 않아도 증명은 그대로다.
- 전체 검사 모드(`--all-checks`)의 `push` 검사는 성장 경로의 검사로 대신된다.

## 7. 필요한 승인

증명 규칙의 변경이다(AUTONOMY §4). 승인되면 ADR을 쓰고 구현한다.

## 8. 우회

승인 전까지는 지금대로다(후보 (라)). 실험 파일의 가드는 그대로 둔다.

## 재현

지금 컴파일러에서 `tree.bmb`의 `put` 몸을 `out.push(b);` 한 줄로 바꾸고 `bmb verify`를 돌리면 E0816 하나로 실패한다(정의 19개 중 18개 증명). 임시 빌드는 `compiler/src/verify.rs`의 `push` 자리에서 `oblige("E0816", ..)`를 같은 식의 가정(`self.pc.push(..)`)으로 바꾼 것이다. 그 빌드는 커밋하지 않았다.
