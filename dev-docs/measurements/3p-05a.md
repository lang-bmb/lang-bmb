# 3P-05a: 포팅 쌍둥이의 첫 측정, 이해와 리팩터링 (H-COMPREHEND, H-REFACTOR)

> 백로그 3P-05a, 관문 B(ADR-0111). 조건은 ADR-0144, 판정 방법은 ADR-0112(두 팔의 차이의 구간, 과제별 토큰 비율), 주장의 기준 모델은 sonnet(ADR-0103 결정 3). 결과 행은 `bench/twin/results/3p-05a/`, 표는 `bench/twin/report.py`(`diff`, `worked`)가 그 행에서 만든다.

## 조건

- **장.** stage0의 C0~C4(Rust, 파일 16개)와 그 포트(`selfhost/`, BMB), 커밋 `c5d56302`의 것(과제의 `commit`). 과제 44개: 이해 24(`c*`: 호출자 7, 영향 5, 진단 7, 상태 5), 리팩터링 20(`r*`: 이름 바꾸기 10, 매개변수 자리 바꾸기 6, 인라인 2, 추출 2).
- **팔.** BMB 팔은 `bmb mcp --write-tool --compact`, Rust 팔은 파일 도구(`list_dir`·`read_file`·`grep`·`edit_file`·`cargo_build`·`cargo_test`). 도구 호출 한도 60회. 문서 조건 `none`(두 팔 모두 정의 문서 없음), 대조로 주석 있는 Rust(`all`, Rust 팔만).
- **모델.** sonnet(`anthropic:claude-sonnet-5-5`) 1회와 주석 있는 Rust 대조 1회, qwen(`openai:qwen3.8-27b`) 3회. 재시도 없음.
- **하네스·컴파일러.** 하네스와 과제는 `db0ff9b8`의 것(측정 동안 `pair.py`·과제·프롬프트는 바뀌지 않았다), 컴파일러는 같은 원문의 릴리스 빌드.
- **사람의 표본 확인(`3P-02`)은 없었다.** `bench/twin/port/REVIEW.md`는 아무도 확인하지 않은 채로 돌았다(2026-11-21 사람의 답은 모델 실행 승인이었고 표본 확인에 대한 답은 없었다: 백로그 행이 정한 대로 결과에 적는다).
- **끊김.** 컨테이너가 두 번 다시 시작됐고 백그라운드 한도(2시간)로 여러 번 끊겼다. 하네스는 끝난 세션의 행을 두고 나머지를 이어 돈다: 끊길 때 돌던 세션은 버려지고 처음부터 다시 돌았다. sonnet과 qwen은 나란히 돌았고, qwen 2회차와 3회차도 한동안 나란히 돌았다(동시 요청 2~3, 게이트웨이 한도 8).
- **버린 행 4개.** qwen 3회차의 마지막 두 과제(`r19`·`r20`, 두 팔)는 끊긴 줄 알았던 프로세스가 살아 있어 두 프로세스가 함께 돌았다(운영 실수). 과제와 팔마다 먼저 끝난 행을 남기고 나중 행 4개를 `qwen-3.dropped.jsonl`로 뺐다(규칙은 결과를 가리지 않는다: 파일의 순서). 버린 행을 넣어도 판정된 성공은 모두 같고, 아래 "사후" 셈에서 `r20` BMB 한 칸이 달라진다(남긴 행은 바꾼 것 없음, 버린 행은 바꿈).
- **용량 장애 없음(ADR-0088).** `api_error`로 끝난 세션은 qwen에만 있고 모두 BMB 팔이다: 1회차 10, 2회차 15, 3회차 16(이해 3·6·6, 리팩터링 7·9·10). 모두 HTTP 400(업스트림이 요청을 거부)이고 402·429는 없다. 그 세션들이 읽은 도구 응답은 5.3만~20.7만 토큰이고 호출의 대부분이 `query`다: 문맥이 넘친 것이다(모델 쪽 원인, ADR-0066대로 그때 상태로 판정). sonnet에는 없다.

## 판정기의 구멍: 아무것도 하지 않은 리팩터링이 성공이다 (사후)

리팩터링의 성공은 빌드, 말뭉치의 출력, 범위 밖 변경 없음이다(ADR-0104). 요청한 변경이 일어났는지는 묻지 않는다. 문맥이 넘쳐 한 줄도 고치지 못하고 끊긴 세션이 성공으로 적혔다. 약한 대조군은 범위 위반과 출력 변경뿐이라 게이트가 이 구멍을 잡지 못했다.

행에는 세션이 바꾼 정의가 있다(`changed`). 판정된 성공을 그것으로 나누면(`report.py worked`: 과제의 범위, 곧 기준 해법이 바꾸는 정의와 정확히 같은가):

- 성공으로 판정된 세션은 둘로만 갈린다: 기준 해법과 같은 정의를 바꿨거나, 아무것도 바꾸지 않았다.
- **사후 셈(ADR-0112 결정 5: 판정을 바꾸지 않고 병기한다).** qwen의 리팩터링에서 "일을 한 성공"은 BMB 14/20·11/20·13/20, Rust 20/20·20/20·20/20이다. 차이 −36.7%p, 95% 구간 −55.6~−17.7%p, 정확 순열 p = 0.100: Rust가 높음(잠정: 팔당 4회 미만). sonnet은 두 팔 모두 20/20이 일을 한 성공이다.
- 판정기를 고치는 일은 백로그 `3P-13`이다. `3P-05b`(커밋 재연)의 과제는 숨은 시험이 새 행동을 요구하므로 이 구멍이 없다.

## 판정

**H-COMPREHEND** (정답률이 Rust 이상, 읽은 토큰이 1/3 이하; 축 전체로 판정, ADR-0144 결정 3): **미충족, 갈래에 따라 갈린다.**

- sonnet: 정답 22/24 대 23/24(차이 −4.2%p, 구간 −22.0~+13.0: 변동 안). 읽은 토큰은 과제별 비율의 중앙값 0.83(구간 0.05~9.43), 합으로는 590,935 대 79,579(7.4배). 기준(1/3 이하)에 닿지 않는다.
- 갈래로 보면 둘로 갈린다. **호출자·영향**(맵의 간선으로 답하는 질문): 정답 12/12 대 11/12, 읽은 토큰 비율의 중앙값 0.05와 0.09: 기준을 채운다. **진단·상태**(정의의 글을 읽어야 하는 질문): 정답 10/12 대 12/12, 읽은 토큰 23배와 7배: 기준의 반대다. BMB 팔의 도구에는 글 찾기가 없어 정의를 통째로 읽는다(`bench/twin/README.md`의 알려진 치우침). Rust 팔은 `grep` 한 번이다.
- qwen: 정답 15·13·15/24 대 19·17·18/24(차이 −15.3%p, 구간 −29.6~+0.0, p = 0.100: 변동 안). 진단 갈래는 1·1·3/7 대 7·7·7/7(Rust가 높음, 잠정): 큰 응답이 문맥을 넘겨 세션이 끊긴다. 호출자·영향은 BMB가 같거나 높고 읽은 토큰이 0.05~0.06배다.
- 주석 있는 Rust 대조(sonnet): 정답 21/24, 읽은 토큰 89,934. 주석 없는 조건(23/24, 79,579)보다 낫지 않다: `none` 조건이 Rust 팔을 불리하게 했다는 흔적은 없다.

**H-REFACTOR** (성공률이 같거나 높고 총 토큰이 같거나 적다): **반증(sonnet: 토큰).**

- sonnet: 성공 20/20 대 20/20(두 팔 모두 일을 한 성공). API가 센 토큰은 과제별 비율의 중앙값 3.52(구간 1.90~5.14), 읽은 토큰은 12.08(4.72~19.47): 구간이 1을 넘는다. 갈래마다 같다(추출만 0.62, 과제 2개).
- qwen: 판정된 성공은 20/20 대 20/20이지만 위의 구멍 탓이다. 사후 셈으로 BMB 팔은 55~70%만 일을 했다. 토큰은 중앙값 4.47(2.94~6.52).
- 원인으로 보이는 것(재지 않았다): 이름 하나를 바꾸는 데 BMB 팔은 단위를 통째로 다시 쓰고(`write`는 단위 하나), 쓰기 전에 단위를 통째로 읽는다. Rust 팔은 `edit_file`로 그 줄만 바꾼다.

## 알려진 치우침과 한계

- sonnet은 1회다(ADR-0077 §4): 성공률의 차이는 모두 변동 안이고, 판정은 토큰 비율의 구간에서 나왔다. qwen은 팔당 3회라 방향이 나와도 잠정이다(ADR-0112 결정 2).
- 사람의 표본 확인이 없었다. 정답은 결정론 도구가 만들었고 오라클과 약한 대조군이 게이트를 통과했지만, 질문이 뜻하는 바와 정답이 맞는지는 아무도 보지 않았다.
- 압축 뷰(`--compact`)가 성공률을 낮추지 않는지는 따로 재지 않았다(T0-15).
- Rust 팔은 C0~C4의 파일만 본다(주석을 지우고 약 2.3만 줄). 포트는 약 3.0만 줄이다.
- 두 쪽 모두 같은 작성자가 옮긴 것이다(ADR-0104 결정 4).
- 자료 구조 교체와 단위 분할 갈래는 없다(`3P-11`).
