## 무엇을 쟀나

세션이 끝난 뒤의 자기 검사가 결함 있는 구현을 잡는가. 과제 24개의 Rust 변이체 96개(숨은 케이스가 전부 죽인다)를 하나씩 놓고:

- **Rust 팔:** 세션의 최종 크레이트에서 과제 함수를 변이체로 바꾸고 에이전트의 테스트를 돌린다(proptest 시드 고정). 실패하면 죽인 것이다.
- **BMB 팔:** 변이체가 기준과 다른 결과를 내는 숨은 케이스(증인, 변이체마다 앞의 넷)에서 그 출력을 에이전트의 계약이 배제함을 `bmb verify`가 계약만 보고 증명하면 죽인 것이다. 패닉·넘침·멈춤으로만 드러나는 변이체(12개)는 계약의 전제가 그 입력을 받아들이면 게이트가 죽인 것으로 센다.

BMB 쪽은 증인 넷에서만 보므로 계약이 다른 입력에서 배제하는 것은 세지 않는다(BMB에 불리한 쪽).

## 읽는 법

- **판정은 "판정 불가"다.** 기준 모델에서 BMB 0.958 대 Rust 0.885로 BMB가 높지만 차이의 구간이 0을 담는다. 등록한 규칙대로 H-ORACLE의 판정은 포팅 쌍둥이(3P-05)로 넘어간다. ADR-0111 결정 3의 한 번의 이월이 이것이다.
- **기준 모델의 Rust 팔 0.885는 변별 불가 문턱(0.9) 바로 아래다.** 보조 모델(qwen)의 Rust 팔은 96/96이다. qwen의 Rust 세션은 24개 모두 proptest를 썼고 sonnet은 11개만 썼다. 이 변이체 집합은 속성 시험을 쓰는 테스트에는 쉽다.
- **BMB 팔이 놓친 것은 계약이 약한 두 과제다**(sonnet: `t15-move-zeros`의 0·1, `t18-count-digits`의 1·2). 증명을 통과한 프로그램이어도 계약이 말하지 않은 성질은 게이트가 지키지 않는다. 이것은 G3(명세 품질, BSB)가 재는 것과 같은 축이다.
- **보조 모델의 BMB 팔은 6개 세션이 빠졌다**(끝에서 자기 검사를 통과하지 못함). 짝지은 과제는 18개다.
- **기준 해법의 계약은 완전한 명세가 아니다.** BRB의 BMB 기준 해법은 변이체 96개 중 29개만 죽인다(`bench/brb/oracle_strength_ref.json`). BRB는 구현의 결함을 숨은 판정으로 재도록 만든 집합이라 기준 해법에 완전한 계약을 요구하지 않았다. ADR-0119 결정 7의 가정이 틀렸고 게이트 규칙을 기록값 대조로 고쳤다(ADR 상태 줄). 모델이 쓴 계약(92/96, 71/72)이 기준 해법의 계약보다 훨씬 강하다.
- **범위:** 함수 단위 과제, 과제 저자가 고른 결함 집합이다. 모델이 실제로 내는 결함의 분포가 아니고, 수명 단위(H-TASK)의 판정도 아니다.
