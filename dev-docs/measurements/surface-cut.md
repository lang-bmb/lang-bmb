읽는 법:

- 쓰임이 가장 적은 것은 `assume`(1), `#[external_body]`(2), 클로저·함수 값 경계·상수 항목·`loop`·`exists`(각 5)다. 표준 라이브러리(`lib/std`)와 벤치 원본은 클로저·함수 값·trait·`?`를 한 번도 쓰지 않는다.
- 전용 파일이 있는 것은 클로저(`closures.rs` 1,193줄)와 상수 항목(`consts.rs` 1,244줄)뿐이다. 나머지 기능의 코드는 검사기·증명 인코딩·코드 생성에 퍼져 있어 기능별로 가르지 못했다(가르려면 기능을 끈 빌드가 필요하다).
- 기능별 증명 비용은 재지 않았다. 코퍼스의 프로그램은 여러 기능을 함께 써서 `rlimit`을 기능에 귀속할 수 없다.
- 셀프호스팅 격차 조사(`selfhost-gap.md` §"필요 없는 것")는 포트가 사용자 제네릭·trait·클로저·`f64`·`char` 없이 쓰일 수 있다고 적었다. 그러나 포트는 받아들이는 언어 전체를 구현해야 하므로, 포트가 안 쓰는 기능도 포팅 대상에서 빠지지 않는다.

## 3. 포팅 지도의 정정

`selfhost-port-map.md` §7.1(4D-07)은 `ast_json`을 "`dump parse`의 출력"이라며 C2(파서)에 넣었다. `dump parse`는 정규형 텍스트를 내고(`main.rs`, `fmt`), `ast_json`을 부르는 것은 `bmb ast`와 MCP의 구문 트리 도구뿐이다. `ast_json`은 C10(도구)이다.

| 범위 | 4D-07 | 정정 |
| --- | --- | --- |
| C2 파서·구문 트리 | 7,503 | 5,106 |
| P2(C1·C2, 관문 B0의 위치) | 8,280(14%) | 5,883(10%) |
| P3까지(C0~C4, 관문 B) | 28,309(47%) | 25,912(43%) |
| 조기 고정점 E1(C0~C4, C8) | 34,079(56%) | 31,682(52%) |
| 도구(C5, C10~C12) | 11,136 | 13,533 |

위 값은 커밋 `8c7c543`의 셈 규칙 그대로다. 그 셈은 하위 모듈 넷(1,912줄)을 빠뜨렸고, 지금 값은 포팅 원장(`port-ledger.md`, `scripts/components.py`)이 낸다: E1 범위 32,979줄(52%).

## 4. 권장안 (JUDGMENT §10)

1. **문제:** 재기준에서 E1까지의 포팅량이 4A-02 추정의 약 6배다(포팅 지도 §7.2). 동결 뒤에는 받아들이는 언어를 줄일 수 없다(ADR-0100).
2. **원인과 귀속 층:** 크기의 대부분은 검사기(C4 16,239줄)와 증명 인코딩(C6 11,781줄)이다. 언어 기능 하나에 귀속되는 전용 코드는 클로저 1,193줄과 상수 항목 1,244줄이고, 합쳐 E1 범위의 8%다. 층은 컴파일러 구조(동결과 무관하게 고칠 수 있다)와 도구 표면(가설이 정한다)이다.
3. **정석 해와 출처:** 언어에서 기능을 빼는 기준은 원칙("검증되지 않는 기능은 언어에 넣지 않는다", CLAUDE.md 운영 규칙)이고, 포팅 비용은 기준이 아니다(JUDGMENT §5). 후보 표면은 측정으로 하나를 고른 뒤 나머지를 지운다(ADR-0111 결정 4의 조정 가설).
4. **후보 비교:**

   | 안 | 판정 |
   | --- | --- |
   | (가) 언어 표면은 그대로 동결, 도구 표면은 가설 판정으로 정리, 내부 정리는 구성 요소 고정 전(권장) | 채택된 기능은 모두 코퍼스와 퍼저로 검증돼 있다(클로저: `soundness_closures`, 상수: `soundness_consts`). 줄일 근거가 원칙에 없다 |
   | (나) 클로저·함수 값을 뺀다(ADR-0053·0114 철회) | 전용 1,193줄과 검사기·증명기에 퍼진 코드가 준다. 그러나 사람 승인으로 채택된 기능이고 검증돼 있으며, 뺄 이유가 비용뿐이다. JUDGMENT §5에 어긋난다 |
   | (다) 쓰임이 적은 것(`assume`·`#[external_body]`·`loop`·`exists`)을 뺀다 | `assume`·`#[external_body]`는 탈출구이고 감사 대상이라(ADR-0029) 빼면 시스템 내장과 증명 탐색의 길이 없다. `loop`·`exists`는 전용 코드가 작다 |
   | (라) JSON 구문 트리 편집 표면을 지금 지운다 | sonnet 자료는 불리하지만 qwen 실행이 남았다. 판정 전에 지우면 등록된 측정(T1-41)을 버린다 |

5. **권장과 결정적 기준:** (가). 갈린 기준은 "작업량은 기준이 아니다"(JUDGMENT §5)와 "등록한 측정을 판정 전에 버리지 않는다"(ADR-0111)이다. 구체적으로:
   - 언어 표면: 줄이지 않는다. 지금의 표면(`surface.json`)으로 동결한다.
   - 도구 표면: H-EDIT·H-PROBE가 판정되면 고르지 않은 표면의 도구를 지운다. 시한은 도구 포팅(P5 이후, 관문 B 뒤) 착수 전이다. 그때까지 판정이 없으면 그 도구는 포팅 범위에서 빼고 stage0과 함께 은퇴시킨다.
   - 포팅 지도: `ast_json`을 C10으로 옮긴다(§3). 관문 B0의 위치는 그대로이고 크기만 5,883줄로 고친다.
   - 내부 정리(`check.rs` `expr_inner` 896줄, `system_builtins` 표 253줄, `verify.rs` `verify_pass` 981줄): 동결 뒤, 해당 구성 요소의 고정(ADR-0113) 전에 한다(2026-11-11 승인 D1).
6. **영향(정보):** E1 범위 34,079 → 31,682줄(−7%). 도구 표면 세 개가 모두 빠지면 전체 포트가 2,988줄(5%) 더 준다. 동결 지문은 바뀌지 않는다.
7. **필요한 승인:** 도구 표면의 정리 규칙(위 둘째 항)은 ADR-0113·0116의 보완이라 승인 안건이다. 언어 표면을 줄이지 않는다는 결론과 포팅 지도 정정은 조사 결과다.
8. **우회:** 없음.
