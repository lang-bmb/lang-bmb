# 문법 대안 오프라인 비교 (2R-04)

> 백로그 2R-04(하위 2R-04a~h). 1차 평가(`syntax-eval-1.md` §5)의 상위 후보마다 대안 문법을 정하고, 모델 없이 결정론적으로 잴 수 있는 것을 잰다. 실제 모델 근거는 2R-03·2R-05가 더하고, 문법 결정은 2R-06(승인)이 한다. 저울은 ADR-0036.

## 2R-04d: 2B 표면(I3·I7)

**대안.** ADR-0026 정본(`canon`)에 세 가지를 차례로 얹었다(`bench/syntax/surface2b.py`).

| 변형 | 바꾸는 것 |
| --- | --- |
| `prelude` | `Option::Some(x)`·`Option::None`·`Result::Ok(x)`·`Result::Err(e)` → `Some(x)`·`None`·`Ok(x)`·`Err(e)`. 사용자 열거형은 `E::V` 그대로 |
| `self` | `impl` 함수의 첫 매개변수 `p: &T` → `self: &T`(`&mut`도) |
| `method` | `prelude` + `self` 위에서 `T::f(&x, ..)` → `x.f(..)`. 정본은 경로 호출로 되돌린다 |

**코퍼스.** ADR-0026 예시와 2B 과제 후보로 쓴 초안 6개(기하, 도형 넓이, `Option`을 돌려주는 검색, `Result`를 돌려주는 검증, 크기 고정 스택, 상태 기계). 2B 구현 전이라 검사·증명은 하지 않고 어휘 토큰만 센다(`bench/syntax/measure.py`의 `lex`).

**측정(2026-10-25).**

| 프로그램 | canon | prelude | self | method |
| --- | ---: | ---: | ---: | ---: |
| geometry | 324 | 324 | 324 | 322 |
| shapes | 342 | 342 | 342 | 340 |
| search | 366 | 340 | 366 | 340 |
| validate | 298 | 270 | 298 | 270 |
| stack | 395 | 385 | 395 | 378 |
| machine | 480 | 450 | 480 | 447 |
| 합 | 2,205 | 2,111(−4.3%) | 2,205(±0) | 2,097(−4.9%) |

- **prelude 이름 예약.** 저장소의 BMB 코드와 벤치 과제 해법(기준·약한 대조군)에서 `Some`·`None`·`Ok`·`Err`라는 이름의 정의는 없다. 예약해도 바뀌는 기존 이름이 없다. 이 이름들은 `print_i64`처럼 내장이라 해석 모호성이 없다(K2·K3 유지).
- **`self: &T`.** 토큰은 같다(이름만 바뀜). 유효한 Rust이고 Rust 습관 `&self`에 가장 가까운 명시 형태다. 타입이 적혀 있어 슬라이스 자급(모든 매개변수 타입 명시)도 그대로다.
- **메서드 호출.** prelude 위에 0.6%를 더 줄인다. 코퍼스의 수신자 7개는 모두 매개변수나 지역 변수다. BMB는 모든 지역·매개변수 타입을 적게 하므로 그 정의의 원문만으로 대상 타입이 정해진다. 필드 투영(`a.b.f()`)이면 구조체 선언이, 호출 결과(`g().f()`)면 피호출자 시그니처가 정한다. 셋 다 추론 없이 검사기가 정한다. 다만 슬라이스 안에서 구문만으로 정해지는 것은 첫째뿐이다. 그래서 정본은 경로 호출로 둔다(K3).

**권고(2B-11의 입력).**

| 구성 | 권고 | 근거 |
| --- | --- | --- |
| I3 `Option`·`Result` 변형 | **차용**: 정본은 `Some`·`None`·`Ok`·`Err`. `Option::Some` 등은 입력 별칭으로 받아 정본으로 옮긴다 | −4.3% 토큰(`Option`·`Result`를 쓰는 프로그램 4개에서 −2.5~−9.4%), 예약 충돌 없음, Rust prelude 습관(C1) |
| I7 수신자 | **변형 유지, 형태 교체**: 정본은 `fn f(self: &T)`. `&self`·`&mut self`는 입력 별칭 | 토큰 같음, 유효 Rust, 명시 타입 유지 |
| I7 호출 | **변형 유지 + 입력 별칭**: 정본은 `T::f(&x)`. `x.f()`는 검사기가 대상을 정해 정본으로 옮긴다 | 구문만으로 간선이 정해지는 성질(K3)은 정본에 있다. 별칭의 대상 결정은 언제나 가능하다(모든 타입 명시) |

**반영(2B-11).** ADR-0026 채택은 앞의 둘(내장 변형 맨이름, `self: &T`)을 반영했다. 셋째(메서드 호출 입력 별칭)는 습관 형태를 오류 없이 받는 쓰기 표면 정책의 변경이라 2R-04e·2R-06(승인)으로 넘겼고, 그때까지는 거부와 기계적 수정이다.

**한계.** 코퍼스는 우리가 쓴 초안 6개다. 2B 과제(2B-10)가 생기면 같은 스크립트로 다시 잰다. 수신자가 필드·호출 결과인 경우가 코퍼스에 없다.

## 2R-04c: 정수 변환 `as` + 의무 (J1)

**대안.** 제안 ADR-0028의 `T::try_from(x).unwrap()`(범위 의무 E0815)과 syntax-eval-1 J1의 `x as T`(정수 사이만, 같은 의무). 두 형태의 의미(값 보존 + 대상 범위 의무, ADR-0028 §1·§5)는 같고 표면만 다르다.

**코퍼스.** `bench/syntax/conv2c.py`의 변환 지점이 있는 초안 5개: `tests/run/search.bmb`의 `show_size` 세기 루프 제거판(`print_size`), `usize` 인덱스와 `i64` 누적의 혼합(`weighted_sum`), 길이로 나눈 평균(`average`), 부호 있는 값을 인덱스로(`index_from_i64`), `u64` 카운터의 차이·자르기(`counter`). ADR-0028 형태로 한 번 쓰고 기계적으로 `as`로 옮긴다. 2C 구현 전이라 검사·증명은 하지 않고 어휘 토큰만 센다.

**측정(2026-10-25).**

| 프로그램 | 변환 | try_from | as |
| --- | ---: | ---: | ---: |
| print_size | 2 | 124 | 110 |
| weighted_sum | 2 | 187 | 173 |
| average | 2 | 139 | 125 |
| index_from_i64 | 2 | 155 | 143 |
| counter | 3 | 125 | 104 |
| 합 | 11 | 730 | 655(−10.3%) |

- **지점당 6.8토큰.** `T :: try_from ( x ) . unwrap ( )`는 피연산자 밖 9토큰, `x as T`는 2토큰이다. 피연산자가 이름·리터럴·필드·인덱스·인자 없는 메서드 호출이 아니면 `(..)`가 붙는다(`as`는 이항 연산자보다 강하게 묶인다: `(k + 1) as usize % 1000`). 이 코퍼스는 변환 밀도가 높아 −10.3%는 상한 쪽 값이다.
- **의무.** 11곳 중 9곳이 의무를 갖는다(`usize`/`u64`→`i64`, `i64`→`usize`/`u64`). 의무가 없는 2곳은 `usize`→`u64`. 의무는 두 형태가 같다.
- **기계적 상호 변환.** `try_from -> as -> try_from` 왕복이 다섯 프로그램 모두 원문과 같다(스크립트가 확인한다). 어느 쪽을 정본으로 정해도 다른 쪽은 정규형·`bmb fix`의 기계적 교체로 받을 수 있다. 정본을 나중에 바꾸는 비용은 코드 손실 없는 교체다.
- **K4(거짓 친구).** 의무가 붙는 `as`는 BMB가 받는 모든 프로그램에서 값이 보존되므로 Rust의 `as`와 같은 값을 낸다. 범위 밖이면 증명이 실패할 뿐 조용히 자르지 않는다(syntax-eval-1 J1).

**권고(2C-05·2R-06의 입력).**

| 구성 | 권고 | 근거 |
| --- | --- | --- |
| J1 변환 표면 | **차용 후보: 정본 `x as T`(정수 사이만, 범위 의무)**. `T::try_from(x).unwrap()`은 입력 별칭(기계적 교체) | 지점당 −6.8토큰, Rust 습관(E0205 예측 빈도 높음, C1), 값 보존(K4). ADR-0028의 반론(의도가 안 보임, 앞으로 부동소수 `as`)은 "정수 사이만"(K2)으로 다룬다 |

**반영.** 표면은 ADR-0028 열린 질문 1이고 문법 결정은 2R-06(승인)이다. 2C-05는 의미(범위 의무, `print_u64`, 포화·검사 산술)를 채택하고, 표면은 ADR-0028 제안 형태로 구현하되 두 형태의 기계적 왕복이 성립함을 근거로 2R-06에서 바꿀 수 있게 둔다.

**한계.** 코퍼스는 우리가 쓴 초안 5개이고 변환 밀도가 높다. 실제 모델의 E0205 빈도(1E-10)가 나오면 다시 본다.

## 2R-04f: 경계 루프 `for` (순위 6)

**대상.** ADR-0049 §2의 범위 `for`(2K-01d에서 구현)와 같은 일을 하는 `while` 셀 루프. 변환기는 W0907 정규형 수정(ADR-0057, `bmb fix`)이고, 하네스는 `bench/syntax/for_tokens.py`(바꾼 루프 수, `measure.py` 렉서의 토큰, 두 판의 `bmb verify` 판정 비교).

**질의.** 범위 `for`의 증명 스크립트는 펼친 `while`(`let mut i = lo; while i < hi invariant lo <= i && (i <= hi || i == lo), P decreases hi - i { body; i = i + 1; }`, `..=`는 증가 앞의 `if i == hi { break; }`, `continue`는 그 앞의 증가)과 바이트 단위로 같다. 컴파일러 시험 `for_queries_are_the_while_expansion`이 `..`, `..=`, `continue`·`break`가 있는 몸 세 경우를 고정한다. 그래서 `for`는 증명 비용을 바꾸지 않는다.

**토큰.** 2K-04 이주 전 판(`eb356b21^`)의 프로그램 22개(실행 14, 증명 코퍼스 7, `lib/bytes.bmb`):

| 묶음 | 바뀐 루프 | 토큰 전 | 토큰 뒤 |
| --- | ---: | ---: | ---: |
| 이주한 22개 | 34 / `while` 54 | 20,300 | 19,638(−3.3%) |
| 그대로 둔 것(벤치 기준선 7, `while` 코퍼스 5) | 22 | 8,430 | 7,988(−5.2%) |

- **루프당 약 20토큰**(19.5, 20.1): `let mut i: T = lo;`, `decreases hi - i,`, `i = i + 1;`이 빠지고 `for i in lo..hi`가 `while i < hi`를 대신한다. 모든 정의의 판정이 두 판에서 같다(34+22곳).
- **바뀌지 않는 `while`**(이주한 파일의 54곳 중 20곳): 루프 뒤에서 변수를 쓰는 탐색(`index_of`), 몸 중간의 증가, 증가를 건너뛰는 `continue`, 끝이 몸에서 바뀌는 루프. 이것들은 `while`로 남는 것이 맞다(ADR-0049 §2: 그 밖의 루프는 `while`).

**권고.** 채택됨(ADR-0049 §2, 2K-01d). 정규형 수정은 동결한 벤치 자산 때문에 경고(W0907)로 두었다(ADR-0057). 2R-06에는 "결정됨"으로 넘긴다.

## 2R-04a: `#[uses]` 기본 문맥 = r2c (순위 1)

**대상.** 1차 평가 §2.2(`syntax-eval-1.md`)의 규칙 r2c: 정의 자신의 계약·불변식·`assert`가 이름으로 부르는 `spec fn`과 피호출자의 `requires`·`ensures`가 부르는 `spec fn`, 그리고 그 본문들이 부르는 것의 닫힘. 1차 평가는 작은 코퍼스 셋을 한 시드로 쟀다. 여기서는 §5 순위 1이 남긴 물음(큰 작업 공간, 시드 0~4, 한도 초과, 증분 키)을 잰다. 하네스 `bench/syntax/uses_default.py`: 각 코퍼스의 모든 `#[uses(..)]`를 규칙의 집합으로 바꾸고 `bmb stability --seeds 5`(모든 시드에서 증명된 정의, 시드에 따라 판정이 바뀌는 정의, 정의별 `rlimit` 최대), `bmb verify --emit-smt`(질의 바이트), 시드 0의 의무별 최대가 ADR-0092 §3 예산(1,000,000)을 넘는 정의 수, 증분 키가 바뀌는 정의 수(정의의 키는 `#[uses]`가 부르는 정의를 담으므로 집합이 쓴 것과 다른 정의)를 센다. 규칙 집합은 2R-02의 근사 파서(`measure.py`)가 계산하고, 이번에 `for` 불변식·`proof fn`·trait 메서드 선언을 읽게 넓혔다. 원자료 `dev-docs/measurements/syntax-uses/2026-11-08.jsonl`.

- **M1 표면에서 r2c는 쓴 목록을 대신한다.** 생성 작업 공간과 m1b 시드의 모든 정의가 다섯 시드 모두에서 증명되고, 비용은 +0.8~2.3%, 질의는 +1.5~2.0%, 예산을 넘는 의무가 없다. 큰 술어 닫힘이 비용을 터뜨리는 일은 이 코퍼스들에서 없었다. r1c(자기 절만)는 모자라다(43/53, 93/223): 피호출자의 계약이 부르는 술어가 필요하다.

**권고.** 변형 후보 유지, 최상위. 결정(2R-06)의 전제: r2c는 근사 파서가 아니라 검사기의 이름 해석 위에서 계산해야 한다(제네릭·trait·불변식·메서드를 포함하는 언급). 그 계산을 컴파일러에 넣는 것이 구현 페이즈의 첫 일이고, 그때 `tests/verify/pass`와 `lib/std` 전체로 이 표를 다시 낸다.

## 2R-04b: 계약 절 인라인 식 (순위 2)

**대상.** 1차 평가 G2: 계약 절은 이름 붙은 술어의 호출만(E0501). 대안 T1(Verus처럼 인라인 식), T2(양화사 없는 식만 인라인, 양화사 술어는 이름 필수), T3(현행 + `bmb fix`가 술어를 추출). 하네스 `bench/syntax/inline_contracts.py`: 한 계약 절만 부르고 다른 어디서도(다른 `spec fn` 몸·불변식·`assert`) 부르지 않는 `spec fn`을 그 절에 인라인한다(매개변수를 괄호 친 인자로 바꿈). 원자료 `dev-docs/measurements/syntax-uses/inline-2026-11-08.jsonl`.

| 코퍼스 | `spec fn` | 인라인 대상 | 그중 양화사 | 그중 잎 | 토큰 | 인라인 뒤 | L1 바이트 | 인라인 뒤 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| m1b 시드 | 63 | 32 | 7 | 28 | 7,604 | 7,118(−6.4%) | 85,974 | 65,038(−24.4%) |
| m1 시드 | 12 | 7 | 2 | 7 | 1,313 | 1,222(−6.9%) | 16,639 | 12,133(−27.1%) |

- **토큰.** 인라인 대상의 머리(`spec fn name(params) -> bool { }`)와 호출이 빠지고 괄호가 더해져 6~7% 준다. 1차 평가의 하한(머리 토큰 8.7%·11.3%, 쓰기 코퍼스)과 같은 방향이다.
- **맵.** L1은 술어 행이 빠져 24~27% 준다. 대신 그 절의 `requires`·`ensures` 텍스트와 `query contracts`의 답이 이름에서 식으로 바뀐다. 이름은 에이전트가 계약을 다시 찾는 열쇠(같은 술어를 쓰는 정의 찾기, 병합의 정의 단위)인데 단일 사용 술어는 그 열쇠가 쓰이지 않는다.
- **증명 비용.** 인라인 판은 지금 검사를 통과하지 않아(E0501) 증명기로 잴 수 없다. 대상 39개 중 35개가 잎(다른 `spec fn`을 부르지 않음)이고 잎 `spec fn`은 질의에서 매크로라(ADR-0067) 펼친 질의가 같다. 잎이 아닌 넷은 부르는 술어가 그대로 남으므로 펼친 뒤 같다. 비용은 같다고 본다(구현 뒤 확인). BSB 판별률도 같은 까닭으로 구현 뒤에 잰다.
- **양화사.** 대상의 9/39가 양화사를 담는다. 양화사 술어는 `#[trigger]`와 재사용(불변식·보조 정리 인자)의 단위라 이름이 남는 편이 낫다(T2의 근거).

**권고.** 변형 후보 유지, T2(양화사 없는 식은 계약 절에 바로, 양화사 술어는 이름 필수). 불변식·`assert`가 이미 인라인을 받으므로 형태 규칙의 비대칭(G2·G5)도 줄어든다. 결정은 2R-06(사람 승인).

## 2R-04e: 쓰기 표면 자동 수정 (순위 5)

**대상.** 검사기가 Rust 습관에 대체 문안(`replacement`)이 있는 진단으로 답하고 `bmb fix --write`가 더 적용할 것이 없을 때까지 고친다(DESIGN §8.2). 물음 둘: 고친 프로그램의 뜻이 그대로인가, 습관을 넣은 변형이 얼마나 돌아오는가. 하네스 `bench/syntax/fix_recovery.py`: `tests/run`의 정본 프로그램(모두 증명됨)에 습관 하나를 첫 자리에 넣고 `bmb fix --write`를 돌린다. 기준은 원본에 `fix`를 돌린 결과다(`fix`는 셀 `while`을 `for`로도 바꾼다, W0907). "원문"은 그 기준과 같은 텍스트, "정규형"은 `bmb fmt` 뒤 같음, "같은 뜻"은 텍스트는 달라도 정의별 증명 판정과 LLVM IR이 같음, "바뀜"은 검사는 되지만 판정이나 IR이 다름, "막힘"은 오류가 남음. 원자료 `dev-docs/measurements/syntax-uses/fix-recovery-2026-11-08.jsonl`.

| 습관 | 진단 | 자리 | 원문 | 정규형 | 같은 뜻 | 바뀜 | 막힘 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `let x = e;`(타입 생략) | E0201 | 64 | 33 | 0 | 11 | 0 | 20 |
| `-> ()` 생략 | E0209 | 68 | 68 | 0 | 0 | 0 | 0 |
| 리터럴 접미사 `5i64` | E0104 | 21 | 21 | 0 | 0 | 0 | 0 |
| `e as T` | E0205 | 15 | 0 | 1 | 14 | 0 | 0 |
| `mut` 매개변수 | E0210 | 60 | 60 | 0 | 0 | 0 | 0 |
| `pub fn` | E0207 | 68 | 68 | 0 | 0 | 0 | 0 |
| `#[effects(pure)]` 생략 | E0601 | 55 | 30 | 8 | 17 | 0 | 0 |
| 타입 인자 생략 `f(x)` | E0237 | 14 | 14 | 0 | 0 | 0 | 0 |

- **뜻은 항상 그대로다.** 365곳 중 "바뀜"은 0이다: 고친 것이 증명 판정이나 생성 코드를 바꾼 적이 없다.
- **고친 결함.** 첫 측정에서 `mut`·`pub`·수명 `'a`를 지운 자리에 공백이 남았고(`( x`, `     fn`, `& [i64]`, `<>`), `#[effects(pure)]`가 `fn`과 같은 줄에 들어갔다(정규형 아님, 0/60·0/68·0/55 원문). 원인은 대체 문안을 그대로 붙이는 적용기였다. 이제 적용기(`lib.rs` `layout`)가 지우는 자리 뒤의 공백, 혼자 남는 `<>`와 앞쪽 `,`를 함께 지우고, 들여쓰기 없는 줄이 든 삽입에 그 줄의 들여쓰기를 준다. E0601의 문안은 속성을 제 줄에 둔다. 시험 `tests/fix_cmd.rs`의 `fixed_habits_are_in_normal_form`.
- **남은 차이.** `as` 25곳 중 14곳의 "같은 뜻"은 하네스가 넣은 괄호(`(x as u64)` → `(u64::try_from(x).unwrap())`)이고, 효과 속성의 17곳은 속성 순서(`#[uses]` 뒤에 들어감)다. 둘 다 뜻은 같다.
- **막힘 20곳: E0201의 추론.** 타입을 생략한 `let`의 수정은 초기값만 보고 타입을 고른다. 정수 리터럴이면 `i64`(Rust의 기본)를 적는데 그 지역이 뒤에서 `usize`·`u64`로 쓰이면 다른 자리에 E0401이 남는다(13곳). `Vec::new()`는 원소 타입을 몰라 수정이 없다(7곳). Rust는 쓰임에서 추론한다. 후속 `2N-12`.

**권고.** 차용(현행 유지). 습관 형태는 입력으로 받아 정본으로 고치는 규칙이 뜻을 바꾸지 않음이 쟀고, 회복은 E0201을 빼면 모두 된다. 2R-06에는 "결정됨(유지), E0201 추론은 도구 개선"으로 넘긴다.
