## 판정

- **H-ENCAP: 두 모델 모두 판정 불가.**
  - README에 등록한 반증 조건은 "BMB 게이트 통과 & 숨은 위반 > 0"이다. 두 모델 모두 이 조건에 해당하지 않는다(0/4). 불변식을 바꿔 통과한 세션도 0이다.
  - 비교 줄은 Rust 쪽 "통과 & 위반"이 0이라 판정 불가다. 두 모델 모두 Rust의 private 필드와 테스트로도 불변식을 깨지 않았다.
  - 이 과제들로는 H-ENCAP의 이득 쪽(Rust는 0보다 크다)을 보이지 못했다.
- **qwen BMB의 미제출 둘(e03, e04)은 모델 출력 한도다.**
  - 두 세션 모두 질의만 11·14번 하고, 첫 쓰기 전에 출력 한도에 닿아 끊겼다(`stop: length`, 출력 6.6만·9.7만 토큰).
  - T0-10의 qwen 실패와 같은 꼴이다. 증명 게이트나 판정이 결함을 찾은 경우가 아니다.
- **비용:**
  - sonnet에서 BMB 팔의 총 토큰은 Rust의 4.0배다(BRB의 15~18배보다 작다).
  - 테스트 코드는 BMB 0줄 대 Rust 158줄이다.
  - qwen에서는 BMB가 Rust의 0.54배다. 다만 BMB가 두 과제를 제출하지 못했다.

## 해석

- 타입 불변식의 증명 경계(ADR-0060)는 이 측정에서 한 번도 우회되지 않았다. 반증 근거가 없다.
- 그러나 비교군도 위반을 만들지 않아, 이 집합은 두 모델에게 변별력이 없다. BRB의 H-ORACLE과 같은 상황이다(과제가 쉬움).
- 변별 과제는 T0-08(`brb-hard`)이 H-ORACLE 쪽에서 시도한다. 자료 구조 판의 더 어려운 과제는 이 결과를 보고 사후에 만들지 않고, 필요하면 새 집합으로 등록한다.
