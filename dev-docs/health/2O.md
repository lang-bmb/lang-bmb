## 실용성 (HEALTH.md §5)

- 실행 프로그램은 위 기준 3. `calc`는 파서가 `Option<Box<Expr>>`를 돌려주고 평가가 `checked_*`로 넘침을 값으로 바꾼다. `vm`은 결과 `Vec`을 문맥 구조체에서 부분 이동으로 꺼내 돌려준다.
- 마찰: `dev-docs/measurements/m1.md` §6에 2O 행 6개, 처리 칸 모두 채움. 셋은 고쳤다(지역 필드의 `match`는 부분 이동, Z3 선언 순서, 구조체만의 재귀). 하나는 사람 결정 대기(아래).
- 발견해 고친 것: 명세 `==`가 `Vec`을 담는 재귀 열거형에서 인코더를 끝나지 않게 했다(2O-03c부터, E0431로 막음), `Box` 필드 읽기 패턴, `%bmb.vec` 선언 순서, 필드 안 `Vec`의 사용 판정, 원소 대입의 옛 원소 해제, `&mut **a`의 상자 풀기, 2O-03c·2O-03d의 Z3 4.15.4 무응답(측정 `dev-docs/measurements/z3-nested-datatypes`).
- 남은 결정(사람 승인):
  - **E0414의 한 갈래 이동.** `calc::parse`에서 오른쪽 파싱이 실패한 갈래는 왼쪽 결과 `a`를 쓰지 않아 E0414였고, `let unused: Box<Expr> = a;`로 옮겨야 했다. ADR-0031 §2는 실행 시 해제 플래그를 두지 않으려고 "아마 이동"을 금지했다. 같은 성질(플래그 없음)을 지키면서 Rust 습관에 맞추는 정석은 덜 옮긴 갈래의 끝에 해제를 넣는 정적 정교화다(사용자 `Drop`이 없어 해제 시점은 관찰되지 않는다). 채택된 ADR의 결정을 바꾸므로 승인을 기다린다(백로그 2O-07, ADR-0031 열린 질문 3).
  - **역참조 강제 변환.** `&Box<Expr>` 바인딩을 `&Expr` 매개변수에 넘기려면 `&**a`가 필요하다. 언어 범위 결정이라 빈도를 더 모은다.
- 열린 질문: ADR-0047 열린 질문 1(모든 데이터 타입을 데이터타입으로 통일)은 열어 둔다. 2O-03d의 측정은 배열에 중첩된 재귀 데이터타입이 Z3 4.15.4에서 불안정하다는 것만 보였다(ADR-0056 §5).
