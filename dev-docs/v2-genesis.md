# BMB v2 착수 기록: 결정, v0 분석, 타당성

> 작성: 2026-10-23~24 · 성격: 과정·결정 문서(`dev-docs/`)
> 현재 확정된 설계는 `docs/DESIGN.md`에 있다. 이 문서는 그 설계가 *왜* 그렇게 되었는지를 남긴다.

## 1. 출발점

v0(v0.100, 2026-01-01~06-07, 커밋 1,872개)를 브랜치로 보존하고 바닥부터 다시 시작한다. 처음에 제시한 착수 취지는 17개 서술이었고, 정제를 거쳐 `docs/DESIGN.md`의 전제 3개, 원칙 9개, 설계 방법으로 정리했다.

처음 서술의 핵심:
- 인간은 코드를 한 줄씩 읽고 쓰지 않는다.
- AI 에이전트를 위한 언어다. 인간에게는 어렵고 에이전트에게는 쉽다.
- 테스트 코드를 거의 쓰지 않는다.
- 성능과 안정성이 최우선이다.
- 인간과 AI는 설계서로 소통한다.
- 빌드는 풍부한 메타정보를 결정론적으로 구성한다.
- 에이전트는 파일을 뒤지지 않고 도구로 읽고 쓴다.
- 대형 프로젝트에서도 실수하지 않는다.
- 코딩을 어렵게 만들어 이득을 극대화한다.
- 건축 비유: 설계사는 도면을 그리고, 벽돌은 노동자가 쌓는다.

### 3.3 흡수 / 폐기 / 신설

v0의 코드는 가져오지 않는다. 가져오는 것은 설계와 측정 자산이다.

**흡수**
- **부트스트랩 `verify-vc` 설계:** 독자 검증기의 직접적인 출발점이다.
  - 모듈 단위 assume-guarantee: 검증된 callee의 post만 가정한다.
  - 64비트 bitvector 인코딩.
  - 자기 재귀의 귀납 가설.
  - unknown·unsupported를 실패로 정직하게 보고하는 판정.
- `tests/verify-vc` 판정 회귀 코퍼스.
- JSONL 진단의 고정 스키마.
- 색인 스키마 아이디어: 함수 + 계약 + 호출 관계.
- 증명 기반 최적화 메커니즘(`llvm.assume`, 검사 제거). 단 "검증된 사실만" 규칙을 붙인다.
- LLVM 텍스트 IR 생성과 최적화 패스 설계(꼬리 호출, 선형 점화식 감지).
- 2026-06-01 정정 이후의 공정한 벤치 하네스.
- 관찰: AI는 장황한 계약을 마다하지 않는다.

**폐기**
- 두 컴파일러(Rust + 셀프호스팅)와 두 LLVM 백엔드(text + inkwell).
- 겹치는 IR·사실 경로 3갈래와 검증기 3벌.
- 검증되지 않은 계약에서 나오는 assume.
- 자동 생성된 공허 계약.
- 파일 경로 = 모듈, 텍스트 `@include` 결합.
- 인간 편의 문법 확장과 독자 문법 자체.
- 핵심 가설 검증 전의 생태계 확장(바인딩 25개, 패키지 매니저, 플레이그라운드 등).
- 문제 지문을 고쳐 올린 AI 벤치 점수.

**신설**
- 독자 BMB 컴파일러(Rust 방언, LLVM 직접).
- 정의 단위 content hash, 결정론적 맵 L0~L2, 확장 맵.
- 도구 계층(읽기·쓰기 트랜잭션, 결정론적 보조).
- 기본 증명 게이트.
- 해시 키 증명 캐시와 계약 방화벽 증분 빌드.
- 효과 시스템.
- 슬라이스 예산.
- 공허 계약 거부와 이름 붙은 술어.
- 해시에 묶인 근거.
- 안정 오류 코드와 다중 오류 보고.
- 측정 체계.

### 3.4 v0 성능 주장에 대한 주석

- v0.60 시점 측정에서 BMB는 Tier 1 벤치 10개 중 8개에서 Rust보다 빨랐다(gcd 0.48×, sieve 0.42×, collatz 0.14× 등).
- v0의 `FAIRNESS_ANALYSIS.md`는 이 차이를 **Rust의 런타임 범위 검사** 때문으로 설명한다.
- 그런데 2026-06-02 감사에서 v0는 애초에 검사를 하지 않았다(unchecked 기본값)는 것이 확인되었다. 즉 그 속도는 증명이 아니라 검사 생략에서 나왔다.
- v2에서 이 우위는 **증명으로 검사를 지울 때만** 정당하다. 그리고 이것이 바로 독자 컴파일러의 존재 이유다.
- 기준선은 다시 측정한다. Rust 쪽에는 `get_unchecked`를 쓴 변형도 둔다.

### 3.5 교훈과 v2 운영 규칙

v0의 실패는 기술보다 순서와 측정의 문제였다.

| v0에서 일어난 일 | v2 운영 규칙 |
| --- | --- |
| "C보다 빠르다"를 5개월 동안 전제로 두었다가 측정 후 폐기 | 차별점 가설은 그 위에 쌓기 전에 최소 실험으로 측정한다 |
| 실제 코드 검증 0/12인 채로 계약 문법이 v0.1부터 존재 | 증명 게이트는 첫 커밋부터 켠다. 검증되지 않는 기능은 언어에 넣지 않는다 |
| 문서는 "범위 검사 제거"를 주장했으나 애초에 방출된 검사가 없었음 | 주장은 코드 경로와 측정으로 뒷받침될 때만 문서에 쓴다 |
| GCC 비율을 Clang 비율로 표기해 게시 | 벤치는 공정한 기준선과 하네스를 함께 커밋한다 |
| 문제 지문 35개 수정·힌트 추가 기간에 AI 벤치가 85%에서 100%로 | 벤치 문제와 프롬프트는 동결한다. 1회 성공률을 재시도 없이 보고한다 |
| 대형 프로젝트 탐색 축을 정의만 하고 측정하지 않음 | 탐색 정확도와 질의당 토큰을 첫 마일스톤의 측정 항목으로 둔다 |
| Rust 동결 선언 후에도 기능 커밋 86개, 두 컴파일러 패리티 유지 | 컴파일러는 하나. 셀프호스팅은 의미론이 안정된 뒤에 결정한다 |
| 언어 동결 후에도 새 문법 추가, 완료 선언은 "약 95%" 추정치 기반 | 동결·완료는 측정 가능한 기준을 통과할 때만 선언한다 |
| 핵심 가설 검증 전에 바인딩 25개·패키지 매니저·플레이그라운드 | 생태계는 원칙 4·6이 측정으로 입증된 뒤에 연다 |
| 세션 종료·핸드오프 커밋 150개, 사이클 로그 688개가 나중에 추적 해제 | 결정 기록은 작고 버전 관리되는 ADR로 남긴다. 물려받은 진단은 행동 전에 재확인한다 |

## 4. 타당성 평가

**결론:** 방향은 타당하다. 표면 승계와 독자 의미론으로 정리하면서 초기 리스크 두 가지(학습 분포, 무에서 시작하는 문법)는 크게 줄었다. 남은 리스크는 아래와 같다.

| 리스크 | 수준 | 근거 | 완화책 |
| --- | --- | --- | --- |
| 증명 비용과 취약성 | 높음 | LLM 검증 코드 작성 성공률: Dafny 약 82%, Verus 44%, Lean 27%([vericoding](https://arxiv.org/abs/2509.22908v1)). 실시스템 Verus 증명은 Sonnet 4.5 기준 46~54%, 작업당 8~39달러([VeruSAGE](https://arxiv.org/html/2602.04910v2)). SMT 증명은 사소한 수정에도 깨진다([Zhou·Parno](https://popl25.sigplan.org/details/dafny-2025-papers/5/Towards-Proof-Stability-in-SMT-based-Program-Verification)) | 증명 자동화 포기(트리거 명시, 기본 불투명, 증명 문맥 선언)로 안정성 확보. 계약 방화벽 증분 빌드. 미증명 면적을 측정 |

## 5. 첫 마일스톤 제안

**범위:** 독자 컴파일러의 최소 관통 경로 + 도구 계층(읽기·쓰기) + 기본 증명 게이트 + L0~L2 맵.
- 최소 관통 경로는 Rust 부분집합 + 명세 문법 → 검증 조건 → Z3 → LLVM IR이다.

**검증할 것:** "에이전트가 파일 없이, 테스트 없이, 증명된 코드를 쓴다"를 수십 개 정의 규모에서 측정한다. 측정 항목은 다음과 같다.
- 탐색 정확도
- 질의당 토큰
- 1회 성공률
- Rust 습관 오류율
- 미증명 면적

**미루는 것:** 언어 표면 확장, 백엔드 최적화, 셀프호스팅, 생태계.

## 6. 다음 단계

1. 최소 관통 경로에 들어갈 언어 부분집합과 도구 질의 목록을 확정한다.
2. v0를 브랜치로 보존하고 main을 비운다(히스토리 보존, force push 없음).
   ```
   git tag v0.100-legacy && git branch legacy/v0
   git push origin legacy/v0 v0.100-legacy
   git submodule deinit --all -f
   git rm -r -q . && git commit -m "reset: BMB v2 from scratch"
   git push origin main
   ```
3. 결정 기록 형식(ADR)을 정하고, 이 문서의 Q1~Q13을 첫 ADR 묶음으로 옮긴다.
4. v0 공정 하네스를 기반으로 Rust 대비 기준선을 다시 잡는다(`get_unchecked` 변형 포함).
