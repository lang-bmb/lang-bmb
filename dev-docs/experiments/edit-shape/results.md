# 편집의 꼴: 포트의 실제 이력 (백로그 T1-51)

> 2026-11-22 · 관행 논의(`dev-docs/reviews/practices-2026-11-22.md` §6)의 첫 결정론 실험. 모델 없음. 컴파일러는 `4c399af7`의 릴리스 빌드, 장은 `selfhost/`를 건드린 커밋 40개(첫 부모, 2026-11-15~11-21)의 연속한 두 판 39쌍. 재현: `python3 dev-docs/experiments/edit-shape/run.py CACHE`(커밋마다 `bmb reads` 약 20초).

## 무엇을 쟀나

두 판 사이에서 정의마다 한 칸에 넣는다(`bmb reads`의 행: 자기 글의 해시, 계약의 해시, 증명 키).

| 칸 | 뜻 |
| --- | --- |
| 더함·지움 | 한쪽 판에만 있다 |
| 본문만 | 자기 글이 바뀌고 계약(시그니처 포함)은 그대로다: 호출자의 증명이 읽는 것은 바뀌지 않았다 |
| 계약도 | 자기 글과 계약이 바뀌었다 |
| 읽는 것만 | 자기 글은 그대로인데 증명 키가 바뀌었다: 읽는 것이 바뀌어 다시 증명한다 |

- **타입 쪽에는 방화벽이 없다.** 재증명의 88%(2,057개)가 타입 선언의 변경에서 온다. 포트의 검사기·출력기 상태(`body::Body`, `codegen::Gen`)에 필드를 하나 더하면 그 타입에 닿는 모든 정의의 키가 바뀐다. 마지막 판의 읽기 행 59,829개 가운데 49,141개(82%)가 타입 행이다.

## 읽는 법

- **H-LIVE의 상한.** 고친 정의의 83%는 호출자가 아무것도 하지 않아도 되는 교체다. 다만 이 수는 넉넉하다: 포트의 계약은 대부분 안전(범위·넘침·종료)뿐이고 기능 계약이 거의 없다. 계약이 약할수록 "계약이 그대로"가 쉽다. 그리고 이 이력은 옮겨 쓰는 일이라 더한 정의(1,757)가 고친 정의(222)의 8배다: 유지보수 이력이 아니다.
- **H-TRUNK의 병목은 타입이다.** 동시에 일하는 에이전트들이 같은 상태 구조체에 필드를 더하면 서로의 읽기 집합과 넓게 겹친다. 교환 판정은 겹친 정의의 재증명으로 풀지만 그 수가 크다(쌍 하나에서 최대 665개).
- **회수할 자리.** 타입의 읽기 집합이 선언 전체다. 정의가 읽는 것을 필드 단위로 좁히면(그 정의가 이름으로 닿는 필드, 값을 통째로 짓거나 옮기는 자리는 전체) 필드를 더하는 편집이 다른 필드만 읽는 정의의 키를 바꾸지 않는다. 증명 인코딩이 구조체를 어떻게 읽는지에 달려 있어 건전성 조건부터 따져야 한다(백로그 `T1-54`).

## 한계

- 장이 하나다(포트, 6일, 작성자 하나). 생성 이력(BCB)이 아닌 실제 이력이라는 점이 값이고, 유지보수 이력이 아니라는 점이 한계다.
- 이름 바꾸기는 지움과 더함으로 센다(경로로 짝짓는다).
- "본문만"은 호출자의 증명이 그대로라는 뜻이다. 돌고 있는 프로그램에서 바꿔 끼워도 되는지(§4.2의 조건 2·3)는 재지 않았다.
