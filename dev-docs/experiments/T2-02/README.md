# T2-02: `f64` 인코딩 비용 (ADR-0061 §5의 기본값)

`run.py`가 질의를 만들고 Z3로 푼다. 표는 `results.md`, 원자료는 `results.csv`다. 질의 꼴과 두 인코딩은 `run.py` 머리 주석에 있다.

- `bits`: 모든 질의에서 `fp.*`를 해석한다(ADR-0061 후보 (a)).
- `opaque`: 연산과 비교를 해석하지 않는 기호로 둔다(후보 (b)의 일반 질의).

## 결과

| 묶음 | 무엇을 재나 | `bits` | `opaque` |
| --- | --- | --- | --- |
| SN(spectral-norm 한 행, 열 1~64개) | 정수 의무(인덱스, `f64::from` 정확성). 부동소수 값은 목표와 무관 | 16행 모두 기대대로. rlimit 최대 290,082 | 16행 모두 기대대로. rlimit 최대 291,870 |
| NB(n-body 쌍 1~40개) | 인덱스 의무. 부동소수 값은 목표와 무관 | 모두 기대대로. 증명 26,344, 반례 72,526(k=40) | 모두 기대대로. 증명 22,984, 반례 64,586(k=40) |
| MB(mandelbrot 반복 1~16번) | 정수 계수기. 부동소수 비교가 경로를 정한다 | k=4 반례와 k=16 증명·반례가 **unknown**(한도 5,000,000) | k=16 증명 173,078~205,459. k=16 반례만 unknown |
| FP1(`sqrt`의 부호) | 부동소수 값 자체의 사실 | 증명, 1,301,088 | 증명 불가(기대대로) |
| FPk(유계 곱 k개 합의 유한성) | 부동소수 값 자체의 사실 | k=1만 증명(2,452,468~2,598,137). k ≥ 2와 반례는 모두 unknown | 증명 불가(기대대로) |

모든 행에서 시드 0을 다시 돌린 답과 rlimit이 같았다(결정론).

## 판정

1. **부동소수가 목표와 무관한 의무(SN·NB)에서는 두 인코딩이 같다.** 판정이 모두 같고 비용 차이는 ±30% 안이다. n-body·spectral-norm의 의무 대부분이 이 꼴이다.
2. **부동소수 비교가 경로를 정하면 `bits`가 무너진다(MB).** 같은 정수 의무를 `opaque`는 한도의 4%로 증명하는데 `bits`는 한도 안에 결정하지 못한다. 반복이 4번이어도 반례 찾기가 한도를 넘는다.
3. **부동소수 값 자체의 사실은 `bits`로만 증명되고, 그것도 아주 작아야 한다.** 곱 하나의 유한성이 한도의 절반을 쓰고 곱 둘의 합은 한도를 넘는다. 비트 정밀 증명은 국소적이어야 한다(ADR-0061 §5의 `by (bit_vector)` 하위 증명).

따라서 ADR-0061 §5의 기본값(일반 질의는 불투명, 비트 정밀은 `by (bit_vector)` 안에서만)을 유지한다. 후보 (a)는 MB 꼴에서 판정을 잃고, (b)가 잃는 것(부동소수 값의 사실)은 (a)도 한도 안에 거의 얻지 못한다.

## 구현에 넘기는 발견

- **불투명 질의의 반례는 거짓일 수 있다.** `opaque`의 sat 모델은 해석하지 않는 기호에 IEEE와 맞지 않는 값을 줄 수 있다(예: `f64.lt`가 참인데 실제 값으로는 거짓). 증명의 건전성(C1)은 그대로지만, 그런 반례를 그대로 보이면 G1의 "거짓 반례 0"을 어긴다. 반례를 보이기 전에 모델의 부동소수 값으로 연산을 실제로 계산해 기호의 값과 맞는지 확인하고, 맞지 않으면 반례 없이 "결정하지 못함"으로 보고해야 한다. 이 일은 백로그 T2-03(F4 인코더)에 넣는다.
- **MB k=16의 반례 찾기는 `opaque`에서도 한도를 넘었다.** 경로가 16겹인 반복을 펼친 질의라 그렇다. 실제 코드는 루프 불변식으로 한 반복만 보므로 이 꼴은 생기지 않는다. 그래도 F7(실행 프로그램)에서 mandelbrot을 쓸 때 다시 잰다.
