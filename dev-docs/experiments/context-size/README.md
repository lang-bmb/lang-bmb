# 차례당 문맥 크기 분해(2D-25)와 압축 에이전트 투영(2D-23)

- 표: `results.md`(`run.py`가 생성, 모델 호출 없음, 두 번 돌려 같은 바이트).
- 결정: ADR-0068. 구현: `compiler/src/view.rs`, `bmb mcp --compact`.

## 무엇으로 쟀나

| 자료 | 무엇을 주나 | 한계 |
| --- | --- | --- |
| 파일럿 BMB 쪽 행(`bench/pilot/results/`, `claude-opus-5-5`, ADR-0058 T0) | 호출마다 도구·인자·결과 바이트. CLI가 보고한 마지막 요청의 입력 토큰(`iterations[-1]`) | 파일럿이라 주장 근거가 아니다(C3). CLI의 `num_turns`는 API 요청 수가 아니다(병렬 호출) |

| 정식 qwen 행(`bench/m1*/results/2026-10-30-qwen3.8-27b.jsonl`) | 세션의 요청 수와 프롬프트 토큰 합(요청당 평균이 정확), 읽기 결과 바이트 합, 끝난 이유 | 요청별 토큰·호출별 결과 크기를 남기지 않았다. 이 커밋부터 켜면 남긴다(아래) |

**토큰.** 오프라인 토크나이저가 없어 추정한다(`tokest.py`): 사전 분할 조각 수 × 1.386. 계수는 T1-05가 잰 Claude 토큰 12점(같은 바이트가 재현되는 것)에 맞췄고, 점별 오차는 −7%~+4%다(`results.md` 1절). 16진 해시가 많은 JSON(L0)은 −5~−7%로 덜 센다. 그래서 해시를 뺀 효과는 과소 추정 쪽이다. qwen 토큰은 고정 부분만 `w08-digits`의 첫 요청(2,291토큰)으로 맞췄다(추정의 0.79배).

- 차이의 52%(1,664)가 매 요청에 들어가는 고정 부분이다. 시스템 프롬프트 3,471바이트 중 언어 규칙 절이 1,674바이트(모델이 모르는 제한을 알려야 한다: 언어 층의 비용), 도구 절이 1,025바이트로 도구 정의의 설명과 겹친다(도구 층). 도구 결과 안에서는 증명 결과가 크다: `write`·`verify`는 작업 공간의 모든 정의의 상태 줄을 매번 돌려준다(BVB에서 성공한 `write` 하나가 약 1,100바이트, 과제와 무관한 주어진 정의 8개 포함).
- 원래 질문(차례당 캐시 읽기 4,700 대 1,400)은 CLI의 `num_turns`로 나눈 값이라 요청당 값이 아니다. 마지막 요청으로 보면 비는 1.9배다.

**m1b(정의 116개), 마지막 요청:** 실측 21,141 중 읽기 결과 13,400(63%), 증명 결과 1,926, 고정 2,922. 읽기는 통째 덤프가 차지한다: 세션 대부분이 첫 호출로 `query units`(L0 전체, 7,181토큰)를 부르고, `map L1` 한 번이 약 32,000토큰(정규형 코드 전체의 3.1배)이다.

**정식 qwen(m1b):** 요청당 프롬프트 평균 14,207토큰, 고정의 몫 16%. 요청당 평균이 30,000을 넘은 세션은 둘이고, 그중 `w11-clamp-all`(평균 47,733, 읽기 14회·92KB)은 출력 한도(`length`)로 끝나 실패했다. 64K 문맥에서 남은 자리가 줄어든 것과 맞는 모습이다(요청별 값이 없어 단정하지 않는다). `api_error`는 0.

## `--compact`의 효과(재실행, 같은 호출)

- 도구 결과 토큰: 집합별 −74%~−79%. 호출당: `query units` 3,221 → 600, `map L1` 32,381 → 5,960, `write` 952 → 102, `verify` 971 → 25, `slice` 401 → 319.
- 마지막 요청: m1b −57%(21,141 → 9,187), m1b-write −54%, m1 −23%, BVB −12%, bvb-write −9%(6,851 → 6,262; Verus 3,660). 도구 설명이 늘어난 만큼(+135)을 더한 값이다.
- qwen m1b의 마지막 요청 하한(고정 + 읽기 결과) 최댓값: 40,150 → 11,434.
- 2D-23 확인(같은 질문, 작업 공간 전체의 표면): L1은 지금 정규형 코드의 3.13~3.56배. 해시 12자 1.88~2.25, 해시를 빼면 1.40~1.68, 위치·비용까지 빼면 0.99~1.21, 빈 필드까지 생략하면 0.82~1.02, Rust 꼴(`--compact`) 0.44~0.59. 추정 오차(−7%~+4%) 밖에서 코드 이하인 것은 Rust 꼴뿐이다.

## 다음 측정에 남기는 것

`BMB_CONTEXT_LOG=1`이면 정식 하네스가 요청마다 입력·출력 토큰(`model_usage.request_input_tokens`·`request_output_tokens`)과 호출마다 도구·결과 바이트(`calls`)를 남긴다(`model_api.context_log`, m1 하네스·Verus 하네스·두 에이전트. BRB는 MANIFEST가 하네스를 담아 그대로). 기본은 꺼져 있어 결과 행이 이전과 같은 바이트이고(HEAD 하네스와 오라클 행 비교), 에이전트가 보는 것은 켜도 같다. 켜고 돈 정식 실행은 분해를 추정 없이 낸다.
