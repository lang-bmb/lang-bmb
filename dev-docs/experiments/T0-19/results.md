# T0-19: BVB 판정기의 명세 비교 미결정

T0-10 BVB(BMB)에서 증명되고 서명도 맞는 여섯 세션(`vb-mbpp-454-contains-z`, `vb-mbpp-804-product-even`, `vb-mbpp-808-contains-k`, `vb-mbpp-809-is-smaller`, `vb-misc-choose-odd`, `vc-vv0039-max-of-list`)이 숨은 명세 강도 검사에서 `spec_rejections: [{reason: "undecided"}]`로 실패했다. 그 실행은 작업 공간을 남기지 않았다(세션 기록 INF-17 이전). 그래서 그 여섯의 계약은 볼 수 없고, 같은 판정기를 그대로 돌려 "어떤 계약이 `undecided`가 되는가"를 잰다.

- 컴파일러: T0-10 BVB가 쓴 것(`condition.py build f83cd47d`, `target/conditions/f83cd47d…/bmb`). 이후 개발 커밋의 디버그 빌드로도 808 H·약한 기준, choose_odd Q2·B를 다시 돌려 같은 판정을 확인했다.
- 판정기: `bench/m1/harness.py`의 `judge_write`를 고치지 않고 부른다(`judge.py`). 작업 공간은 BVB 시드에 변형 하나를 `src/tasks.bmb`로 더한 것이다.
- Z3 4.15.4, 시드 0, rlimit 5,000,000.

읽는 법:

1. **`undecided`는 약함과 같은 뜻을 가르지 못한다.** 과제가 동결한 약한 기준 해법 넷(454·804·808·809)이 `refuted`가 아니라 `undecided`다. 해법기는 반례 후보를 낸다(454: `text = [122] (len 1)`, `r = false`. 실제 반례다). 그러나 기저 인스턴스 재시도(ADR-0023)가 "정의의 몸에 `forall`이 있으면 불완전"으로 보아 그 모형을 확인하지 않고, 하네스의 `spec_rejection`은 "solver could not decide"를 보면 `undecided`로 적는다. 그래서 T0-10의 여섯 `undecided`는 "명세가 같은 뜻인데 판정기가 못 가름"의 증거가 아니다. 약한 명세여도 같은 기록이 남는다.
2. **같은 뜻인 짧은 명세가 미결정이 되는 꼴은 둘이다.**
   - (가) 재귀 술어: 여섯 과제 모두 재현. 함의에 귀납이 필요하다(T1-14, ADR-0062, `T1-25`·`T1-24`).
   - (나) 색인 술어 적용을 트리거로 쓴 존재 꼴(H, Q2): 증명되는 작업 공간으로 454·804·808·choose_odd에서 재현, 809는 숨은 검사만. 원소 값을 받는 스칼라 술어(D)는 받는다. 원인은 §2.
3. 계약을 숨은 계약과 같은 모양(`!(forall ..)`, 원소 읽기 트리거)으로 쓰면 모두 받는다. 파일럿의 넷도 그렇게 받았다.

## 2. (나)의 원인: 배열을 묶는 정의 공리 위의 모형 기반 인스턴스화

H(808)의 숨은 검사 질의(`bmb verify --emit-smt`, `bmb_accept.check.smt2`):

- 에이전트 사후조건은 `r == !(forall|j| !hit_at(arr, k, j))`이고 트리거가 `hit_at(arr, k, j)`다. `r = false`이면 가정에 `∀j. ¬hit_at(arr, k, j)`가 있다. 목표의 부정은 숨은 계약의 존재 꼴이라 새 기호 `i0`와 `arr[i0] = k`를 준다. 모순을 내려면 가정을 `j := i0`로 인스턴스화해야 하는데 질의에 `hit_at(arr, k, i0)` 항이 없어 트리거가 걸리지 않는다.
- Z3의 모형 기반 인스턴스화(MBQI)가 이런 경우를 메워야 하지만, `hit_at`의 정의 공리가 배열 정렬 변수를 묶는다(`∀ a: (Array Int Int), len, k, j. …`). 트리거에 쓰인 기호라 ADR-0064의 매크로가 될 수 없다. 첫 질의는 `unknown`(`incomplete (theory array)`)으로 끝난다.
- 기저 인스턴스 재시도는 한정 기호 밖의 적용만 인스턴스화한다(`collect_apps`는 `forall` 안으로 내려가지 않는다). `hit_at(arr@0, len@0, k@0, j)`는 묶인 `j` 아래에 있어 인스턴스가 없다. 그래서 `sat`이지만 불완전(`a model exists for the instantiated definitions only`)이 되어 E0811이다.

에이전트 자신의 증명은 통과한다. 루프 불변식의 인스턴스가 `hit_at(arr, k, i)` 항을 만들기 때문이다. 판정기의 질의에는 그런 항이 없다. 판정기가 에이전트의 증명보다 어려운 질문을 한다.

### 시제품(`specialize.py`, 질의 텍스트에서): 묶인 변수 아래 적용의 특수화 인스턴스

재시도 질의에서 한정 기호 아래에 나오는 비재귀 `spec fn` 적용마다, 묶인 변수를 쓰지 않는 인자(여기서는 배열 `arr@0`, 길이, `k`)를 대입하고 나머지 매개변수만 남긴 정의 인스턴스를 더한다. `∀j. guard(j) ⇒ (hit_at(arr@0, len@0, k@0, j) = (j < len@0 ∧ arr@0[j] = k@0))`, 패턴은 그 적용. 정의의 인스턴스라 이것으로 얻은 `unsat`은 증명이다. 배열 정렬 변수가 남지 않아 질의가 MBQI가 완전한 조각(본질적으로 해석되지 않는 조각, Ge·de Moura CAV 2009 "Complete instantiation for quantified formulas in SMT")에 든다. 배열 성질 조각의 결정 절차(Bradley·Manna·Sipma VMCAI 2006)가 색인 집합으로 인스턴스화하는 것과 같은 방향이다.

| 사례(`specialize.out`) | 첫 질의 | 재시도(지금) | 재시도 + 특수화 |
| --- | --- | --- | --- |
| 454 H | unknown 10,125 | sat(불완전) 3,511 | **unsat 8,293** |
| 804 H | unknown 14,911 | sat(불완전) 3,008 | **unsat 9,222** |
| 808 H | unknown 12,196 | sat(불완전) 2,986 | **unsat 6,993** |
| choose_odd D(요구 조건) | unknown 7,703 | sat(불완전) 2,181 | **unsat 7,552** |

| 809 D(숨은 검사) | unknown 10,941 | sat(불완전) 5,568 | **unsat 8,283** |

| 재귀 B 일곱 | unknown | sat(불완전) 또는 한도 | 특수화 0개, 그대로 |

- 같은 꼴로 실패하던 에이전트 쪽 증명도 풀린다: 809 D의 루프 불변식 의무 unknown 16,167 → unsat 13,767, max_of_list D의 사후조건 `contains` unknown 10,905 → unsat 6,943(`specialize.out` 끝 두 항목).
- 첫 시제품은 질의의 배열 상수마다 배열을 묶는 정의 전체를 특수화했는데, 재귀 B에서 지상 적용뿐인 `post`까지 특수화해 rlimit 5,000,000까지 돌았다. 한정 기호 아래 적용 단위로 좁히자 B·약한 기준에서는 아무것도 더하지 않는다(비용 0).
- 약한 기준의 `sat` 모형은 실제 반례다(454: `text = [122]`, `r = false`). 이 질의에서 정의 적용은 모두 인스턴스가 있고(한정 기호 아래 적용이 없다), 남은 `forall`은 정의의 몸 자체다. Z3의 `sat`은 그 한정 기호까지 모형 검사를 거친 답이다. 그런데 재시도의 완전성 판단(`ground_instances`의 `complete`)은 "몸에 `forall`이 있으면 불완전"이라 이 모형을 버린다. 완전성을 "모든 적용(한정 기호 아래 포함)이 인스턴스를 갖고 깊이에서 잘린 것이 없다"로 정확히 하면 이 넷은 `refuted`(확인된 반례)가 되고, 재귀 B는 깊이에서 잘리므로 계속 미결정이다.

## 3. 상류 원인: 명세 언어에 `exists`가 없다

- 존재 꼴 과제(454·804·808·choose_odd·max_of_list)에서 에이전트는 먼저 `exists`를 쓴다. 파일럿 2차(BVB 45세션)의 호출 기록에서 11세션이 `exists|..|`를 썼고, 이 다섯 과제가 모두 그 안에 있다. qwen도 BRB(`t12-second-max`, 진행 중인 T0-10 BRB의 세션 기록)에서 첫 계약에 `exists|i: usize|`를 썼다.
- 컴파일러는 이것을 `E0103 expected ';', found ':'`과 수정 "insert `;` before `:`"으로 거부한다(`f83cd47d`에서 재현). 틀린 기계적 수정이다.
- 에이전트는 다른 꼴로 돌아간다. 파일럿의 454·choose_odd는 재귀 술어(가)로, qwen의 Verus 팔 choose_odd 계약을 BMB로 옮기면 색인 술어 트리거(나, Q2)가 된다. 둘 다 같은 뜻인데 판정기가 결정하지 못하는 꼴이다.

## 5. 권장안(JUDGMENT §10)

1. **문제:** 판정기의 `undecided`가 같은 뜻 명세(재귀 술어, 색인 술어 트리거)와 약한 명세 모두에서 나와, BVB 실패를 모델·판정기 어느 쪽에도 귀속할 수 없다. 재현은 §1·§2.
2. **원인과 귀속 층:** (나)와 약함의 미결정은 증명기의 기저 인스턴스 재시도가 한정 기호 아래 적용을 인스턴스화하지 않고(ADR-0023 `collect_apps`), 배열을 묶는 정의 공리 위에서 MBQI가 불완전하며(ADR-0064와 같은 원인), 재시도의 완전성 판단이 몸에 `forall`이 있으면 모형을 버리는 데 있다. 컴파일러 층. (가)는 귀납이라 판정기·컴파일러(`T1-25`·`T1-24`). 상류에 언어의 `exists` 부재(`T0-25`).
3. **정석 해와 출처:** 지상 항에 대한 한정 기호 인스턴스화로 결정 가능한 조각에 넣기(Ge·de Moura 2009 완전 인스턴스화, Bradley·Manna·Sipma 2006 배열 성질 조각). 판정 쪽은 Dafny·Verus처럼 같은 SMT 증명기로 함의를 묻고 미결정을 실패로 세는 지금 방식을 유지하되 증명기의 완전성을 높인다.
4. **후보:**
   - (A) 증명기: 재시도에 한정 기호 아래 적용의 특수화 인스턴스, 완전성 판단을 적용 단위로(`T0-24`). C1(인스턴스만 더함, 모형은 모든 적용이 인스턴스를 가질 때만 반례), C2, C3(판정기·동결 파일 그대로), C4 통과. S2: 판정기와 에이전트 증명을 함께 고친다.
   - (B) 판정기: 검사 함수에 트리거 항을 심거나 계약을 다시 써 비교. 동결 하네스 변경(ADR-0070 조건 변경)이고 증상만 판정기에서 흡수(§2.1 위반). 기각.
   - (C) 판정기: 미결정이면 시험 입력으로 두 계약을 계산해 비교. 반례 확인에는 쓸 수 있으나 증명이 아니라 같은 뜻을 받을 수 없고, 증명기가 이미 내는 모형을 확인하는 (A)보다 일반성이 낮다.
   - (D) 프롬프트에 "계약을 숨은 꼴로 쓰라" 안내. 동결 프롬프트 변경이고 도구 결함을 프롬프트로 메움(§3 도구 행 "하지 않는 것"). 기각.
5. **권장과 결정적 기준:** (A). S2(원인 제거, 판정기와 게이트 모두)와 C3(동결 집합 바이트 그대로). (가)는 `T1-25`·`T1-24`, 상류는 `T0-25`.
6. **영향(정보):** `verify.rs`의 재시도(`ground_instances`, `collect_apps`, 재시도 판정)만. 재시도는 첫 질의가 `unknown`일 때만 돌므로 지금 결정되는 의무의 판정은 그대로이고, 바뀌는 것은 미결정 → 증명(같은 뜻) 또는 미결정 → 확인된 반례(약함)뿐이다. 다만 에이전트가 보는 진단도 바뀐다(E0811 → 증명 또는 E0802 반례). 실패 코퍼스에서 E0811 → E0802가 생길 수 있고 기대 출력을 갱신한다. 판정기의 숨은 검사는 `bmb verify`를 부르므로 고친 컴파일러로 도는 실행은 자동으로 새 판정을 쓴다.
7. **측정 조건(ADR-0070):** 컴파일러 트리가 바뀌므로 새 조건이다. 기록된 결과(T0-10 등)는 그대로 두고, 고친 커밋 이후의 측정은 `--same-as`로 이전 커밋과 같은 조건을 주장할 수 없다(ADR-0066 §5: 새 커밋의 새 측정). 세션 기록이 있는 실행의 작업 공간은 고친 판정기로 다시 판정해 따로 보고할 수 있다(원 판정을 대체하지 않음).
8. **필요한 승인:** 인코딩 수준 결정이라 ADR 자율 채택(AUTONOMY §4). `T0-25`의 `exists` 추가는 언어 범위 확대라 사람 승인.
