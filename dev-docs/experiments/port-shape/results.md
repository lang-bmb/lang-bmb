# 포트의 자료 모양: 소유 트리 대 아레나 (2026-11-11)

포팅 지도 §5.2가 꼽은 가장 큰 증명 위험(아레나 인덱스의 수량자 불변식)을 파서(C2)에 닿기 전에 작은 파서로 쟀다. ADR-0121(제안)의 근거다.

## 설계

- 과제: 한 줄에 식 하나를 읽어 정규형을 찍는 재귀 하강 파서. 문법·깊이 한도(64)·정규형은 `ref.py`가 정본이다(이항 연산 두 단계, 단항 `-`, 괄호, 인자 수가 변하는 호출).
- 두 팔이 같은 구조를 쓴다: `parse`가 구조를 만들고(찍으면서 파싱하지 않는다), `print`와 `count`가 그 구조를 따로 걷는다. 노드는 글자를 복사하지 않고 바이트 범위를 가진다.
  - `tree.bmb`: stage0의 구문 트리와 같은 모양. `enum Expr { Num, Name, Neg(Box<Expr>), Bin(u8, Box<Expr>, Box<Expr>), Call(usize, usize, Vec<Expr>) }`.
  - `arena.bmb`: `Vec<Node>` 하나와 인덱스. 불변식은 포팅 지도 §5.2의 대안 (1)이다: 자식 인덱스 < 부모 인덱스(타입 불변식 `#[invariant(sound)]`, 수량자 하나). 호출의 인자는 같은 아레나의 연결 칸이다.
- 두 팔의 조건: 모든 정의가 증명되고 탈출구가 없다. 기능 계약 하나(모든 범위가 `start < end <= len`)를 `parse`가 세우고 `print`가 써서 글자 인덱싱에 런타임 검사가 없다. 아레나 접근은 불변식에서 증명한다(검사하는 접근 함수로 감싸지 않는다).
- 각 팔은 위임된 세션 하나가 썼다(같은 지시문, 서로의 파일을 보지 않음). 수치는 `measure.py`가 다시 잰다.

## 읽기

- **둘 다 된다.** 아레나의 수량자 불변식은 미결정(E0811)도 불안정도 내지 않았다. 포팅 지도 §5.2가 걱정한 "증명 가능성"은 이 크기에서 문제가 아니다.
- **증명 비용은 아레나가 2.6배다.** 의무가 87개 많고(노드 접근마다 인덱스 의무), 가장 비싼 의무는 10배다. 그 의무는 `add`(노드를 넣고 불변식을 다시 세우는 유일한 함수)에 있고, 시드 폭 3.09도 거기서 나온다. 트리는 메모리 안전이 타입에서 나와 인덱스 의무가 없다.
- **아레나의 계약 대부분은 불변식과 무관한 용량 논증이다.** `Vec::push`의 길이 의무(E0816)를 풀려고 "노드 수 ≤ 읽은 바이트 수"를 모든 파싱 함수의 계약에 실었다. 트리에는 그 논증이 인자 벡터 하나에만 있다.
- **실행 시간은 같은 수준이다**(아레나가 16% 빠르다). 트리의 할당·해제 비용이 이 입력에서 판정을 가르지 않는다.
- **줄 수는 같다.** 실행 줄 272 대 277, 명세 줄 67 대 65.

## 한계

- 한 과제, 팔마다 한 세션이다. 세션 토큰과 게이트 실행의 차이(5%, 1회)는 잡음과 구분되지 않는다.
- 340줄이다. 수량자 불변식의 비용이 크기에 따라 어떻게 자라는지는 재지 않았다(파서 C2는 5,124줄이다).
- 아레나 팔은 대안 (1)만 쟀다. 검사하는 접근 함수(대안 2)와 탈출구(대안 3)는 재지 않았다.
