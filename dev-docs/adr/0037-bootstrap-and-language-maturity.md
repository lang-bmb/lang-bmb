# ADR-0037: 셀프호스팅 부트스트랩 필수와 언어 성숙 단계

- 상태: 채택 (사람 지시 2026-10-25)
- 날짜: 2026-10-25
- 관련: ADR-0012(독자 컴파일러, "셀프호스팅은 의미론이 안정된 뒤에 결정"을 대체), ADR-0034(미션 목표), genesis §3(v0: 두 컴파일러 패리티 비용)

## 맥락
ADR-0012는 셀프호스팅을 "의미론이 안정된 뒤에 결정"으로 미뤘다. 사람의 지시(2026-10-25): BMB는 **부트스트랩(1단·2단)을 포함해 언어가 밟아야 할 단계를 모두 통과해야 한다.** v0는 Rust 컴파일러와 셀프호스팅 컴파일러를 함께 유지하며 기능 커밋마다 패리티를 맞추느라 큰 비용을 치렀다(genesis §3.5). 필수화하되 그 실패를 되풀이하지 않는 절차가 필요하다.

## 결정
1. **셀프호스팅은 필수다.** 4단계의 목표는 "결정"이 아니라 "달성"이다.
2. **부트스트랩 정의(고정점):**
   - stage0: 현재의 Rust 컴파일러(`compiler/`).
   - stage1: BMB로 쓴 컴파일러를 stage0으로 빌드한 것.
   - stage2: 같은 소스를 stage1로 빌드한 것.
   - stage3: 같은 소스를 stage2로 빌드한 것.
   - **통과:** stage2와 stage3 바이너리(또는 IR)가 바이트 단위로 같고, stage2가 전체 코퍼스·벤치·퍼저에서 stage0과 같은 출력을 낸다(차등 시험). CI가 매 커밋 확인한다.
3. **두 컴파일러를 함께 키우지 않는다(v0의 교훈):**
   - 포팅 기간에는 stage0에 언어 기능을 추가하지 않는다. 기능 동결 선언은 포팅 착수 시점에 하고, 이후 stage0 변경은 버그 수정과 부트스트랩에 필요한 최소 변경만이다.
   - 포팅은 구성 요소 단위(렉서→파서→검사기→증명기→코드 생성→맵·도구)로 하고, 구성 요소마다 stage0과 차등 시험으로 동일 출력을 확인한 뒤 넘어간다.
   - 고정점 달성 후 stage0은 "부트스트랩 씨앗"으로 동결·보존하고(태그·바이너리), 개발은 BMB 컴파일러 하나로 한다.
4. **자기 증명:** BMB로 쓴 컴파일러는 자기 증명 게이트를 통과해야 한다. 탈출구(ADR-0029 제안)를 쓰는 부분은 미증명 면적으로 집계해 보고하고, 그 면적의 상한을 단계 통과 기준에 둔다.
5. **언어 성숙 단계:** 셀프호스팅에 더해 언어로서 갖춰야 할 단계(명세·적합성 시험, 표준 라이브러리, 시스템 인터페이스, 안정성·버전 정책, 재현 가능한 빌드·배포, 다중 타깃, 디버그 정보, 문서)를 ROADMAP 4·5단계의 페이즈로 둔다.
6. **2단계와의 관계:** 컴파일러를 BMB로 쓰는 데 필요한 기능(문자열·바이트, 힙 컬렉션, 데이터 타입, 오류 처리, 파일·프로세스)은 2단계 언어 페이즈의 범위와 우선순위 입력이 된다(격차 분석 4A-01). 2R 문법 결정은 포팅 전에 마친다.

## 근거
- 자기 자신을 컴파일하고 증명하는 것은 "AI가 대형 코드를 증명된 형태로 다룰 수 있다"는 미션의 가장 강한 실증이다. 컴파일러는 수만 줄 규모의 실제 프로그램이다(3단계 규모 가설의 실전 시험).
- 고정점·차등 시험은 측정 가능한 통과 기준이다(genesis §3.5: 동결·완료는 기준을 통과할 때만).
- 기능 동결과 구성 요소 단위 포팅은 v0의 이중 유지 비용을 직접 막는다.

## 결과
- 4단계는 2단계 언어 페이즈(2B·2C·2G 등)에 의존한다. 순서는 1E-07과 4A-01 격차 분석이 함께 정한다.
- stage0 기능 동결 시점부터 언어 확장은 BMB 컴파일러 쪽에서만 일어난다.
- 되돌리려면 이 ADR을 대체하는 ADR이 필요하다(사람 승인).
