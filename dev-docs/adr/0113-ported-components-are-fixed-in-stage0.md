# ADR-0113: 포팅된 구성 요소는 stage0에서 고정한다

- 상태: 채택(사람 승인 2026-11-11 "모두 승인, 권장안 채택": 종합 검토 R10, 백로그 4D-09). ADR-0100을 보완한다
- 날짜: 2026-11-11
- 관련: ADR-0037(부트스트랩, 두 컴파일러를 함께 키우지 않는다), ADR-0100(stage0 기능 동결: 대상은 받아들이는 언어), ADR-0105(도구 변경은 그 포팅 전이 싸다), HEALTH.md S4, 포팅 지도(`selfhost-port-map.md`)

## 맥락

- ADR-0100의 동결 대상은 받아들이는 언어다. 도구(맵·질의·작업 공간·진단·MCP)는 동결 대상이 아니다.
- stage0은 계속 자란다: S4(시험 제외 줄 수)가 42,712에서 53,459로 늘었다(`progress.md`). 동결 뒤에도 도구 쪽 변경은 이어진다(ADR-0108~0110 같은 측정 대응).
- 구성 요소가 BMB로 옮겨진 뒤 stage0 쪽이 바뀌면 포트가 낡는다. 차등 시험이 그것을 잡지만, 잡은 뒤에는 두 쪽을 고쳐야 한다. v0의 교훈이 그것이다.

## 결정

1. **구성 요소가 차등 시험을 통과하면 그 stage0 구성 요소는 고정이다.** 포팅 지도의 구성 요소(C0~C13)마다, BMB 포트가 그 구성 요소의 차등 시험을 게이트에서 통과한 커밋부터 적용한다.
2. **고정된 구성 요소의 변경은 두 쪽을 한 커밋에서 바꾼다.** stage0의 그 구성 요소 파일을 바꾸는 커밋은 포트의 대응 변경을 함께 담고 차등 시험을 통과해야 한다. 결함 수정도 같다.
3. **아직 옮기지 않은 구성 요소는 자유다.** 그래서 도구의 변경은 그 구성 요소(P5·P9~P11)의 포팅 전에 끝내는 것이 싸고(ADR-0105), 관문 B의 실패 귀속이 도구 수정을 요구하면 P5 착수 전에 한다(ADR-0111).
4. **S4 예산의 `accept`는 구성 요소 단위 사유를 적는다.** 4D부터 붙는 +2% 예산(HEALTH S4)을 넘길 때, 어느 구성 요소가 왜 늘었는지와 그 구성 요소의 포팅 상태를 이유에 적는다.
5. **감지는 게이트가 한다.** 구성 요소별 파일 목록과 고정 여부를 `dev-docs/health/`의 한 파일에 두고, 게이트가 고정된 구성 요소의 stage0 파일이 바뀐 커밋에서 포트 쪽 변경과 차등 시험 통과를 확인한다. 구현은 첫 구성 요소가 통과하기 전(4D-02 안)이다(백로그 4D-10).

## 근거

| 안 | 판정 |
| --- | --- |
| **옮긴 구성 요소부터 차례로 고정(채택)** | 이주 중에는 옮긴 쪽과 원본이 갈라지지 않게 원본을 닫는다(확립된 이주 방법). 측정이 요구하는 도구 변경의 여지는 포팅 전 구성 요소에 남는다 |
| 동결 때 stage0 전체 고정 | 증거 단계와 관문 B가 요구할 도구 수정(2D-17 계열)을 막는다 |
| 지금대로(언어만 동결, S4 예산) | 예산은 `accept`로 넘길 수 있고, 어느 구성 요소가 포팅됐는지와 묶여 있지 않다 |

## 결과

- 포팅 순서가 도구 변경의 마감 순서가 된다: 맵·질의(P5) 전에 질의 범위·상한(2D-17), 진단·MCP(P9~P11) 전에 미결정 정보·탐침(ADR-0108·0109)의 기본값 결정.
- 고정 뒤의 stage0 결함 수정은 비용이 두 배다. 그 비용이 4G(stage0 은퇴)까지 이어진다.
