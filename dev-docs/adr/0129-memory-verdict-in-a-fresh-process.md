# ADR-0129: 메모리로 인한 미결정은 새 프로세스의 첫 질의에서만 판정한다

- 상태: 채택(자율 채택, AUTONOMY §4 "결정 기록": 백로그 `T2-17`). ADR-0123·ADR-0126을 보완한다
- 날짜: 2026-11-12
- 관련: ADR-0018(의무마다 새 상태), ADR-0123(해법기의 메모리 한도), ADR-0126(권고 질의의 메모리 한도), `compiler/src/smt.rs`, `compiler/src/cache.rs`, 측정 `dev-docs/measurements/t2-17.md`

## 맥락

- Z3의 `-memory`는 프로세스의 할당 합계를 센다. 프로세스는 답한 질의마다 조금씩 남긴다: `lib/std`의 2,213질의를 한 프로세스에 보내면 `(reset)` 직후의 할당이 0.10MB에서 0.45MB로 자란다.
- 그래서 한도 가까이 쓰는 질의의 판정이 앞선 질의에 달린다. `-memory:18`에서, 혼자 물으면 답하는 질의(정점 17.96~17.99MB) 20개 중 16개가 790질의 뒤에서는 한도에서 끝났다. 반대 방향도 있다: 혼자 물으면 끝나는 질의(정점 18.00MB) 5개 중 3개가 앞에 질의 하나가 있으면 답했다. 혼자 물은 결과는 12번 반복해 같았다.
- 프로세스는 시작 뒤 60초(벽시계)까지 다시 쓰이므로, 어느 질의들이 한 프로세스에 모이는지도 벽시계에 달린다.
- 창이 0.05MB쯤이라 지금 코퍼스에서는 드러나지 않는다(`lib/std`를 한도 19~24MB로 낮춘 전체 실행과 `--def` 단독 실행의 판정이 실패 정의 22개에서 모두 같았다).
- 증명 캐시의 키에는 메모리 한도가 없었다. 게이트의 한도로 찾은 증명이 같은 텍스트의 권고 질의(더 작은 한도)에 답해서, `lint` 출력이 `--cache`의 내용에 달렸다(재현: `tests/lint.rs` `a_cached_gate_proof_does_not_answer_an_advisory_query`의 앞 판).
- 탐침이 한도에서 끝나면 전체 질의는 끝난 프로세스로 가서 묻지 않은 채 미결정이 됐고, 한도에서 끝난 질의는 기저 인스턴스 재시도를 받지 않았다.

## 결정

1. **메모리로 인한 미결정은 그 질의가 새 프로세스의 첫 질의로 한도에 닿았을 때만 판정한다.** 모든 질의에 같은 상태이므로 판정이 앞선 질의에 달리지 않는다.
2. **여러 질의를 맡는 프로세스는 한도의 절반으로 돈다**(`smt::working_memory_mb`: 게이트 512MB, 권고 64MB). 거기서 끝난 질의는 `(reset)`부터 새 프로세스에 혼자, 한도 그대로 다시 묻고 그 답이 판정이다. 절반 아래에서 답한 질의는 혼자 물었어도 한도 안에서 답했을 것으로 본다(아래 가정).
3. **한도에서 끝난 질의의 다음 질의는 바로 혼자 묻는다.** 어디서 묻는지는 답을 바꾸지 않으므로 비용의 문제다(거짓 의무의 질의들은 잇달아 한도에 닿는다).
4. **한도(`rlimit`·메모리)가 끝낸 질의는 `unknown`과 같은 미결정이다.** 탐침 뒤의 전체 질의, 기저 인스턴스 재시도, 범위 탐색이 그대로 따른다. 재시도가 결정하지 못하면 사유는 한도 그대로다.
5. **증명 캐시의 키에 질의의 메모리 한도를 넣는다**(형식 v5, 증분 캐시의 증명 키에도). 게이트의 증명은 권고 질의에 답하지 않는다. `lint`의 재검증은 바뀌지 않은 의무도 권고 한도로 한 번 다시 푼다.

## 근거

| 안 | 판정 |
| --- | --- |
| **절반 한도의 작업 프로세스, 끝나면 혼자 다시(채택)** | 판정의 정의가 "혼자 물은 결과"이고, 보통 질의는 비용이 그대로다. 가정 하나에 기댄다(아래) |
| 질의마다 새 프로세스(Why3의 방식) | 가정이 없다. 새 프로세스의 첫 질의는 13.2ms, 이어 묻는 질의는 2.3ms(200회): `lib/std` 검증(2,213질의, 23초)에 약 24초가 더 든다 |
| 끝난 질의만 한도 그대로 다시 묻는다 | 반대 방향(혼자는 끝나고 뒤에서는 답함, 측정 3건)을 막지 못한다 |
| 지금대로 | 판정이 질의 순서와 벽시계에 달린다(C2) |
| 캐시: 권고 질의가 이번 실행의 게이트 증명만 쓴다 | 증분 캐시가 정의를 통째로 다시 쓰면 그 의무의 키를 알 수 없어 캐시 유무로 갈린다 |

가정: 작업 프로세스가 절반 아래에서 답한 질의는 혼자 물어도 한도를 넘지 않는다. 어긋나려면 같은 질의의 정점이 혼자일 때 한도의 절반(512MB, 권고 64MB)만큼 더 커야 한다. 측정된 차이는 양쪽으로 0.05MB 아래이고, 가장 작은 질의의 정점 전체가 16.8MB다. 외부 도구의 한계에 대한 대응이라 `smt::Solver::ask` 한 곳에 둔다(JUDGMENT §3).

## 결과

- 고정 한도에서 `lib/std`의 `verify` 출력은 이전과 바이트 단위로 같다(218정의, 판정과 `rlimit`). 수치는 `dev-docs/measurements/t2-17.md`.
- 한도를 낮추면 미결정이 준다(`lib/std`, 18MB: 메모리 미결정 132 → 73). 한도에서 끝난 질의의 기저 인스턴스 재시도가 증명한 의무: 18MB에서 95개 중 25개, 19MB 12개 중 4개, 20MB 5개 중 4개.
- 폭주 질의가 있는 입력은 더 든다: `port-shape/tree.bmb`의 `lint`는 보고 19줄이 그대로이고 CPU 시간이 21.5 → 49.1초다(한도에서 끝나는 질의 44 → 82개: 새로 받는 재시도 35개가 모두 다시 한도에서 끝난다. 작업 한도에서 끝나 다시 묻는 질의 43개).
- 프로세스 재사용 시한(60초)은 이제 판정에 닿지 않는다.
- 시험: `compiler/tests/gate.rs` `a_memory_end_in_a_working_process_is_asked_again_alone`, `after_a_probe_at_the_memory_limit_the_query_is_asked`, `a_query_at_the_memory_limit_gets_the_ground_instance_retry`, `compiler/tests/lint.rs` `a_cached_gate_proof_does_not_answer_an_advisory_query`.
- 남는 것: `lint`의 시간(백로그 `T2-17` (e)). 권고 질의의 `rlimit`은 ADR-0126 그대로이고, 낮추는 것은 `lint`의 보고를 바꿀 수 있는 결정이라 권장안으로만 올린다.
