# ADR-0109: 커밋하지 않는 일괄 탐침: 후보 불변식을 거르는 읽기 도구

- 상태: 채택(자율 채택, AUTONOMY §4 "결정 기록": 읽기 도구 하나를 더하는 도구 층 결정. 쓰기 표면 ADR-0101과 언어는 그대로다. 아홉째 실행 계획, 사람 승인 "권장안 채택")
- 날짜: 2026-11-10
- 관련: ADR-0101(정식 쓰기 표면 `write`), ADR-0108(미결정 응답의 정보), ADR-0068·0071(측정 전에는 플래그 뒤), DESIGN §3 원칙 6, 백로그 2D-35·T0-37

## 맥락

- sonnet `brb-write`의 `t14-dedup-sorted`는 `write` 34번 중 22번이 미결정이었다. 대부분 "후보 하나를 바꿔 정의 전체를 다시 쓰기"였다(AI 사용자 의견서 2026-11-10 P2).
- `write`는 커밋하는 연산이다. 그래서 탐색용 시도가 모두 작업 공간과 대화 이력에 남는다.
- 후보 불변식을 여럿 내는 것은 에이전트가 잘하는 일이다. 그것이 맞는지 가르는 것은 결정론적 계산이다. 원칙 6의 분업이다.

## 결정

1. **도구.**
   - CLI는 `bmb probe --def PATH [--loop K] --candidate EXPR..`이다.
   - MCP는 `probe {def, loop, candidates}`이고 `--probe-tool`일 때만 목록에 나온다.
   - 함수 하나의 K번째 루프(문장의 `while`·`for`와 `loop` 식, 소스 순서, 0부터)에 후보 식을 최대 16개 받는다.
   - 파일과 작업 공간을 바꾸지 않는다.
2. **판정(Houdini).**
   - 후보마다 자기 파일 id를 가진 래퍼(`fn __candidate() -> bool { C }`)로 파싱한다. 그래서 진단이 어느 후보 것인지 파일로 가린다.
   - 남은 후보를 모두 그 루프의 불변식에 더한 복사본에서 그 함수 하나만 검사·증명한다.
   - 검사 오류이거나, 진입(E0806)·보존(E0807)이 실패하거나 그 둘이 미결정(E0811의 `obligation`)인 후보를 빼고 다시 한다. 빠지는 후보가 없을 때 남은 집합이 함께 귀납적인 최대 부분집합이다.
3. **보고.**
   - 남은 후보는 둘 다 `holds`다.
   - 빠진 후보는 빠진 라운드와, 실패하거나 미결정이었던 쪽만 적는다. 다른 쪽은 `-`다. 증명기는 실패한 의무를 뒤에서 가정하므로, 다른 후보가 실패한 라운드의 "성립"은 공허할 수 있기 때문이다. 실패에는 모델이 있다.
   - 반례가 있으면 싣는다.
   - 끝에 남은 집합과, 그것으로 함수가 증명되는지(`verified`)를 적는다.
4. **측정 전에는 플래그 뒤.** MCP 도구는 `--probe-tool`일 때만 있다. 동결된 집합의 도구 목록은 그대로다. 효과는 T0-37이 이 플래그 하나만 더한 판으로 잰다.
   - 지표는 성공당 토큰과 세션당 `write` 수다.
   - 도구 호출만 늘고 토큰 차이가 D(ADR-0077) 안이면 반증이다.

## 근거

| 안 | 판정 |
| --- | --- |
| **복사본에서 함수 하나를 증명하는 Houdini(채택)** | 증명기의 판정을 그대로 쓴다. 인코딩을 새로 만들지 않는다. 결과가 결정론이다 |
| 후보마다 따로 증명 | 서로 기대는 불변식(한 후보의 보존에 다른 후보가 필요)을 거르지 못한다 |
| `write`에 "커밋하지 않음" 옵션 | 쓰기 표면(ADR-0101)이 바뀌고, 후보 여럿을 한 번에 거르지 못한다 |
| 첫 라운드의 답을 그대로 보고 | 다른 후보의 실패 뒤의 "성립"이 공허할 수 있다(구현 중 확인: `i > 5`가 진입에서 실패한 라운드에서 `s == 0`의 보존이 "성립") |
