# ADR-0114: 클로저의 증명 문맥은 그것을 쓴 함수의 것이다

- 상태: 채택(자율 채택, AUTONOMY §4 "결정 기록": ADR-0096의 기본 문맥 규칙을 ADR-0053의 클로저에 적용하는 구현 수준 결정. 사람 승인 2026-11-11 "권장안 채택, 자율 실행/검증 승인"의 범위. 되돌리려면 `closures::lower`의 `closure_uses`와 `verify::default_contexts`의 `call` 갈래를 지운다)
- 날짜: 2026-11-11
- 관련: ADR-0053(함수 값), ADR-0095 A1·ADR-0096(기본 증명 문맥), DESIGN §4.1 "증명 자동화", 백로그 2V-20k

## 맥락

- 클로저는 생성된 구조체와 trait 구현으로 낮춰진다(ADR-0053). 클로저가 적은 `requires`·`ensures`는 생성된 `pre`·`post` spec fn의 본문이 되고, 몸은 생성된 `call`이 된다.
- 기본 문맥(ADR-0096)은 정의 자신의 절이 부르는 spec fn을 드러내고 그 본문 속으로는 들어가지 않는다. 그래서 `call`은 `pre`를 보지만 `pre`의 본문이 부르는 spec fn, 곧 클로저가 절에 적은 spec fn은 이름으로만 본다. 진단은 "`#[uses(small)]`를 더하라"고 하는데 클로저에는 속성을 붙일 수 없다(2V-20i 퍼저가 드러냄).
- 클로저를 쓴 함수의 `#[uses(..)]`도 `call`에 닿지 않는다.

## 결정

1. **클로저가 적은 절은 `call` 자신의 절이다.** `call`의 기본 문맥은 생성된 `pre`·`post`의 본문이 부르는 spec fn을 포함한다. 보통 함수가 제 절의 spec fn을 보는 것과 같은 규칙이다. 그 spec fn의 본문 속으로는 들어가지 않는다(ADR-0096 그대로).
2. **클로저는 그것을 쓴 함수의 `#[uses(..)]`를 물려받는다.** 생성된 `call`은 바깥 함수의 `#[uses(..)]`를 그대로 갖는다. 클로저 안의 클로저는 바깥 클로저의 `call`에서 물려받는다.
3. 함수 항목을 값으로 넘길 때 생기는 `call`은 해당 없다(그 함수 자신의 계약을 따른다).

## 근거

| 안 | 판정 |
| --- | --- |
| **절은 자신의 것, `#[uses]`는 물려받음(채택)** | Rust·Verus에서 클로저는 그것을 쓴 함수의 일부이고 같은 문맥에서 검증된다(JUDGMENT S1). 낮춤은 구현 방식이지 의미가 아니다: 사용자가 쓴 절이 낮춤 때문에 한 단계 멀어지면 안 된다(S3) |
| 클로저에 `#[uses]`를 붙이는 문법 | 새 표면이다. 물려받기로 필요가 없어진다 |
| 지금대로 | 사용자가 고칠 길이 없는 미결정·실패다(컴파일러 층 결함, JUDGMENT §3) |
| `pre`·`post` 본문을 닫힘으로 펼침 | ADR-0096이 버린 r2c와 같은 비용 문제 |

## 결과

- `closures::lower`가 바깥 함수의 `uses` 속성을 `call`에 옮기고, `verify::default_contexts`가 생성된 `call`에 `pre`·`post` 본문의 spec fn을 더한다.
- 바깥 함수의 `#[uses]`가 넓으면 클로저의 증명 문맥도 넓어진다(비용). 바깥 함수와 같은 선택이다.
- 코퍼스 `tests/verify/pass/closure_context.bmb`(절의 spec fn만으로, 물려받은 `#[uses]`로).
