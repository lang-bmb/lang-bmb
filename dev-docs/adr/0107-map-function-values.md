# ADR-0107: 맵의 함수 값: `passes` 간선, 생성 정의의 위치, `display`

- 상태: 채택(자율 채택, AUTONOMY §4 "결정 기록": ADR-0020 §1의 하위 호환 규칙 안의 추가. 여덟째 실행 계획 "2V-20f 맵 스키마 자율 채택 ADR")
- 날짜: 2026-11-10
- 관련: ADR-0020(맵 스키마), ADR-0053(클로저와 함수 값), ADR-0059(정체성), 백로그 2V-20g·2V-20h

## 맥락

- 클로저와 함수 값은 검사 전에 trait·구조체·`impl`로 낮춘다(ADR-0053, `closures::lower`). 맵은 낮춘 프로그램을 본다. 그래서 세 가지가 빠져 있었다.
  - 맵 L2에 "이 정의가 이 클로저(또는 함수 항목)를 넘긴다"는 간선이 없다. 클로저를 넘기는 정의와 클로저 몸이 맵에서 이어지지 않는다(`calls`는 받는 제네릭 함수까지만 간다).
  - 생성된 정의의 `file`·`line`이 `<generated>` 1행이다.
  - 경로가 내부 이름이다(`<u::__closure_0 as u::__fn_0_0>::call`). 진단은 2V-20g부터 `u::f::{closure#0}`로 부른다.
- 내부 경로는 바꾸지 않는다. 캐시·`--def`·정체성(ADR-0059)의 키이고, 질의 인자다.

## 결정

1. **L2 `passes`.** 함수 값을 넘기는 자리마다 간선 하나를 둔다.
   - `from`: 그 인자를 몸에 가진 정의. 가장 안쪽 것이다. 클로저 안의 클로저는 바깥 클로저의 `call`이 넘긴다.
   - `to`: 클로저의 `call`, 또는 넘긴 함수 항목 자신(`u::inc`).
   - 키는 다른 간선과 같다: `level`, `from`, `to`, `kind`.
2. **생성 정의의 위치.** `file`·`line`은 그 정의가 대신하는 원문 자리다.
   - 클로저의 구조체와 `call`·`pre`·`post`: 클로저.
   - 함수 항목의 구조체와 메서드: 그 함수의 이름.
   - 경계의 trait와 메서드: 경계 매개변수의 이름.
   - ADR-0020 §1은 위치를 "정의 이름의 위치"로 정한다. 생성 정의에는 원문 이름이 없고 `<generated>` 1행은 아무 데도 가리키지 않았다. 그래서 키의 뜻을 바꾸지 않고 빈칸을 채운다.
3. **`display`.** L0·L1 행에 키 `display`를 더한다. 진단이 그 정의를 부르는 이름(`Tables::shown`)이고, 경로와 다를 때만 둔다. 예: `u::f::{closure#0}`, `..::ensures`, `<u::inc as u::apply::F>::call`, `u::apply::F`.
4. **질의와 도구는 내부 경로를 받는다.** `display`는 읽기용이다. 질의 인자로 받는 일은 이 ADR의 범위가 아니다.

## 근거

| 안 | 판정 |
| --- | --- |
| **간선·위치·`display`를 더함(채택)** | ADR-0020 §1의 하위 호환(키 추가, `kind` 추가) 안이다. 정체성·캐시 키가 그대로다 |
| 맵 경로를 표시 이름으로 바꿈 | 키의 뜻이 바뀐다(`version` 올림). 캐시·`--def`·정체성이 함께 바뀐다 |
| `calls` 간선으로 클로저 몸을 잇기 | 넘기는 정의는 클로저를 부르지 않는다. 부르는 것은 받는 함수다. `calls` 기반 분석(W0903 등)이 틀어진다 |

## 결과

- `closures::Lowered::passes`·`at`, `Tables::passes`·`at`. 맵 `Index::build`가 간선을 넣고 위치를 고른다. `Entry`·`TypeEntry`에 `display`.
- 시험: `tests/map.rs`의 `function_values_pass_and_sit_where_written`.
- `impact` 등 질의가 `passes`를 따라갈지는 정하지 않는다. 필요가 드러나면 질의 쪽 결정으로 한다.
