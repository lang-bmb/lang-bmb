# ADR-0039: 지속 관리 체계(다축 지표, 래칫, 자립 사다리, 실용성 규칙)

- 상태: 채택 (사람 지시 2026-10-25)
- 날짜: 2026-10-25
- 관련: ADR-0034(미션 목표 G1~G6), ADR-0037(부트스트랩 필수), AUTONOMY.md, genesis §3.5(주장은 측정으로만)
- 운영 문서: `dev-docs/HEALTH.md`

## 맥락

사람의 지시(2026-10-25): 언어를 체계적으로 검증하며 목표를 달성하도록 다각도 지표로 완성도를 관리하고, 자가 검증·실용성·자기 완결성(Rust 의존 제거)을 지속 관리할 지침과 기준을 세운다.

## 결정

### 1. 다섯 축

| 축 | 질문 | 지표 출처 |
| --- | --- | --- |
| M 미션 효과 | 북극성을 달성하는가 | ADR-0034 G1~G6(벤치마크). 이 ADR은 바꾸지 않는다 |
| V 증명 신뢰 | "증명되었다"를 믿을 수 있는가, 비용이 통제되는가 | `scripts/health.py` V1~V6, 퍼저, 1B-38 |
| S 자립성 | Rust·외부 도구 의존이 줄고 있는가 | `scripts/health.py` S1~S6, §3 사다리 |
| P 실용성 | 실제 프로그램을 쓸 수 있는가, 오류가 고칠 길을 주는가 | `scripts/health.py` P1~P3, §4 규칙 |
| O 운영 | 기록·문서·절차가 일관되는가 | `scripts/health.py` O1~O2, `check_backlog.py`, `scripts/ship.sh` |

### 2. 지표와 래칫

- 기계로 셀 수 있는 지표는 `scripts/health.py`가 계산하고 게이트가 매 커밋 확인한다. 기준선은 `dev-docs/health/baseline.json`이다.
- 규칙은 네 종류다.
  - **고정:** 항상 성립해야 한다. 기준선으로도 바꿀 수 없다(예: 외부 크레이트 0, 진단 코드 전부 시험됨).
  - **래칫:** 나빠지지 않는다(예: 실행 프로그램 수, 도움이 붙은 오류 비율).
  - **예산:** 정해진 비율까지만 늘 수 있다(증명 비용 합 +10%).
  - **보고:** 값만 기록한다(포팅 착수 전의 stage0 줄 수).
- 래칫·예산을 넘는 변경은 `health.py accept --reason`으로만 기준선에 들어가고, 이유가 기준선 이력에 남는다(커밋 리뷰 대상). 외부 의존을 늘리는 변경(S2)은 이유 외에 ADR과 사람 승인이 필요하다(AUTONOMY §4 의존성 행).
- 개선되면 게이트가 알려 주고, 다음 커밋에서 기준선에 반영한다(래칫을 조인다).

### 3. 자립 사다리

ADR-0037의 끝점까지 중간 단계를 측정 가능한 칸으로 나눈다.

| 칸 | 조건 | 지표 | 시점 |
| --- | --- | --- | --- |
| L0 | 외부 크레이트 0, 외부 프로세스 {z3, clang}, 생성 바이너리는 libc만 | S1·S2·S3 고정 | 지금 ✅ |
| L1 | 통합 시험이 stage0 내부 API가 아니라 CLI로 돈다. 포팅 뒤에도 그대로 쓸 수 있다 | S5 래칫(감소만) | 4A-04 |
| L2 | stage0 기능 동결 | S4를 보고 → 예산(+2%, 버그 수정만)으로 전환 | 4D 착수 |
| L3 | BMB 컴파일러가 stage2=stage3 | S6 증가, 차등 시험 | 4E |
| L4 | Rust 툴체인은 씨앗 재현에만 필요. 게이트·CI가 cargo 없이 돈다 | 게이트 단계별 cargo 사용 0 | 4G |
| 유지 | Z3, LLVM/clang, libc, Linux는 신뢰 기반으로 남긴다. 벤치 하네스의 Python은 언어 밖 측정 도구로 두되 4G 뒤 재결정(5D-03) | S2·S3 고정 | — |

### 4. 실용성 규칙

1. **기능은 프로그램으로 보인다.** 언어 페이즈(2B~2G, 2S)는 그 기능을 쓰는 실행 프로그램(`tests/run/`, 기대 출력 포함)을 2개 이상 더해야 닫는다. 2S·4C 뒤에는 입출력이 있는 실제 도구(줄 세기, 정렬, JSON 검사 등)를 포함한다.
2. **표현 불가 원장.** 쓰려다 쓸 수 없었던 것은 `dev-docs/measurements/m1.md` §6 마찰 표에 처리와 함께 적는다. 처리 칸이 빈 항목이 있으면 페이즈를 닫지 않는다.
3. **오류는 고칠 길을 준다.** 오류 진단 중 반례·수정 제안이 붙은 비율(P3)은 래칫이다. 지금 0.46이고 2D-18이 개선 목표를 정한다.

### 5. 자가 검증 장치

- **푸시는 `scripts/ship.sh`로만 한다.** 커밋된 트리에서 게이트를 돌리고, 종료 코드가 0일 때만 푸시한다. 출력 해석이 끼어들 자리를 없앤다(미비점 7).
- **증명기 검출력**을 잰다(1B-38). 증명기·코드 생성에 의도적 결함을 넣어 게이트가 잡는 비율을 측정하고, 놓친 결함마다 시험을 더한다.
- **신뢰 기반을 명시**하고(HEALTH.md §3), 단일 솔버 위험은 두 번째 솔버 교차 확인 후보로 둔다(1B-39, 외부 도구라 승인 필요).
- **증명 비용은 벤치 부하에서도 잰다**(INF-11). 코퍼스만으로는 1B-37 같은 회귀가 보이지 않았다.

## 근거

- 통과·실패만 보는 게이트는 기준 아래로 떨어지는 순간만 알린다. 래칫은 나빠지는 방향의 변화를 모두 사람이 읽는 기록(이력의 이유)으로 바꾼다.
- 자립성은 끝점(고정점)만으로는 진행을 잴 수 없다. 사다리의 칸마다 지표가 있어야 "얼마나 왔는가"를 말할 수 있다(genesis §3.5).
- 실용성 규칙은 "기능이 있다"와 "그 기능으로 프로그램을 쓸 수 있다" 사이의 간격을 페이즈마다 메운다. 지금 실행 프로그램은 6개뿐이고 셀프호스팅(4단계)은 수만 줄 프로그램을 요구한다.
- 미비점 4의 측정은 지표 설계가 틀릴 수 있음을 보여 준다. 그래서 지표 자체도 실제 회귀로 시험하고(1B-38, INF-11), 못 잡으면 지표를 고친다.

## 결과

- 게이트에 `health`와 `health rules` 작업이 추가된다(약 9초, 병렬).
- 기준선 파일이 생기고, 의도된 악화는 이유와 함께 커밋해야 한다.
- 되돌리려면 이 ADR을 대체하는 ADR이 필요하다. 지표 추가·임계 조정은 이 ADR 범위 안의 구현 결정으로 자율 처리하고 보고한다. 단 고정 규칙의 완화는 승인이 필요하다.
