# ADR-0041: 트레이드오프 원장 (수용하는 비용, 극대화하는 축, 규칙)

- 상태: 채택 (사람 지시 2026-10-25)
- 날짜: 2026-10-25
- 관련: DESIGN.md §2(목표)·§4.1(편의 포기 원장), ADR-0034(G1~G7), ADR-0039(지속 관리), ADR-0040(전제 수정)

## 맥락

사람의 지시(2026-10-25):

> 캐시로 줄이는 것과 언어 구조적으로 테스트를 필요 없게 만드는 것은 차원이 다른 이야기다.

트레이드오프는 다음과 같이 지시되었다.

- **수용:** 언어가 배우고 쓰기 어렵다. 첫 빌드가 오래 걸린다(맵이 없음). 빌드가 다소 시간이 걸린다.
- **규칙:** 읽기·쓰기는 도구를 통한다. 코드 파일 직접 편집은 권장하지 않는다.
- **극대화:** 안정성·성능 최상, 테스트 코드 최저, AI 코딩 효율 최상(토큰 효율·탐색·쓰기 다각도), 바이너리 크기 최저, 코드 재사용 최상, 그 밖에.

DESIGN.md §4.1은 개별 문법 편의를 무엇과 바꾸는지 적는다. 그러나 언어 전체가 무엇을 내주고 무엇을 끝까지 올리는지를 한 표로 적은 곳은 없었다. ADR-0040은 반복 실행 비용을 "선택·캐시 기준선 대비"로만 주장하도록 정했다. 그런데 그 문구는 테스트를 덜 돌리는 것(실행 최적화)과 테스트가 필요 없는 것(구조적 제거)을 같은 축에 놓았다.

## 결정

### 1. 테스트 비용의 두 차원

| 차원 | 무엇을 줄이나 | 누가 | BMB의 주장 |
| --- | --- | --- | --- |
| **실행 최적화** | 있는 테스트를 덜 돌린다(선택·캐시·스케줄링) | 빌드 시스템·CI | 주장하지 않는다. 업계가 이미 한다 |
| **구조적 제거** | 테스트가 존재할 필요가 없다. 작성·유지·실행·오라클 판단이 모두 사라진다 | 언어(증명 게이트, 전함수, 효과, 계약 방화벽) | **BMB의 본래 주장** |

- 캐시된 테스트도 작성되고 유지되어야 한다. 의존이 바뀌면 다시 돈다. 판정의 강도도 테스트가 덮는 입력에 머문다.
- 구조적으로 제거된 테스트는 이 네 비용이 모두 0이다. 증명은 모든 입력을 덮는다.
- 그래서 주 지표는 **실행 횟수가 아니라 테스트 코드의 양**(G8)이다.
- 누적 실행 비용(G7·BCB)은 보조 지표다. 운영 규칙(공정한 기준선)에 따라 선택·캐시 기준선은 BCB에 남긴다. 다만 그 비교는 "구조적 제거 + 남은 테스트의 실행"이 "작성된 테스트의 최적화된 실행"보다 싼가를 보는 것이다. 업계의 회수율(40~67%)은 BMB 주장의 상한이 아니다.

### 2. 원장

**극대화하는 축.** 목표 수준과 지표를 함께 둔다. 지표가 없는 축은 주장하지 않는다.

| 축 | 수준 | 지표 | 현재 |
| --- | --- | --- | --- |
| 안정성(정확성) | 최상 | G1 건전성 위반 0, 증명 게이트, V3 | 위반 0 ✅ |
| 성능 | 최상 | G6 안전 Rust 대비 시간, 증명 기반 검사 제거 | ±5% ✅ |
| 테스트 코드 | 최저 | **G8**: 같은 숨은 판정 통과에 필요한 테스트 코드 줄 수. BMB(컴파일러가 산출한 남은 테스트 면적) 대 Rust(BRB 에이전트 테스트) | 미측정(2H-06) |
| AI 코딩 효율 | 최상 | 토큰 효율(G5 총 토큰, G7), 탐색(G4), 쓰기 1회 성공(G2), 명세 강도(G3) | 실제 모델 측정 대기 |
| 바이너리 크기 | 최저 | **G9**: 같은 프로그램의 strip 크기. 기준선: 안전 Rust(`-O`, `panic=abort`, strip). 래칫 `health.py` B1 | 벤치 7개 BMB 약 14.5KB 대 Rust 약 342KB(2026-10-25) |
| 코드 재사용 | 최상 | H-REUSE(중복·범위 초과율), `duplicates` 질의, 동형 함수 병합(3D) | 미측정(3A-07) |
| 결정론·재현성 | 최상 | V6 같은 입력 같은 출력, 재현 빌드(5C) | verify 결정론 ✅ |
| 변경 안전성 | 최상 | 계약 방화벽 무효화 범위, `impact`, H-MAINT | 미측정(1B-41) |
| 런타임 의존 | 최저 | S3 생성 바이너리는 libc만 | ✅ |
| 고칠 길(진단) | 최상 | P3 반례·수정 제안 비율 | 0.46 |

**수용하는 비용.** 줄이려고 최적화하지 않는다. 다만 관측은 하고, 극대화 축을 침해하면 원인 조사 태스크를 만든다.

| 비용 | 왜 수용하나 | 관측 |
| --- | --- | --- |
| 배우기·쓰기 어렵다(학습 안 된 표면, 장황한 명시) | 쓰기 때 한 번 치러 반복 검증·탐색을 없앤다(E3). 명시의 노동은 도구가 맡는다(`fix`·`uses`) | 쓰기 토큰. 단 **총 토큰**은 극대화 축(AI 효율)에 속한다. 쓰기 비용이 늘어도 쓰기+검증+탐색+수정의 합이 줄어야 한다(G5) |
| 첫 빌드가 오래 걸린다(맵·전체 증명) | 맵과 증명 캐시가 이후 모든 질의·빌드를 범위 비례로 만든다 | 정의당 첫 빌드 시간(INF-13) |
| 빌드가 다소 오래 걸린다(증명) | 증명이 테스트를 대체한다. 바뀐 정의만 다시 증명한다 | V4 증명 비용 예산(+10%), 증분 빌드 시간(INF-13) |
| 표현력 제한(증명할 수 없는 기능은 넣지 않음, 탈출구는 근거 필수) | 검증되지 않는 기능은 언어에 넣지 않는다(운영 규칙) | 탈출구 면적(2E) |
| 외부 툴체인 의존(Z3, LLVM) | 신뢰 기반으로 명시(HEALTH.md §3) | S2 고정 |
| 초기 생태계 부재 | 생태계는 원칙 4·6 입증 뒤(5E) | — |

**규칙.** 트레이드오프가 아니라 지킨다.

| 규칙 | 근거 |
| --- | --- |
| 읽기·쓰기는 도구를 통한다. 코드 파일 직접 편집은 권장하지 않는다 | 원칙 6. 도구가 정규형·해시·맵·증명 캐시의 일관성을 지킨다 |
| 한 가지 일에 표현 하나, 정규형 하나 | 원칙 8 |
| 탈출구는 근거 선언 필수, 미증명 면적으로 집계 | §4.1 |

### 3. 원장의 긴장 관계

- **"쓰기 어렵다(수용)" 대 "AI 효율 최상":** 판정 단위는 쓰기 한 번이 아니라 과제 전체의 총 토큰이다. 총 토큰이 Rust+테스트보다 크면(G5 반증) 수용 범위를 넘은 것으로 보고 표면·도구를 고친다.
- **"빌드 느림(수용)" 대 "테스트 최저":** 비교 단위는 빌드 시간이 아니라 빌드+테스트의 누적이다(G7).
- **"바이너리 최저" 대 "성능 최상":** 인라이닝 등 성능을 위한 크기 증가는 허용한다. 크기 래칫(B1)은 기능 없이 커지는 것을 막는다.

## 결과

- DESIGN.md §2 목표에 원장 요약을 둔다.
- ROADMAP 미션 목표에 G8(테스트 코드)·G9(바이너리 크기)를 추가한다(잠정).
- `health.py`에 B1(바이너리 크기, 예산 +5%)을 넣는다.
- 백로그에 2H-06(G8 측정), 2D-21(남은 테스트 면적 질의), INF-13(빌드 시간 관측)을 추가한다.
- ADR-0040의 반복 실행 비용 문구는 §1의 두 차원 구분을 따른다.
- 되돌리려면 이 ADR을 대체하는 ADR이 필요하다(사람 승인).
