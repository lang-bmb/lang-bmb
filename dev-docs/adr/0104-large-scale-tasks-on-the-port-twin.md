# ADR-0104: 대규모 과업 축(이해·리팩터링·과업 달성)과 그 측정 장: 포팅 쌍둥이

- 상태: 채택(사람 승인 2026-11-09 "Ok 제안 및 권장안 채택 / 대규모 코드로 갈수록 코드 이해, 리펙토링 등 과업달성 - 측정 하기 어렵겠지만 중요한 축", 종합 평가의 결정 D3)
- 날짜: 2026-11-09
- 관련: DESIGN.md §3 원칙 6·7, ADR-0037(부트스트랩, 포팅의 차등 시험), ADR-0102(G5-L), ADR-0103(증거 단계), `dev-docs/measurements/selfhost-port-map.md`(P0~P11), 백로그 3A-05·3A-06·3A-08, 2H-02

## 맥락

- BMB가 이겨야 할 곳은 큰 코드다. 맵·슬라이스·영향 질의(원칙 6·7), 정의 단위 정체성, 증분 재증명은 코드가 클수록 값어치가 커야 한다. 그러나 지금 모델 측정은 모두 정의 수십 개 규모라 그 효용이 드러날 수 없다(utility §4.2).
- 대규모 과업은 재기 어렵다. 정답(이 질문의 답, 이 리팩터링이 행동을 보존하는가, 이 기능이 맞게 들어갔는가)을 결정론적으로 만들어야 하고, 같은 기능의 공정한 Rust 비교군이 있어야 하며, 과제가 작성자의 편향을 덜 타야 한다.
- 지금 있는 것: BNB(`bench/bnb`). 생성기 작업 공간(정의 1k~10k)과 Rust 쌍둥이, 탐색·수정 과제 27개가 동결돼 있고 오라클 팔만 돌았다. 생성된 코드라 실제 코드의 구조(깊은 자료 구조, 상태, 오류 경로)가 없다.
- 4단계 포팅(ADR-0037)은 stage0(Rust, 약 5만 줄, S4)을 BMB로 옮긴다. 구성 요소마다 stage0과 같은 바이트를 내는지를 차등 시험(P0~P11)으로 확인한다. 즉 포팅이 진행되면 **같은 기능의 실제 Rust 코드베이스와 BMB 코드베이스가 쌍으로 생기고, 둘에 공통인 행동 판정기(차등 코퍼스)가 이미 있다.**

## 결정

1. **대규모 과업 축 셋을 가설로 등록한다(측정 전 등록).** 비교군은 같은 기능의 Rust 코드베이스와 표준 파일 도구(읽기, 검색, 편집, `cargo test`)다.
   - **H-COMPREHEND(이해):** 큰 코드베이스에 대한 질문(이 함수를 부르는 곳, 이 변경의 영향, 이 진단 코드가 나오는 경로, 이 불변식이 지켜지는 곳)의 정답률이 같거나 높고, 읽은 토큰이 1/3 이하다. 정답은 결정론 도구(맵·`impact`·호출 그래프)와 사람이 확인한 표본으로 만든다.
   - **H-REFACTOR(리팩터링):** 행동 보존 리팩터링(이름 바꾸기, 시그니처 변경과 호출처 갱신, 함수 추출·인라인, 단위 분할, 자료 구조 교체)의 성공률이 같거나 높고, 총 토큰이 같거나 적다. 성공은 세 가지가 모두 참일 때다: 차등 코퍼스의 출력 바이트가 같다, 증명 게이트(BMB) 또는 시험(Rust)을 통과한다, 요청 범위 밖이 바뀌지 않는다(BMB는 정의 정체성 해시, Rust는 diff 범위).
   - **H-TASK(과업 달성):** 실제 이력에서 뽑은 기능 추가·결함 수리 과제의 성공률(숨은 판정)과 G5-L(ADR-0102)이 Rust+테스트보다 같거나 낫다. 과제는 **커밋 재연**으로 만든다: stage0 이력의 커밋 하나를 쌍둥이 두 쪽에서 되돌리고, 그 커밋의 문제문(커밋 메시지와 백로그 항목)만 주고, 그 커밋이 더한 코퍼스 시험을 숨은 판정으로 쓴다.
   - 기존 가설 H-SCALE·H-SLICE·H-SPLIT·H-AMORT·H-EFFECT도 같은 장에서 잰다.
2. **주 측정 장은 포팅 쌍둥이다.** stage0의 구성 요소와 그 BMB 포트가 쌍둥이다. 판정기는 포팅의 차등 시험 그대로다. 포팅을 위해 이미 해야 하는 일이라 측정용 코드베이스를 따로 만드는 비용이 없고, 실제 코드라 합성 벤치의 구조 편향이 없다.
3. **크기 축은 포팅 진행이 준다.** 첫 측정은 P0~P3(기반 라이브러리, 렉서, 파서, 검사기) 포트가 차등 시험을 통과한 때, 다음은 P0~P7, 마지막은 전체다. 같은 과제 틀을 세 크기에서 다시 만들어 H-SCALE의 기울기를 본다.
4. **판정 힘과 공정성을 먼저 정한다.** 축마다 과제 20개 이상, qwen 3회 반복과 sonnet 1회(ADR-0103 결정 2·3). Rust 팔은 같은 문제문, 같은 모델, 같은 호출 한도, 표준 에이전트 도구다. 과제·문제문·판정은 첫 실행 전에 동결한다(ADR-0021). 쌍둥이 두 쪽 모두 같은 작성 계보(stage0을 옮긴 것)라는 편향은 보고서에 적는다.
5. **BNB는 보조로 남는다.** 포팅 전의 첫 모델 근거(ADR-0103 결정 1.5)이고, 크기를 자유롭게 바꿀 수 있는 대조(1k·3k·10k)다. 3단계의 합성 대형 코드베이스 계획(3A)은 포팅 쌍둥이 측정이 서면 범위를 다시 정한다(2H-02).
6. **3단계와 4단계는 이 장에서 합쳐진다.** 3단계 통과 기준(수천 정의 규모의 탐색·증명 비용, 여러 에이전트 편집의 정의 단위 병합)은 포팅 쌍둥이 측정으로 판정한다. 남은 3단계 페이즈의 우선순위는 2H-02가 2H-01(ADR-0103) 결과로 정한다.

## 근거

| 안 | 판정 |
| --- | --- |
| **포팅 쌍둥이(채택)** | 실제 코드, 같은 기능의 Rust 비교군, 공통 행동 판정기가 포팅 부산물로 생긴다. 커밋 재연은 실제 과제 분포를 준다 |
| 합성 대형 코드베이스만(BNB 확장) | 크기 조절은 쉽지만 생성기의 구조가 곧 결과다. 리팩터링·과업의 현실성이 없다 |
| 공개 Rust 프로젝트를 BMB로 옮겨 쌍둥이로 | 현실성은 같지만 포팅 비용이 측정만을 위해 든다. 판정기도 새로 만들어야 한다 |
| 대규모 축을 재지 않음 | 원칙 6·7과 E2(탐색 병목)의 주장이 근거 없이 남는다 |

어려운 점과 대응: 정답 만들기(이해 과제)는 결정론 도구의 결과를 정답 후보로 두고 표본을 사람이 확인한다. 행동 보존 판정(리팩터링)은 차등 코퍼스가 맡는다. 과제 현실성(과업)은 커밋 재연이 맡는다. 범위 밖 변경은 BMB에서는 정체성 해시로 정확히, Rust에서는 diff 범위로 근사한다.

## 결과

- 가설 등록부(ROADMAP)에 H-COMPREHEND·H-REFACTOR·H-TASK. 효용 보고서 §1의 효용 축에 "큰 코드에서 이해·리팩터링·과업".
- 백로그 3P(포팅 쌍둥이 측정): 다중 파일 Rust 팔 하네스, 이해 과제 생성기, 리팩터링 과제와 범위 판정기, 커밋 재연 생성기, 크기별 첫 측정. 첫 측정은 포팅 P3 통과 뒤다.
- 포팅 지도의 구성 요소 순서(P0~P11)는 바뀌지 않는다. 측정이 포팅 순서를 정하지 않는다.
