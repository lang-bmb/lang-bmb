# ADR-0141: 메모리를 가진 값의 `clone`

- 상태: 채택 (사람 승인 2026-11-15 "권장안 채택, 자율 실행/검증 승인": 동결 중의 표면 변경, ADR-0100 결정 4의 예외)
- 날짜: 2026-11-15
- 관련: ADR-0031 §1(`Vec`의 `clone`), ADR-0047 §1·§4(이동 타입, drop glue), ADR-0050(`String`), ADR-0051(메서드 호출), ADR-0091 §2(`Child`), ADR-0100(동결), `dev-docs/BACKLOG.md` 열일곱째 계획의 결정 기준, 백로그 4D-27·4D-28

## 맥락

- `clone`은 `Vec`(복사 타입 원소)과 `String`에만 있었다. 구조체·열거형·`Box`와 이동 원소의 `Vec`은 E0404였고, 안내는 "루프로 새 값을 넣어 사본을 만들라"였다.
- 포트(`4D-03b`)가 그 값을 치렀다: 구문 트리의 깊은 사본 `ast::clone_*` 86개(약 890줄)를 타입 선언에서 기계로 만들었고, 타입이 바뀌면 다시 만들어야 한다. 검사기의 본체(`4D-03d`~)는 타입·시그니처 표의 사본을 더 많이 쓴다(stage0의 `check.rs`에 `.clone()`이 수백 곳).
- 결정 기준(사람 지시 2026-11-15)은 "포트를 쓰는 에이전트가 그 코드를 쓰고 싶은가"다. 타입마다 손으로 쓰는 사본 함수는 그렇지 않다. Rust의 습관(`x.clone()`)과도 어긋난다.
- 조사 중에 건전성 결함을 찾았다(4D-27): 제네릭 함수 안의 `Vec<T>.clone()`(`T`에 `Copy` 없음)이 받아들여졌고, `T = String`으로 인스턴스화하면 버퍼만 복사해 원소를 두 번 해제했다(valgrind `Invalid free`).

## 결정

1. **`x.clone()`은 메모리를 가진 값이면 어느 타입에나 있다.** 이동 타입(ADR-0047 §1)인 구조체·열거형(`Option`·`Result` 포함)·`Box<T>`·배열, 그리고 원소가 이동 타입인 `Vec`이다. 결과는 수신자의 값 타입이고(`&T`·`&mut T` 수신자면 `T`), 원본과 같은 값이며 자기 메모리를 갖는다. 선언에 표시하지 않는다: 복사·이동이 구조로 정해지는 것(ADR-0047 §1)과 같다.
2. **만들지 않는 사본은 E0404다.** (a) `Copy` 경계가 없는 타입 매개변수를 이름에 담은 타입: 그 값이 메모리를 가질 수 있는데 사본을 쓰는 자리에서 타입을 모른다. `Vec<T>`도 같다(4D-27의 수정). `Copy` 경계가 있으면 된다. (b) `std::process::Child`를 담은 타입: 자원 하나에 소유자 하나다. (c) 복사 타입: 값으로 복사되므로 안내는 "`.clone()`을 빼라"다(전과 같다).
3. **타입의 자기 `clone`이 먼저다.** 자기 `impl`의 `clone`이나 구현한 trait의 `clone` 메서드가 있으면 그 호출이다(메서드 해석의 차례 그대로, ADR-0051).
4. **효과는 `alloc`, 명세 안에서는 E0503, 수신자는 읽힌다(이동이 아니다).** 증명에서 결과는 원본과 같은 값이다(`Vec`의 `clone`과 같은 인코딩: 새 의무도 새 공리도 없다). 타입 불변식은 같은 값이라 그대로 선다.
5. **코드 생성은 타입별 glue다.** `@"bmb_clone.<타입>"(ptr %dst, ptr %src)`가 `%dst`에 사본을 짓는다: 바이트를 복사한 뒤 메모리를 가진 부분(`Vec`의 버퍼와 원소, `Box`의 값, 구조체의 필드, 열거형 변형의 페이로드)을 다시 짓는다. 프로그램이 복제하는 타입과 그것이 담는 타입에만 낸다(복제가 없는 프로그램의 IR은 그대로다). 할당 실패는 다른 할당처럼 `abort`다.

## 근거

| 안 | 판정 |
| --- | --- |
| **구조로 정해지는 내장 `clone`(채택)** | 선언이 늘지 않고 Rust의 호출 꼴 그대로다. 증명의 뜻은 이미 있는 것(같은 값)이고, 코드 생성은 drop glue와 같은 모양이다. 포트의 사본 함수 86개가 사라진다 |
| `#[derive(Clone)]`과 `Clone` trait | Rust와 같은 표시지만 `derive`는 쓰지 않기로 했고(E0220) 복사·이동도 구조로 정한다. trait 경계(`T: Clone`)까지 가면 제네릭 코드에서도 쓸 수 있으나, 내장 trait의 사전 전달은 `Copy`·`Eq`·`Ord`와 다른 장치가 필요하다. 필요가 측정되면 그때 연다(결정 2a의 자리) |
| 그대로 두고 생성기로 사본 함수를 만든다 | 언어를 바꾸지 않는다. 그러나 타입이 바뀔 때마다 생성물을 다시 만들고, 사본 함수마다 증명 시간을 쓴다(86개). 결정 기준에 어긋난다 |
| 와일드카드 갈래도 함께 연다 | 하지 않는다. 갈래를 다 쓰는 규칙(ADR-0026)은 변형이 늘 때 빠진 자리를 컴파일러가 짚게 하는 것이고, 포트의 비용(빈 갈래)은 줄 수이지 유지 위험이 아니다 |

## 결과

- stage0: `check.rs`(`builtin_clone`·`clone_method`·`clone_blocked`), `codegen.rs`(`clone_glue`). 버전은 0.x의 MINOR 변경이다(ADR-0138: 받아들이는 프로그램이 는다).
- 표면 지문(`dev-docs/health/surface.json`): 코퍼스에서 결과가 바뀐 항목을 예외로 적는다(사유 4D-27·4D-28).
- 시험: `tests/run/clone_values`(구조체·재귀 열거형·`Box`·이동 원소의 `Vec`·`Option`·배열·자기 `clone`·`Copy` 매개변수, valgrind 깨끗), `tests/check/err/clones`, 적합성 `05/clone_owned_values`·`05/clone_not_built`.
- 포트: `ast::clone_*`를 지우고 `.clone()`으로 쓴다. 검사기가 포트로 오면(`4D-03e`) 같은 규칙을 옮긴다. 코드 생성의 glue는 `4D-05`에서 옮긴다.
