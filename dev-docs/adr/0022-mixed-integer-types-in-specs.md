# ADR-0022: 명세에서 정수 타입 혼합 허용

- 상태: 채택 (자율 채택, AUTONOMY.md §4)
- 날짜: 2026-10-24
- 관련: ADR-0017 §2, ADR-0016, 백로그 1E-05

## 맥락
벤치 프로그램을 쓰다가 드러났다. M1에는 정수 변환이 없고, 검사기는 명세에서도 `i64`와 `usize`를 한 연산에 섞지 못하게 했다. 그래서 `usize` 인덱스로 도는 루프에서 `i64` 누적값의 상한을 인덱스로 표현할 방법이 없었다(`c <= k`를 쓸 수 없음). 출력은 `print_i64`뿐이라 누적값을 `usize`로 둘 수도 없었다.

ADR-0017 §2에 따르면 명세 산술은 이미 무한 정수이고 SMT에서는 모두 `Int`다. 명세에서 타입을 나누는 것은 의미상 근거가 없는 제약이다.

## 결정
- **명세 문맥에서는** 서로 다른 정수 타입(`i64`·`u64`·`usize`)을 산술·비교에 섞을 수 있다. 혼합 산술의 결과는 정수다(검사기 내부 표기는 `i64`, 의미는 무한 정수).
- **명세 문맥에서는** `spec fn` 인자에 다른 정수 타입을 넘길 수 있다. 범위 밖 값이면 그 호출은 정의 공리의 범위 가드 밖이라 값이 정해지지 않는다(ADR-0017 §4). 그래서 건전하다.
- **실행 코드는 그대로다.** 타입이 다르면 오류다(E0401). 변환은 M1에 없다.

## 근거
- Verus의 `int` 승격과 같은 방식이다. 표면 승계(ADR-0013)와도 맞다.
- 의미가 이미 무한 정수이므로 새 증명 의무나 신뢰 기반이 생기지 않는다.

## 결과
- 실행 코드의 변환 부재는 여전히 남는다. `u64`·`usize` 값을 출력할 수 없는 문제는 2단계 "검사된 변환" 후보의 근거로 기록한다(ROADMAP 1C 관찰).
