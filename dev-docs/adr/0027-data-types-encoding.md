# ADR-0027: 데이터 타입의 증명 인코딩

- 상태: 채택 (사람 승인 2026-10-24). 구현은 2B 착수(1E-07 이후) 때. §6 반례의 내장 변형 표기(`Option::Some(992)`)는 대체됨(ADR-0026: 맨이름 `Some(992)`)
- 날짜: 2026-10-24
- 관련: DESIGN.md 원칙 4·6·9, §8.2(반례), ADR-0017·0018·0023·0026, 백로그 2B-02, 실험 `dev-docs/experiments/2B-02/`

## 맥락
ADR-0026의 구조체·열거형을 증명 게이트에 넣으려면 SMT 인코딩을 정해야 한다(ROADMAP 2B 기준 1). 후보는 둘이다.

- **(a) SMT 데이터타입:** `declare-datatypes`. 구조체는 생성자 하나, 열거형은 변형마다 생성자, 구조체 배열은 `(Array Int S)`.
- **(b) 필드 분해:** 구조체는 스칼라 항의 벡터, 열거형은 태그 `Int` + 모든 변형의 필드, 구조체 배열은 필드마다 `(Array Int Int)`(SoA).

현재 검증기(`compiler/src/verify.rs`)는 값을 `Val::S`(스칼라 항)와 `Val::A`(원소 배열 + 길이)로 들고, 대입은 항 치환이며 200자가 넘는 병합 항만 새 상수에 묶는다(`merge`, 1B-26). 의무마다 `(reset)` 후 기반을 다시 보낸다(ADR-0018).

## 실험
`python3 dev-docs/experiments/2B-02/run.py`(표준 라이브러리만, 약 7초). 손으로 설계한 생성기가 의무 하나짜리 질의를 만들고, 고정 Z3 4.15.4에 BMB와 같은 옵션(`produce-models`, `smt.random_seed`·`sat.random_seed`, `rlimit 5000000`)으로 시드 0·1·2와 시드 0 반복을 돌린다. 원자료는 `results.csv`, 표는 `results.md`. 109개 (질의, 인코딩) 묶음, 436회 실행.

| 묶음 | 내용 | 크기 |
| --- | --- | --- |
| S1 | 구조체 필드 갱신 n번 후 모든 필드 상한 | 필드 k=4·16, n=8·32·128 |
| E1 | k변형 `match`, 갈래마다 페이로드 합 | k=2·8·32 |
| E2 | `Option<i64>` 연쇄(검사된 증가) n번 | n=8·32·128 |
| E3 | `match`로 같은 값을 다시 만들어 `r == e` | k=2·8·32 |
| E4 | 불투명 `spec fn p(E)`: `p(e1) ∧ e1 == e2 ⇒ p(e2)` | k=2·8·32 |
| A1 | 구조체 배열, 루프 불변식 `∀j<i. a[j].f0 ≤ a[j].f1` 유지 | k=2·8·32 |
| A2 | `a[i].f0 = v`의 프레임(다른 원소·다른 필드 불변) | k=2·8·32 |
| A3 | `Option` 배열의 양화 불변식 유지 | — |

증명 변형(unsat 기대)과 버그 변형(sat 기대, 반례)을 함께 돌렸다. 인코딩: `adt`, `flat`(열거형의 비활성 필드를 0으로 고정한 정준형), `flatj`(E4만, 정준형 없음), `hybrid`(S1만: 매개변수는 데이터타입 상수, 기호 상태는 선택자를 잎으로 한 필드 벡터).

| --- | --- | --- | --- |
| S1 k=4, n=128 증명 | 18,666 | 842 | 1,798 |
| S1 k=16, n=128 증명 | 49,086 | 1,346 | 1,442 |
| E1 k=32 증명 | 46,894 | 80,467 | |
| E2 n=128 증명 | 42,894 | 91,361 | |
| E3 k=32 증명 | 20,824 | 74,481 | |
| E4 k=32 | 240 | 59,919 (`flatj`: **sat**, 26,503) | |
| A1 k=32 증명 | 7,618 | 6,229 | |
| A2 k=32 증명 | 5,057 | 1,759 | |
| A3 증명 | 2,491 | 2,573 | |

- **판정:** `flatj`를 뺀 모든 질의가 기대대로 판정되었고, 판정은 시드 0·1·2에서 같았다. 시드 0 반복은 판정·`rlimit`·모델 텍스트가 모두 같았다.
- **여유:** 가장 비싼 질의가 91,695로 `rlimit`의 1.8%다. 이 크기에서는 어느 쪽도 한도에 가깝지 않다.
- **시드 변동:** S1은 시드와 무관하게 같은 값이었다. 열거형 묶음은 시드에 따라 `rlimit`이 달랐다. 최대 폭은 `flat` 23%(E1 k=32 증명, 69,759~85,532), `adt` 16%(E1 k=32 버그, 46,095~53,614)다.
- **E4 `flatj`:** 정준형 없이 분해하면 의미상 같은 두 값이 비활성 필드(쓰레기 값)에서 달라, 불투명 술어의 합동을 쓸 수 없다. 거짓 반례(`e1.V1.0 = -9223372036854775810`, `i64` 범위 밖 쓰레기)가 나온다. 건전성 문제는 아니지만 완전성을 잃는다. `flat`은 비활성 필드 = 0을 모든 진입·생성 지점에서 단언해야 하며, 그 비용이 E1·E3·E4의 `flat` 비용 대부분이다.
- **반례 가독성(Z3 `get-value` 원문):** `adt`는 값 하나가 항 하나다: `(Some 992)`, `(|E::V1| 0 (- 9223372036854754570))`, `(P 1000 0 712 217)`. `flat`은 구조체 하나에 k개 항, 열거형 하나에 태그 + 모든 변형의 필드 항이 필요하고 태그로 걸러야 한다: `(|x.some| true) (|x.v| 992)`. 둘 다 컴파일러가 Rust 표기로 재조립할 수 있다(인코더가 필드 이름을 안다). 열거형은 `adt` 쪽이 재조립이 거의 없다.

### 해석
- S1의 `adt` 비용은 **갱신마다 새 데이터타입 값을 만드는 것**에서 온다. 같은 데이터타입 정렬을 쓰되 기호 상태를 필드 벡터로 든 `hybrid`는 `flat`과 거의 같다(1,442 대 1,346). 즉 구조체에서 갈리는 것은 정렬이 아니라 기호 상태의 표현이다.
- 구조체 배열에서 필드 분해는 쓰지 않은 필드의 배열을 건드리지 않는다(A2: `flat`은 `store` 하나, `adt`는 원소 전체를 다시 만든다).
- 열거형에서 필드 분해는 비활성 필드 처리 비용(정준형 단언, 태그별 동등)을 낸다. 데이터타입은 판별·동등·합동을 해법기 이론으로 처리한다.

## 결정(제안)
**곱 타입은 분해하고, 합 타입은 데이터타입으로 쓴다.**

1. **구조체 = 필드 분해.** `Val::Struct`(필드 이름 순서의 `Val` 벡터)를 추가한다. 매개변수는 필드마다 새 상수와 범위 사실(ADR-0017 §3, 사용 지점 단언). 필드 쓰기는 그 필드 항만 바꾼다. 명세 `==`는 필드별 동등의 논리곱이다. `spec fn`의 구조체 인자는 잎 필드들로 펼친다(합동이 그대로 성립한다: 구조체에는 비활성 필드가 없다).
2. **구조체 배열 = 필드별 배열.** 잎 필드마다 `Val::A`의 `elems`를 두고 길이는 공유한다. 기존 배열 인코딩(`store`·`select`, 원소 범위 사실)을 그대로 쓴다. 길이 상한은 원소 크기(필드 크기의 합)로 계산한다(ADR-0017 §3).
3. **열거형(`Option`·`Result` 포함) = 단형 데이터타입.** 인스턴스마다 하나(`|Option<i64>|`, 생성자 `|Option<i64>::Some|`). 페이로드의 구조체는 잎 필드로 펼쳐 생성자 필드가 된다. 구조체 필드가 열거형이면 그 필드는 데이터타입 정렬의 잎이다. 열거형 배열은 `(Array Int E)`.
4. **`match` = 판별자.** 갈래마다 경로 조건 `((_ is C) e)`를 쌓고 선택자로 페이로드를 묶는다. 갈래의 의무는 그 경로 조건 아래 만든다. 값은 판별자 `ite`로 병합한다(기존 `merge`와 묶기 규칙).
5. **범위 사실:** 페이로드의 정수 범위는 판별자로 가드해 사용 지점에서 단언한다(`(=> ((_ is C) e) 범위)`).
6. **반례:** Rust 표기로 재조립한다. 구조체는 필드 값으로 `Point { x: 1, y: 2 }`, 열거형은 `get-value` 결과의 생성자 이름을 `Option::Some(992)`로 바꾼다.
7. **신뢰 기반:** 새 보조 사실을 넣지 않는다. 데이터타입 공리는 Z3 내장 이론이고, 필드 분해는 정의상의 번역이다(ADR-0018 §2의 기계 증명 규칙에 해당하는 새 사실 없음). 건전성 퍼저(2B-09)가 두 인코딩의 조합을 해석기와 대조한다.

## 근거
- **비용:** 구조체 갱신 연쇄에서 분해가 6~36배 싸고(S1 증명, n=128에서 22~36배), 구조체 배열의 필드 쓰기에서 2.9배 싸다(A2 k=32). 열거형에서는 데이터타입이 1.3~3.6배 싸다(E1·E3 전 크기, E2 n=32·128. 예외로 E2 n=8은 분해가 2,455 대 3,294로 쌌다). 합동은 데이터타입에서 상수 비용이다(E4: 240 대 59,919). A1·A3은 두 인코딩이 25% 안에서 비슷했다.
- **완전성:** 분해한 열거형은 정준형 불변식을 인코더가 모든 지점에서 지켜야 합동이 성립한다(E4 `flatj`). 놓치면 거짓 반례가 생긴다(건전하지만 에이전트를 오도한다: 원칙 6 "실수를 지적한다"를 해친다). 데이터타입은 이 불변식이 필요 없다.
- **결정론·안정성:** 두 인코딩 모두 시드에 따라 판정이 바뀌지 않았고, 같은 시드의 반복 실행은 판정·`rlimit`·모델이 같았다. 이 기준으로는 둘을 가르지 못한다.
- **구현:** 구조체 분해는 기존 `Val::S`·`Val::A` 기계를 재사용한다. 데이터타입은 열거형에만 필요해 선언 생성이 좁다.
- **앞으로:** 재귀 열거형(목록·트리, 힙과 함께 2G)은 데이터타입만 표현할 수 있다. 열거형을 처음부터 데이터타입으로 두면 그때 인코딩을 바꾸지 않는다.

검토한 대안: (a) 전부 데이터타입: 구조체 갱신·필드 쓰기 비용(S1·A2), 매개변수 범위 사실이 선택자 항으로 바뀌는 것 외에 이득이 없다. (b) 전부 분해: 열거형의 정준형 부담과 비용(E1~E4). `hybrid`(구조체도 경계에서는 데이터타입 정렬, 내부는 필드 벡터)는 S1에서 분해와 비슷했다. `spec fn` 인자가 필드 수만큼 늘어 질의가 커지는 것이 문제가 되면 이쪽으로 옮긴다.

## 결과
- 2B-05는 이 인코딩을 구현한다(사람 승인 후). `--emit-smt` 스크립트에 `declare-datatypes`가 들어가고, 질의 텍스트 결정론(1B 기준 4)은 선언을 경로순으로 내보내 유지한다.
- 기저 인스턴스 재시도(ADR-0023)가 데이터타입 항을 담은 술어 적용도 다뤄야 한다. 2B-05에서 확인한다.
- 이 실험의 한계: 질의는 손으로 설계한 인코딩이지 컴파일러 출력이 아니다. 크기가 작아 모두 한도의 2% 아래다. 비선형 산술, 트리거가 선택자에 걸리는 양화 공리, 중첩 데이터 타입은 다루지 않았다. 2B-05 이후 코퍼스와 `stability`(1B-19)·`rlimit_max`(1B-15)로 다시 측정한다.
