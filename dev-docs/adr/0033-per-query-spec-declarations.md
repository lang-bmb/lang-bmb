# ADR-0033: 질의마다 닿는 `spec fn` 선언만 보낸다

- 상태: 채택(자율)
- 날짜: 2026-10-24
- 관련: ADR-0018 §1, ADR-0032(증명 키의 "질의 머리" 행을 대체), DESIGN.md §4.1·§8.1, 백로그 2D-14

## 맥락
모든 의무의 질의는 프로그램의 모든 `spec fn` 선언을 머리에 담았다(`verify::header`). 그래서 `spec fn` 하나를 더하거나 시그니처를 바꾸면 모든 질의 텍스트가 바뀌어 증명 캐시(키: 질의 텍스트)도 증분 캐시(키에 머리 해시)도 전부 놓쳤다(ADR-0032 결과의 한계). DESIGN.md §4.1은 무관한 문맥을 해법기에 보내지 않는 것을 증명 안정성의 수단으로 든다.

## 결정
- 질의 머리는 옵션(시드, `rlimit`)과 전주곡만이다(`verify::query_header`).
- 의무마다 그 뒤에 보내는 텍스트(펼친 정의, 지역 선언, 가정, 부정된 목표)가 기호 `|경로|`로 언급하는 `spec fn`만, 경로 순서로 선언한다(`verify::needed_decls`). 펼친 정의는 이미 본문이 부르는 정의까지 닫혀 있으므로(`relevant_axioms`) 한 번 훑으면 된다. 기저 인스턴스 재시도(1B-14)는 그 재시도 텍스트로 따로 고른다. W0901 충족 가능성 질의도 같다.
- 증분 키(ADR-0032)의 "질의 머리" 행은 다음 두 행으로 바뀐다.

| 요소 | 이유 |
| --- | --- |
| 질의 머리(옵션·시드·`rlimit`·전주곡)의 해시 | 모든 질의에 그대로 들어간다 |
| 정의의 한정 정규형에서 출발해, 실행 피호출자는 계약(서명·절·`#[uses]`) 텍스트를, `spec fn`은 전체 텍스트를 따라 닿는 모든 `spec fn`의 SMT 선언 | 질의의 기호는 정의 자신, 피호출자 계약, 펼친 본문(재귀 성분의 측정식 포함)에서만 오므로 질의가 선언할 수 있는 것을 모두 덮는다(과대 근사) |

## 근거
- 판정 불변: 코퍼스 전체(`tests/check`·`tests/verify`·`tests/run`의 31개 파일, m1·m1b 시드)에서 `bmb verify` 출력이 이전 바이트와 같다. 판정뿐 아니라 `rlimit` 수치도 같다(합 12,455,584, 최대 5,000,190 그대로). Z3는 쓰지 않는 선언에 자원을 쓰지 않는다. m1·m1b 오라클·약한 에이전트 실행 기록도 판정 필드가 같다. `tests/stability.rs` 통과.
- 질의 크기: m1b 시드의 `--emit-smt` 스크립트 합계 1,987,446 → 746,728바이트, `spec fn` 선언 줄 21,294 → 707.
- 증분 키는 텍스트로 닿는 집합을 쓰므로 실제 질의보다 넓다. 넓으면 불필요한 재인코딩만 생기고, 좁으면 같은 키에 다른 질의가 나와 건전성이 깨진다. `tests/incremental.rs`의 감사 모드(적중해도 다시 계산해 스크립트 해시 비교)가 편집들(명명된 새 `spec fn` 포함)에서 불일치 0을 확인한다.
- 대안: 질의별 선언 집합을 키에 정확히 넣기. 인코딩 전에는 알 수 없다(인코딩을 건너뛰는 것이 목적). 기각.

## 결과
- 무관한 `spec fn`을 더하거나 빼도 다른 정의의 질의 텍스트는 바이트 단위로 같고, 증명 캐시와 증분 캐시가 모두 적중한다(`tests/incremental.rs`의 `adding_an_unrelated_spec_fn_reencodes_nothing`: 다시 인코딩·IR 생성 0).
- `spec fn`의 시그니처 변경은 그 선언에 닿는 정의만 다시 인코딩한다. `impact`의 `names` 간선(직접 명명)보다 넓을 수 있다(피호출자 계약이 그것을 부르는 경우).
- ADR-0018 §1의 "기반(옵션, 정의, 공리, 선언)"에서 선언은 이제 의무마다 다르다. 의무 격리는 그대로다.
