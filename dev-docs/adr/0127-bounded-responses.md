# ADR-0127: 에이전트 경계의 응답은 바이트 예산 안의 창이다

- 상태: 채택(사람 승인 2026-11-12 "권장안 채택/승인", 백로그 `2D-38`의 권장안)
- 날짜: 2026-11-12
- 관련: ADR-0020(맵과 질의), ADR-0021(동결 집합), ADR-0068(압축 뷰), ADR-0070(측정 조건), `compiler/src/map.rs`의 `bound`, `compiler/src/mcp.rs`, 백로그 2D-17·2D-38

## 맥락

- 질의 범위(`2D-17`) 뒤에도 큰 응답이 남는다. N=10,000 작업 공간(`bench/m3/gen.py --defs 10000`, 단위 500개)에서 범위 없는 `units` 1,192,293바이트(10,501행), `edges DEF both 64` 2,596,064바이트(36,474행), `status` 2.5MB. 범위 없는 `status`는 qwen 세션을 끝냈다.
- 범위가 있는 응답은 작다(`units m0` 2,355바이트, `status m0` 5,253바이트). 문제는 시작점(무엇이 있는지 모를 때의 `units`), 본래 큰 답, 그리고 여전히 부를 수 있는 범위 없는 꼴이다.
- 행 크기는 33바이트에서 9KB까지라 행 수로는 응답 크기를 묶지 못한다.

## 결정

1. **창.** 응답(JSONL)의 창은 `offset`번째 행부터, 예산(바이트) 안에 드는 온전한 행들이고 `limit`행을 넘지 않는다. 첫 행은 예산을 넘어도 나온다(어느 `offset`에서나 앞으로 간다). 맵 머리 행도 행이다.
2. **잘림은 기록된다.** 창이 응답 전체가 아니면 마지막에 한 행이 붙는다: `{"truncated":true,"offset","shown","rows","bytes"}`, 남은 행이 있으면 `"next"`(이어 받을 `offset`)와 `"hint"`(범위·`overview`·깊이·간선 종류로 좁히라는 안내). 전체가 창에 들면 응답은 그대로다(같은 바이트).
3. **에이전트 경계에만 건다.** `bmb mcp --bounded`가 `query`·`map`의 결과를 예산 32,768바이트의 창으로 주고, 두 도구가 `offset`·`limit` 인자를 받는다. 도구 설명은 잘림 행, `overview`, 범위 인자, `edges`의 종류 인자를 말한다. 플래그가 없으면 도구 목록과 응답은 그대로다(동결 집합, ADR-0021). CLI는 선택이다: `bmb query|map --budget BYTES --offset ROWS --limit ROWS`.
4. **`overview [PATH..]`.** 단위마다 한 행, L0 단위 행의 목록(`units`·`defs`)을 개수로 바꾸고 `types` 개수를 더한다. 행 크기가 단위의 크기와 무관하다.
5. **예산은 압축 뷰 전의 JSONL 바이트로 센다.** `--compact`의 뷰는 JSONL보다 작으므로 상한이 유지되고, 창은 뷰와 무관하게 같은 행들이다.

## 근거

| 안 | 판정 |
| --- | --- |
| **바이트 예산의 창과 잘림 행, 이어 받기(채택)** | 응답 크기의 상한이 작업 공간 크기와 무관하다. 잘린 사실과 전체 크기를 에이전트가 안다. 창은 응답 본문의 순수 함수라 결정론이 유지되고, 창들을 이으면 전체와 같다(시험) |
| 행 수 상한 | 행 크기가 270배까지 달라 바이트를 묶지 못한다 |
| 범위 없는 꼴을 거부 | 시작점이 없어진다. 작은 작업 공간에서는 범위 없는 꼴이 가장 싼 답이다 |
| 조용히 자른다 | 없는 것을 없다고 읽게 된다(틀린 답) |
| CLI에도 기본으로 | CLI의 소비자는 스크립트와 게이트다. 출력이 바뀌면 그쪽이 깨지고 얻는 것이 없다 |

측정(N=10,000, 예산 32,768): `units` 1,192,293 → 첫 창 32,903바이트(37창), `edges m0::all_inb both 64` 2,596,064 → 32,967(80창), `overview` 67,313바이트(501행, 단위당 134바이트, 3창), `duplicates` 120,437(4창), `effects` 37,409(2창). 범위 있는 응답(`units m0`, `status m0`)은 창 하나에 그대로 든다.

## 결과

- 예산 32,768은 참고값이다. 실제 모델에서의 기본값(성공률과 토큰)은 `--bounded`로 동결한 집합에서 잰다(백로그 `2D-39`, 측정 머신). 그때까지 주장하지 않는다.
- `verify`·`write`의 응답(진단과 상태 줄)은 창에 들지 않는다. 그 크기는 다른 원인(상태 줄, ADR-0068)이고 따로 본다.
- 이어 받는 사이에 작업 공간이 바뀌면 창들이 서로 다른 응답에서 온다. `rows`·`bytes`가 달라지는 것으로 드러난다.
- 플래그 하나가 는다(ADR-0120: 표면은 가설을 따른다). 판정 뒤 기본값으로 올리거나 지운다.
- 2026-11-13(`2D-39a`): 예산 두 값을 비교하려고 `--bounded-16k`(같은 창, 16,384바이트)를 더했다. 동결 판은 `bench/bnb-bounded`·`bench/bnb-bounded-16k`다. `2D-39`의 판정 뒤 둘 중 하나만 남기거나 둘 다 지운다.
