# ADR-0081: 한 갈래에서만 옮긴 값은 다른 갈래 끝에서 정적으로 해제한다

- 상태: 채택 (사람 승인 2026-11-01 "권장안 채택, 승인사항 승인": 백로그 2O-07의 권장). ADR-0031 §2의 합류점 규칙("아마 이동이면 E0414")을 `if`·`else`와 `match`의 합류점에서 바꾼다. ADR-0047 §2(소유 타입의 이동)도 같은 규칙을 따른다
- 날짜: 2026-11-02
- 관련: ADR-0031 §2·열린 질문 3, ADR-0047 §2, ADR-0049 §4(`return`의 해제), 백로그 2O-06·2O-07

## 맥락

- ADR-0031 §2: 분기 합류점과 루프 머리에서 변수는 "확실히 초기화"이거나 "확실히 이동"이어야 하고, "아마 이동"이면 E0414다. 해제 지점이 정적으로 정해지고 실행 시 해제 플래그가 없게 하려는 규칙이다.
- 실제 프로그램에서 걸렸다. `tests/run/calc`(2O-06)의 `parse`는 오른쪽 피연산자가 없으면 왼쪽 트리 `a`를 버리는데, 그 갈래는 `a`를 옮기지 않아 E0414가 났다. 우회는 `let unused: Box<Expr> = a;`였다. Rust는 이 프로그램을 받는다.
- Rust는 "아마 이동"된 값을 실행 시 drop 플래그로 해제한다. BMB는 그 플래그를 두지 않는다(DESIGN §4.1 이동 상태 행).

## 결정

1. `if`·`else`와 `match`의 합류점에서 값(지역, 그 필드 경로)이 어떤 갈래에서는 옮겨지고 다른 갈래에서는 아직 소유되어 있으면, **소유하는 갈래마다 그 갈래의 끝에서 해제**하고 합류 뒤에는 옮겨진 것으로 본다. 해제 지점은 프로그램 텍스트로 정해진다(그 갈래의 값을 계산해 담은 뒤). 실행 시 플래그는 없다.
2. 갈래가 자신의 끝을 갖지 않는 합류점은 그대로 E0414다. `else` 없는 `if`(블록을 건너뛰는 길), `&&`·`||`·`==>`의 오른쪽, 루프 머리(돌아오는 길과 머리)가 그렇다. 루프 머리의 "아마 이동"을 해제로 메우려면 회차마다 다른 해제가 필요하다(ADR-0031 §2 그대로).
3. 부분 이동(2O-03)도 같다. 한 갈래가 필드 `s.a`를 옮기면, 다른 갈래는 끝에서 `s.a`를 해제하고, 나머지 필드는 블록 끝에서 지금처럼 해제된다.

## 근거

- **원인과 귀속 층:** Rust가 받는 프로그램을 받지 못하는 제한이고, 원장(DESIGN §4.1)이 포기한 것은 "실행 시 drop 플래그"이지 이 프로그램이 아니다(JUDGMENT §7). 층은 컴파일러(이동 검사와 코드 생성)다.
- **정석:** Rust는 해제를 범위 끝에 두고, 그 지점에서 상태가 갈래에 따라 다르면 drop 플래그로 가른다. 상태가 정적으로 정해진 지점의 플래그는 drop elaboration이 지운다. BMB는 플래그를 두지 않으므로, 상태가 갈래마다 정해진 이 경우에 해제를 그 갈래의 끝으로 당긴다. 그러면 범위 끝에서는 모든 길에서 "이동"이 되어 플래그가 필요 없다.
- **관찰되지 않는 해제 시점:** BMB에는 사용자 `Drop`이 없어서(ADR-0047) 해제를 합류 직전으로 당겨도 프로그램이 관찰하는 것이 바뀌지 않는다. 증명도 해제를 모형화하지 않으므로 바뀌지 않는다.

## 결과

- 코드: `moves::Mv::join_branches`(`if`·`else`와 `match`의 n갈래 합류, `MoveInfo::branch_drops`에 갈래 끝의 해제), `codegen`의 `drop_branch`(갈래의 값을 담은 뒤 해제).
- 시험: 실행 프로그램 `tests/run/branch_drops.bmb`(`if`·`else`, 세 갈래 `match`, 필드 하나), `tests/run/calc.bmb`의 우회를 지움. 둘 다 valgrind(`--leak-check=full`)가 깨끗하고 출력이 기대와 같다. 검사 코퍼스: `tests/check/err/boxes.jsonl`·`moves.jsonl`·`owned_fields.jsonl`에서 `if`·`else`와 `match`의 E0414 다섯이 사라지고, `else` 없는 `if`(`moves.bmb`의 `no_else`), `&&`, 루프의 E0414는 남는다.
- 측정 조건: 컴파일러 트리가 바뀌므로 새 조건이다(ADR-0070 (a)). 이전에 E0414로 거부되던 프로그램만 다르게 처리된다.
- 되돌리기: `join_branches`를 2갈래 `join`(E0414)으로 바꾸면 ADR-0031 §2 그대로다.
