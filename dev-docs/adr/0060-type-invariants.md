# ADR-0060: 타입 불변식: 가시성 대신 경계에서 증명하는 자료 불변식

- 상태: 제안 (초안 작성은 사람 승인 2026-10-28, 채택은 별도 승인. 언어 범위 확대, AUTONOMY §4)
- 날짜: 2026-10-28
- 관련: `dev-docs/reviews/direction-2026-10-28.md` §3·§6.2(H-ENCAP), ADR-0015(2차 참조), ADR-0017 §4(불투명 `spec fn`), ADR-0026·0027(데이터 타입), ADR-0032·0043(증분 키), ADR-0046(제네릭), ADR-0047(소유 타입), ADR-0055(참조 `match`), DESIGN.md 원칙 7, §4.1

## 맥락
- BMB에는 가시성이 없다. `pub`가 없고 다른 단위의 정의는 전체 경로로 부른다(`compiler/README.md` "구성 단위"). 어느 단위의 어느 함수든 구조체 필드를 읽고 쓸 수 있다.
- 그래서 자료 구조의 불변식은 타입의 성질이 아니다. 그것을 선언한 함수들의 계약일 뿐이다.
  - 예: `tests/run/generic_stack.bmb`의 `Stack<T>`는 `len <= 8`을 `new`·`push`·`pop`의 `requires`·`ensures`(`room`, `some`, `pushed`, `popped`)로 함수마다 다시 쓴다.
  - 이 계약을 쓰지 않은 새 함수는 `s.len = 100`인 값을 만들어 돌려줄 수 있다. 그 값을 받는 함수는 아무것도 가정할 수 없다.
- Rust는 이 문제를 가시성(private 필드 + 생성자)으로 푼다. 불변식 자체는 주석과 테스트로 지킨다.
- 방향성 논의(H-ENCAP)의 질문은 이렇다. 도구로만 접근하고 증명 게이트가 있는 언어에서 불변식 보호는 "누가 쓸 수 있나"(가시성)로 할 것인가, "쓴 결과가 맞나"(증명)로 할 것인가.
- 이미 있는 선례: 정수 타입의 범위가 BMB의 내장 타입 불변식이다.
  - 인코더는 새 기호를 만들 때마다 그 타입의 범위를 가정한다(`verify.rs:2143`의 `fresh_val`이 `range(t, &c)`를 경로 조건에 넣음).
  - 범위를 벗어날 수 있는 연산마다 의무를 낸다(E0803).
  - 사용자 타입에는 이 장치가 없다.

## 선례 (JUDGMENT S1 순서)

| 출처 | 방식 | 비고 |
| --- | --- | --- |
| Rust | private 필드 + 생성자·메서드로만 변경. 불변식은 주석·테스트 | 보호는 "누가"로 한다. 맞는지는 증명하지 않는다 |
| Verus | `#[verifier::type_invariant]`를 붙인 `spec fn`. 생성식 뒤, 필드 대입 뒤, 그 값의 `&mut`을 받는 호출 뒤에 성립해야 한다. 쓰는 쪽은 `use_type_invariant(&x)`로 가정을 꺼낸다. 불변식을 잠시 깨는 것은 지원하지 않는다(교환으로 우회) | [레퍼런스](https://verus-lang.github.io/verus/guide/reference-type-invariants.html), [컨테이너 예](https://verus-lang.github.io/verus/guide/container_bst_type_invariant.html). 이 환경에서 원문이 열리지 않아 검색 요약으로 확인했다(원문 미확인). 가시성 요구 여부는 확인하지 못했다 |
| Creusot | 타입 불변식을 함수 경계에서 가정·검사 | [가이드](https://creusot-rs.github.io/creusot/guide/type_invariants.html), 원문 미확인 |
| Dafny | 관례 술어 `Valid()`를 모든 메서드의 `requires`·`ensures`에 쓰고, 유령 필드 `Repr`로 프레임을 잡음 | 언어 장치가 아니라 관례다. BMB의 현행(안 a)과 같은 꼴 |
| Ada 2012/SPARK | `Type_Invariant`는 private 타입에만 붙고, 패키지 공개 연산의 경계에서 검사 | [ARM 7.3.2](https://docs.adacore.com/live/wave/arm12/html/arm12/arm12-7-3-2.html). 가시성과 묶인 설계 |
| Spec#/Boogie | 소유 방법론. 객체마다 "유효/열림" 상태(pack/unpack)를 둔다 | 힙에 저장된 참조를 통한 별칭 때문에 필요하다. 다른 객체가 내 내부를 가리키고 바꿀 수 있기 때문이다 |

**관찰.** 가시성이나 pack/unpack이 건전성에 필요한 이유는 둘이다.

1. 검사를 공개 연산의 경계에만 두는 설계(Ada).
2. 저장된 참조를 통한 별칭(Boogie).

BMB에는 둘 다 없다.

- 참조는 인자 자리에만 있고 저장·반환되지 않는다(ADR-0015).
- 그래서 어떤 값을 바꿀 수 있는 것은 그 값을 소유한 함수, 또는 유일한 `&mut`을 받은 함수 하나뿐이다.
- 그 함수가 값을 내보내는 길은 모두 텍스트로 보이는 경계다(호출 인자, 반환, `&mut` 매개변수의 함수 끝).

## 결정

### 1. 표면
```rust
#[invariant(fits)]
struct Stack<T: Copy> { items: [T; 8], len: usize }

spec fn fits<T: Copy>(s: &Stack<T>) -> bool { s.len <= 8 }
```
- 속성 `#[invariant(p)]`는 구조체와 열거형에 붙는다.
  - `p`는 그 타입 하나를 받아(`x: &T`) `bool`을 돌려주는 `spec fn`이고, 이름 붙은 술어 규칙을 따른다(본문이 `true`면 거부).
  - 제네릭 타입이면 `p`는 같은 타입 매개변수를 받는다.
  - 속성은 타입마다 하나다. 여러 조건은 술어 하나에 `&&`로 묶는다(정규형 하나).
- **속성은 타입 쪽에 둔다.** Verus는 표시를 술어 쪽에 둔다. 타입 정의는 그 타입을 쓰는 모든 슬라이스와 맵 L1 타입 표면에 들어가므로, 불변식이 타입과 함께 보인다(원칙 5, DESIGN §7.2 타입 능력 뷰).
- **술어는 다른 `spec fn`처럼 불투명하다(ADR-0017 §4).** 가정은 `fits(x)` 원자로 들어온다. 내용을 쓰려면 `#[uses(fits)]`가 필요하다(`bmb uses`가 채운다).

### 2. 의미: 새 값은 유효하다고 가정하고, 잊는 값은 유효해야 한다
타입 `T`의 깊은 유효성 `valid_T(x)`를 인코더가 만든다.

- `T`의 불변식과, 필드·페이로드·`Box` 내용·`Vec` 원소 전부(양화, `select`에 트리거)의 깊은 유효성을 합친 것이다.
- 불변식이 없는 타입은 그 부분이 `true`다.
- 재귀 타입에서는 재귀 `spec fn`처럼 불투명한 정의와 펼침 공리로 들어간다(ADR-0023 지상 인스턴스).

| 지점 | 가정 | 의무 |
| --- | --- | --- |
| 함수 진입: 매개변수(값, `&`, `&mut`) | `valid_T(p)` | — |
| 호출: 인자(값, `&`, `&mut`) | — | `valid_T(arg)` (E0823) |
| 호출 뒤: 결과, `&mut` 인자 자리의 새 값 | `valid_T` | — |
| 함수의 모든 출구(꼬리, `return`, `?`): 결과와 `&mut` 매개변수의 현재 값 | — | `valid_T` (E0823, 사후조건 검사 `post_check`와 같은 곳) |
| 루프 머리에서 havoc되는 지역 | 머리에서 `valid_T` | 들어갈 때와 매 반복 끝에서 `valid_T` (E0823, 함축 불변식) |

- 이것은 정수 범위가 하는 일(새 기호에서 가정)을 사용자 술어로 넓힌 것이다. 다른 점은 의무를 연산이 아니라 **값을 잊는 지점**에 둔다는 것이다.
- 함수 몸 안에서는 불변식을 잠시 깨도 된다.
  - 예: `self.len = self.len + 1` 뒤에 `self.items[..] = x`.
  - 지역과 `&mut` 매개변수는 그 함수만 볼 수 있으므로 건전하다(ADR-0015).
  - Verus가 우회로 쓰는 "교환으로 잠시 비우기"가 필요 없다.
- `std::mem::replace`·`swap`, 필드·원소 대입, `match`의 `&mut` 바인딩(ADR-0055)을 통한 쓰기는 의무를 만들지 않는다. 결과는 위 경계 중 하나에서 확인된다.
- `spec fn`과 명세 안의 값에는 가정이 붙지 않는다(Verus와 같음). 계약은 가정된 매개변수 위에서 계산되므로 `requires fits(s)`를 다시 쓸 필요가 없다.
- 제네릭 함수 안에서 `T`의 유효성은 해석되지 않는 술어 `valid_T`다. 같은 지점에서 가정·의무가 되고, 값을 옮기기만 하는 코드에서는 프레임으로 끝난다.
- 런타임 비용은 없다. 의무가 증명되지 않으면 바이너리가 없다(원칙 4).

### 3. 증분 키와 맵
- 증분 키는 이미 정의가 닿는 타입의 정의 줄(`incremental.rs:719`~`728`, `type` 행)을 담는다. 그 줄에 불변식 속성을 넣고, 술어의 본문 해시를 키에 더한다(ADR-0032 "인코딩이 읽는 것 전부").
- 불변식을 바꾸면 `T`를 쓰는 모든 정의의 의미가 바뀐다. `impact`는 타입 정의 변경을 `T`가 나오는 정의 전부로 넓힌다.
- 맵 L1의 타입 표면에 불변식 이름을 싣는다.

## 근거 (JUDGMENT §10)
1. **문제:** 자료 불변식이 타입의 성질이 아니다. 계약을 빠뜨린 함수가 깨진 값을 만들어도 막을 장치가 없고, 지키는 함수들은 같은 계약을 되풀이한다(`generic_stack`).
2. **원인과 귀속 층:** 언어. 정석 해법(불변식을 가진 추상 자료형)을 표현할 수 없다(JUDGMENT §3 둘째 행).
3. **정석 해와 출처:** Rust는 가시성이다. 검증 언어(Verus, Creusot, Ada/SPARK)는 타입 불변식이고, 일부는 가시성과 함께 쓴다.
4. **후보 비교:**

| 안 | C1~C4 | 평가 |
| --- | --- | --- |
| (a) 현행: 불변식을 함수마다 `requires`·`ensures`로(Dafny `Valid()` 관례) | 통과 | 타입 수준 보장이 없다(S2 실패). 계약 반복으로 토큰이 늘고(S4), 빠뜨림은 증명 실패로만 드러난다 |
| (b) 가시성(`pub`/private) | 통과. 단 C4와 긴장: 단위·파일에 의미를 준다(원칙 7) | Rust 표준(S1-a). 그러나 "누가 쓰나"를 줄일 뿐 "맞나"는 여전히 테스트나 (a)다. 에이전트는 접근자 우회를 써야 한다 |
| (c) **경계에서 증명하는 타입 불변식(권장)** | 통과 | 검증 언어 표준(S1-b). 같은 부류 전체를 푼다(S2). 정수 범위와 같은 장치이고, 가시성이라는 두 번째 개념이 없다(S3). 계약 반복이 없다(S4) |
| (d) (b)+(c) | 통과. 단 C4 긴장은 (b)와 같다 | 검증 언어에서 가장 흔한 조합(Ada, 아마 Verus)이다. 그 조합에서 가시성이 맡는 몫은 "검사를 공개 경계에만 둔다"와 "별칭"인데, BMB에는 둘 다 없다(위 관찰) |

5. **권장과 결정적 기준:** (c).
   - S1에서는 (d)가 검증 언어 선례에 가장 가깝다.
   - 그러나 (d)의 가시성이 건전성에 하는 일을 BMB에서는 2차 참조(ADR-0015)가 이미 한다. 그래서 S3(개념 경제)과 C4(원칙 7: 단위는 의미를 갖지 않음)에서 (c)가 이긴다.
6. **영향(정보):**
   - 파서·검사기·인코더(`fresh_val`·`call`·`post_check`·루프 havoc), 증분 키, 맵 L1, `impact`가 바뀐다.
   - 기존 코퍼스의 반복 계약(`generic_stack`의 `room`·`fits` 계열)은 `bmb fix` 대상이 아니라 손 이주 대상이다. 의미가 다르기 때문이다(계약은 함수의 약속, 불변식은 타입의 약속).
7. **필요한 승인:** 언어 범위 확대(AUTONOMY §4)라 채택은 승인이 필요하다.

**(c)가 잃는 것(정직하게):** 가시성의 협업 몫(K), 곧 표현을 숨겨 안정 API를 두는 일은 대신하지 못한다. 에이전트가 내부 필드에 직접 기대면 표현을 바꿀 때 바꿀 곳이 많아진다. 이 비용은 증명으로 안전해지지만 줄지는 않는다. 계약 방화벽과 `impact`가 범위를 보여 줄 뿐이다. 이 몫이 측정에서 문제가 되면 별도 장치(필드 직접 접근 린트 등)를 따로 정한다. 열린 질문 1.

## 결과
- **DESIGN §4.1 원장에 더할 행:**

  | 영역 | Rust·Verus가 허용한 편의 | BMB | 얻는 것 |
  | --- | --- | --- | --- |
  | 보호 | 가시성(`pub`/private)으로 자료 불변식을 모듈 경계에서 지킴. 불변식은 주석·테스트 | 가시성 없음. 불변식은 타입에 붙은 이름 붙은 술어이고 모든 경계에서 증명된다 | 불변식이 맵(L1 타입 표면)에 남고, 어느 정의가 고쳐도 게이트가 지킨다. 계약 반복 제거. 단위가 의미를 갖지 않는다(원칙 7) |

- **H-ENCAP 측정:**
  - **모델 필요(BRB 확장):** 자료 구조 수정 과제를 만든다(정렬 집합, 고리 버퍼, 구간 목록, 최소 힙). 각 과제에 숨은 불변식 판정을 둔다. BMB 팔(타입 불변식)과 Rust 팔(private + 테스트)의 "통과 & 숨은 불변식 위반" 비율을 비교한다. 반증 조건: BMB 팔에서 위반이 게이트를 통과한다.
  - **결정론 부분:** 코퍼스에서 불변식 이주로 없어지는 계약 절 수와 토큰.
- **제안 태스크(ID는 백로그에서):**
  1. 검사·표면: `#[invariant(p)]` 파싱·정규형·E0254·E0255, 맵 L1 표시, 슬라이스에 술어 포함.
  2. 인코딩: `valid_T` 생성(깊은 유효성, 재귀·`Vec`·`Box`, 제네릭은 불투명), 가정 지점(`fresh_val` 계열), 의무 지점(호출 인자, 출구, 루프 havoc), E0823과 반례.
  3. 증분 키·`impact`: 타입 줄에 속성, 술어 본문 해시. `incremental` 감사 시험으로 확인.
  4. 코퍼스: `verify/pass`·`fail`(경계별 반례)·`check/err`·`run`(고리 버퍼, 정렬 집합). `generic_stack`을 이주하고 줄어든 계약 수를 보고.
  5. 퍼저·검출력: `soundness_data`에 무작위 불변식을 넣는다. 게이트 검출력 변이체를 더한다(`&mut` 출구 의무 빠뜨림, 루프 진입 의무 빠뜨림, 인자 의무 빠뜨림).
  6. BRB 확장 과제(H-ENCAP). 실행은 측정 트랙(T0).

## 열린 질문
1. 가시성의 협업 몫(표현 숨김)이 측정에서 비용으로 드러나면 어떤 장치로 할 것인가.
2. 깊은 유효성의 증명 비용: `Vec<S>` 원소 양화와 재귀 타입 펼침. V4·V7로 재고, 비싸면 얕은 유효성 + 꺼낼 때 가정으로 바꾸는 안을 비교한다.
3. 루프를 건너 불변식을 깨 두는 코드(반복 사이에 깨진 상태 유지)가 실제로 필요한지. 지금 안은 루프 머리에서 유효성을 요구한다.
