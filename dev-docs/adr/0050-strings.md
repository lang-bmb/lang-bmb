# ADR-0050: `String`·`&str`·`char`

- 상태: 채택 (2026-10-26, 사람 승인 "1/2 채택, 승인", 백로그 2V-12)
- 날짜: 2026-10-26
- 관련: ADR-0045, ADR-0044(바이트·바이트 문자열, 일부 대체), ADR-0015, ADR-0047(소유 타입), 점검 R10, 백로그 2V-10


## 채택 시 확인 (2026-10-26)
- 진단 번호: E0820 문자 경계·UTF-8 불변식 의무(비어 있음 확인). E0234(식의 `"..."` 거부)는 구현과 함께 은퇴한다. E0101의 `b'a'` 교체와 E0402의 `String`·`str`·`char` 교체는 없어진다.
- 열린 질문 1(문자 보기 `Seq<char>`)은 필요가 생길 때. 2(문자 순회)는 4B 표준 라이브러리에서 정한다.
- 구현 페이즈: ROADMAP 2U(문자열). 소유 타입(2O) 뒤.

## 구현 시 확인 (2026-11-05, 백로그 2U-01~05)
- **낮춤:** 증명기와 코드 생성기는 텍스트를 바이트로 본다(`Tables::lowered`: `String`은 `Vec<u8>`, `&str`은 `&[u8]`, `char`는 `u32`). 그래서 기존 바이트 인코딩·배치·해제를 그대로 쓰고, 검사기는 타입을 구분해 둔다(맵·진단의 타입 이름은 그대로). 바이트와 뜻이 다른 연산(`char`의 `push`, 비교)은 검사기의 `Tables::text`(값이 텍스트인 식)로 가른다.
- **불변식(§3):** 텍스트를 만드는 길은 모두 내장 연산(리터럴, `String::new`, 텍스트의 `push_str`, `char`의 `push`, 검사를 거친 `from_utf8`, 경계에서의 조각)이라 구성으로 지켜진다. 그래서 생성 지점의 의무는 정리이고 내지 않는다. 사용 지점의 사실도 아직 넣지 않았다: 이 단계의 증명에 필요한 것이 없었다. 그 대가로 "ASCII 바이트 뒤는 경계"처럼 불변식에서 나오는 사실은 `is_char_boundary` 검사로 증명한다(`tests/run/strings`·`escape`). 사실로 넣을지는 2U-06.
- **문자 순회(2026-11-08, 4B-02 (b)):** 열린 질문 2는 `std::str::decode_utf8(s, i) -> Option<Decoded>`(글자와 다음 위치, 표 3-7의 잘 짜인 시퀀스와 정확히 같은 계약)로 답했다. 반복자 없이(ADR-0049) `while`과 그 결과로 돈다(`tests/run/std_str`의 `chars`).
- **사용 지점 사실(2026-11-08, 2U-06):** 경계를 묻는 곳에서만 사실로 둔다. 조각 `&s[a..b]`의 의무(E0820)는 각 끝 바로 앞 네 바이트에 대해 UTF-8이 말하는 것(허용 바이트, ASCII·온전한 글자 뒤는 이음 바이트가 아님, 첫 바이트 뒤의 이음 바이트 수, 이음 바이트 넷 연속 없음, 이음 바이트의 첫 바이트는 셋 안쪽 앞, 첫 바이트는 이음 바이트가 아님)을 그 의무 하나에만 가정한다. 대상은 조각을 내는 텍스트와 정의가 받은 텍스트(텍스트 매개변수, 호출 결과, 호출 뒤의 `&mut` 텍스트: 검사기의 `Tables::text_sigs`)이고, 받은 텍스트는 그 끝에서도(마지막 글자가 온전함: 접두사가 맞으면 그 뒤가 경계). 정량 사실은 없다(`verify/text.rs`의 `utf8_window`). 그래서 ASCII 바이트 뒤·온전한 글자 뒤·첫 바이트 앞의 경계가 실행 검사 없이 증명되고(`tests/verify/pass/utf8_facts`: 앞 공백 건너뛰기, `:`에서 나누기, 접두사 떼기. `tests/run/strings`·`escape`의 `is_char_boundary` 검사를 지웠다), 반박된 경계의 반례는 유효한 UTF-8이다(전에는 `[128, 128]`처럼 텍스트일 수 없는 값). 먼저 텍스트가 들어오는 곳마다 정량 사실 하나를 넣어 쟀다: 인스턴스가 바이트에서 바이트로 이어져 반박된 경계가 모형 없이 한도에 닿거나(`push_str` 길이 의무), 한도의 절반을 썼고(시드 8개에서 rlimit 폭 12배), 뒤를 보는 절을 빼면 접두사 떼기가 1.8M이었다. 지금 형태는 시드 폭 1.02, `escape`는 검사를 지우고도 전보다 싸다(1,536,353 → 1,491,315). 단언·계약은 이 사실을 받지 않는다(`tests/verify/fail/utf8_facts`의 `text_begins`): 수요가 나오면 같은 국소 사실을 그 의무에. 변이 `v-utf8-char-ends-before-ascii`.
- **조각:** `&s[a..b]`는 E0820(`a <= b`, 두 위치 모두 Rust의 `is_char_boundary`). 값은 선언 함수 `bmb_shift`와 공리 하나이고, 그 공리는 쓰는 질의에만 들어간다. `lambda`를 먼저 썼으나 Z3가 "incomplete (theory array)"로 포기했다(`tests/run/escape.bmb`, 실제 원인은 거짓인 불변식이었지만 반례를 만들지 못했다).
- **`push(c)`:** 상수 `c`는 정확한 UTF-8 바이트, 그 밖은 정확한 길이(`len_utf8`)와 ASCII 바이트, 나머지는 첫 바이트(192..=244)와 이음 바이트(128..=191)의 갈래만 사실이다. 정확한 인코딩의 `div`·`mod`가 텍스트의 정량 사실과 함께 있는 질의를 무겁게 했다. 경계 증명에는 갈래로 충분하다.
- **비교:** 코드에서는 최장 공통 접두의 새 상수와 그 정의 사실로 여섯 비교를 모두 정확히, 명세에서는 `==`가 슬라이스 동등, 순서는 공통 접두에 대한 정량 식.
- **`from_utf8`:** 증명은 성공 여부를 모형화하지 않는다(새 조건). 결과는 `Ok`·`Err` 모두 같은 바이트다. 런타임 검증은 Rust `str::from_utf8`의 규칙.
- **Rust 습관:** `&str` 자리의 `&s`·`s`는 E0218(제목을 `String`까지 넓힘, `s.as_str()`로), `&[u8]` 자리의 `"..."`와 `u8` 자리의 `'a'`는 E0401과 `b".."`·`b'a'` 수정(E0234 은퇴), `to_string`·`to_owned`는 `String::from` 하나로(E0404 안내), `chars()` 등 순회는 바이트와 `while`(열린 질문 2는 4B), `+`·`format!`·`s[i]`·`char` 산술은 안내가 붙은 거부.
- **허용 범위:** `Vec<String>`·`&[String]`은 되고 `[String; N]`은 `Vec`처럼 안 된다. `char::from_u32`는 명세에서도 쓴다(순수 함수). 명세 함수는 `String`을 받지 않는다(`&str`, `Vec`과 같은 규칙).
- **런타임:** `memcmp`(libc)를 비교에 쓴다. 덧붙이기는 자기 버퍼에서 온 바이트도 받는다(키우기 전 오프셋으로 다시 찾는다: `s.push_str(&s[a..b])`).

## 맥락
ADR-0044는 `String`·`&str`·`char`를 거부하고 `Vec<u8>`·`&[u8]`·`u8`로 대체했다. 근거는 UTF-8 불변식을 증명에 들이는 비용과 "컴파일러 문자열은 사실상 ASCII"였다. 비용은 기준이 아니고(ADR-0045 §5), 문자열은 Rust의 정석 타입이자 LLM의 사전 지식이 가장 많은 영역이다(S1, S4의 Rust 습관 오류율). Verus는 `String`을 `Seq<char>` 보기로 명세한다.

## 결정

### 1. 타입
- `String`: 소유, 유효한 UTF-8 바이트 열. 이동 타입(ADR-0047).
- `&str`: 빌린 문자열. 참조 규칙(ADR-0015)대로 인자 자리에서만.
- `char`: 유니코드 스칼라 값(`0..=0x10FFFF`에서 대리 영역 제외). 리터럴 `'a'`, `'\u{1F600}'`.
- 문자열 리터럴 `"..."`은 `&str`이다(인자 자리, `b"..."`와 같은 규칙).

### 2. 연산(Rust 표준 라이브러리의 이름과 의미)
- 생성·확장: `String::new()`, `String::with_capacity(n)`, `s.push_str(t)`, `s.push(c)`, `s.clone()`.
- 보기: `s.len()`(바이트), `s.as_str()`, `s.as_bytes()`(`&[u8]`, 인자 자리), `s.is_char_boundary(i)`.
- 변환: `String::from_utf8(v: Vec<u8>) -> Result<String, Vec<u8>>`(Rust는 `FromUtf8Error`, 바이트를 돌려받는 같은 정보), `String::from(t: &str)`, `char::from_u32(x) -> Option<char>`, `u32::from(c)`, `c.len_utf8()`.
- 비교: 실행 코드의 `==`·`<`(바이트 사전순, Rust와 같음).
- 조각: 조각은 참조를 반환할 수 없어(ADR-0015) `(시작, 끝)` 바이트 위치로 다루고, 조각을 받는 함수에는 `&s[a..b]`를 인자 자리에서 넘긴다(경계 의무: `is_char_boundary`).
- 출력: 내장 `print_str(s: &str)`(`io`). 매크로 `print!`·`println!`·`format!`는 원장대로 없다(메타프로그래밍).

### 3. 증명 인코딩
- `String`/`&str` 값은 바이트 열 `(Array Int Int, Int)`에 불변식 `utf8(bytes, len)`(재귀 `spec fn`)을 붙인 것이다. 불변식은 생성 지점에서 의무이고(내장 연산은 보존이 정리), 값을 쓰는 곳에서는 사실이다(정수 범위 사실과 같은 방식).
- `char`는 `Int`와 범위 사실(스칼라 값)이다.
- 명세용 보기 `s.view()`: 문자 열(`Seq<char>`, Verus와 같음)은 열린 질문 1.

### 4. 코드 생성
- `String`은 `Vec<u8>` 머리와 같은 배치, `&str`은 (포인터, 길이). `from_utf8`은 검증 루프(런타임 검사는 결과 타입에 담긴 실패 경로라 의무가 아님).

### 5. ADR-0044와의 관계
- `u8`, `Vec<u8>`, `b'a'`, `b"..."`, `print_bytes`, `lib/bytes.bmb`는 그대로 둔다(바이트는 바이트로).
- 바뀌는 것: `"..."`·`'a'`·`String`·`&str`·`char` 거부(E0234, E0101의 `b'a'` 교체, E0402의 `String` 교체)가 없어진다. E0234의 의미를 바꾸지 않고 코드를 은퇴시킨다(재사용 금지).

## 근거(검토한 대안)
| 안 | 판정 |
| --- | --- |
| **UTF-8 불변식을 가진 `String`·`&str`·`char`(채택 제안)** | Rust 표면 그대로(S1). 불변식은 생성 지점 의무 + 사용 지점 사실로, 바이트 연산 증명은 지금과 같은 비용 |
| 바이트만(ADR-0044 현행) | 표현력 결함(ADR-0045 §7). 에이전트가 쓰는 Rust 문자열 코드가 모두 거부된다 |
| 검증 없는 `String`(불변식 없음) | `as_bytes`·경계 연산의 정확성을 증명할 수 없다(C1) |

## 결과
- 렉서·진단 문구·JSON처럼 텍스트를 다루는 코드가 Rust 형태가 된다.
- 소유 타입(ADR-0047)과 제네릭(ADR-0046) 뒤에 구현한다(`String`은 이동 타입, 비교는 `Ord`).
- 퍼저: 바이트 퍼저에 UTF-8 경계, `from_utf8` 실패 경로를 넣는다.

## 열린 질문
1. 명세의 문자 보기(`Seq<char>`): 문자 단위 명세가 필요한 과제가 나오면 넣는다.
2. 문자 순회: 반복자가 없으므로(ADR-0049) `decode_utf8(s, i) -> (char, usize)` 같은 라이브러리 함수를 4B에서 정한다.
