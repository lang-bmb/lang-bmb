# ADR-0085: 0 쪽 자름 나눗셈을 같은 피연산자의 `div`·`mod` 한 쌍으로

- 상태: 채택 (자율 채택, AUTONOMY.md §4: ADR-0017 범위 안의 인코딩 결정). ADR-0017의 `tdiv`·`trem` 정의식을 보완한다(제수가 0이 아닐 때 같은 함수)
- 날짜: 2026-11-04
- 관련: ADR-0017(정수 의미론과 SMT 인코딩), ADR-0018(나눗셈 보조 사실), ADR-0064·0067(정의 공리와 탐침), 백로그 1B-47·T1-14, JUDGMENT §8

## 맥락

- 파일럿 BVB `vc-va0093-max-balance`(2026-10-28)는 증명은 통과했지만 명세 강도가 미결정이었다(T1-14). 에이전트 계약(`0 - (9 - n) / 10`처럼 0 쪽 자름으로 쓴 내림 나눗셈)과 숨긴 계약(제수 매개변수 `d`로 쓴 `(n % d + d) % d`)이 정의역 -128..127에서 같은 식이다.
- 2026-11-04 HEAD에서 같은 함의를 다시 풀면(`tests/verify/pass/const_division.bmb`) 여전히 E0811 미결정이었다. 탐침은 6,439,133, 전체 질의는 11,211,090 rlimit이 들어 한도 5,000,000을 넘는다.
- 원인은 ADR-0017의 정의식이다. `tdiv(a,b) = sign(a)·sign(b)·div(|a|,|b|)`는 `(div a b)`와 `(div (- a) b)` 두 항을 만들고, 해법기는 `div` 항마다 몫·나머지 쌍을 따로 둔다. `trem(a,b) = a − b·tdiv(a,b)`는 제수가 변수(정의 공리의 매개변수)면 곱이라 비선형이다.

## 결정

해법기 앞부분(`verify::PRELUDE`)의 두 정의를 바꾼다.

```
tdiv(a,b) = ite(a ≥ 0 ∨ mod(a,b) = 0, div(a,b), ite(b > 0, div(a,b) + 1, div(a,b) − 1))
trem(a,b) = ite(a ≥ 0 ∨ mod(a,b) = 0, mod(a,b), mod(a,b) − |b|)
```

- `div`·`mod`는 SMT-LIB의 유클리드 나눗셈이다(`a = b·div + mod`, `0 ≤ mod < |b|`). 제수가 0이 아니면 두 식은 ADR-0017의 정의와 같은 함수다. z3로 확인했다(`b ≠ 0`에서 옛 식과 다름을 가정하면 `unsat`).
- 피연산자 쌍마다 `div`·`mod` 한 쌍만 생기고, `trem`에 제수와의 곱이 없다.
- 제수가 0이면 두 식 모두 SMT-LIB의 0 나눗셈(해석되지 않은 값)이다. 옛 식은 `tdiv(a,0) = −tdiv(−a,0)` 같은 사실을 따로 만들었는데 이 사실에는 근거가 없다(실행에서는 E0804가 0 제수를 막고, 명세의 0 나눗셈 값은 정해져 있지 않다). 새 식은 그런 사실을 만들지 않는다.

## 근거

- **측정:** 같은 함의의 탐침 6,439,133 → 456,403, 전체 질의 11,211,090 → 621,942이고, 한도 안에서 증명된다(판정 E0811 → 증명). 건강 지표(`health.py`)는 V4 7,428,098 → 7,225,434(이 ADR의 회귀 시험 추가 전), V8 24,254,414 → 23,914,744, V10 12,178,127 → 12,021,529로 줄었고, V5 0.1355 → 0.1244, V11(충족 가능성 검사) 282,057,550 → 283,986,695(+0.7%, 예산 안)이며 위반이 없다. 기준선은 회귀 시험을 넣은 값으로 받아들였다(V4 7,898,495). 실패 코퍼스(`tests/verify/fail`, 39개 파일)는 `rlimit` 값 밖에서 진단·반례가 그대로다.
- **기각한 것:** (가) 백로그 1B-47의 원안, 곧 상수 제수마다 몫·나머지 새 기호와 선형 제약. 이 과제의 비용은 상수 제수의 직접 나눗셈이 아니라 매개변수 제수를 쓴 정의 공리에서 나와 원안으로는 닿지 않는다. 같은 일(쌍마다 몫·나머지 하나)은 해법기가 `div`·`mod` 공유로 이미 한다. (나) 0 제수에서 옛 식과 같게 하는 가드(`ite (= b 0) 옛식 새식`). 함수로는 완전히 같지만, 변수 제수에서 가드가 남아 탐침이 7,912,698로 옛 식보다 비싸다. 가드가 지키는 것은 근거 없는 사실뿐이라 버렸다. (다) 매개변수 제수를 쓴 잎 `spec fn`을 매크로로. 전체 질의 9,291,538로 한도를 넘는다.

## 결과

- 코드: `compiler/src/verify.rs`의 `PRELUDE`. 증명 캐시 키는 질의 텍스트(앞부분 포함)라 형식 버전을 올리지 않아도 옛 항목과 겹치지 않는다.
- 시험: `tests/verify/pass/const_division.bmb`(파일럿 계약의 함의), 실패 코퍼스 기대 출력의 `rlimit` 갱신, 건전성 퍼저 전부 통과(`cargo test`).
- 되돌리기: `PRELUDE`의 두 줄을 ADR-0017의 식으로 되돌린다.
