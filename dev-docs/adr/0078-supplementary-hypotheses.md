# ADR-0078: 보완 가설 여섯의 등록(H-EFFECT, H-INTENT, H-REVIEW, H-SMALL, H-REPAIR, H-COMPAT)

- 상태: 채택 (사람 승인 2026-11-01 "권장안 채택, 승인사항 승인": 검토 `dev-docs/reviews/hypotheses-2026-11-01.md` §3의 권장안 (나)). ADR-0058 §4의 가설 등록부에 행을 더하므로 T1의 통과 기준 대상이 는다
- 날짜: 2026-11-01
- 관련: ADR-0034(목표값), ADR-0040·0058(가설), ADR-0030(효과), ADR-0066(측정 모델), ADR-0076(측정 조건), ADR-0077(판정 규칙), 백로그 T1-42

## 맥락

- 사람이 낸 초안 "보완 가설 후보" 스물(검토 문서 부록 A)을 설계·결정·백로그와 대조했다(같은 문서 §2). 효용 보고서(`dev-docs/reports/utility.md`)가 보인 공백 가운데 셋이 등록부에 없었다. 상태 있는 코드의 테스트 면적, 사람이 명세만 보는 검토(DESIGN 전제 E1·E2(d)), 모델 격차다.
- 승인 내용: 여섯을 등록한다. H-INTENT·H-REVIEW의 평가자는 리뷰 모델이 기본이고 사람 표본은 교정용이다. 판정 수치는 등록 때 G 목표와 맞춰 동결한다. H-GRADUAL과 H-PRIOR의 "완화" 쪽은 DESIGN을 바꾸지 않고 다시 짠다.

## 결정

### 1. 등록하는 가설(판정 기준은 측정 전에 동결)

모든 비교는 ADR-0077로 읽는다. 반복이 있는 수치는 95% 구간, 한 번만 잰 차이는 최소 차이 D를 넘을 때만 차이다. 모델은 ADR-0066대로 qwen이 먼저이고 sonnet이 교차 비교다.

| ID | 가설 | 측정 | 판정 기준(동결) |
| --- | --- | --- | --- |
| H-EFFECT | I/O·상태·외부 의존을 효과(ADR-0030)로 드러내면 증명되는 순수 핵심과 테스트가 필요한 껍데기가 갈리고, 남은 테스트 면적이 작다 | 입출력·상태가 있는 과제 집합(BRB 꼴, Rust 팔과 같은 숨은 판정)에서 성공 세션의 남은 테스트 면적(`test_needed_defs` / 정의 수)과 에이전트 테스트 코드 줄 | 확정: 남은 테스트 면적이 정의의 20% 이하이고 테스트 코드 줄이 Rust 팔의 1/3 이하(두 모델 모두). 반증: 둘 중 하나라도 넘음. 순수 과제의 G8 목표(1/10)는 그대로이고, 이것은 효과가 있는 코드의 별도 목표다(원칙 4: 신뢰 경계의 시험은 남는다) |

### 2. 등록하지 않는 것(사유)

- **H-DECIDE**는 언어에 관한 주장이 아니라 판정기의 공학 성질이다. 지표로 둔다: 정식 실행마다 숨은 명세 검사의 `undecided` 비율을 보고한다(T0-28).
- **H-REFINE**는 H-SPLIT(계약을 먼저 고정한 분업)의 과제 집합에 "정제 작성" 팔로 넣는다(3단계).
- **H-PARSE**는 H-ENCAP(타입 불변식, ADR-0060)의 과제 집합에 외부 데이터 경계 과제를 더하는 다음 판으로 한다(T1-47).
- **H-GRADUAL**은 원칙 4("증명이 없으면 바이너리도 없다")와 비목표("빠른 프로토타이핑")에 맞선다. DESIGN 안에서 다시 짠 꼴은 "근거 있는 탈출구(ADR-0029)로 시작한 코드는 편집이 쌓이며 미증명 면적이 줄어든다"이다. 탈출구 구현(2E-02~2E-04) 뒤에 다시 본다.
- **H-PRIOR**의 "규칙 완화"는 §4.1 원장(ADR-0045)과 원칙 8을 바꾸므로 등록하지 않는다. "자동 변환" 쪽은 H-FAMILIAR와 문법 재평가(2R-04), Rust 습관 진단(2D-29)이 이미 다룬다.
- **H-CONC, H-COST**는 DESIGN에 없는 언어 범위다(ADR-0016). **H-FFI**는 생태계 관문(CLAUDE.md: 원칙 4·6의 입증 뒤)에 걸린다. **H-CAP**은 효과(2F) 뒤 H-GAME 집합의 확장으로, **H-PROV**는 다중 에이전트 실측(H-SPLIT) 때, **H-TRACE**는 근거(2E-04) 뒤 "에이전트의 요구-조항 연결 정확도"로 다시 짠다. **H-MIGRATE**의 "동등성 증명"은 Rust 의미론이 증명기에 없어 지금 잴 수 없다. 숨은 차등 시험과 계약 강도로 바꾸면 잴 수 있다.

### 3. 평가자

H-INTENT·H-REVIEW의 평가자는 리뷰 모델이다. ADR-0066의 두 모델이고, qwen을 먼저 쓰고 sonnet을 교차로 쓴다. 리뷰 프롬프트와 판정(결함을 찾았는가)은 과제 집합과 함께 동결한다. 사람 표본은 리뷰 모델의 판정이 사람의 판정과 맞는지 교정할 때만 쓰고, 그 규모와 방법은 과제 집합의 동결 ADR에서 정한다.

## 근거

- **전제를 재는 가설이 있어야 한다:** DESIGN 전제 E1(검토 대상은 의도와 명세로 옮긴다)과 E2(d)(명세 타당성)는 BMB의 첫 전제인데 등록부에 그것을 재는 가설이 없었다. H-INTENT·H-REVIEW가 그 자리다.
- **수치를 G 목표와 맞춘 방식:** 순수 코드의 테스트 코드 목표(G8 1/10)는 그대로 두고, 효과가 있는 코드는 원칙 4가 시험을 남기는 경계를 가지므로 1/3을 따로 둔다. 토큰 비율(1/2, 1/5)은 G5의 "총 토큰" 축과 같은 단위다. 성공률 비교는 모두 ADR-0077의 규칙으로 읽어 1회 측정의 흔들림을 차이로 착각하지 않게 한다.
- **H-COMPAT을 결정론으로 두는 이유:** 판정에 모델이 필요 없다. 이미 있는 근거(2D-19: BCB 이력 두 판에서 편집한 정의 2,005개의 판정이 생성기 정답과 모두 일치)가 판정 정확도 쪽을 덮고, 호출처 재현율만 남았다(T1-46).

## 결과

- 등록부(`docs/ROADMAP.md` "가설 등록부")에 여섯 행. H-COMPAT은 "결정론 근거(부분)", 나머지는 "미측정"이다.
- 백로그: 과제 집합과 도구 T1-43(H-EFFECT, 2F-02 뒤), T1-44(H-INTENT·H-REVIEW: 의도 어긋난 명세 집합, 예시·반례 생성 도구, 리뷰 하네스), T1-45(H-REPAIR 절제 하네스), T1-46(H-COMPAT 호출처 재현율), T1-47(H-ENCAP 경계 파서 판), 지표 T0-28(판정기 미결정률). H-SMALL은 T0-13의 원판 실행이 기준선이다.
- T1의 통과 기준("등록부의 모든 가설이 확정·반증·보류")이 이 여섯에도 걸린다.
- 되돌리기: 등록부에서 행을 빼고 상태를 "보류(사유)"로 남긴다(행은 지우지 않는다).
