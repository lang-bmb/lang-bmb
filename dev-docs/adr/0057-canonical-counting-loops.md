# ADR-0057: 셀 수 있는 `while`의 정규형 수정은 린트 경고와 `bmb fix`로

- 상태: 채택 (2026-10-28, 자율 채택: AUTONOMY §4 "기존 ADR 범위 안의 구현 수준 결정", 백로그 2K-04)
- 날짜: 2026-10-28
- 관련: ADR-0049 §2("같은 일을 하는 `while` 셀 루프는 정규형에서 `for`로 바꾸는 기계 수정을 둔다"), DESIGN.md §3 원칙 8·§4.1 원장 "표현", ADR-0021(벤치 동결), 백로그 2K-01d·2K-04

## 맥락
ADR-0049 §2는 셀 수 있는 루프의 정규형을 범위 `for`로 정하고 `while` 셀 루프를 바꾸는 기계 수정을 두라고 했다. 진단의 등급(오류인가 경고인가)은 정하지 않았다. 정규형 규칙의 다른 예(`match` 갈래 순서 E0426, Rust 습관 E02xx)는 `check`의 오류다. 그런데 `while` 셀 루프는 동결된 벤치 자산에 있다: M1 시드 작업 공간(`bench/m1/seed/src`, 2곳)과 기준선 프로그램(`bench/baseline`, 9곳). 오류로 만들면 동결한 과제의 출발 상태가 검사를 통과하지 못한다.

## 결정
1. **진단.** 셀 수 있는 `while`은 W0907(경고)이다. `bmb lint`가 보고하고(`lint::canonical_loops`, 구문만 본다), 진단의 수정이 바꿀 원문을 담는다. `check`·`verify`·`build`는 바뀌지 않는다.
2. **`bmb fix`가 적용한다.** 검사를 통과한 프로그램이면 `bmb fix`가 W0907의 수정도 다른 기계 수정과 같은 회차 규칙(겹치면 다음 회차)으로 적용한다. 중첩된 셀 루프는 바깥부터 회차마다 하나씩 바뀐다.
3. **조건.** `let mut i: T = lo;` 바로 뒤의 `while i < hi [invariant ..] decreases d { ..; i = i + 1; }`에서: 마지막 문장만 `i`를 바꾸고(대입·`&mut`·변경 메서드 없음), 몸이 `hi`가 읽는 변수를 바꾸지 않으며 `hi`는 변수·상수·필드·산술·`len()`뿐이고, 이 루프로 가는 `continue`가 없고, 루프 뒤에서 `i`를 쓰지 않으며, 두 끝이 모두 리터럴이면 `T`가 `i64`일 때만(리터럴 두 끝의 `for`는 `i64`). 범위 `for`는 정확히 이 펼친 꼴에 머리 불변식과 측정 `hi - i`를 더한 것으로 인코딩되므로(2K-01d, 질의 동일성 시험), 바꾼 프로그램은 사용자 불변식을 그대로 두고도 증명이 그대로 통과한다(더해지는 의무는 늘 참인 머리 불변식과 측정뿐).
4. **원문을 잇는다.** 수정은 원문 조각을 이어 붙여 만든다(`let`과 루프 사이의 주석은 루프 앞에 남고, `decreases` 줄과 증가 문장 줄만 빠진다). 정규형 출력기는 주석을 버리므로 쓰지 않는다.
5. **이주.** 실행 프로그램·증명 코퍼스·`lib/bytes.bmb`를 `bmb fix`로 옮긴다. `while` 자체를 시험하는 코퍼스(`loops`·`loop_exits`·`returns`)와 틀린 코퍼스, 동결한 벤치 자산은 그대로 둔다.
6. **다시 볼 때.** 벤치 과제를 새 판으로 낼 때(동결 해제) W0907을 `check`의 오류로 올리는 것을 다시 정한다.

## 근거(검토한 대안)
| 대안 | 판단 |
| --- | --- |
| `check`의 오류(E02xx, 수정 포함) | 원칙 8에 가장 곧다. 동결한 M1 시드와 기준선 프로그램이 검사를 통과하지 못해 ADR-0021의 동결을 깬다 |
| 정규형 출력기(`bmb fmt`)가 바꿈 | 출력기는 구문 정규화만 한다. 이 변환은 이름의 쓰임(루프 뒤)과 몸의 쓰기를 봐야 하고, `fmt --check`가 동결 자산에서 실패하는 것은 같다 |
| **린트 경고 + `bmb fix` 적용(채택)** | 동결 자산은 그대로 검사를 통과하고, 기계 수정은 도구 한 번으로 적용된다. 정규형이 아닌 코드가 남을 수 있는 대가는 `bmb lint`의 보고로 드러난다 |
