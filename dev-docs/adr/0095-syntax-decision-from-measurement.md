# ADR-0095: 측정에 따른 문법 결정 (2R-06)

- 상태: 제안
- 날짜: 2026-11-08
- 관련: DESIGN.md §4, ADR-0013, ADR-0036, ADR-0026, ADR-0028, ADR-0049, ADR-0057, `dev-docs/measurements/syntax-eval-1.md`(2R-02), `syntax-eval-2.md`(2R-04), `syntax-evidence.md`(2R-03)

## 맥락

ADR-0036은 구성마다 차용·확장·변형·기각을 측정으로 정한다고 했다. 2R-02가 현행 구성 약 70개를 1차 평가했고, 2R-04가 변형·기각 후보를 오프라인으로 비교했고(토큰, 정규형, 맵 크기, 증명 비용, 수정 회복), 2R-03이 동결 하네스의 실제 모델 세션 1,205개에서 구성별 습관과 진단을 셌다. 종합은 `syntax-eval-2.md` §2R-04h다.

세 가지가 크다. (1) 루프·계약 절의 꼴이 세션의 약 40%에서 막혔다: 절 키워드 되풀이(`invariant a, invariant b,`) 19.7%, 계약 절의 인라인 식 16.6%, 루프 몸 안의 불변식 11.5%. (2) 셰도잉 규칙(E0303)이 152세션에서 나왔고 73세션은 그 오류로 끝났다. (3) `#[uses]` 목록이 손으로 쓰는 문맥인데, 규칙 r2c가 큰 생성 작업 공간에서도 그것을 대신한다.

## 결정 (제안)

**A. 정본을 바꾸는 변형 넷**

1. **`#[uses]` 기본 문맥 = r2c.** 정의의 증명 문맥은 자기 계약·불변식·`assert`와 피호출자의 `requires`·`ensures`가 부르는 `spec fn`의 닫힘이다. `#[uses(..)]`는 그 밖의 사실을 더할 때만 쓰고, 정본에서는 도구가 r2c와 같은 목록을 지운다. r2c는 검사기의 이름 해석 위에서 계산한다(제네릭·trait·불변식·메서드 포함).
2. **계약 절의 양화사 없는 인라인 식(T2).** `requires`·`ensures`는 이름 붙은 술어의 호출이나 양화사 없는 식이다. 양화사(`forall`·`exists`)를 담는 절은 이름 붙은 술어여야 한다(E0501의 뜻이 그쪽으로 좁아짐). L1의 `requires`·`ensures`는 정규형 식 텍스트다.
3. **셰도잉을 진짜 가림으로 좁힘.** 같은 이름을 안쪽 범위가 바깥에서 보이는 이름을 가릴 때만 거부한다(E0303). 겹치지 않는 범위(형제 블록, 다른 `match` 갈래의 바인딩)의 같은 이름은 받는다. 매개변수를 가리는 `let`은 계속 거부한다.
4. **정수 변환의 정본 `x as T`(정수 사이만, 범위 의무).** `T::try_from(x).unwrap()`은 입력 별칭으로 받아 정본으로 옮긴다. 2R-04c의 권고 그대로다(ADR-0028 열린 질문 1).

**B. 정본을 바꾸지 않는 입력 별칭 둘** (쓰기 표면 정책, DESIGN §8.2의 수정 규칙을 넓힘)

5. **절 키워드 되풀이.** `invariant a, invariant b,`(`ensures`·`requires`도)는 오류 대신 대체 문안이 있는 진단(E02xx)으로 받아 키워드 하나의 목록으로 고친다.
6. **루프 몸 안의 불변식.** `while c { invariant a, decreases d, .. }`의 첫 절들은 머리로 옮기는 수정을 낸다.

**C. 결정됨으로 기록** (바꾸지 않음): 쓰기 표면의 기계 수정(2R-04e: 365곳 뜻 바뀜 0), `self: &T`·메서드 호출(ADR-0026·0051), 범위 `for`(ADR-0049·0057), 명시 트리거와 E0511 기계 수정(2R-04g), 명세 별칭 `int`·`nat`·`@` 기각, `decreases` 필수(증명 게이트의 규칙, 안내를 `for`로).

**D. 이 결정 밖:** 복합 대입은 2N-07(승인 대기), 경계가 다른 `impl` 블록은 2T-11, 명세에서 옮긴 값은 2T-12.

## 근거

- A1: m3 생성 작업 공간 223정의와 m1b 시드 53정의가 r2c로 다섯 시드 모두 증명되고, `rlimit`은 +0.8~2.3%, 질의 바이트는 +1.5~2.0%, 예산(1,000,000)을 넘는 의무는 없다. 키가 바뀌는 정의는 36·5개로, 한 번 다시 증명된다(2R-04a). E0509는 세션의 2.7%다. 이름 해석 위의 계산이 전제인 것은, M1 뒤 표면(제네릭 등)이 든 `tests/verify/pass`에서 근사 파서가 언급을 못 읽어 30정의가 실패했기 때문이다. 이 실패는 규칙의 반례가 아니다.
- A2: 단일 사용 술어 39개를 인라인하면 토큰 −6.4~6.9%, L1 −24~27%다. 35개가 잎이라 질의가 같다(ADR-0067의 매크로). 양화사 술어 9개는 트리거와 재사용의 단위라 이름을 남긴다(2R-04b). 실제 모델에서는 인라인 식이 16.6%, E0501이 245세션이다(2R-03).
- A3: E0303 152세션 중 46은 `let`이 매개변수를 다시 묶은 것(계속 거부), 21은 한 함수의 두 `let`이다. 형제 범위의 같은 이름은 Rust에서 흔하고 BMB에서도 뜻이 모호하지 않다. 정규형 하나(원칙 8)는 이름의 범위가 겹치지 않으면 그대로다.
- A4: 지점당 −6.8토큰. E0205는 sonnet 49세션에서 나온다(2R-03).
- B5·B6: 두 습관은 뜻이 하나로 정해지는 다른 꼴이다(19.7%, 11.5%). 정본을 바꾸지 않으므로 맵·정규형·증명이 그대로이고, 2R-04e의 규칙(수정은 뜻을 바꾸지 않는다)과 같은 꼴이다.
- C: 각 절의 측정이 현행을 지지하거나 이미 반영됐다.

검토한 대안: A2의 T1(양화사 포함 모든 식 인라인)은 트리거가 절 안에 흩어지고 재사용 단위가 사라져 기각했다. T3(현행 + 추출 도구)는 모델 근거(16.6%)를 메우지 못한다. A3의 "Rust처럼 모든 셰도잉 허용"은 매개변수 가림(46세션)이 뜻을 바꾸는 쪽이라(원래 값이 사라짐) 기각했다.

## 결과

- 구현 페이즈(채택 뒤): A1 검사기에서 r2c 계산과 `#[uses]` 정본 정리(도구가 지움), 증분 키 재계산. A2 파서·검사기·인코더·맵(L1 식 텍스트)·`query contracts`. A3 검사기(E0303 범위). A4 ADR-0028 열린 질문 1의 표면 교체와 두 형태 왕복. B5·B6 새 진단과 대체 문안.
- 동결된 벤치 자산(과제·프롬프트)은 바꾸지 않는다. 바뀐 표면에서 같은 과제의 1회 성공률은 2R-05(A/B, 같은 모델)로 잰다. 습관의 대부분이 작은 모델의 것이라 그 모델로 잰다.
- DESIGN §4는 채택과 같은 커밋에서 고친다(A1~A4).
- 채택은 사람의 승인이다(AUTONOMY §4: 언어 표면 변경).
