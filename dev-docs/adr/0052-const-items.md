# ADR-0052: `const` 항목

- 상태: 제안
- 날짜: 2026-10-26
- 관련: ADR-0045, DESIGN.md 원칙 5·8, §4.1 "이름"·"효과", ADR-0026(항목 표면), ADR-0050(문자열), 점검 R14, 백로그 2V-14

## 맥락
BMB는 `const`·`static` 항목을 "not supported in milestone 1"(E0207)로 거부하고 "`spec fn`으로 값을 돌려주거나 리터럴을 쓰라"고 안내한다. 그런데 `spec fn`은 명세 전용이라 실행 코드에서 부를 수 없다. 그래서 실행 코드에서는 같은 리터럴을 여러 곳에 쓰거나, 값을 돌려주는 `#[effects(pure)]` 함수를 만들어야 한다. 배열 길이(`[u8; N]`)에는 둘 다 쓸 수 없다. 이것은 원장 근거가 없는 제외다(점검 R14). 셀프호스팅 분석(`dev-docs/measurements/selfhost-gap.md` §3.1)에서는 `const`·`static` 항목이 46곳이고, 진단 코드표와 버퍼 크기가 그 예다.

원장 "이름" 행(DESIGN v1.2)은 `const`와 같은 일을 하는 불변 `static`과 전역 가변 상태(`static mut`, "효과" 행)를 이미 금지한다. 남는 정석 형태는 Rust의 `const`다.

## 결정

### 1. 표면
- 단위 안의 항목으로 `const NAME: T = e;`를 둔다. 타입 표기는 필수다(원장 "타입": 모든 타입 명시).
- 이름공간은 단위이고, 같은 단위에서는 `NAME`, 다른 단위에서는 전체 경로 `unit::NAME`으로 쓴다. 단위 안에서 이름은 하나에 정의 하나다(E0302).
- `impl T { const NAME: U = e; }` 연관 상수는 이 ADR에 넣지 않는다. 연관 상수는 trait 연관 항목(ADR-0046)과 함께 정한다.
- `#[effects(..)]`는 붙지 않는다. `const`를 읽는 것은 순수하다.

### 2. 타입
- 값 타입만 받는다: 정수·`bool`·`char`, 그런 값으로 이루어진 구조체·열거형, 고정 길이 배열 `[T; N]`.
- ADR-0050을 구현한 뒤에는 정적 데이터를 가리키는 `&str`과 `&[T]`도 받는다(`T`는 값 타입). 리터럴 `"..."`·`b"..."`·`&[..]`이 같은 일을 하므로, 이것은 참조를 데이터에 담는 것이 아니다. 2차 참조(§5)와 충돌하지 않는다.
- 소유 타입(`Vec`·`String`·`Box`, ADR-0047)과 참조를 담은 데이터 타입은 받지 않는다. Rust도 `const`에서 할당하지 않는다.
- 거부 코드는 E0434다.

### 3. 상수 식
- 초기화 식은 다음만으로 이루어진다:
  - 리터럴;
  - 다른 `const`;
  - 단항·이항 연산자와 비교;
  - 내장 정수 메서드(`wrapping_*`·`checked_*`·`saturating_*`, `T::try_from(x).unwrap()`, `as` 변환);
  - 구조체·열거형 생성;
  - 배열 리터럴과 반복 `[e; N]`;
  - 필드 접근과 인덱싱;
  - `if`와 `match`.
- 사용자 함수 호출은 받지 않는다. Rust의 `const fn`은 넣지 않는다. 열린 질문 1에서 측정 뒤 정한다.
- 상수 식이 아닌 초기화는 E0242다. 안내는 어떤 부분이 상수 식이 아닌지 가리킨다.
- `const`끼리의 순환 참조는 E0314다.

### 4. 평가
- 검사기가 위상 순서로 모든 `const`를 평가한다. 위 식 집합에는 루프·호출이 없으므로 평가는 언제나 끝나고 결정론적이다.
- 평가 실패는 Rust처럼 컴파일 오류(E0243)다. 실패에는 오버플로, 0으로 나누기, 범위 밖 인덱스, 실패한 `try_from(..).unwrap()`이 있다. 오류는 실패한 연산과 피연산자 값을 보인다.
- 값은 검사 단계에서 정해진다. 그래서 `usize` 상수를 배열 길이 `[T; N]`과 반복 `[e; N]`의 `N`에 쓸 수 있다. 타입 동일성은 평가된 길이로 정한다(`[u8; 4]`와 `[u8; FOUR]`는 같은 타입).
- 정규형: 배열 길이에는 이름 붙은 `const`나 리터럴만 쓴다. 길이 자리의 식(`[u8; N + 1]`)은 받지 않는다. Rust도 일반 const 식을 길이 자리에서 제한한다. 이 경우는 따로 `const`를 둔다.

### 5. 증명 인코딩
- `const`는 투명한 값이다(정의는 기본 불투명인 `spec fn`과 다르다. 값이지 정의가 아니다). 질의마다 쓰인 `const`가 SMT 상수 하나가 되고, 정의 등식 `(define-fun unit__NAME () T v)`의 `v`는 평가된 값이다. 배열 값은 원소 등식으로 적는다.
- 명세와 실행 코드 양쪽에서 쓸 수 있다. 증명 문맥(`uses`)에 넣지 않아도 보인다.
- 초기화 식 자체에는 증명 의무가 없다. 평가가 성공했으면 모든 산술이 범위 안에 있다.

### 6. 코드 생성
- 스칼라는 쓰는 곳마다 LLVM 상수로 넣는다.
- 배열·구조체·슬라이스는 `private unnamed_addr constant` 전역 하나로 만들고, 쓰는 곳에서 읽는다. 값으로 쓰면 복사하고, 슬라이스로 쓰면 포인터와 길이를 넘긴다.

### 7. 맵과 도구
- 맵 L0에 상수가 나오고, L1에 타입과 평가된 값이 나온다. L2에는 상수를 쓰는 곳의 엣지가 생긴다. 값이 바뀌면 그 상수를 쓰는 증명이 무효화된다. 이것은 증명 캐시의 키가 된다.
- E0207의 `const`·`static` 안내를 바꾼다:
  - `const`는 받는다.
  - 불변 `static`은 E0244로 거부하고 `static`→`const` 기계 교체를 붙인다(원장 "이름").
  - `static mut`은 E0244로 거부하고 안내만 단다(원장 "효과": 명시적 문맥으로 넘긴다).

## 근거(검토한 대안)
| 안 | 판정 |
| --- | --- |
| **Rust `const`, 검사기 평가, 투명한 값(채택 제안)** | Rust 표면 그대로(S1). 배열 길이에 쓸 수 있다. 증명에서 값이 보여 단언 비용이 없다. Verus도 `const`를 받는다 |
| 지금처럼 `spec fn` 또는 리터럴 | 실행 코드에서 쓸 수 없어 리터럴이 중복되고, 배열 길이에 이름을 붙일 수 없다. 원장 근거 없는 제외(R14) |
| 값을 돌려주는 `#[effects(pure)]` 함수 | 같은 일에 두 형태다(원칙 8). 배열 길이에 쓸 수 없다. 증명에서는 계약으로만 보인다 |
| `const fn` 포함 | Rust 정석이지만, 검사기 안에 실행 해석기를 둬야 한다(종료는 `decreases`가 보장). 셀프호스팅의 46곳이 호출을 필요로 하는지 먼저 잰다(열린 질문 1) |
| 증명기가 초기화 식의 의무를 진다 | 배열 길이는 검사 단계에 값이 필요하다. 평가기 하나로 값과 실패를 함께 정하는 편이 단순하고 Rust와 같다 |

## 결과
- 진단:
  - 새 코드 E0242(상수 식이 아닌 초기화), E0243(상수 평가 실패), E0244(`static`), E0314(`const` 순환), E0434(`const`에 쓸 수 없는 타입).
  - E0207은 `const`·`static`에 더는 쓰이지 않는다.
- 퍼저: 산술 퍼저의 상수를 `const` 항목으로 꺼내는 변형을 더한다. 검사기 평가와 실행 결과의 일치를 차분으로 확인한다.
- DESIGN §4.1 원장 "이름" 행은 바뀌지 않는다(불변 `static` 금지는 이미 적혀 있다).

## 열린 질문
1. `const fn`: 셀프호스팅 46곳과 2B-10 측정에서 초기화에 함수 호출이 필요한 비율을 잰 뒤 정한다.
2. 참조를 담은 표(`&[(&str, &str)]` 같은 코드표): 2차 참조와 맞물리므로 ADR-0050 구현(2U) 뒤에 따로 정한다. 그때까지 정석 대안은 정수 코드와 `match` 함수, 또는 구조체 배열이다.
3. 연관 상수(`impl` 안 `const`): trait 연관 항목(ADR-0046 구현, 2T)과 함께 정한다.
