# ADR-0051: 메서드 호출 구문을 정본으로

- 상태: 채택 (2026-10-26, 사람 승인 "1/2 채택, 승인", 백로그 2V-12)
- 날짜: 2026-10-26
- 관련: ADR-0045, ADR-0026 §1·§3(메서드 호출 구문 금지), DESIGN.md 원칙 5·8, §4.1 "호출 해석", 2R-04d(메서드 호출 입력 별칭), 점검 R11, 백로그 2V-11


## 채택 시 확인 (2026-10-26)
- 진단 번호: E0313 둘 이상의 경계 trait에 같은 메서드 이름(경로 형태 요구, 비어 있음 확인). `T::f(&x, ..)` 형태는 진단 없이 정규형(`bmb fmt`)이 메서드 구문으로 바꾼다.
- 2R-06(문법 결정)보다 먼저 채택한다(사람 승인). 2R-06은 나머지 구성의 결정을 맡는다.
- 원장 "호출 해석" 행은 이 채택과 함께 고친다.
- 구현 페이즈: ROADMAP 2M(메서드 구문). 제네릭(2T) 뒤.

## 구현 시 확인 (2026-11-07, 2M-01)
- 해석 순서: 수신자 타입(참조면 한 단계 벗긴 타입)의 고유 `impl` 함수, 없으면 `f`를 가진 trait. trait 후보는 타입 매개변수면 그 경계, 구체 타입이면 그 타입에 `impl`이 있는 trait이다(Rust와 같다. 결정의 "경계 trait"을 구체 타입의 구현 trait까지 읽었다). 내장 타입의 내장 메서드 이름(`len`, `push`, 정수·`f64` 메서드 등)은 trait보다 먼저다(Rust의 고유 메서드 우선).
- 진단: E0313(trait 둘 이상, 경로 호출 안내), 새 E0314(수신자가 없는 연관 함수나 자기 타입 매개변수가 있는 함수를 메서드로 부름, 경로 호출 문구). 메서드의 타입 인자 구문(`x.f::<U>(..)`)은 넣지 않았다: 그런 함수는 경로로 부른다. E0227은 은퇴.
- 제네릭 타입의 고유 `impl`은 타입 인자를 수신자 타입과 `impl` 머리의 통일로 정한다(E0237 없음: 수신자 타입이 명시 타입에서 정해진다).
- 방식: 검사기가 해석한 호출을 `T::f(조정(x), ..)` 경로 호출로 다시 쓰고(`check::check_resolved`), 해석할 메서드 호출이 남지 않을 때까지 다시 검사한다. 이동·재귀·효과·증명·코드 생성·맵이 따로 메서드를 알 필요가 없고, 진단은 마지막 검사의 것이라 첫 검사에서 수신자를 두 번 본 흔적이 남지 않는다. 다시 쓴 호출은 `ExprKind::Call`의 `method: Some(조정)`을 달고, 출력(슬라이스, 보기, 진단)은 그것을 `x.f(..)`로 쓴다. `bmb fmt`는 파싱한 프로그램을 쓴다.
- 맵 L2의 조정: `calls` 간선의 대상이 해석된 함수이고, 조정은 그 함수의 수신자 타입(슬라이스 `deps`의 시그니처)과 `&mut self`의 `writes` 간선(`arg` 0)이 말한다. 간선에 따로 필드를 두지 않았다: 간선 집합은 (호출자, 대상, 종류)마다 하나라 같은 대상을 메서드와 경로로 함께 부르면 둘로 갈라진다.
- 정규형(2026-11-07, 2M-02): `bmb fmt`는 바꾼 프로그램을 다시 검사해 호출마다 원래 함수로 해석될 때만 `x.f(..)`로 쓰고, 정의의 정체성 해시가 그대로인지도 본다(`check::methodize`). 결정의 "진단 없이"는 `check`가 경로 호출을 거부하지 않는다는 뜻으로 읽었다: 제자리 이주에는 W0907(ADR-0057)과 같이 린트 경고 W0911과 그 수정(`bmb fix`가 적용, 원문을 이어 붙여 주석이 남음)을 두었다. `check`·`verify`·`build`는 바뀌지 않는다. 코퍼스·`lib/`는 W0911로 옮겼고(실행 9개·증명 3개 파일, 85곳; `lib/`는 0곳), 틀린 코퍼스(기대 출력이 위치를 담음)와 동결 벤치 자산(경로 호출 0곳)은 그대로 둔다.
- 작업 공간 `rename`은 대상으로 해석된 메서드 호출의 이름을 바꾼다(`refs::Rewrite::method`). 정체성(ADR-0059)은 해석된 프로그램에서 계산하므로 메서드 호출 지점도 대상의 `id`를 참조한다.

## 맥락
ADR-0026은 사용자 함수의 메서드 호출 구문을 금지하고 `Point::norm1(&p)`만 허용했다. 근거는 원칙 5: 해석된 호출 대상이 텍스트에 없으면 슬라이스가 자급하지 않는다. 그런데 내장은 `v.len()`, `v.push(x)`, `x.wrapping_add(y)`, `u8::try_from(x).unwrap()`처럼 메서드 구문이다. 같은 일에 두 규칙이다(S3). 또 BMB는 모든 지역 타입을 명시하고 auto-deref 연쇄·Deref 강제를 금지하므로, 수신자 식의 타입은 슬라이스 안의 시그니처로 결정론적으로 정해지고 호출 대상도 그렇다. 내장 메서드가 이미 그렇게 동작한다.

## 결정
- `x.f(a, ..)`는 `T::f(조정(x), a, ..)`다. `T`는 `x`의 타입(참조면 가리키는 타입)이고 `f`는 `T`의 고유 impl 또는 경계 trait(ADR-0046)의 메서드다.
- 수신자 조정은 **한 단계**이고 `f`의 선언된 수신자가 정한다: `self: &T`이면 `&x`, `self: &mut T`이면 `&mut x`(`x`는 쓰기 가능한 자리), `self: T`이면 `x`(이동 또는 복사). `x`가 이미 `&T`/`&mut T`이면 그대로. 그 밖의 자동 참조·역참조 연쇄와 Deref 강제는 없다(원장 "호출 해석"의 나머지는 유지).
- 정본은 메서드 구문이다. `T::f(&x, ..)` 형태는 기계 수정으로 바뀐다(원칙 8). 연관 함수(수신자 없음)는 `T::f(..)` 그대로.
- 맵 L2는 해석된 대상(`unit::T::f`)과 조정을 기록한다. 슬라이스는 수신자 타입의 impl 시그니처를 포함한다(원칙 5 유지).
- 같은 이름이 고유 impl과 경계 trait 둘 다에 있으면 Rust처럼 고유 impl이 우선하고, trait 둘 사이의 모호성은 오류(경로 형태 요구)다.

## 근거(검토한 대안)
| 안 | 판정 |
| --- | --- |
| **메서드 구문 정본, 한 단계 수신자 조정(채택 제안)** | Rust 표면(S1). 대상은 명시 타입과 시그니처로 결정론적이라 원칙 5의 대가를 그대로 회수. 내장과 사용자 정의가 같은 규칙(S3) |
| 현행(사용자 함수만 경로 호출) | 같은 일에 두 형태(원칙 8 위반), Rust 습관 오류(2R-04d가 측정한 입력 별칭) |
| Rust의 전체 auto-ref/deref | 수신자 조정이 연쇄되면 대상 해석이 Deref 구현에 달린다. 원장 "호출 해석"의 대가를 잃는다 |

## 결과
- DESIGN §4.1 원장 "호출 해석" 행을 고친다: "auto-deref 연쇄, Deref 강제 변환 금지. 메서드 호출의 수신자 한 단계 조정은 시그니처가 정한다".
- ADR-0026 §1의 "메서드 호출 구문(§4.1 호출 해석 금지)" 제외와 §3 연관 함수 행의 호출 형태가 대체된다.
- 코퍼스·라이브러리의 `T::f(&x)` 호출을 기계 수정으로 옮긴다. 2R-06(문법 결정)과 함께 채택한다.
