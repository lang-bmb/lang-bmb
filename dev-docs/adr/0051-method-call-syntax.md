# ADR-0051: 메서드 호출 구문을 정본으로

- 상태: 제안
- 날짜: 2026-10-26
- 관련: ADR-0045, ADR-0026 §1·§3(메서드 호출 구문 금지), DESIGN.md 원칙 5·8, §4.1 "호출 해석", 2R-04d(메서드 호출 입력 별칭), 점검 R11, 백로그 2V-11

## 맥락
ADR-0026은 사용자 함수의 메서드 호출 구문을 금지하고 `Point::norm1(&p)`만 허용했다. 근거는 원칙 5: 해석된 호출 대상이 텍스트에 없으면 슬라이스가 자급하지 않는다. 그런데 내장은 `v.len()`, `v.push(x)`, `x.wrapping_add(y)`, `u8::try_from(x).unwrap()`처럼 메서드 구문이다. 같은 일에 두 규칙이다(S3). 또 BMB는 모든 지역 타입을 명시하고 auto-deref 연쇄·Deref 강제를 금지하므로, 수신자 식의 타입은 슬라이스 안의 시그니처로 결정론적으로 정해지고 호출 대상도 그렇다. 내장 메서드가 이미 그렇게 동작한다.

## 결정
- `x.f(a, ..)`는 `T::f(조정(x), a, ..)`다. `T`는 `x`의 타입(참조면 가리키는 타입)이고 `f`는 `T`의 고유 impl 또는 경계 trait(ADR-0046)의 메서드다.
- 수신자 조정은 **한 단계**이고 `f`의 선언된 수신자가 정한다: `self: &T`이면 `&x`, `self: &mut T`이면 `&mut x`(`x`는 쓰기 가능한 자리), `self: T`이면 `x`(이동 또는 복사). `x`가 이미 `&T`/`&mut T`이면 그대로. 그 밖의 자동 참조·역참조 연쇄와 Deref 강제는 없다(원장 "호출 해석"의 나머지는 유지).
- 정본은 메서드 구문이다. `T::f(&x, ..)` 형태는 기계 수정으로 바뀐다(원칙 8). 연관 함수(수신자 없음)는 `T::f(..)` 그대로.
- 맵 L2는 해석된 대상(`unit::T::f`)과 조정을 기록한다. 슬라이스는 수신자 타입의 impl 시그니처를 포함한다(원칙 5 유지).
- 같은 이름이 고유 impl과 경계 trait 둘 다에 있으면 Rust처럼 고유 impl이 우선하고, trait 둘 사이의 모호성은 오류(경로 형태 요구)다.

## 근거(검토한 대안)
| 안 | 판정 |
| --- | --- |
| **메서드 구문 정본, 한 단계 수신자 조정(채택 제안)** | Rust 표면(S1). 대상은 명시 타입과 시그니처로 결정론적이라 원칙 5의 대가를 그대로 회수. 내장과 사용자 정의가 같은 규칙(S3) |
| 현행(사용자 함수만 경로 호출) | 같은 일에 두 형태(원칙 8 위반), Rust 습관 오류(2R-04d가 측정한 입력 별칭) |
| Rust의 전체 auto-ref/deref | 수신자 조정이 연쇄되면 대상 해석이 Deref 구현에 달린다. 원장 "호출 해석"의 대가를 잃는다 |

## 결과
- DESIGN §4.1 원장 "호출 해석" 행을 고친다: "auto-deref 연쇄, Deref 강제 변환 금지. 메서드 호출의 수신자 한 단계 조정은 시그니처가 정한다".
- ADR-0026 §1의 "메서드 호출 구문(§4.1 호출 해석 금지)" 제외와 §3 연관 함수 행의 호출 형태가 대체된다.
- 코퍼스·라이브러리의 `T::f(&x)` 호출을 기계 수정으로 옮긴다. 2R-06(문법 결정)과 함께 채택한다.
