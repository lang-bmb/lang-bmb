# ADR-0040: 페인포인트 조사에 따른 전제 수정과 새 가설

- 상태: 채택 (사람 승인 2026-10-25, "모두 동의")
- 날짜: 2026-10-25
- 관련: DESIGN.md §2·§3 원칙 4, ADR-0034(미션 목표), ADR-0039(지속 관리)
- 근거 자료: `dev-docs/research/BMB 페인포인트 가설 검증/report.md`, `dev-docs/research/테스트 실행 비용 누적 근거/report.md`와 각 `notes/`

## 맥락

두 차례 웹 조사로 BMB의 전제를 외부 근거에 대 보았다. 주의: 이 환경에서 1차 원문 다수가 열리지 않아 많은 수치가 검색 요약에서 왔다. 각 보고서에 "원문 미확인" 표시가 있다. 이 ADR은 방향만 정하고, 문서에 수치를 주장으로 옮길 때는 원문 대조를 거친다(genesis §3.5).

1차 조사(페인포인트 가설 검증)의 결론:

- 네 가설(테스트, 규모, AI 한계, 협업)의 방향은 지지된다. 다만 근거가 문서에 적힌 이유와 다르다.
- 가장 강한 근거는 "테스트 통과는 정답을 보장하지 않는다"(오라클 부족)이다. UTBoost(ACL 2025)에서 SWE-bench Verified 통과 패치의 15.7%가 오답이었다.
- 인간은 코드를 덜 쓰지만 덜 읽지는 않는다. 리뷰가 새 병목이다.
- 다음 병목은 명세 타당성이다(N1).
- 가설에 없던 페인이 일곱 가지 나왔다(N1~N7).

2차 조사(테스트 실행 비용 누적, 사람이 직접 겪는 페인)의 결론:

- **반복 실행 비용의 누적은 대규모에서 기록되어 있다.**
  - Google TAP: 변경 수와 테스트 수가 함께 늘어 "모든 변경에 모든 테스트"의 계산량이 이차로 늘었다.
  - 테스트 실행 중 실패를 찾은 것은 약 1%다.
  - Meta·Uber·Shopify는 테스트 선택과 큐 개선으로 테스트 인프라 비용을 절반 안팎 줄였다.
- **AI 시대에 PR·push·CI 실행이 크게 늘었다.** GitHub Actions 분은 수 배 늘었고(2023→2026), 에이전트 PR도 급증했다. Stripe의 에이전트 파이프라인은 CI 라운드를 작업당 2회로 제한한다.
  - main 브랜치 처리량과 배포는 거의 늘지 않았다(CircleCI 2026). 반복이 일어나는 곳은 "배포마다"보다 "PR·push·재시도마다"다.
- **반대 근거도 있다.**
  - 보통 팀의 CI는 짧다(중앙값 약 3분).
  - 테스트 선택·캐시가 낭비의 큰 몫을 이미 회수한다.
  - 증명도 매 빌드 재검사·유지 비용(솔버 업그레이드, 증명 수리)이 있다.
  - "한 번 검증 대 반복 테스트"를 정량 비교한 모델은 문헌에 없다.
- **현장 선례가 있다.** 항공(DO-333, Airbus)에서 증명이 단위 테스트를 대체했다. 통합·대상 하드웨어 시험은 남는다.

## 결정

### 1. 전제 수정 (DESIGN.md §2)

- **E1.** 줄 단위 읽기는 AI의 산출량을 따라가지 못한다. 인간의 검토 대상은 코드에서 의도와 명세로 옮긴다.
- **E2.** AI 코딩의 병목은 생성이 아니라 검증과 탐색이다. 검증 쪽 병목은 네 가지다.
  - (a) 테스트 통과가 정답을 보장하지 못하는 오라클 부족
  - (b) 산출량을 따라가지 못하는 리뷰 비용
  - (c) 변경마다 반복 실행되어 변경 수 × 테스트 수로 누적되는 테스트 비용. AI가 PR·push 빈도를 올리면서 커진다
  - (d) 명세가 의도와 맞는지(명세 타당성)

  탐색 쪽 병목은 대형 코드베이스에서 수정할 곳과 영향을 파악하는 비용이다.
- **E3.** 쓰기 때 한 번 치르는 비용으로, 변경마다 반복되는 검증 비용과 빠져나가는 결함을 줄이는 거래는 이득이다.
  - 한 번 치르는 비용에는 명세·증명 작성, 학습하지 않은 표면의 비용이 포함된다.
  - 손익은 총 토큰, 누적 실행 비용, 결함률로 측정한다.

### 2. 원칙 4 수정 (DESIGN.md §3)

**증명이 반복 테스트를 대체한다.**

- 증명이 없으면 바이너리도 없다.
- 증명은 한 번 치르고, 바뀐 정의와 그 계약에 기대는 정의만 다시 증명한다(증명 캐시·증분 빌드).
- 테스트가 필요한 면적은 컴파일러가 산출해 지표로 보고하고 최소화한다.
- 대체 범위는 단일 프로그램의 기능 정확성(단위 수준)이다. 통합, 신뢰 경계(외부 입력, 솔버·컴파일러 자신), 코드 밖 구성(설정·배포)의 시험은 남는다.
- "테스트 0"은 지향점이지 주장이 아니다.

### 3. 범위 밖 명시 (DESIGN.md 비목표)

- 코드 밖 장애(설정·배포·재시도 폭주, N5)는 범위 밖이다.
- 에이전트 도구의 보안(프롬프트 인젝션, 공급망, N7)도 언어의 보장 범위 밖이다. BMB 자신의 도구 표면(MCP 서버)은 위협 모델을 갖는다(2D-20).

| ID | 가설 | 반증 조건 | 담당 |
| --- | --- | --- | --- |
| H-SPEC | BMB 도구(반례, 명세 강도, 린트)를 쓰면 에이전트 명세의 변이체 판별률이 Verus 기본 툴체인보다 높다 | 같은 모델·과제에서 BSB 판별률 차이 ≤ 0 | BSB, BVB(명세 강도 열) |
| H-ORACLE | 증명 통과는 테스트 통과보다 숨은 결함을 덜 놓친다 | BRB에서 "게이트 통과 & 숨은 실패" 비율 ≥ "테스트 통과 & 숨은 실패" 비율 | BRB |
| H-GAME | 탈출구 금지와 명세 변경 감사가 있으면 게이트 우회가 0이다 | 명세와 숨은 기준이 모순되는 과제에서 게이트 통과율 > 0 | BMB-Impossible(신규) |
| H-STABLE | 증명은 의미 보존 변형과 시드에 안정적이다 | 불안정 질의 비율 ≥ 2.6%(Mariposa 기준선) | 안정성 퍼저(신규, G1) |
| H-MAINT | 변경당 재증명은 영향 집합 안에 국소화된다 | 재증명 정의가 `impact` 집합 밖으로 샘 | 편집 재생 시험(신규) |
| H-FAMILIAR | BMB 표면의 '학습 안 됨' 비용은 Verus의 이중 표현 비용보다 작다 | BVB에서 BMB 1회 성공률 ≤ Verus | BVB |
| H-SCALE | BMB에서 성공률·토큰은 코드베이스 크기와 무관하고 파일 기반에서는 아니다 | 정의 수(1k→10k)에 따른 기울기가 Rust 쌍둥이와 같음 | BNB(크기 축) |
| H-REUSE | 결정론적 맵은 중복 생성과 범위 초과를 줄인다 | 중복 정의·요구 밖 정의 비율 ≥ Rust 쌍둥이 | BNB(신규 지표) |
| H-AMORT | 변경 이력에서 BMB의 누적 검증 비용(증분 재증명 + 남은 테스트)은 같은 결함 검출력의 Rust 테스트 실행 비용보다 작다 | 커밋 이력 재생에서 누적 CPU 시간이 테스트 선택·캐시를 쓴 Rust 쌍둥이 이상 | BCB(신규) |

| 목표 | 지표 | M2 | M3 |
| --- | --- | --- | --- |
| G7 누적 검증 비용 | 커밋 이력 재생의 누적 CPU 시간과 결함 검출(BCB) | 측정 시작, Rust 쌍둥이(전체 실행) 대비 비율 보고 | 테스트 선택·캐시를 쓴 Rust 쌍둥이 이하, 결함 검출 동등 이상 |

## 근거

- E2의 "쌓이는 테스트"는 사람의 경험과 대규모 기업 기록(이차 증가, 실패 검출 약 1%)이 뒷받침한다. 다만 보통 규모 팀에서는 작고, 선택·캐시가 일부를 회수한다. 그래서 손익은 공정한 기준선(선택·캐시를 쓴 Rust)과 비교해 BMB에서 직접 잰다(H-AMORT, G7).
- 오라클 부족은 실행 비용과 독립적인, 실행으로는 얻을 수 없는 이득이다. 두 근거를 함께 둔다. 요약하면 테스트는 약한 판정을 실행할 때마다 다시 사고, 증명은 더 강한 판정을 변경이 있을 때만 다시 산다.
- BMB 고유의 차별점은 계약 방화벽이다(ADR-0032). 본문만 바뀌면 호출자를 다시 검증하지 않으므로, 무효화 범위가 테스트 영향 분석(의존자 전부)보다 좁다. 외부 문헌에는 이에 대한 측정이 없으니 BCB가 잰다.
- 업계는 테스트 선택·캐시·스케줄링으로 반복 실행 낭비의 약 40~67%를 이미 회수한다(Meta, Uber, Google, 원문 미확인). 그래서 "매번 전수 실행" 대비 수치는 주장으로 쓰지 않고, 선택·캐시 기준선 대비만 쓴다.
- 증명도 반복 비용이 있다. 컴파일러 정체성이나 Z3 버전이 바뀌면 캐시 전체가 무효가 되고, 증명 유지(솔버 불안정, 증명 수리) 비용도 든다. BCB는 이 사건을 이력에 넣어 잰다.
- 명세 타당성(N1)은 BMB의 가장 큰 내부 위험이다. BSB 우선순위를 올리고 게이밍(H-GAME)과 함께 잰다.

## 결과

- DESIGN.md §2·§3·비목표, ROADMAP 미션 목표(G7)와 페이즈 표, 백로그(2A-11~2A-15, 1B-40, 1B-41, 2D-19, 2D-20, 2H-04, 2H-05, 3A-06~3A-08)가 바뀐다.
- 되돌리려면 이 ADR을 대체하는 ADR이 필요하다(사람 승인).
