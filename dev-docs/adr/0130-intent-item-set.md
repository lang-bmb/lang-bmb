# ADR-0130: H-INTENT 항목 집합의 동결과 그 한계

- 상태: 채택(자율 채택, AUTONOMY §4 "결정 기록": ADR-0078이 정한 가설의 과제 집합 동결. 판정 기준은 바꾸지 않는다)
- 날짜: 2026-11-12
- 관련: ADR-0078(H-INTENT), ADR-0128(H-REVIEW 집합과 같은 하네스), ADR-0021(동결), `bench/intent`, `bmb examples`(T1-44c), 백로그 T1-44e·T1-44f

## 맥락

- ADR-0078은 H-INTENT를 "의도와 어긋난 명세를 심은 집합에서 (a) 코드+명세 검토와 (b) 명세+생성한 예시·반례 검토"로 재고, 확정 기준을 "(b)의 탐지율이 (a) 이상(D 안이면 같음)이고 (b)가 읽은 토큰이 (a)의 1/2 이하"로 동결했다.
- 예시·반례는 `bmb examples`가 계약만 읽어 결정론으로 만든다.

## 결정

1. **집합.** `bench/intent`: 동결된 BVB 과제 45개마다 항목 둘, 모두 90개. 기준 계약의 프로그램(무결 45)과 약한 계약의 프로그램(결함 45)이고 의도 문장은 같다. 손으로 쓴 것은 없다. `bench/review`의 하네스에 자료로 더했고 그쪽의 동결 파일은 그대로다.
2. **두 판.** (a) `code+spec`은 프로그램 전체(계약과 몸). 계약을 한 번 더 붙이지 않는다(붙이면 (a)가 커져 가설에 유리해진다). (b) `spec+examples`는 계약 텍스트와 `bmb examples`의 출력 그대로(JSONL, 기본 3입력)다. 예시는 한 번 만들어 커밋한 텍스트가 동결물이고, 만든 컴파일러 커밋은 `set.json`에 있다.
3. **프롬프트와 판정.** 프롬프트는 "계약이 의도를 보장하는가"를 묻고 `allowed`·`rejected`·`excluded`의 뜻, 행이 없거나 `undecided`가 있으면 도구가 만들지 못했다는 뜻임을 말한다. 답의 꼴과 판정은 ADR-0128과 같다. 확정·반증 규칙은 ADR-0078 그대로다.
4. **평가자는 모델 리뷰어뿐이다**(사람 결정 2026-11-11, `2H-05` 취소). 판정은 모델 리뷰어에 한한다.
5. **게이트.** `bench intent`: 구조, 프로그램 90개 증명과 라벨, 커밋된 예시가 지금 컴파일러의 출력과 같은지, 판의 결정성, 대본 리뷰어 둘, 판정 규칙. 예시 비교는 63초이고 세 번 같은 바이트였다. `bmb examples`의 출력이 바뀌는 컴파일러 변경은 이 시험에 걸린다: 정식 실행 전이면 다시 동결하고, 뒤라면 비교를 게이트 밖으로 옮기는 결정을 따로 한다.

## 결과

모두 모델 실행 전에 결정론으로 잰 값이다.

- **토큰 기준(1/2)은 이 집합에서 닿지 않는다.** (b)/(a) 토큰 비는 1.571(무결 1.402, 결함 1.749)이고 1/2 안의 항목은 없다. 예시 출력만 평균 222토큰으로 프로그램 전체(216토큰)보다 크다. 계약 텍스트만은 (a)의 0.39다. 이 집합이 낼 수 있는 판정은 "반증"이거나 "확정 아님"이다. 기준은 바꾸지 않는다.
- **라벨을 예시의 겉모습으로 읽을 수 있다.** "한 입력에 `allowed` 결과가 둘이면 결함"이라는 규칙이 계약과 의도를 읽지 않고 90개 중 82개를 맞힌다(탐지 42/45, 오경보 5/45). 이것은 예시가 주려던 신호(명세가 결과를 정하지 않음)이기도 하지만, 의도가 여러 결과를 허락하는 과제(무결 5개)에서는 틀린다. (b)의 탐지율은 이 규칙의 값(93%)과 함께 읽는다.
- **무결 항목이 예시를 덜 받는다.** `allowed` 행이 없는 항목이 무결 10, 결함 2다(재귀 술어의 계약에서 해법기가 모형을 못 찾음). 항목을 빼서 고르게 만들지 않았다.
- **결함은 한 종류다.** 45개 모두 명세가 모자란 것(약한 계약)이다. ADR-0078의 "다른 뜻"(틀린 것을 말하는 계약, 지나치게 좁은 `requires`)은 없다.
- 토큰 축과 다른 종류의 결함은 `T1-44f`(실제 크기의 프로그램에서 도출한 집합)로 넘긴다. 예시 출력을 줄이는 것(요약 행의 `rlimit` 같은 독자에게 소음인 필드, 입력 수)은 도구 표면의 결정이라 그때 함께 본다.
- 실제 모델 실행은 측정 머신에서 한다.
