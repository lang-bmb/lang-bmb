# ADR-0016: 첫 마일스톤 범위: 언어 부분집합과 도구 질의

- 상태: 채택
- 날짜: 2026-10-24
- 관련: DESIGN.md 전체, ADR-0009·0012·0015, genesis §5·§6-1

## 맥락
첫 마일스톤(M1)은 "에이전트가 파일 없이, 테스트 없이, 증명된 코드를 쓴다"를 수십 개 정의 규모에서 측정한다(genesis §5). 그러려면 최소 관통 경로(파싱 → 타입·소유권 검사 → 검증 조건 → Z3 → LLVM IR)에 들어갈 언어 부분집합과, 에이전트가 쓸 도구 질의 목록이 먼저 정해져야 한다.

선정 기준은 셋이다.
1. 원칙 4(증명 게이트)와 원칙 6(도구 경유)을 *측정 가능하게* 만드는 데 필요한가.
2. 원칙 9(증명 → 검사 제거)를 IR에서 한 번이라도 보여 줄 수 있는가.
3. 빼도 위 둘이 성립하면 뺀다.

## 결정

### 1. 언어 부분집합

**포함**

| 영역 | 포함 항목 | 비고 |
| --- | --- | --- |
| 구성 단위 | `mod 이름 { ... }` 선언 | 파일 경로와 무관. 단위마다 한 줄 요약 필수(L0용) |
| 정의 | `fn`, `spec fn` | `spec fn`은 기본 불투명 |
| 타입 | `i64`, `u64`, `usize`(64비트), `bool`, `()` | 모든 지역 변수 타입 명시 |
| 참조 | 인자 위치의 `&[i64]`, `&mut [i64]`만 | 2차 참조(ADR-0015). 저장·반환 불가 |
| 문장 | `let`/`let mut`(타입 필수), 대입, `if`/`else`, `while` | 정규형 하나(원칙 8) |
| 산술 | `+ - * / %` (무오버플로·비영 증명 필수), `wrapping_add/sub/mul` | `as` 변환 없음 |
| 인덱싱 | `a[i]` (범위 증명 필수), `a.len()` | 검사 제거 시연 대상 |
| 호출 | 경로로 확정되는 직접 호출, 자기 재귀 | 메서드 탐색·auto-ref 없음 |
| 명세 | `requires`, `ensures`, 이름 붙은 결과 `-> (r: T)`, `invariant`, `decreases`(루프·재귀 필수), `old(x)`, `forall`+명시 트리거, `assert` | 계약 절은 이름 붙은 술어(`spec fn ... -> bool`) 호출만 허용 |
| 증명 문맥 | 정의마다 사용할 사실 선언(문법 미정, 예: `#[uses(p, q)]`) | 선언 밖 사실은 Z3에 넘기지 않음 |
| 효과 | `#[effects(pure)]`, `#[effects(io)]` | 모든 `fn`에 필수 |
| 경계 | `io` 내장 1개(`print_i64`) | 미증명 면적·테스트 필요 면적 1로 집계 |

**제외 (M1 이후)**

- 구조체·열거형(`Option` 포함), 제네릭, trait·impl
- 힙·`Vec`·문자열, 소유권 이동이 의미를 갖는 타입 전반
- 탈출구(`assume`, `external_body`, `unsafe`). M1의 미증명 면적은 `io` 경계뿐이다
- 근거 선언(ADR-0006) 문법, 확장 맵, 최적화 패스, 셀프호스팅

구조체·열거형은 M1 측정 직후 첫 확장 후보로 둔다. 에이전트 과제에서 `Option` 부재가 가장 먼저 걸릴 것으로 본다.

### 2. 도구 질의

모든 출력은 정규화된 JSON이다. 키 정렬, 시각·경로 같은 비결정 요소 없음. 같은 코드면 바이트 단위로 같은 결과가 나와야 한다.

**읽기**

| 질의 | 맵 | 돌려주는 것 |
| --- | --- | --- |
| `units` | L0 | 구성 단위 계층, 이름, 한 줄 요약 |
| `surface(def)` | L1 | 시그니처, 계약 술어 이름, 효과, 증명 상태 |
| `edges(def, 방향, 깊이)` | L2 | 해석이 끝난 호출 엣지(정·역방향, 전이) |
| `slice(def)` | — | 본문 + 의존 계약(+ 선언된 증명 문맥의 술어 정의). 크기와 예산 대비 비율 |
| `find(이름)` | L0 | 정의 위치와 해시. 이름 하나에 정의 하나 |
| `contracts(술어)` | 계약 뷰 | 이 술어를 보장하는 곳과 요구하는 곳 |
| `status` | — | 정의별 증명 상태, 미증명 면적, 테스트 필요 면적 |

**쓰기**

| 질의 | 동작 |
| --- | --- |
| `tx.begin` | 트랜잭션 시작 |
| `tx.put(def, 코드)` | 정의 추가·교체 |
| `tx.remove(def)` | 정의 삭제 |
| `tx.commit` | 구조·타입 유효성 검사 후 반영. 실패 시 전체 거부 + 구조화 진단(ADR-0009) |
| `tx.abort` | 폐기 |
| `build` | 증명 게이트 → LLVM IR → 바이너리. unknown·timeout·솔버 부재는 실패 |

**진단:** JSONL, 안정 오류 코드, 다중 오류 보고. 반례가 있으면 구체 입력값을 같이 준다.

M1에서 제외: 자동 채움, 보존형 리팩터링, 사전 영향 분석, 재사용 검색(DESIGN.md §8.2). 측정에서 필요가 확인되면 추가한다.

### 3. 완료 기준

1. 증명 게이트가 기본이고 끌 수 없다. unknown·timeout·솔버 부재로 빌드가 실패함을 회귀 코퍼스로 보인다.
2. 같은 코드에 대해 맵(L0~L2)과 모든 질의 출력이 두 번 실행에서 바이트 단위로 같다.
3. 증명된 범위 사실로 인덱스 범위 검사가 사라진 것을 LLVM IR에서 확인한다. 증명되지 않은 계약에서는 `llvm.assume`이 나오지 않는다.
4. 동결된 과제 집합(수십 개 정의 규모)에서 다음을 재시도 없이 측정해 커밋한다: 탐색 정확도, 질의당 토큰, 1회 성공률, Rust 습관 오류율, 미증명 면적.

### 4. 세부 결정

| # | 질문 | 결정 |
| --- | --- | --- |
| O1 | 컴파일러를 무슨 언어로 쓰나 | Rust. 셀프호스팅은 의미론 안정 후(ADR-0012) |
| O2 | Z3 연결 방식 | SMT-LIB 텍스트를 프로세스로 전달. `rlimit` 고정, 질의 텍스트가 곧 캐시 키 |
| O3 | LLVM 연결 방식 | 텍스트 IR 생성 후 LLVM 도구로 컴파일(v0 흡수 항목). 바인딩 없음 |
| O4 | 도구 계층의 노출 방식 | MCP 서버 + 같은 기능의 CLI. 둘 다 같은 JSON |
| O5 | 조기 `return` 허용 여부 | 정규형 원칙상 꼬리 식 하나만. 측정에서 Rust 습관 오류가 크면 재검토 |
| O6 | 슬라이스 예산의 단위와 값 | 토큰 수. 값은 M1 측정 후 정한다(M1에서는 계산·보고만, 거부는 안 함) |
| O7 | 증명 문맥 문법 | 속성 형태(`#[uses(...)]`)로 "더 장황한 Rust"를 유지 |

## 근거
- 정수·슬라이스·루프만으로 증명 게이트, 무오버플로, 범위 검사 제거, 종료성을 모두 보일 수 있다. M1의 가설을 측정하는 데 구조체·제네릭은 필요하지 않다.
- 효과는 `pure`·`io` 두 개만으로도 테스트 필요 면적 산출(ADR-0003)을 보여 줄 수 있다.
- 탈출구를 아예 빼면 M1의 신뢰 기반이 `io` 경계 하나로 고정되어, 미증명 면적 측정이 단순해진다.

## 결과
- M1 과제 집합은 정수·배열 알고리즘(탐색, 정렬 검사, 누적, 점화식 등)에 한정된다. 이 편향은 측정 보고에 명시한다.
- 이 ADR이 채택되면 DESIGN.md는 바꾸지 않는다. 범위 결정이지 설계 변경이 아니다.
