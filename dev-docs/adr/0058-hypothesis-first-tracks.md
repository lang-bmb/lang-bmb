# ADR-0058: 가설 우선 트랙 재설정(T0~T5)과 수요 기반 언어 페이즈

- 상태: 채택 (사람 승인 2026-10-28: 트랙 재설정 "채택", 측정 경로 "CLI 파일럿 먼저", 언어 후보 셋의 ADR 초안 진행)
- 날짜: 2026-10-28
- 관련: ADR-0021(측정 절차), ADR-0034(미션 목표), ADR-0037(부트스트랩), ADR-0040(가설), ADR-0045(판단 기준). 논의 기록 `dev-docs/reviews/direction-2026-10-28.md`

## 맥락

v2 리셋 뒤 4일 동안 언어 페이즈 일곱(2B·2C·2G·2S·2T·2O·2K)을 닫았다. 그러나 모델이 있어야 재는 것은 데이터가 0이다.

- 미션 목표 G2·G3·G5·G8
- ADR-0040 가설 여섯: H-SPEC, H-ORACLE, H-GAME, H-FAMILIAR, H-SCALE, H-REUSE

모델 실행 경로가 "사용자 머신 + 유료 API" 하나뿐이고, 그 경로가 10-24부터 막혀 있다(1E-10 🚫). 그 결과 genesis §3.5의 첫 운영 규칙("차별점 가설은 그 위에 쌓기 전에 최소 실험으로 측정한다")을 어기고 있다. 귀속 층은 프로세스다(JUDGMENT §3).

같은 논의에서, 도구가 읽기·쓰기를 맡는다는 전제 아래 인간용 구성(파일, 네임스페이스, 이름, 가시성, 상속, 인터페이스)의 필요성을 다시 따졌다. 그 결과로 새 가설 아홉을 등록했다(논의 기록 §6.2).

## 결정

### 1. 트랙

웨이브 W0~W6(BACKLOG 실행 계획)을 다음 트랙으로 대체한다.

| 트랙 | 목적 | 끝나는 조건 |
| --- | --- | --- |
| T0 측정 경로 | 모델 데이터가 흐르게 한다 | 동결 과제(m1·m1b·BVB·BRB)의 첫 정식 결과 커밋, 미션 목표값 확정(ADR-0034) |
| T1 가설 | 차별점과 AI 네이티브 구성을 판정한다 | 가설 등록부의 모든 가설이 확정·반증·보류(사유) 중 하나 |
| T2 언어 완성 | 정석 프로그램을 쓸 수 있는 언어 | 각 페이즈의 통과 기준 |
| T3 공인 벤치 | 외부가 인정하는 잣대로 능력을 증명한다 | 정확성(BVB, HumanEval·MBPP 이식)과 성능(Computer Language Benchmarks Game)의 동결과 측정 |
| T4 라이브러리 | 공인 시험 벡터가 있는 증명된 라이브러리로 실용성을 증명한다 | 라이브러리마다 전부 증명, 공인 벡터 통과, Rust 크레이트 대비 속도·크기 표 |
| T5 자립 | ROADMAP 4단계 | 4단계 통과 기준 |

**웨이브 대응.**

| 옛 웨이브 | 새 트랙 |
| --- | --- |
| W0(BCB) | T1 |
| W1·사용자 트랙 | T0 |
| W4b의 남은 언어 페이즈 2U·2N·2M | T2 |
| W5 | T5 |
| W6 | T5 뒤 |

### 2. 측정 경로: 파일럿 먼저

사람의 결정에 따라 Claude Code CLI로 파일럿 실행을 먼저 한다(`bench/pilot/`).

**파일럿이 지키는 것**

- 동결 과제와 MANIFEST
- 시스템 프롬프트(`prompt.md`)
- 도구는 `bmb mcp`뿐
- 40회 호출 한도
- 과제당 한 세션, 재시도 없음
- 하네스와 같은 판정

**파일럿이 지키지 못하는 것**

- 에이전트 루프, 캐시, 추론 설정을 CLI가 쥔다.

**규칙**

- 파일럿 결과는 ADR-0021 측정이 아니다. 행마다 `"pilot": true`를 붙인다.
- 문서의 주장 근거로 쓰지 않는다(C3).
- 방향 판단과 가설 우선순위에만 쓴다.

정식 경로(API 키를 시크릿으로 둔 자동 실행, `bench/run_models.py --budget`)는 여전히 권장안이다. 사람이 승인하면 전환한다.

### 3. 수요 기반 언어 페이즈

- T2의 새 페이즈는 둘 중 하나가 있을 때 연다.
  - T3·T4의 구체 수요: 쓰려는 벤치 프로그램이나 라이브러리가 그 기능을 필요로 한다.
  - T1의 판정: 가설이 언어를 바꾸라고 가리킨다.
- JUDGMENT §7의 결함("정석 Rust 프로그램을 쓸 수 없다")은 수요와 상관없이 결함으로 남는다.
- 진행 중인 2N은 계속한다. 비트 연산은 T4의 SHA-256·CRC-32가 필요로 한다.

### 4. 가설 등록부

- 등록부는 ROADMAP "가설 등록부" 절에 둔다. ADR-0040의 아홉과 논의 기록의 아홉이 들어간다.
- 상태는 넷이다: 미측정, 결정론 근거, 파일럿, 확정·반증.
- 진척이 없어 판정을 못 한 가설은 미측정으로 둔다. 판정을 추정하지 않는다.
- 페이즈 종료 감사(AUTONOMY §3.2)에 "가설 등록부 변화"를 넣는다.

### 5. 언어 후보의 ADR 초안

T1에서 나온 언어 변경 후보 셋을 "제안" 상태의 초안으로 쓴다. 채택은 각각 따로 승인받는다.

- ADR-0059: 해시 참조(H-ID)
- ADR-0060: 타입 불변식(H-ENCAP)
- ADR-0061: `f64`(T3 수요)

## 근거

JUDGMENT §10 형식의 권장안은 논의 기록 §7.1에 있다. 요약하면 다음과 같다.

- 원인이 프로세스에 있으므로 프로세스를 고친다(§2.1).
- 정석은 평가 파이프라인의 자동화다(S1).
- 결정적 기준은 증거가 지속적으로 생기는가다(S5).

파일럿은 정석 경로를 기다리는 동안 방향을 판단할 데이터를 주는 표시된 임시 조치다(JUDGMENT §2.5). 해제 조건은 정식 경로의 승인이다.

수요 기반 페이즈 규칙의 근거는 genesis §3.5다. v0는 핵심 가설을 검증하기 전에 기능과 생태계를 넓혔다. 수요가 있는 기능만 열면 언어의 크기가 측정과 벤치의 진행에 묶인다.

## 결과

- ROADMAP에 "트랙(ADR-0058)"과 "가설 등록부" 절이 생긴다. 웨이브 표는 역사 기록으로 남는다.
- BACKLOG에 트랙 태스크(`T0-`·`T1-`·`T3-`·`T4-` ID)가 생기고, 백로그 검사(`scripts/check_backlog.py`)가 그 ID를 받는다.
- 파일럿 실행은 사람이 결정한 범위 안에서 이 계정의 Claude Code 사용량을 쓴다. 정식 경로는 승인 대기다.
- 되돌리려면 이 ADR을 대체하는 ADR이 필요하다(사람 승인).
