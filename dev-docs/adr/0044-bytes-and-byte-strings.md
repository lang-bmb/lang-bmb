# ADR-0044: 바이트 `u8`, 바이트 문자열 리터럴, 바이트 출력과 바이트 라이브러리

- 상태: 채택 (2026-10-25. 2S 착수 승인과 권장안 채택 지시에 따름, 백로그 2S-03). §5의 `"..."`·`'a'`·`String`·`&str`·`char` 거부는 대체됨(ADR-0050: 바이트 API는 그대로)
- 날짜: 2026-10-25
- 관련: DESIGN.md §4.1·§5, ADR-0015(2차 참조), ADR-0016, ADR-0017 §3, ADR-0022, ADR-0028, ADR-0031, ROADMAP 2S, 백로그 2S-01, 측정 `dev-docs/measurements/selfhost-gap.md`(4A-01)

## 맥락
셀프호스팅 격차 분석(4A-01)에서 어떤 페이즈도 덮지 않는 필수 기능 첫째가 바이트와 문자열이었다(`selfhost-gap.md` §3 (a)). 현재 컴파일러는 `String` 651곳, `&str` 294곳, `u8` 89곳, 문자열 리터럴 2,212개(45KB)를 쓰고, 출력은 사실상 전부 기본 `Display`(정수·문자열)를 덧붙인 텍스트다(같은 문서 표). 렉서부터 바이트가 필요하다.

지금 BMB에는 바이트 타입이 없다. 문자 리터럴 `'a'`는 E0101(수정 없음), 식 자리의 `"..."`는 일반 구문 오류(E0103)다. 출력은 `print_i64`·`print_u64`(줄 단위 정수)뿐이다. 2G(ADR-0031)로 `Vec<T>`이 들어와 가변 크기 버퍼는 이미 있다.

격차 분석의 권고는 문자열 타입을 새로 만들지 않고 `Vec<u8>` + (시작, 길이) 핸들로 쓰고, 문자 타입 없이 바이트로 처리하는 것이다(UTF-8 문자 수는 연속 바이트가 아닌 바이트를 세어 얻는다).

## 채택 시 확인 (2026-10-25)
- 진단 번호 E0234가 `compiler/src/diag.rs`에서 비어 있음을 확인했다.
- 열린 질문은 제안대로 둔다: 자동 포함 없음(4B), 정렬된 맵과 입력은 이 ADR 밖.

## 결정

### 1. `u8`
- 정수 타입 `u8`(범위 0..=255)을 더한다. 산술·비교·`wrapping_*`·`checked_*`·`saturating_*`·나눗셈 의무는 `u64`와 같은 규칙이고 범위만 다르다(넘침 E0803).
- 변환은 ADR-0028의 형태 그대로다. `u8::try_from(x).unwrap()`은 `0 <= x <= 255` 의무(E0815), `u8`에서 `u64`·`usize`·`i64`로는 의무가 없다. 정수 리터럴은 기대 타입이 `u8`이면 0..=255여야 한다(기존 리터럴 범위 진단).
- 메모리에서 1바이트(LLVM `i8`)다. 배열·`Vec`·구조체 필드·열거형 페이로드의 원소가 될 수 있다. `Vec<u8>`이 바이트 버퍼다.
- 명세에서는 다른 정수와 섞인다(ADR-0022).

### 2. 바이트 리터럴과 바이트 문자열 리터럴
- `b'a'`는 `u8` 값이다. 이스케이프는 `\n` `\r` `\t` `\\` `\'` `\"` `\0` `\xHH`(Rust와 같음).
- `b"..."`은 `&[u8]`이다. 참조는 2차라(ADR-0015) **호출 인자 자리에서만** 쓴다(그 밖은 E0409, `v.as_slice()`와 같은 규칙). 원소는 ASCII 문자와 위 이스케이프다(Rust와 같음: 비ASCII는 `\xHH`).
- 버퍼에 넣는 것은 라이브러리 `bytes::extend(&mut v, b"...")`다(§4).
- 증명: 리터럴은 길이가 상수이고 원소가 하나하나 알려진 배열이다(`store` 연쇄). 코드 생성: 모듈의 private 상수 전역, 인자로는 (포인터, 길이).

### 3. 바이트 출력
- 내장 `print_bytes(s: &[u8])`(효과 `io`): 바이트를 그대로 표준 출력에 쓴다(줄바꿈을 붙이지 않는다). Rust의 `std::io::stdout().write_all(s)`에 대응한다. `print_i64`·`print_u64`처럼 맵의 `io` 경계 간선이다.

### 4. 라이브러리 `bytes`(BMB로 쓰고 증명)
- 저장소의 `lib/bytes.bmb`, 단위 `bytes`. 컴파일러에 묶지 않는다: 쓰는 프로그램이 파일을 함께 넘긴다(`bmb build lib/bytes.bmb app.bmb`). 꾸러미·자동 포함은 4B에서 정한다.
- 함수(모두 계약과 함께 증명): `eq(a, b) -> bool`, `starts_with(s, p) -> bool`, `find(s, p) -> Option<usize>`(첫 위치), `extend(v: &mut Vec<u8>, s: &[u8])`(Rust `extend_from_slice`), `push_u64(v: &mut Vec<u8>, x: u64)`·`push_i64(v: &mut Vec<u8>, x: i64)`(10진), `parse_u64(s) -> Option<u64>`(10진, 넘치면 `None`).
- 나누기·조각은 핸들로 쓴다: `find`가 위치를 주고 조각은 (시작, 길이)다. 조각을 값으로 돌려주는 함수는 두지 않는다(참조는 반환할 수 없다).

### 5. 거부할 Rust 습관과 진단(채택 시점에 `diag.rs`에서 비어 있음을 확인한 번호)

| 습관 | 처리 | 코드 |
| --- | --- | --- |
| 식 자리의 `"..."`(`&str`) | `b"..."`로 기계 교체(비ASCII는 `\xHH`) | E0234(신규) |
| `'a'`(`char`) | 기존 E0101에 `b'a'` 기계 교체 추가(ASCII일 때) | E0101(기존) |
| `String`, `&str`, `char` 타입 | 기존 E0402, 안내: `Vec<u8>`, `&[u8]`, `u8` | E0402(기존) |
| `format!`, `println!` | 기존 E0202, 안내에 `bytes::push_u64`·`print_bytes` 추가 | E0202(기존) |
| `s.len()` 등 슬라이스 메서드 | 그대로(`&[u8]`은 슬라이스) | — |

### 6. 테스트·퍼저
- 코퍼스: `tests/check/err`(위 표), `tests/verify/pass|fail`(`u8` 산술·변환 의무, 리터럴 내용), `tests/run`(바이트 출력, 라이브러리를 쓰는 프로그램).
- 라이브러리 `lib/bytes.bmb`는 게이트에서 전부 증명된다.
- 퍼저: 부호 없는 산술 퍼저(1B-33, 2C-04)에 `u8` 값과 변환을 넣고, `Vec` 퍼저(2G-05)에 `Vec<u8>`과 바이트 문자열 인자를 넣는다. 2S 통과 기준의 "퍼저가 다룬다"다.

## 근거(검토한 대안)

| 안 | 판정 |
| --- | --- |
| **`u8` + `Vec<u8>` + 인자 자리 바이트 문자열(채택 제안)** | 새 값 타입이 하나(`u8`)뿐이고 나머지는 2G의 `Vec`, 슬라이스, ADR-0015 규칙을 그대로 쓴다. 증명 인코딩은 기존 (배열, 길이) 쌍이다 |
| `String`·`&str`(UTF-8 불변식) | 유효 UTF-8 불변식을 증명에 들이거나 실행 시 검사해야 한다. 컴파일러의 문자열은 사실상 ASCII와 바이트 비교라(4A-01) 얻는 것이 적다. 기각 |
| `char` 타입 | 컴파일러가 문자를 쓰는 곳은 열 번호 계산뿐이다(`chars()` 14곳). 바이트로 처리할 수 있다. 기각 |
| 라이브러리를 내장 메서드로(`v.extend_from_slice(s)` 등) | 증명 인코딩과 코드 생성이 메서드마다 늘어난다. BMB로 쓰고 증명하면 신뢰 기반이 늘지 않고, 4B(라이브러리)의 첫 사례가 된다 |
| `print_str` 같은 줄 단위 출력 | 출력 조립은 버퍼 + 한 번의 쓰기가 기본이다(4A-01: `format!`·`push_str`). 바이트 그대로 쓰는 함수 하나면 된다 |

## 결과
- 출력이 정수 줄에서 바이트 스트림으로 넓어진다. 실행 프로그램이 텍스트를 만들 수 있다.
- 라이브러리 파일이 처음 생긴다(`lib/`). 자동 포함이 없으므로 쓰는 쪽이 넘긴다(4B에서 다시 본다).
- `u8` 산술은 넘침 의무가 자주 생긴다(255). `wrapping_*`·`checked_*`가 이미 있다.

## 열린 질문
1. `bytes` 라이브러리를 프로그램에 자동으로 포함할지(4B).
2. 정렬된 맵의 바이트 문자열 키(4A-01 (b))는 이 ADR 밖이다.
3. 표준 입력·파일 읽기(4A-01 (c))는 이 ADR 밖이다. 입력이 없으면 렉서는 리터럴로 시험한다.
