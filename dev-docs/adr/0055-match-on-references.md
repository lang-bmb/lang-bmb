# ADR-0055: 참조에 대한 `match`와 참조 바인딩

- 상태: 채택 (2026-10-27, 자율 채택: AUTONOMY §4 "기존 ADR 범위 안의 구현 수준 결정", 백로그 2O-02)
- 날짜: 2026-10-27
- 관련: ADR-0015(2차 참조), ADR-0026 §3(`match`), ADR-0047 §1·§2(소유 타입, 재귀 타입), ADR-0054, 백로그 2O-02

## 맥락
재귀 자료(ADR-0047)를 읽는 함수는 `&Expr`을 받아 갈래마다 하위 값을 본다. Rust에서 이것은 `match e { Expr::Add(a, b) => .. }`(기본 바인딩 모드, RFC 2005: `a: &Box<Expr>`)나 `match &*e`로 쓴다. `match *e { Expr::Add(a, b) => .. }`는 참조 뒤에서 `Box`를 꺼내는 이동이라 Rust도 거부한다(E0507).

지금까지 BMB는 `match`의 피검사 값이 열거형 값이어야 했다(참조는 E0423, 수정 `*r`). 이동하는 페이로드가 없을 때는 `match *r`이 복사로 충분했지만, 소유 페이로드(2O-01부터 `Box`)를 묶으려면 참조를 거쳐 읽는 수단이 필요하다. 또 `&`는 인자 위치에만 올 수 있었다(E0409).

## 결정
- `match`의 피검사 값으로 참조를 받는다: `&E` 타입의 식(`match r`, `r: &E`)과 피검사 자리의 `&식`(`match &n.next`, `match &**z`). 이 경우 각 바인딩은 그 페이로드를 가리키는 참조다: 페이로드 타입 `P`에 대해 바인딩은 `&P`(Rust의 기본 바인딩 모드와 같다). 정수 페이로드도 `&i64`이고 값은 `*n`으로 읽는다(Rust는 일부 연산에서 자동 역참조하지만 BMB는 쓰지 않는다: 의미는 같고 받는 프로그램이 더 좁다). `&Box<E>`를 `&E` 매개변수에 넘길 때도 역참조를 쓴다(`f(&**a)`; Rust의 역참조 강제 변환은 쓰지 않는다).
- 참조 바인딩은 2차 참조 규칙(ADR-0015)을 따른다: 지역·필드·결과에 담을 수 없고 인자로 넘기거나 읽기만 한다. 참조 `match`는 피검사 값을 이동하지 않는다.
- `&mut E`에 대한 `match`(바인딩 `&mut P`, 제자리 수정)는 아직 받지 않는다(E0207, 백로그 2O-04): 증명 인코딩이 페이로드 자리에 대한 쓰기를 아직 모른다.
- 소유 페이로드를 참조 뒤나 필드에서 값으로 묶는 `match *e`·`match n.next`는 E0413이고, 기계 수정이 참조 `match`(`match e`, `match &n.next`)로 바꾼다.
- 증명: 참조는 값과 같으므로(ADR-0015) 바인딩의 값은 페이로드 값 그대로다. 코드 생성: 공유 참조라 바인딩은 페이로드의 얕은 사본이고 해제하지 않는다.

## 근거
| 안 | 판정 |
| --- | --- |
| **Rust 기본 바인딩 모드의 참조 `match`(채택)** | Rust 표면과 의미 그대로(S1). 재귀 자료를 읽는 정석 형태 |
| `match *e`에서 소유 페이로드를 암묵적으로 참조로 묶기 | Rust가 거부하는 프로그램을 받는다(표면은 승계, 의미는 엄격화 원칙 위반) |
| 페이로드 읽기를 위한 접근자 함수만 허용 | 우회(ADR-0045 §3). 모든 재귀 타입에 보일러플레이트 |

## 결과
- 재귀 열거형을 받는 함수(평가기, 크기, 접기)를 `match e`로 쓴다(`tests/verify/pass/recursive`, `tests/run/expr_tree`).
- 참조 바인딩을 값 자리에 쓰면 E0401에 `*x` 안내가 붙는다.
