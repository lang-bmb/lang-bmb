# ADR-0108: 미결정 의무가 판정 정보를 싣는다: 범위를 줄인 반례 찾기, `uses` 탐색

- 상태: 채택(자율 채택, AUTONOMY §4 "결정 기록": 진단의 정보를 더하는 도구 층 결정. 게이트 판정·언어는 바뀌지 않는다. 아홉째 실행 계획, 사람 승인 "권장안 채택")
- 날짜: 2026-11-10
- 관련: ADR-0103 결정 5(산문 수리 제안 투자 멈춤), ADR-0078(H-REPAIR), ADR-0067·0069(탐침), ADR-0075(기저 인스턴스), DESIGN §6(미결정은 실패)·§8.2(결정론), 백로그 2D-32·2D-33·2D-34·T0-37

## 맥락

- sonnet `brb-write`(2026-11-04)의 토큰 88%가 미결정 응답을 한 번이라도 받은 세션 9개에 있다(AI 사용자 의견서 2026-11-10 §3, 세션 기록에서 재현). 미결정이 없던 15세션은 Rust의 2.2~2.8배다.
- 그 실행의 미결정 `write` 50건을 지금 컴파일러로 재생하면 45건이 여전히 미결정이다(rlimit 28, 불완전 10, 기타 7). ADR-0095·0096이 이 몫을 줄이지 않았다.
- 미결정 응답에는 위치와 "결정하지 못함"만 있다. 에이전트는 자기 후보가 틀린 것인지 증명기가 못 따라온 것인지 알 수 없어 구조를 통째로 바꿔 다시 쓴다(`t14-dedup-sorted`: `write` 34번 중 22번 미결정, 정의 25개를 쌓고 지움).
- H-REPAIR(반례와 산문 수리 제안이 수리 반복을 줄인다)는 qwen 1회로 반증됐고, ADR-0103 결정 5는 산문 수리 제안에 새 투자를 멈췄다. 이 ADR이 더하는 것은 산문이 아니라 판정 결과다.

## 결정

1. **범위를 줄인 반례 찾기(2D-33).** 미결정으로 끝난 의무에 한 번 더 묻는다. 같은 인코딩에 입력의 범위만 더한다.
   - 정수 입력은 `-B..=B`, 길이가 정해지지 않은 배열·`Vec`·텍스트의 길이는 `0..=L`, 그 원소는 정수면 `-B..=B`. `B = 8`, `L = 4`로 고정한다.
   - 한도는 의무의 `rlimit`의 1/10이다. 탐침과 같은 고정 몫이다(ADR-0067).
   - `sat`이면 그 모델은 범위 없는 질의의 모델이기도 하다. 그래서 확정 반례다. 진단은 의무 자신의 코드(E0802·E0807 등)와 반례 값으로 낸다. 메시지에 "범위 안에서 찾은 반례"를 적는다.
   - `unsat`이면 E0811을 그대로 내고 `bounded` 필드에 `{"b":8,"l":4}`를 싣는다. 증명이 아니다. "이 범위에 반례 없음"이다.
   - 미결정이면 E0811 그대로다.
   - 게이트 판정은 바뀌지 않는다. 미결정은 실패이고, 확정 반례도 실패다.
2. **응답 안의 `uses` 탐색(2D-34).** E0811의 `fix`가 `#[uses(..)]`를 권하는 정의는 MCP의 `write`·`verify` 응답에서 `bmb uses`의 탐색을 그 정의 하나에 한해 돌린다. 재검증은 4번까지다. 결과(`proved`와 목록, 또는 `not_found`)를 같은 응답의 행으로 넣는다. CLI의 `bmb verify` 출력은 바뀌지 않는다(비용이 정의 수에 비례하기 때문).
3. **요청할 때만 켠다.** `bmb verify --bounded-search`와 `bmb mcp --undecided-info`(1과 2를 함께 켬)다. 기본은 꺼져 있어, 동결된 측정 집합과 게이트의 출력은 그대로다. 켠 실행은 질의 머리에 표지가 붙어 증명 캐시를 따로 쓴다. 기본값은 T0-37이 정한다. 압축 뷰(ADR-0068 §5)와 고정 문맥(ADR-0071 §4)의 전례와 같다.
4. **결정론.** 범위·한도·열거 순서를 고정하고 해법기 시드를 고정한다(§8.2). 같은 프로그램은 같은 응답을 받는다.
5. **가설 H-UNDECIDE(등록, 측정 전).** 미결정 응답에 판정 정보(1·2)를 더하면, 미결정을 한 번이라도 받은 작성 세션의 성공당 토큰과 `write` 수가 준다. 측정은 T0-37에서 한다.
   - 비교: `brb-write`·`bvb-write`에 서버 플래그 `--undecided-info` 하나만 더한 판 대 원판. 같은 커밋, sonnet 1회(ADR-0103 결정 3), qwen은 ADR-0103 결정 2의 순차 반복.
   - 반증: 성공당 토큰의 차이가 D(ADR-0077) 안이면 반증이다. 성공률이 D를 넘게 떨어져도 반증이다.

## 근거

| 안 | 판정 |
| --- | --- |
| **같은 인코딩 + 입력 범위(채택)** | `sat`이 그대로 확정 반례다(범위는 질의를 좁힐 뿐이다). 인코딩·판정 경로를 새로 만들지 않는다 |
| 작은 입력의 구체 실행(해석기) | 명세(양화, `spec fn`)를 실행할 해석기가 따로 필요하고, 증명기 인코딩과 뜻이 어긋날 수 있다 |
| 범위 없이 한도만 키움 | 미결정의 원인(불완전 이론, 비선형)은 한도로 풀리지 않는다. 비용만 는다 |
| 산문 안내를 더 씀 | H-REPAIR 반증, ADR-0103 결정 5 |

## 결과

- `verify`: 미결정 뒤 범위 질의(`set_bounded_search`), E0811의 `bounded` 필드, 범위 반례의 의무 코드 진단. `uses_fill::fill_uses_limited`, `mcp`: 응답 안의 `{"uses_search":..}` 행(정의마다 재검증 4번).
- 시험: `tests/verify.rs`의 `bounded_search_turns_undecided_into_a_verdict`, `tests/mcp.rs`의 `undecided_info_runs_the_uses_search_in_the_response`.
- 측정 판과 실행은 T0-37(증거 단계 2H-01 뒤, 측정 세션).
- 가설 등록부(ROADMAP)에 H-UNDECIDE.
