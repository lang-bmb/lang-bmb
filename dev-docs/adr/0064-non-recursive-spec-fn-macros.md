# ADR-0064: 비재귀 `spec fn`의 정의는 양화 공리 대신 매크로로 쓴다

- 상태: 채택 (자율 채택, AUTONOMY.md §4). ADR-0017 §4의 정의 공리 행을 비재귀 `spec fn`에 대해 보완한다. 뜻은 그대로이고 SMT에 쓰는 꼴만 바뀐다
- 날짜: 2026-10-29
- 관련: ADR-0017 §4(불투명 `spec fn`, 정의 공리), ADR-0023(기저 인스턴스 재시도), ADR-0061(`f64`), 백로그 T2-04

## 맥락

- ADR-0017 §4는 펼친 `spec fn`의 정의를 `∀ 인자. 범위(인자) ⇒ f(인자) = 본문`(트리거 `f(인자)`)으로 넣는다. 재귀든 아니든 같은 꼴이다.
- T2-04(`f64` 구현 중 발견): 정의 공리가 `(Array Int Float64)` 매개변수를 묶으면, 반례가 있는 질의를 Z3 4.15.4가 끝내지 못했다. 최소 재현은 공리 하나와 단언 다섯 개다. 원소가 `Int`이면 rlimit 240에 `sat`, `Float64`이면 382,936에 `unknown`(`incomplete (theory array)`). 그 뒤 기저 인스턴스 재시도(ADR-0023)가 답을 냈으므로 판정은 옳았지만, 실패 의무마다 수십만 rlimit을 버렸다.
- 같은 현상이 정수 쪽에도 있다. ADR-0023이 생긴 이유("거짓 계약이 펼친 술어 정의를 거치면 Z3가 모델을 만들지 못한다")가 이것이고, 실패 코퍼스의 반례 하나가 5,000,000까지 도는 경우가 남아 있었다(2N-02 보고의 `bf::or`).

## 결정

1. **재귀하지 않고 몸이 다른 `spec fn`을 부르지 않는 `spec fn`**(잎. 재귀 성분 `Tables::recursive`에 없고, 제네릭 인스턴스는 그 제네릭으로 판단한다)의 정의는 매크로다.
   `(declare-fun f!ext (정렬..) 결과)`와 `(define-fun f ((인자 정렬)..) 결과 (ite 범위(인자) 본문 (f!ext 인자..)))`.
   범위가 `true`이면 `f!ext` 없이 본문만 둔다.
2. **재귀 `spec fn`과 다른 `spec fn`을 부르는 `spec fn`은 그대로 양화 공리다.** 매크로는 자기 자신을 부를 수 없다. Z3는 매크로를 쓰는 곳마다 펼치므로 매크로가 매크로를 부르면 항이 곱으로 커진다. 처음 구현은 비재귀 전부를 매크로로 했는데, `lib/sha256.bmb`(라운드 함수가 시그마 함수들을 부른다)의 도달성 질의(공허 검사)가 rlimit 1,000,000 안에서 해법기 시간 수 분을 썼다. rlimit은 펼친 항의 단순화를 거의 세지 않는다. 잎만 매크로로 하면 펼친 크기가 원문에 선형이다.
3. **뜻은 같다.** 양화 공리는 범위 안에서 `f = 본문`이고 범위 밖에서는 아무것도 말하지 않는다. 매크로는 범위 안에서 본문이고 범위 밖에서는 해석하지 않는 `f!ext`의 값이다. 두 정의의 모델은 서로 대응한다(양화 공리의 모델에서 `f!ext`를 범위 밖의 `f`로 두면 매크로의 모델이고, 거꾸로도 같다). 그래서 증명되는 것과 반례가 있는 것이 같다. 범위 밖 인자에서의 뜻(백로그 2N-10)은 바꾸지 않는다.
4. **질의 조립:** 매크로로 정의된 기호는 선언하지 않는다(`needed_decls`). 정의는 자신이 쓰는 매크로 뒤에 온다(`relevant_axioms`의 의존 순서). 펼치지 않은 `spec fn`은 지금처럼 선언만 된다(불투명).

## 근거

- **원인과 귀속 층:** 해법기가 양화 정의 위에서 모델을 만들지 못하는 것이고, 층은 인코더다. 언어의 뜻은 바뀌지 않는다.
- **정석:** 비재귀 함수 정의는 SMT-LIB의 `define-fun`이 정석 꼴이다. 양화는 재귀처럼 매크로로 쓸 수 없을 때 쓴다. Z3의 `macro_finder`는 범위 조건이 붙은 우리 공리를 매크로로 알아보지 못했다(같은 질의에서 `unknown`, rlimit 383,042).
- **측정(T2-04, 같은 커밋):**
  - 최소 재현: `unknown` 382,936 → `sat` 1,397. 범위를 무시한 매크로는 1,261로 비슷했지만, 범위 밖의 뜻을 바꾸므로 택하지 않았다.
  - 실패 코퍼스 rlimit 합: 137,479,381 → 20,609,594(−85%, 잎 규칙. 비재귀 전부를 매크로로 했을 때는 −89%). 진단 코드와 위치는 모두 같다. 한 곳(`fail/generics.bmb`의 `fill_short`, 루프 불변식이 쓴 원소를 잊는 사례)은 해법기 미결정(E0811)이 반례가 있는 실패(E0802)로 바뀌었다. 반례 문구는 37곳이 다른 모델 값을 보인다.
  - 공허 검사(`proofs_are_not_vacuous`): 잎 규칙으로 138초(부하가 있는 공유 머신). 비재귀 전부를 매크로로 하면 `lib/sha256.bmb`에서 시간 한도를 넘었다.
  - 증명 코퍼스와 V4·V7은 `dev-docs/health/baseline.json`의 이 커밋 항목에 있다.

## 결과

- 질의 텍스트가 바뀌므로 증명 캐시는 한 번 비워지는 셈이다(키가 질의 텍스트). 캐시 형식은 그대로다.
- 기저 인스턴스 재시도(ADR-0023)는 재귀 정의에만 일이 남는다. 매크로 기호의 인스턴스는 정의로부터 이미 참인 등식이라 해가 없다.
- 되돌리기: `Prog::axiom`에서 매크로 갈래를 지우면 된다. 저장 형식과 언어는 바뀌지 않는다.
