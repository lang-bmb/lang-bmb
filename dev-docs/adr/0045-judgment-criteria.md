# ADR-0045: 판단 기준 — 원인 층에서 고치고 정석을 택한다, 비용은 기준이 아니다

- 상태: 채택 (2026-10-26, 사람 지시)
- 날짜: 2026-10-26
- 관련: `dev-docs/JUDGMENT.md`, DESIGN.md §2·§3·§4.1, ADR-0041, `dev-docs/AUTONOMY.md` §1·§4

## 맥락
권장안의 근거가 일정하지 않았다. 컴파일러의 한계를 코퍼스를 고쳐 피하거나(2G-05의 `k*k` → `3*k`, `primes`의 시작점 변경), 언어 표현력의 한계를 우회로 덮는 안(사용자 제네릭 없이 단형 맵)을 권하기도 했다. 작업량과 영향 범위가 암묵적인 기준으로 작동했다. 사람이 판단 기준을 명시적으로 정렬하라고 지시했다.

## 결정
1. 판단 기준을 `dev-docs/JUDGMENT.md` 한 곳에 둔다. 모든 권장안, 설계 결정, 태스크 도출과 검토는 그 기준으로 판단하고, 적용한 기준 번호를 적는다.
2. 문제는 원인이 있는 층(언어, 컴파일러, 도구, 프로세스, 자산, 외부, 사용자)에서 고친다. 다른 층에서 증상을 흡수하지 않는다.
3. 해는 제약(건전성, 결정론, 정직성, 정의)을 통과한 후보 가운데 정석성 → 근본성·일반성 → 일관성 → 목표 함수 → 증거 순으로 고른다.
4. 작업량, 영향 범위, 기존 자산 보존, 현행 규칙과의 일치, 승인 필요 여부, 지표 수치는 해를 고르는 기준이 아니다.
5. 0.x(안정성 정책 5B-01 채택 전) 동안 하위 호환 의무 없이 리팩터링을 언제나 허용한다.
6. ADR-0041의 수용 항목 "표현력 제한"은 "원리적으로 증명 대상이 될 수 없는 것만 근거 있는 탈출구로 둔다"는 뜻이다. 의도된 엄격화는 DESIGN §4.1 원장에 있어야 하고, 그 밖의 제한은 결함이다.

## 근거
- 증상을 다른 층에서 흡수하면 원인이 남아 같은 부류의 문제가 반복되고, 측정이 실제 능력을 가린다(벤치와 코퍼스가 컴파일러에 맞춰지면 C3 정직성도 깨진다).
- BMB의 사용자는 에이전트이고 표면은 Rust를 승계한다. 정석 해법을 표현할 수 없는 언어는 유추 손실과 우회 코드 비용을 에이전트에게 넘긴다.
- 0.x에는 외부 사용자가 없어 호환 비용이 없다. 지금 바로잡지 않은 구조는 안정성 정책 이후 비용이 된다.
- 검토한 대안: (1) 기준을 AUTONOMY.md에 섞기: "누가 결정하는가"와 "무엇이 최선인가"가 섞여 승인 필요 여부가 해 선택에 스며든다. (2) 비용을 동률 해소 기준으로만 두기: 동률은 드물고 기준으로 쓰는 순간 암묵 기준이 된다. 동률이면 일반성·단순성으로 가른다.

## 결과
- 기존 결정 가운데 컴파일러 한계를 코퍼스로 흡수한 것, 표현력 한계를 우회로 둔 것을 이 기준으로 다시 본다. 채택된 ADR을 바꾸게 되면 새 ADR로 한다.
- DESIGN.md §2 원장의 "표현력 제한"에 이 ADR을 가리키는 주석을 붙인다.
- 권장안에 "영향" 칸이 생기지만 판단 근거로는 쓰지 않는다.
