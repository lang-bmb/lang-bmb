# ADR-0047: 소유 타입 일반화: `Box<T>`, 재귀 타입, `Vec`을 담는 타입

- 상태: 제안
- 날짜: 2026-10-26
- 관련: ADR-0045, ADR-0015, ADR-0026 §1(재귀 타입 금지), ADR-0027, ADR-0031 §1·§2(`Vec`을 담는 구조체 제외, E0414), DESIGN.md §5, 점검 R6·R7, 백로그 2V-07

## 맥락
ADR-0026은 재귀 타입을 "힙은 2G"로 미뤘고, ADR-0031(2G)은 `Vec<T>`만 넣고 `Vec`을 담는 구조체와 `Vec<Vec<T>>`를 범위 밖에 두었다. 그 결과 구문 트리·JSON 값 같은 재귀 자료와 여러 버퍼를 가진 문맥 구조체를 정석 형태로 쓸 수 없고, 아레나·매개변수 펼치기 우회가 셀프호스팅 비용 "상"으로 잡혔다(`selfhost-gap.md` §4.1). 원장에 이 제한의 대가 항목은 없다. SMT 데이터타입은 재귀를 지원한다.

## 결정

### 1. 소유 타입
- **이동 타입:** `Vec<T>`, `Box<T>`, `String`(ADR-0050), 그리고 이것을 필드·페이로드·원소로 담는 구조체·열거형·배열. 그 밖의 값(스칼라, 이동 타입을 담지 않는 데이터 타입·배열)은 지금처럼 복사다. 분류는 구조적이고 결정론적이다(Rust의 `Copy` 파생을 쓰지 않는 ADR-0026의 값 의미를 이어 감).
- `Box<T>`: `Box::new(v)`, 읽기 `*b`·`b.f`(필드 투영은 구문으로 확정), 쓰기 `*b = v`·`b.f = v`. 참조 규칙(ADR-0015)은 그대로다: `&*b`는 인자 자리에서만.
- 재귀 타입: 자기 자신을 `Box`나 `Vec` 아래에만 담는 구조체·열거형(`enum Expr { Num(i64), Add(Box<Expr>, Box<Expr>) }`, `struct Node { kids: Vec<Node> }`). 직접 담으면 지금처럼 E0421.
- 중첩 컨테이너: `Vec<Vec<T>>`, `Vec<S>`(`S`가 이동 타입), `Option<Box<T>>`.

### 2. 이동과 해제
- ADR-0031 §2의 규칙을 모든 이동 타입으로 넓힌다: 값 쓰임이 이동, 이동 뒤 사용 E0413, 합류점의 "아마 이동" E0414(해제 지점이 텍스트로 정해진다: 실행 시 drop 플래그 없음).
- 지역 구조체에서 필드를 꺼내는 부분 이동은 Rust처럼 허용한다. 꺼낸 필드는 다시 대입하기 전까지 쓸 수 없고, 남은 필드는 블록 끝에서 해제된다. `&mut` 뒤의 필드는 꺼낼 수 없고 `std::mem::replace(&mut x.f, v)`·`std::mem::swap(&mut a, &mut b)`를 쓴다(Rust 표준. ADR-0031이 거부한 `mem::take`는 `Default` trait(ADR-0046) 뒤로).
- 해제는 타입별 drop glue로 재귀적이다(rustc와 같음). 순서는 Rust와 같다(필드 선언 순서, 원소 순서).

### 3. 증명 인코딩
- `Box<T>`는 값 `T` 그대로다(증명에서 보이지 않는다).
- 재귀 타입과 그것을 담는 타입은 SMT 데이터타입이다(ADR-0027 §3을 구조체에도 적용). 재귀 없는 데이터 타입은 지금의 필드 분해(ADR-0027 §1)를 유지한다. 두 인코딩의 경계와 안정성은 구현 때 V7·V4로 재고, 하나로 합치는 것이 나으면 그때 정한다.
- 원소가 이동 타입인 `Vec<T>`는 `(Array Int ⟦T⟧, Int)`다(⟦T⟧는 원소의 정렬: 데이터타입 또는 `(Array, Int)` 쌍의 데이터타입).
- 종료: 재귀 데이터의 함수는 `decreases x`(데이터 값)로 구조적 크기를 쓸 수 있다. 인코더가 타입마다 크기 `spec fn`을 만들고 하위 값의 크기가 작다는 사실을 준다(Dafny의 데이터타입 순위, Verus의 `height`).

### 4. 코드 생성과 런타임
- `Box<T>`는 `malloc`한 `T`의 주소다. 재귀 타입의 배치는 포인터로 끊긴다.
- drop glue는 타입별 내부 함수다(`@"bmb_drop.<type>"`). `Vec<S>` 해제는 원소마다 glue를 부른 뒤 버퍼를 푼다.
- 깊은 재귀 자료의 해제는 재귀 깊이만큼 스택을 쓴다(rustc와 같음). 스택 크기는 4C(시스템 인터페이스)에서 정한다.

### 5. 거부할 Rust 습관과 진단(번호는 채택 때 확정)
| 습관 | 처리 |
| --- | --- |
| `Rc`, `RefCell`, `Cell`, `Arc` | 거부, 안내: 소유 트리(`Box`·`Vec`) 또는 인덱스 핸들 |
| `&mut` 뒤 필드의 이동 | E0413 계열, 수정: `std::mem::replace(&mut x.f, v)` |
| 직접 재귀 `struct L { next: L }` | E0421 유지, 수정: `Box<L>` |

ADR-0031 §1의 "`Vec`을 담는 구조체·`Vec<Vec<T>>`는 범위 밖(E0402)"은 이 ADR이 채택되면 대체된다.

## 근거(검토한 대안)
| 안 | 판정 |
| --- | --- |
| **`Box`·재귀 타입·중첩 소유를 Rust 규칙으로, 해제는 정적 지점의 drop glue(채택 제안)** | Rust 표면과 의미 그대로(S1). E0414로 drop 플래그 없이 해제 지점이 텍스트에 고정되는 2G의 성질을 유지 |
| 아레나(`Vec<Node>` + `usize` 핸들)만 허용 | 우회(ADR-0045 §3). 핸들의 유효성이 증명 의무로 번지고, 정석 표현과 멀다 |
| `Rc`/`RefCell` | 공유 가변 상태가 프레임 조건과 별칭 분석을 깬다(ADR-0015의 근거). 원장 "수명"의 대가와 충돌 |
| drop 플래그로 "아마 이동" 허용 | Rust는 허용하지만 해제 지점이 실행 상태에 달린다. E0414의 대가(결정론적 해제, 런타임 플래그 없음)를 원장 항목으로 올리는 것을 함께 제안 |

## 결과
- 구문 트리·JSON·S-식을 재귀 열거형으로, 문맥을 여러 `Vec` 필드의 구조체로 쓸 수 있다(셀프호스팅 "상" 항목 두 개가 해소).
- DESIGN §4.1 원장에 행을 더한다: "이동 상태: Rust는 drop 플래그로 '아마 이동'을 허용 → BMB는 합류점에서 같은 상태 요구(E0414) → 해제 지점이 텍스트로 고정, 런타임 플래그 없음".
- 퍼저: `Vec` 퍼저를 소유 트리(삽입·제거·교체·`mem::replace`)로 넓히고 valgrind로 누수·이중 해제를 본다.

## 열린 질문
1. 재귀 없는 데이터 타입까지 SMT 데이터타입으로 통일할지(인코딩 하나, S3). 측정으로 정한다.
2. `Box<[T]>`·`Vec`의 `drain`류 연산: 필요가 생기면 따로.
