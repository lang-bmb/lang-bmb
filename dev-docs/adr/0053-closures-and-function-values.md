# ADR-0053: 클로저와 함수 값

- 상태: 제안
- 날짜: 2026-10-26
- 관련: ADR-0045, ADR-0046(제네릭과 trait), ADR-0047(소유 타입), ADR-0015(2차 참조), DESIGN.md 원칙 5·6·8, §4.1 "수명"·"다형성"·"호출 해석"·"효과", 점검 R14, 백로그 2V-16

## 맥락
BMB는 클로저를 "not supported in milestone 1"(E0207)로 거부한다. 원장의 근거는 "수명"(2차 참조)뿐이다. 참조를 캡처하는 클로저는 참조를 담는 값이기 때문이다. 이동 캡처 클로저, 캡처 없는 클로저, 함수 값은 원장 근거가 없다(점검 R14). 정렬 기준(`sort_by`), 탐색 술어, 순회처럼 동작을 인자로 넘기는 Rust 정석은 지금 함수를 복제하거나 열거형으로 동작을 고르는 식으로 우회한다.

검증 쪽 선례로 Verus는 클로저에 `requires`/`ensures`를 붙이고, 명세에서 `f.requires(args)`·`f.ensures(args, r)`로 함수 값의 계약을 말한다. ADR-0046이 제네릭과 trait 경계를 들였으므로 `Fn` 계열 경계가 그 위에 놓인다.

## 결정

### 1. 범위
| 넣음 | 뺌(사유) |
| --- | --- |
| 클로저 식 `move \|x: i64\| -> i64 { .. }`, 매개변수·결과 타입 표기 | 참조 캡처(비-`move` 캡처 클로저): 원장 "수명" |
| 캡처 없는 클로저 `\|x: i64\| -> i64 { .. }` | 클로저 반환 `-> impl Fn(..)`: 열린 질문 1 |
| 내장 trait `Fn`·`FnMut`·`FnOnce`를 경계로(`F: Fn(i64) -> i64`) | 함수 포인터 타입 `fn(i64) -> i64`: 동적 호출 대상(열린 질문 2) |
| 함수 항목을 값으로 넘기기(`apply::<_>(geo::norm, x)`) | `dyn Fn`, `Box<dyn Fn>`: ADR-0046 §6과 같음 |
| 클로저 계약 `requires`·`ensures`, 명세의 `f.requires(..)`·`f.ensures(.., r)` | 인자 위치 `impl Fn(..)`: 제네릭 매개변수와 같은 일(원칙 8), 기계 수정으로 바꾼다 |

### 2. 캡처와 소유
- 변수를 캡처하는 클로저는 `move`로 쓴다. Rust에서 `move` 없는 클로저는 참조로 캡처하므로, 같은 텍스트가 같은 뜻이려면(S1) `move`가 필요하다. 빠지면 E0245를 내고, 기계 수정이 `move`를 붙인다. 캡처가 없는 클로저의 `move`는 기계 수정이 지운다(형태 하나).
- `Copy` 값은 복사되고, 그 밖의 값은 클로저로 이동한다(ADR-0031 §2, ADR-0047). 클로저 값은 캡처를 필드로 가진 이름 없는 구조체와 같은 소유 규칙을 따르고, 해제 지점은 텍스트로 정해진다.
- 어떤 trait를 구현하는지는 Rust와 같다:
  - 캡처를 이동해 내보내면 `FnOnce`만 구현한다.
  - 캡처를 고치면 `FnMut`까지 구현한다.
  - 그 밖은 `Fn`을 구현한다.
  - 호출은 각각 `f(x)`(`f: F`, `F: FnOnce`), `f(x)`(`f: &mut F`), `f(x)`(`f: &F`)이고, 참조 매개변수는 2차 참조 규칙 그대로다.
- 매개변수·결과 타입은 표기가 정본이다(원장 "타입"). 생략하면 E0246을 내고, 기계 수정이 기대 경계(`F: Fn(i64) -> i64`)에서 채운다(원칙 6).
- 클로저와 함수 항목의 타입은 이름이 없다(Rust와 같음). 그래서 그 자리의 타입 인자는 `_`로 쓰고, 그것이 정본이다. 이것은 ADR-0046 §3(타입 인자 명시)의 유일한 예외다. 그 인자는 같은 호출의 값 인자로 결정론적으로 정해지고, 맵 L2는 해석된 클로저 노드를 기록한다.

### 3. 클로저가 바깥으로 나가지 않음
- 클로저 타입은 이름이 없고 클로저 반환(`impl Fn`)이 없으므로, 클로저 값은 만든 함수의 실행 중에만 존재한다. 클로저는 인자로 아래로 내려가거나, 같은 함수 안의 지역·구조체 필드에 담긴다.
- 이 성질이 §4의 종료 규칙과 §5의 캡처 사실의 근거다. 열린 질문 1을 열면 두 규칙을 다시 정한다.

### 4. 증명 인코딩
- 경계 `F: Fn(A..) -> R`이 있는 타입 매개변수는 비해석 정렬이다(ADR-0046 §4). 비해석 술어 `req_F(f, a..)`와 `ens_F(f, a.., r)`가 함께 생긴다. 명세의 `f.requires(a..)`·`f.ensures(a.., r)`가 이 술어다. 튜플 없이 인자를 그대로 나열한다(원장 "표현").
- 제네릭 함수 안의 `f(a..)` 호출:
  - 의무는 `req_F(f, a..)`다.
  - 결과 `r`은 새 기호이고, `ens_F(f, a.., r)`가 사실이다.
  - `FnMut` 호출은 `f`의 상태를 새 기호로 바꾼다. 상태 사이의 관계는 열린 질문 3이다.
- 클로저 식 `move |a..| -> (r: R) requires P ensures Q { body }`는 만든 지점에서 한 번 증명한다:
  - 전제는 `P`, 그 지점의 경로 조건, 캡처한 값에 대한 사실이다. `Fn`·`FnOnce`의 캡처는 바뀌지 않으므로 만든 지점의 사실이 그대로 성립한다. `FnMut`의 캡처는 바뀔 수 있으므로 `P`만 전제다.
  - 의무는 `Q`다.
  - `requires`·`ensures`가 없으면 각각 참이다(Verus와 같음).
- 클로저 타입 `C`로 인스턴스를 만들 때 `req_C`·`ens_C`는 그 클로저의 `P`·`Q`다. 이때 캡처는 클로저 값의 필드다. 피호출자의 전제에 있는 `f.requires(..)`는 그 정의로 펼쳐져 호출 지점의 의무가 된다.
- 함수 항목 값 `g`의 `req`·`ens`는 `g`의 `requires`·`ensures`다.
- 종료: 클로저 몸의 호출은 둘러싼 함수에 속한 호출로 콜 그래프에 넣고, 둘러싼 함수의 `decreases` 기준으로 확인한다. 이것이 건전한 근거는 §3이다(클로저는 둘러싼 호출보다 오래 살지 않는다). 함수 값 `g`를 넘기는 곳에는 둘러싼 함수에서 `g`로 가는 간선을 둔다. `F` 매개변수 호출에는 간선이 없다. 단형화한 인스턴스에는 함수 포인터와 `dyn`이 없으므로, 함수 값을 통한 재귀는 위 간선이 이루는 순환으로 모두 드러난다.
- 함수 값 `g`를 `g`와 같은 순환(콜 그래프의 강연결 요소)에 있는 함수 안에서 넘기면 E0249다. 피호출자가 어떤 인자로 `g`를 부를지 모르므로 `decreases`를 확인할 수 없기 때문이다. 안내는 측정 조건을 `requires`로 가진 클로저로 감싸는 것이다(`move |x: i64| -> i64 requires x < n { g(x) }`). 그러면 위 클로저 규칙으로 확인된다.

### 5. 효과
- 클로저의 효과는 몸에서 계산한다. 효과 주석은 붙지 않는다(식에는 속성이 없다).
- 제네릭 함수 안에서 `F`를 호출하는 효과는 그 함수가 선언한 효과에 들어 있어야 한다. 함수를 넘기는 쪽에서는 클로저 또는 함수 값의 효과가 피호출자의 선언 효과에 포함되는지 확인한다. 넘치면 E0608이다.
- 효과 다형성(효과 매개변수)은 넣지 않는다. 열린 질문 4.

### 6. 코드 생성
- 클로저는 캡처 구조체와 그 구조체를 첫 인자로 받는 함수 하나다.
- 제네릭은 단형화하므로(ADR-0046 §5) 호출은 모두 정적 호출이고 인라인 대상이다. 함수 항목 값은 크기 0 타입이다.

### 7. 맵과 도구
- 맵 L2에는 클로저 몸의 호출이 둘러싼 함수의 간선으로 들어간다. 함수 값을 넘기는 곳은 "값 사용" 간선이다.
- 클로저는 단위 안의 이름 없는 노드이고 노드 해시는 둘러싼 함수에 속한다.
- 기계 수정:
  - `move`를 붙이거나 지운다.
  - 매개변수·결과 타입을 채운다.
  - 인자 위치 `impl Fn(..)`을 제네릭 매개변수로 바꾼다(E0248).

## 근거(검토한 대안)
| 안 | 판정 |
| --- | --- |
| **이동 캡처 클로저 + `Fn` 계열 경계 + Verus식 계약, 단형화(채택 제안)** | Rust 표면 그대로(S1)이고 원장 "수명"과 양립한다. 호출 대상이 정적이다(원장 "호출 해석"). 검증 선례가 Verus다 |
| 지금처럼 금지 | 원장 근거 없는 제외(R14). 동작별로 함수를 복제하거나 열거형으로 디스패치하는 우회(ADR-0045 §3) |
| 참조 캡처 허용 | 클로저가 참조를 담는 값이 되어 2차 참조(ADR-0015)의 대가, 곧 수명 표기 소멸과 별칭 분석 단순화를 잃는다 |
| 함수 포인터·`dyn Fn` | 호출 대상이 실행 시 값이다. 콜 그래프와 종료 확인이 정적으로 닫히지 않는다(열린 질문 2) |
| 클로저 계약을 몸에서 자동 도출 | 몸이 바뀌면 계약이 따라 바뀌어 제네릭 정의의 증명이 흔들린다. 명시 계약이 Verus·Dafny의 정석이다 |

## 결과
- 진단:
  - 새 코드 E0245(`move` 없는 캡처, 기계 수정), E0246(클로저 타입 표기 생략, 기계 수정), E0247(클로저 반환과 함수 포인터 타입), E0248(인자 위치 `impl Fn`, 기계 수정), E0249(같은 순환 안에서 넘긴 함수 값), E0608(효과가 피호출자 선언을 넘는 함수 값).
  - E0207의 클로저 메시지는 없어진다.
  - 번호는 채택 때 `diag.rs`와 제안 ADR들의 잠정 번호에서 비어 있음을 다시 확인한다.
- 표준 라이브러리(4B)의 정렬·탐색이 `sort_by<F: Fn(&T, &T) -> Ordering>`처럼 쓰인다(`Ordering`은 내장 열거형).
- 퍼저: 데이터 퍼저에 캡처와 경계가 있는 고차 함수를 넣는다. 클로저 계약의 반례 재생으로 인코딩을 차분 확인한다.
- 구현 페이즈: 제네릭(2T) 뒤. 셀프호스팅 임계 경로에서의 위치는 채택 때 정한다.

## 열린 질문
1. 클로저 반환(`-> impl Fn(..)`): §3의 "바깥으로 나가지 않음"이 깨진다. 종료 규칙과 캡처 사실을 다시 정해야 한다(Dafny의 함수 값 `reads`·`decreases` 방식 참고).
2. 함수 포인터 `fn(..)`(핸들러 표 등): 동적 호출 대상이다. 계약을 타입에 붙이는 방식(Verus의 `FnSpec`)과 함께 정한다.
3. `FnMut` 상태 사이의 관계(누적 상태에 대한 추론): 첫 구현은 상태를 새 기호로 둔다. 필요한 정도는 셀프호스팅에서 잰다.
4. 효과 다형성: 순수 호출자와 IO 호출자가 같은 고차 함수를 쓰려면 필요하다. 사용 빈도를 2T 뒤에 잰다.
