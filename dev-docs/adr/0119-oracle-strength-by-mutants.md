# ADR-0119: H-ORACLE의 변이체 판(오라클 강도)

- 상태: 제안(백로그 T0-40. 초안 작성은 사람 승인 2026-11-11 "모두 승인, 권장안 채택"·D3, 채택은 승인 안건. 계산은 채택 뒤)
- 날짜: 2026-11-11
- 관련: ADR-0040(가설과 반증 조건), ADR-0034·0115(G5, 변별 불가 규칙), ADR-0111(H-ORACLE은 존재 가설, 이월은 한 번), ADR-0112(차이의 구간), ADR-0103 결정 3(기준 모델), 백로그 2H-04(`final_sources`), 2A-10(BSB의 판정 방법), `dev-docs/reviews/roadmap-2026-11-11.md` §2.2 M5

## 맥락

- H-ORACLE("증명 통과는 테스트 통과보다 숨은 결함을 덜 놓친다")의 지금 판정은 "자기 검사 통과 & 숨은 실패" 비율의 비교다. 네 번 변별하지 못했다(T0-07 두 모델, T0-10, T0-11, T0-08 sonnet): 모델이 Rust 쪽에서 결함을 내지 않으면 분모가 0이다.
- 그 판정은 모델이 결함을 내는지에 기댄다. 가설이 묻는 것은 오라클의 강도다: 결함 있는 구현이 주어졌을 때 그 팔의 자기 검사(계약 + 게이트, 또는 테스트)가 그것을 잡는가.
- BRB의 과제 24개는 숨은 판정 자료로 Rust 변이체 96개를 갖고, 숨은 케이스가 그 전부를 죽인다(`harness.py adequacy`, 게이트). 동등 변이체가 없다.
- 결과 행은 세션의 최종 파일을 담는다(`final_sources`, 2H-04): Rust 팔은 에이전트가 쓴 테스트, BMB 팔은 에이전트가 쓴 계약. 유료 실행 없이 다시 계산할 수 있다.
- 계약이 변이체를 죽이는지는 BSB가 이미 판정한다(`bench/m1/bsb.py`): 증인 입력에서 변이체의 출력을 계약이 허용하지 않음을 `bmb verify`가 계약만 보고 증명하면 죽인 것이다.

## 결정

1. **지표: 변이체 살해율.** 과제마다 그 과제의 Rust 변이체 각각에 대해, 세션의 자기 검사가 그 변이체를 잡는지 본다.
   - **Rust 팔:** 세션의 최종 크레이트에서 과제 함수를 변이체로 바꾸고 에이전트의 테스트(`cargo test`, 세션과 같은 proptest 설정과 고정 시드)를 돈다. 실패하면 죽인 것이다. 빌드되지 않으면 그 변이체는 그 세션에서 뺀다(수를 보고).
   - **BMB 팔:** 증인은 숨은 케이스 중 변이체가 기준 해법과 다른 결과를 내는 입력이다(판정기가 이미 계산한다). 에이전트의 최종 계약이 증인 중 하나에서 변이체의 출력을 배제함을 `bsb.kill_check`가 증명하면 죽인 것이다. 변이체가 증인에서 패닉·넘침으로 끝나면 게이트가 죽인 것으로 센다: 최종 소스가 전부 증명됐다는 것은 그런 실행이 없다는 뜻이다. 미결정은 죽이지 못한 것이다.
2. **대상 세션.** 자기 검사를 통과한 세션만이다(`final_check_ok`). 과제 단위로 짝을 지어, 두 팔 모두 대상 세션이 있는 과제만 판정에 쓴다. 빠진 과제 수를 팔별로 보고한다.
3. **자료(계산 전 고정).** 기준 모델(sonnet): Rust 팔 `bench/brb/results/2026-11-04-claude-sonnet-5-5-rust.jsonl`, BMB 팔 `bench/brb-write/results/2026-11-04-claude-sonnet-5-5-bmb.jsonl`(정식 표면, ADR-0101). 보조(qwen): `bench/brb/results/2026-11-03-qwen3.8-27b-rust.jsonl`과 `bench/brb-write/results/2026-11-02-qwen3.8-27b-bmb.jsonl`. `brb-hard`는 과제에 변이체 자료가 생기면 같은 규칙으로 더한다.
4. **판정(이 커밋으로 등록).** 과제별 살해율(죽인 수 / 변이체 수)의 팔 간 차이를 과제에 대해 평균한다(BMB − Rust). 짝지은 정확 순열 검정(부호 뒤집기, 양측)의 p와 차이의 95% 구간(짝 차이의 t 구간)을 함께 낸다.
   - **성립:** 기준 모델에서 구간이 0보다 위이고 p < 0.05, 보조 모델에서 차이의 부호가 같다.
   - **반증:** 기준 모델에서 구간이 0보다 아래이고 p < 0.05.
   - **변별 불가:** 기준 모델의 Rust 팔 평균 살해율이 0.9 이상(ADR-0115의 규칙). 이때는 더 어려운 변이체 집합이 필요하다는 결론만 낸다.
   - **판정 불가:** 그 밖. H-ORACLE의 판정은 포팅 쌍둥이(3P-05)로 넘어간다. 이것이 ADR-0111 결정 3의 한 번의 이월이다.
5. **민감도(판정에 쓰지 않고 함께 보고).** (가) 패닉·넘침으로만 드러나는 변이체를 뺀 살해율, (나) proptest를 끈 Rust 살해율, (다) 변이체별 표.
6. **알려진 편향과 방향.**
   - BMB 쪽 살해는 숨은 케이스의 증인에서만 본다. 계약이 다른 입력에서 변이체를 배제해도 세지 않는다. BMB에 불리한 쪽이다.
   - Rust 쪽 살해는 실제 실행이라 정확하다.
   - 변이체는 Rust로 쓰였고 BMB 팔에는 그 행동(입력 → 출력)만 쓴다. 변이체의 BMB 구현이 증명될 수 있는지는 묻지 않는다: 계약이 그 출력을 배제하면 건전성에 의해 증명될 수 없다.
   - 변이체 96개는 과제 저자가 "흔한 결함"으로 고른 것이다. 모델이 실제로 내는 결함의 분포가 아니다. 그래서 이 판은 오라클의 강도를 재고, 결함률(G5)을 재지 않는다.
7. **도구와 게이트.** `bench/brb/oracle_strength.py`(동결 대상 아님: 저장된 결과를 읽는 분석 도구). 게이트는 기준 해법의 세션(오라클 에이전트)으로 확인한다: BMB 기준 계약은 변이체를 모두 죽이고, Rust 기준 테스트의 살해율은 과제의 기준 테스트가 정하는 값으로 고정된다. 약한 대조군(자기 검사는 통과하지만 숨은 판정에 걸리는 해법)의 계약·테스트는 자기 자신의 결함에 해당하는 변이체를 죽이지 못한다.

## 근거

| 안 | 판정 |
| --- | --- |
| **과제의 기존 변이체로 살해율(제안)** | 변이체가 이미 동결돼 있고 동등 변이체가 없다. 두 팔에 같은 결함 집합을 준다. 유료 실행이 없다. 변이 분석으로 테스트 집합의 강도를 재는 것은 확립된 방법이다(JUDGMENT S1) |
| 연산자 기반 변이를 두 언어에 | Rust용 변이 도구가 없어 외부 도구(S2 고정)나 새 도구가 필요하고, 동등 변이체를 가려야 한다 |
| 지금 판정 유지 | 모델이 결함을 내야만 변별된다. 네 번 실패했다 |
| 더 어려운 과제(T0-08)만 | 이미 sonnet에서 변별에 실패했다. 과제 난이도에 기대는 것은 같다 |

## 결과

- 채택되면 `oracle_strength.py`와 시험을 쓰고 결과를 `dev-docs/measurements/t0-40.md`로 커밋한다. 가설 등록부의 H-ORACLE 근거 칸과 효용 보고서를 갱신한다.
- 판정이 "성립"이어도 범위는 "함수 단위 과제, 과제 저자의 결함 집합"이다. 수명 단위(H-TASK)의 판정은 관문 B 그대로다.
