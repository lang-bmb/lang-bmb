# ADR-0048: 정수 타입 완비, 비트 연산, 정수 리터럴 형식

- 상태: 채택 (2026-10-26, 사람 승인 "1/2 채택, 승인", 백로그 2V-12)
- 날짜: 2026-10-26
- 관련: ADR-0045, ADR-0017(정수 인코딩), ADR-0028(변환), ADR-0044 §1(`u8`), 점검 R8, 백로그 2V-08


## 채택 시 확인 (2026-10-26)
- 진단 번호: 시프트 양이 비트 폭 이상인 의무는 기존 E0803(넘침)과 같은 뜻이라 그대로 쓴다. E0818 `by (bit_vector)` 하위 증명 실패(비어 있음 확인).
- 열린 질문 1(`i128`·`u128`)은 필요가 생길 때. 2(좁은 정수의 레지스터 폭)는 구현 때 IR 크기와 성능을 재서 정한다.
- 구현 페이즈: ROADMAP 2N(정수·비트).

## 구현 시 확인 (2026-10-28, 백로그 2N-02)
- §2 "시프트 양은 `u32`, Rust와 같음": Rust의 `<<`·`>>` 연산자는 양으로 모든 정수 타입을 받는다(`impl Shl<i64> for u32` 등). `u32`는 `wrapping_shl`·`checked_shl`·`rotate_left` 같은 메서드의 양 타입이다. 구현은 근거 "Rust와 같음"을 따라 연산자의 양에 모든 정수 타입을 받고 리터럴 양을 `u32`로 둔다. 부호 있는 양은 음수도 E0803이 막는다(Rust 디버그 빌드와 같음).
- §3 정규형: 진법은 유지하고 `_` 구분자·앞의 0·16진 대소문자는 정규형에 없다(공백과 같은 배치). 규칙은 `compiler/README.md`의 리터럴 행.
- §4 비용: bitvector 정의가 있는 질의는 Z3가 필요 없을 때도 비트 단위로 풀어 비쌌다(64비트 가변 시프트 하나의 범위 의무가 rlimit 735859). 의무는 먼저 bitvector 항을 정수 상수로 추상하고 결과 범위 사실만 둔 질의로 풀고(증명되면 끝, 약한 질의의 증명은 증명), 아니면 정확한 질의로 간다. 실행 코드는 피연산자 bitvector를 상수로 선언하고 그 값을 준다(`int2bv`보다 반례를 수십 배 빨리 찾는다: 32비트 `|`의 반례 rlimit 216385 → 4469). 측정과 코드 경로는 `compiler/README.md`의 비트 연산 항목.

## 구현 시 확인 (2026-10-28, 백로그 2N-03)
- **하위 증명이 보는 것(§4):** Verus 규칙을 따른다. 질의는 단언 `e`의 자유 변수만 보고, 각 변수는 제 타입의 모든 값(폭 `w`의 bitvector)을 돈다. 경로 사실·`requires`·앞의 단언은 보지 않는다. 필요한 사실은 `e` 안에 `p ==> q`로 쓴다(Verus의 `assert(e) by (bit_vector) requires p;`는 같은 일을 하는 두 번째 표기라 받지 않는다: 표기 하나, DESIGN 원칙 8). 유령 `let`(`proof` 블록)도 자유 변수이고 그 정의는 보이지 않는다. 바깥 질의는 증명된 `e`를 그 자리의 값으로 가정하되 "자유 변수가 제 타입 안이면"을 앞에 붙인다(`(=> (and ranges..) e)`): 실행 코드의 변수는 언제나 타입 안이라 비용이 없고, 명세 산술로 타입 밖일 수 있는 유령 `let`(`x + 1`이 256)에 대해 거짓을 가정하지 않는다(`tests/verify/fail/bit_vector`의 `ghost_range`).
- **유령 문맥:** `assert(e) by (bit_vector);`는 `assert`가 오는 곳(실행 코드, `proof` 블록, `proof fn` 몸, ADR-0062)에 같은 뜻으로 온다. 명세 안은 `assert`처럼 E0503. Verus의 `by { .. }`(블록 형태)와 다른 증명기 이름(`nonlinear_arith`, `compute`)은 새 진단 E0516(이름이면 `by (..)`를 지우는 기계 수정). 단언의 항이 아닌 것(원소, 필드, 수량자, `old`, 참조 뒤의 값, 데이터 값)은 검사기가 E0515로 거부한다(`let`으로 묶으라는 안내).
- **번역(§4):** 구문이 아니라 인코더가 `e`로 만든 항(자유 변수마다 새 기호)을 번역한다(`compiler/src/subproof.rs`). 그래서 하위 증명은 바깥 질의가 가정하는 바로 그 사실을 증명한다: 상수 시프트의 선형 꼴, `&` 마스크의 `mod`, `!`의 `-a - 1` 등 인코더가 고른 꼴이 모두 그대로 옮겨진다. 정수 부분항마다 구간을 두고 그 값을 모두 담는 폭의 2의 보수 bitvector로 옮기므로 `+`·`-`·`*`·양의 상수로 나눈 `div`·`mod`·비교·`bv2nat`·`int2bv`가 정확하다(명세 산술이 타입 밖으로 나가도). 정확성은 `tests/lemmas.rs`의 `bit_vector_translations_are_exact`가 인코더의 항을 표본 값에서 계산해 확인한다. 질의 논리는 `QF_BV`.
- **spec fn:** 단언이 부르는 spec fn은 정의 공리와 같은 번역(`spec_block`)으로 펼친다. 재귀가 아니고 제네릭이 아니며 정수·`bool`만 받고 돌려주는 것만, 그리고 그 정의가 `#[uses]`로 드러난 것만이다(드러나지 않은 것은 E0818과 `#[uses]` 안내: `bmb uses`가 채운다). 정의 공리는 매개변수가 타입 안일 때만 성립하므로, 구간으로 타입 안임이 보이지 않는 정수 인자는 하위 증명의 가정이 되고 바깥 사실의 앞에 붙는다(`tests/verify/fail/bit_vector`의 `spec_guard`). 인자는 `define-fun`으로 한 번씩 이름을 붙여 중첩 펼침(`byte`는 `bit` 여덟 겹)이 커지지 않는다.
- **다른 이론의 자리:** 자유 변수의 정렬(`subproof::Sort`)과 번역기의 머리 기호가 연결점이다. ADR-0061 §5의 `f64`는 `(_ FloatingPoint 11 53)` 정렬과 `f64.*` 기호를 `fp.*`로 해석하는 갈래, 그리고 두 이론을 담는 논리를 더한다(구현하지 않음).
- **비용(측정):** CRC-32 표 보조 정리 `byte(c, b) == byte((c ^ b) & 0xff, 0) ^ (c >> 8)`가 rlimit 104,291에 증명된다(혼합 인코딩에서는 5,000,000에서 끝나지 않았다, T4-04). 하위 증명 실패는 E0818과 자유 변수의 반례(제 타입의 값), 번역할 수 없으면 E0818과 사유.
- **메서드(§2):** `rotate_left`·`rotate_right`·`wrapping_shl`·`wrapping_shr`(양은 `u32`, 폭으로 나눈 나머지), `count_ones`·`count_zeros`·`leading_zeros`·`trailing_zeros`(`u32`), `swap_bytes`. 상수 양의 회전·감싸는 시프트는 선형 꼴(§4), 나머지는 이름 붙은 bitvector 함수(`bmb_rotl32` 등) 하나를 `bv2nat`로 감싼 항과 결과 사실(범위, 개수는 `0..=w`이고 0에서만 극단). 코드 생성은 LLVM `fshl`/`fshr`·`ctpop`·`ctlz`/`cttz`(0에서 정의)·`bswap`. `to_be_bytes`/`from_be_bytes`/`to_le_bytes`/`from_le_bytes`는 배열 값이 걸려 따로 한다(백로그 2N-09).
- **추상 질의의 합동(§4 비용):** 표 방식의 `t[i] ^ (c >> 8)`(코드)와 보조 정리의 `byte(i, 0) ^ (c >> 8)`(명세)는 잎의 값이 다르게 쓰인 같은 모양의 항이다. 1B-49의 합동 사실은 잎의 값까지 같은 읽기끼리만이었으므로, 같은 모양(잎을 폭으로만 읽음)의 대표끼리도 "다른 잎이 같으면 같다"를 준다(모양당 최대 64개, `MAX_SHAPE_PAIRS`). 어느 모형에서나 참이라 추상 질의는 여전히 약하다. `table_step`이 5,000,000(실패) → 5,859, `lib/sha256.bmb` 전체는 +0.4%.

## 맥락
BMB의 정수 타입은 `i64`·`u64`·`usize`·`u8`뿐이고 비트 연산(`&`·`|`·`^`·`!`·`<<`·`>>`)과 16진·2진 리터럴이 없다. 정수를 SMT `Int`로 인코딩한 결정(ADR-0017)에서 비트 연산이 비선형이 된다는 인코딩의 어려움이 기능 부재로 남았다(ADR-0045 §7). 셀프호스팅 분석은 SHA-256(32비트 래핑, 회전, xor)을 탈출구로 두자고 권했다(`selfhost-gap.md` §4.1). 검증 도구의 선례는 비트 연산 의무를 bitvector 이론으로 보내는 것이다(Verus `by (bit_vector)`, Dafny `bv` 타입).

## 결정

### 1. 정수 타입
- Rust의 고정 폭 정수를 모두 둔다: `i8`·`i16`·`i32`·`i64`, `u8`·`u16`·`u32`·`u64`, `usize`·`isize`(64비트 타깃). 128비트는 열린 질문 1.
- 산술·비교·`wrapping_*`·`checked_*`·`saturating_*`·나눗셈 의무·변환(ADR-0028)은 범위만 다르고 규칙이 같다. 리터럴 기본 타입은 기대 타입에서 정한다(지금 규칙).

### 2. 비트 연산
- 연산자 `&`·`|`·`^`·`!`(정수의 비트 반전)·`<<`·`>>`. 피연산자 타입은 같아야 한다(시프트 양은 `u32`, Rust와 같음).
- 시프트 양이 비트 폭 이상이면 넘침 의무(E0803 계열, Rust 디버그 빌드의 panic 조건과 같음). `wrapping_shl`·`wrapping_shr`는 의무 없음.
- 메서드: `rotate_left`·`rotate_right`·`count_ones`·`leading_zeros`·`trailing_zeros`·`swap_bytes`·`to_be_bytes`/`from_be_bytes`(배열 반환은 2V-04 이후)·`to_le_bytes`/`from_le_bytes`.
- `>>`는 부호 있는 타입에서 산술 시프트다(Rust와 같음).

### 3. 리터럴
- `0x`·`0o`·`0b` 접두와 `_` 구분자, 접미 타입(`0xffu32`)은 쓰지 않고 기대 타입을 쓴다(지금 규칙과 같음: 정규형 하나). 정규형은 쓴 진법을 유지한다(의미가 담긴 표기).

### 4. 증명 인코딩(혼합)
- 정수는 계속 `Int`다(ADR-0017). 비트 연산 항은 `(bv2nat (bvand ((_ int2bv w) a) ((_ int2bv w) b)))` 꼴로 그 항만 bitvector를 거친다(부호 있는 타입은 2의 보수 사상). 결과 범위 사실(`0 <= a & b <= min(a, b)` 등)을 1B-42의 나눗셈 사실처럼 인코더가 함께 준다.
- 비트 수준 성질은 Verus처럼 `assert(e) by (bit_vector);`로 bitvector 이론에서 따로 증명하고 그 결과를 사실로 쓴다. `e`는 비트 연산·비교·산술만 담는 닫힌 식이다. 새 구문이지만 Verus 표면을 승계한다(DESIGN §4: Rust·Verus에서 온 형태).
- 시프트·회전은 상수 양이면 곱셈·나눗셈으로 펼친다(선형 의무 유지).

### 5. 코드 생성
- LLVM 정수 연산 그대로. 좁은 정수는 메모리에서 제 폭, 레지스터에서 `i64`(지금의 `u8` 방식)로 둘지, LLVM 제 폭으로 둘지는 구현 때 IR 크기와 성능을 재서 정한다.

## 근거(검토한 대안)
| 안 | 판정 |
| --- | --- |
| **Rust 정수 타입 전부 + 비트 연산 + 혼합 인코딩과 `by (bit_vector)`(채택 제안)** | Rust 표면 그대로(S1), Verus·Dafny 선례. SHA-256이 증명된 BMB 코드가 된다 |
| 비트 연산을 탈출구(`external_body`)로 | 증명할 수 있는 것을 신뢰 기반에 넣는다(ADR-0045 §7). 탈출구 면적(4F 기준)이 는다 |
| 정수 전체를 bitvector로 재인코딩 | 선형 산술 의무의 비용이 크게 오른다(ADR-0017의 근거). 혼합이 필요한 곳만 비용을 치른다 |
| 산술로 흉내(`x / 2^k`) | 우회. xor·and는 비트 루프가 된다 |

## 결과
- 셀프호스팅의 SHA-256, 해시, 바이트 조립(`to_be_bytes`)을 정석 형태로 쓴다. `u32`·`u16`이 생긴다.
- 인코더에 bitvector 경로와 `by (bit_vector)` 하위 증명이 들어온다. 비용과 안정성을 구현 때 잰다.
- 부호 없는 산술 퍼저에 비트 연산과 새 폭을 넣는다.

## 열린 질문
1. `i128`·`u128`: 셀프호스팅에는 필요 없다(`selfhost-gap.md` §4.1). Rust 표준 타입이므로 넣되 시점은 필요가 생길 때.
2. 좁은 정수의 레지스터 폭(§5).
