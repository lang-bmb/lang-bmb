# ADR-0031: 힙 `Vec<T>`과 소유·이동 검사

- 상태: 채택 (2026-10-25. 2G 착수 승인과 권장안 채택 지시에 따름, 백로그 2G-07. 아래 "채택 시 갱신"이 제안과 달라진 점)
- 날짜: 2026-10-24(제안), 2026-10-25(채택)
- 관련: DESIGN.md §4.1(수명·실패)·§5·§8.1(별칭 부재), ADR-0015, ADR-0016, ADR-0017 §3, ADR-0024, ADR-0028·0029·0030(제안), ROADMAP 2G, 백로그 2G-01

## 맥락
M1의 값은 정수·`bool`과 고정 길이 배열 `[T; N]`뿐이고, 참조는 매개변수 위치의 `&[T]`·`&mut [T]`뿐이다(ADR-0016). 크기가 실행 중 정해지는 데이터가 없어서 과제가 고정 크기 배열 알고리즘에 한정된다(측정 보고서 `dev-docs/measurements/m1.md` §2 편향 1). 이동이 의미를 갖는 타입도 없어서 소유권 검사는 이름·별칭 규칙(E0410, ADR-0024)뿐이다.

DESIGN.md §5는 소유·이동 + 2차 참조를 정했다. 참조는 저장·반환할 수 없으므로 수명이 없고, 참조를 담는 구조(반복자·뷰)는 핸들·인덱스로 대체한다. 그 첫 힙 타입이 `Vec`이다.

관련 증거:
- 슬라이스 길이 상한 사실(ADR-0017 §3, `isize::MAX / size_of(T)`)이 이미 인코딩에 있다(`compiler/src/verify.rs`의 `LEN_MAX_WORD`). 같은 사실이 `Vec`에도 맞는다.
- M1 마찰: 원소 합 루프는 길이 상한(`a.len() <= N`)이 없으면 증명되지 않았다(m1 §6). `Vec`에서도 같은 조건이 필요하다.
- 증명으로 검사를 지우는 속도 이득은 기준선 벤치에서 관찰되지 않았다(1E-08, m1 §4). `Vec`의 `noalias` 강화도 이득을 미리 주장하지 않는다.

## 채택 시 갱신 (2026-10-25, 2B 표면 위에서)

제안 뒤 2B(ADR-0026·0027)와 2C(ADR-0028)가 들어왔다. 채택하며 정한 것:

1. **2B 의존 해소(열린 질문 1):** `pop`은 `Option<T>`를 돌려준다(ADR-0026의 내장 `Option`). 핸들 새 타입은 이름 붙은 필드 구조체 `struct Id { i: usize }`다(튜플 구조체는 E0233).
2. **원소 타입(열린 질문 2):** `Copy`인 스칼라와 `Copy`인 구조체·열거형이되, 원소 안에 배열이 있는 데이터 타입은 뺀다(데이터 타입 슬라이스와 같은 증명 게이트 경계, E0814). `Vec`을 담는 구조체·`Vec<Vec<T>>`는 범위 밖(E0402).
3. **"아마 이동"(열린 질문 3):** 제안대로 E0414로 시작한다. 빈도는 `m2` 과제에서 잰다.
4. **`with_capacity`·`drop`(열린 질문 4):** 제안대로 `with_capacity` 허용, `drop` 거부(E0219).
5. **버퍼 `noalias` 메타데이터(열린 질문 5):** 측정 전에는 내지 않는다. 기준선 벤치의 `Vec` 판으로 잰 뒤 정한다.
6. **`resize`·`extend_from_slice`(열린 질문 6):** 이번 범위 밖. `bmb stability`로 인코딩 안정성을 잰 뒤 따로 넣는다.
7. **`alloc` 효과:** ADR-0030(2F)은 1E-07 뒤에 정한다. 그때까지 `Vec` 연산에는 효과가 없다(지금 효과 집합 `pure`·`io` 그대로, `pure` 함수가 `Vec`을 쓸 수 있다). ADR-0030이 채택되면 §4의 효과 규칙이 그대로 적용되고, 선언이 모자란 함수는 효과 검사 진단의 기계적 수정으로 고친다. 2G-04는 해제 지점과 런타임까지만 한다.
8. **`vec!`(§7):** E0202의 기존 교체 `vec![a, b]` → `[a, b]`는 `Vec`이 들어오면 의미를 바꾼다. 교체를 없애고 안내만 둔다(2G-06).
9. **주소 검사 빌드(§8):** 컨테이너에 AddressSanitizer 런타임이 없을 수 있다. 퍼저의 세 번째 빌드는 ASan이 있으면 ASan(LeakSanitizer 포함), 없으면 valgrind memcheck(`--leak-check=full`, 오류면 실패)로 하고, 어느 쪽도 없으면 실패한다(조용히 건너뛰지 않는다). nightly는 ASan으로 돈다.
10. **진단 번호:** E0218·E0219·E0413·E0414·E0514·E0816이 `compiler/src/diag.rs`에서 비어 있음을 확인했다.

## 결정

### 1. 범위
- 원소 타입은 `Copy`인 스칼라(`i64`·`u64`·`usize`·`bool`)와, 2B 이후 `Copy`인 구조체·열거형이다. `Vec<Vec<T>>`, `Vec`을 담는 구조체, `Box`·`Rc`·`String`·`HashMap`은 M2 밖이다.
- **API(정규형 하나):** `Vec::new()`, `Vec::with_capacity(n)`, `v.push(x)`, `v.pop()`, `v.len()`, `v[i]`(읽기·대입), `v.truncate(n)`, `v.clone()`, `v.as_slice()`, `v.as_mut_slice()`. `pop`은 `Option<T>`를 돌려주므로 **2B 이후**(2G는 2B 뒤, ROADMAP 기본 순서와 같음).
- 매개변수 타입: `Vec<T>`(이동), `&Vec<T>`, `&mut Vec<T>`(길이가 바뀔 수 있음). 슬라이스 매개변수에는 `v.as_slice()`·`v.as_mut_slice()`를 인자 위치에서 넘긴다(2차 참조라 인자 위치에서만 허용). 반환은 `Vec<T>` 값만.

### 2. 소유·이동 검사(M2 범위)
- `Vec` 값을 `let`·대입의 오른쪽, 값 인자, 꼬리 식에 쓰면 이동이다. 이동된 변수의 사용·참조는 E0413. 이동된 변수에 다시 대입하면 초기화된다.
- **합류점 규칙:** 분기 합류점과 루프 머리에서 변수는 "확실히 초기화" 또는 "확실히 이동" 중 하나여야 한다. "아마 이동"이면 E0414. Rust보다 엄격하지만, 해제 시점이 정적으로 정해져 실행 시 해제 플래그가 없다. 루프 안에서 바깥 변수를 이동하고 같은 회차에 다시 대입하는 형태(`acc = f(acc);`)는 허용된다.
- 같은 호출에서 `&mut v`·`v.as_mut_slice()`와 `v`의 다른 사용(이동·참조)은 E0410(기존 별칭 규칙의 확장). 값으로 계산되는 스칼라 읽기(`v.len()`, `v[i]`)는 ADR-0024 규칙대로 허용한다.
- 참조가 저장·반환되지 않으므로(ADR-0015) 빌림 기간은 호출 하나다. "빌린 동안 이동"은 위 규칙으로만 생기고, 수명 분석은 필요 없다.
- 해제: 확실히 초기화된 `Vec` 변수는 블록 끝에서 해제된다. 이동된 변수는 해제하지 않는다. 명시적 `drop(v)`는 두지 않는다(열린 질문 4).

### 3. 증명 인코딩
- `Vec<T>` 값은 슬라이스와 같은 쌍 `(Array Int Int, Int)`(원소, 길이)이다(ADR-0017 §3). 값이므로 대입은 쌍의 복사이고, 이동은 검사기에서만 다룬다. 용량은 모델에 없다(관찰할 수 없다).
- 길이에는 사용 지점에서 `0 ≤ len ≤ LEN_MAX(T)` 범위 사실을 단언한다(기존 `len_max`).

| 연산 | 의무 | 결과 |
| --- | --- | --- |
| `Vec::new()`, `Vec::with_capacity(n)` | `with_capacity`: `n ≤ LEN_MAX(T)`(Rust는 넘으면 panic) → E0816 | 길이 0, 원소 미정 |
| `v.push(x)` | `len < LEN_MAX(T)` → E0816 | `store(e, len, x)`, `len + 1` |
| `v.pop()` (2B) | 없음 | `len = 0`이면 `None`, 아니면 `Some(e[len−1])`과 `len − 1` |
| `v[i]`, `v[i] = x` | `i < len` → 기존 E0805 | `select`/`store` |
| `v.truncate(n)` | 없음 | `len = min(len, n)` |
| `v.clone()` | 없음 | 같은 쌍 |
| `as_slice`/`as_mut_slice` | 없음 | 같은 쌍. `&mut [T]`로 넘긴 callee는 길이를 바꿀 수 없으므로 길이 보존이 공짜 프레임 사실 |

- `&mut Vec<T>` 인자 호출 뒤에는 원소와 길이를 모두 새 상수로 두고 callee의 `ensures`만 가정한다(기존 `&mut` 슬라이스와 같고 길이만 추가). `old(v)`는 `&mut Vec<T>` 매개변수에 허용한다(E0508 규칙 확장).
- **명세의 `Vec` 동등:** 길이 뒤의 원소는 `pop`·`truncate` 뒤에도 배열에 남으므로, 배열 동등은 `Vec` 동등이 아니다. 명세에서 `Vec`끼리 `==`는 E0514로 거부하고 길이·원소를 술어로 비교하게 한다.
- 명세에서 `Vec`은 `spec fn`의 `&[T]` 매개변수에 `v.as_slice()`로 넘긴다(실행 코드와 같은 형태 하나).
- 메모리 부족은 증명 대상이 아니다. `alloc` 효과(ADR-0030)로 드러난다.
- 새 보조 사실은 없다. 넣게 되면 ADR-0018 §2대로 `lemmas.rs`에 기계 증명을 둔다.

### 4. 코드 생성과 런타임
- 머리 `{ptr, len, cap}`을 스택에 둔다. `push`는 `len == cap`이면 `realloc`(용량 두 배, 최소 4)이고, 할당 실패는 `abort`다. 용량 계산은 `len ≤ LEN_MAX(T)`가 증명되어 있어 넘치지 않는다(`cap ≤ LEN_MAX(T)`로 자른다).
- 증명된 인덱스는 지금처럼 검사 없는 `getelementptr inbounds`(`; proved E0805`). 해제는 §2의 정적 지점에서 `free`.
- **별칭:** `&mut Vec<T>` 매개변수는 머리 포인터에 `noalias`, `&Vec<T>`는 `readonly`(ADR-0015와 같은 근거). 원소 버퍼는 머리에서 읽은 포인터라 매개변수 `noalias`가 덮지 않는다. 버퍼는 항상 그 `Vec` 하나가 소유하고(복제는 깊은 복사, 공유 타입 없음) 참조가 2차이므로, 매개변수별 `!alias.scope`/`!noalias` 메타데이터를 버퍼 접근에 붙일 수 있다. 이 사실은 타입 규칙에서 나온다. 속도 이득은 측정 후에만 주장한다(열린 질문 5).
- `as_mut_slice()` 인자는 기존 `&mut [T]` 하강(버퍼 포인터 + 길이, `noalias`)을 그대로 쓴다.
- 효과: `Vec::new`·`with_capacity`·`push`·`clone`은 `alloc`(ADR-0030). `Vec::new`는 실제로 할당하지 않지만 규칙을 단순하게 둔다. 해제·`pop`·`truncate`·인덱스는 효과가 없다.

### 5. 핸들·인덱스 패턴(DESIGN.md §5)
- 참조를 담는 구조 대신 `Vec<T>` 저장소 + `usize` 인덱스(2B 이후 `struct Id(usize)` 같은 새 타입)를 쓴다. 핸들 유효성은 `spec fn valid(h: usize, s: &[T]) -> bool { h < s.len() }` 같은 술어로 계약에 쓴다.
- 저장소가 늘기만 하는 API는 `ensures`에 `old(s).len() <= s.len()`과 기존 원소 보존을 쓴다. 이 프레임 조건을 빠뜨리면 호출자의 핸들이 무효가 되어 증명이 실패한다. 반복될 마찰로 보고, 자동 채움 후보(DESIGN.md §8.2 "프레임 조건 후보")로 둔다.
- 세대 번호 핸들, 해제 목록 같은 고급 패턴은 M2 밖이다.

### 6. 맵·해시
- `Vec` 연산은 내장이라 호출 간선을 만들지 않는다. L1 시그니처에 `Vec<T>`·`&Vec<T>`·`&mut Vec<T>`가 나타난다. 변이·데이터 흐름 뷰(DESIGN.md §7.2)의 원천으로 `&mut Vec` 매개변수를 표시한다(3B에서 사용).
- 정규형·해시 규칙(ADR-0019)은 바뀌지 않는다. 타입 텍스트가 정규형에 그대로 들어간다.

### 7. 거부할 Rust 습관과 진단(번호는 제안)

| 습관 | 처리 | 코드 |
| --- | --- | --- |
| `vec![..]`, `vec![x; n]` | 기존 E0202. 안내: `Vec::with_capacity(n)` + `push` 루프 | E0202(기존) |
| `f(&v)`로 `&[T]` 매개변수에 넘김(Deref 강제 변환) | `v.as_slice()`/`v.as_mut_slice()`로 기계 교체 | E0218 |
| `drop(v)`, `std::mem::take/replace/swap` | 거부. 해제는 블록 끝 | E0219 |

| `v.get(i)`, `first()`, `last()`, `is_empty()` | 기존 E0404. 안내: 증명된 `v[i]`, `v.len() == 0` | E0404(기존) |
| `Box`·`Rc`·`RefCell`·`String`·`HashMap`·`Vec<Vec<T>>` | 기존 E0402. 타입별 안내 | E0402(기존) |

| 명세의 `Vec ==` | 오류 | E0514 |
| `push`·`with_capacity`가 최대 길이를 넘을 수 있음 | 증명 실패 + 반례 | E0816 |

### 8. 테스트·퍼저
- 코퍼스: 이동 검사(`tests/check/err/moves.bmb`: 이동 후 사용, 아마 이동, 같은 호출의 `&mut`과 이동), `tests/verify`(push·pop·인덱스·프레임·핸들 유효성의 통과·실패), `tests/run`(성장·축소·복제·반환).
- 건전성 퍼저(새 `soundness_vec.rs`): `Vec` 지역 변수와 `&mut Vec` 매개변수에 push·pop·truncate·인덱스·clone·이동을 무작위로 생성한다. 해석기는 `Vec`을 값으로 모델링한다. 성질은 기존과 같다(증명된 함수는 오류 없음과 사후 조건, 확정 반례는 실제로 깨뜨림, 두 빌드가 해석기와 같은 출력). 추가로 **세 번째 빌드를 AddressSanitizer(LeakSanitizer 포함)로** 만들어 해제 지점(이중 해제, 해제 후 사용, 누수)을 확인한다. 60배치 위반 0이 2G 통과 기준 2다.
- 효과: 해석기가 할당을 기록하고 "동적 효과 ⊆ 정적 효과"(ADR-0030 §8)를 확인한다.

## 근거(검토한 대안)

| 안 | 판정 |
| --- | --- |
| **값 쌍 모델 + 검사기의 이동 검사(채택 제안)** | 기존 슬라이스 인코딩과 길이 상한 사실을 그대로 쓴다. 증명기에는 힙·포인터가 없다. 2차 참조 덕에 빌림 검사기 없이 이동 검사만으로 충분하다 |
| 힙 모델(포인터·소유권 술어, 분리 논리) | 2차 참조와 유일 소유가 이미 별칭을 없애므로 얻는 것이 없고, 해법기 부담이 크다. 기각 |
| Verus식 `v@`(수학적 시퀀스 뷰)와 `Seq` 이론 | 명세 표현이 깔끔하지만 새 명세 타입과 공리 묶음이 신뢰 기반에 들어간다. 현재 `(Array, Int)` 쌍으로 같은 질문에 답할 수 있다. 명세 `==`가 필요해지면 다시 본다 |
| Rust처럼 "아마 이동" 허용 + 해제 플래그 | Rust 습관과 더 맞지만 코드 생성에 실행 시 플래그가 생기고 퍼저가 덮을 상태가 는다. 엄격하게 시작하고 E0414 빈도로 다시 본다(열린 질문 3) |
| `pop`을 2B 없이 `requires len > 0`인 `T` 반환으로 | Rust의 `pop() -> Option<T>`와 다른 의미가 같은 이름에 붙는다(원칙 8, ADR-0013). 기각. 2B 전에는 `v[v.len() - 1]` + `truncate`로 같은 일을 한다 |
| `&Vec<T>`를 `&[T]` 매개변수에 바로 허용 | Rust의 Deref 강제 변환 그 자체다. DESIGN.md §4.1 호출 해석 행이 금지한다. 기각 |

## 결과
- 처음으로 해제 코드와 런타임(`malloc`/`realloc`/`free`/`abort`)이 생긴다. 실행 파일이 libc 할당자에 의존한다.
- `alloc` 효과(ADR-0030)와 함께 들어가야 한다. 2B(`Option`)에 의존한다.
- 이동 규칙이 Rust보다 엄격한 곳(아마 이동, `drop`)은 Rust 습관 오류율로 비용을 잰다.

## 열린 질문(측정 1E-07 또는 사람이 정함)
1. **2G의 우선순위와 2B 의존:** `pop`과 핸들 새 타입은 2B 뒤다. 2B를 먼저 닫을지, `pop`을 뺀 `Vec`을 먼저 넣을지.
2. **원소 타입 범위:** `Copy` 원소만(제안) 대 `Vec`을 담는 구조체·`Vec<Vec<T>>`까지. 후자는 부분 이동과 중첩 해제가 필요하다.
3. **"아마 이동" 금지(E0414):** `m2` 과제에서 E0414 빈도가 높으면 해제 플래그를 들여 Rust와 맞춘다.
4. **`drop(v)`·`Vec::with_capacity`:** 명시적 조기 해제와 용량 힌트는 성능 도구다. 정규형 하나 원칙과 성능 목적함수 중 무엇을 따를지 사람이 정한다(제안: `with_capacity` 허용, `drop` 거부).
5. **버퍼 `noalias` 메타데이터의 이득:** 기준선 벤치에 `Vec` 판을 추가해 잰다. 이득이 없으면 메타데이터는 내지 않는다(코드 생성 단순성).
6. **`resize`·`extend_from_slice`:** `vec![x; n]` 습관의 대체로 필요하지만 `resize`는 상수 배열이나 `lambda` 인코딩이 필요하다. Z3 고정 버전(4.15.4)에서 안정성을 `bmb stability`로 잰 뒤 넣는다.
