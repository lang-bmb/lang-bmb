# ADR-0123: 해법기의 메모리 한도

- 상태: 채택(자율 채택, AUTONOMY §4 "결정 기록": 열셋째 실행 계획의 `T2-16`, 사람 승인 2026-11-11 "권장안 채택, 자율 실행/검증 승인"). ADR-0017의 고정 옵션에 하나를 더한다
- 날짜: 2026-11-11
- 관련: ADR-0017(정수 의미론과 SMT 인코딩: 고정 옵션), ADR-0018(의무마다 새 상태), DESIGN §6(unknown·timeout·솔버 부재는 실패), `scripts/toolchain.env`, 백로그 T2-16

## 맥락

- 거짓인 의무 하나에서 Z3가 반례도 한도 도달도 내지 않고 메모리를 12.5GB까지 쓴 뒤 시스템에 죽었다(`port-shape` 실험의 `tree::call`: 재귀 술어 안의 중첩 수량자가 문맥에 있을 때의 `push` 길이 의무).
- 그때 게이트는 E0812("solver error")를 내고 그 정의의 뒤 의무 20개를 풀지 않은 채 실패로 셌다. 56초가 걸렸고 같은 머신의 다른 작업이 함께 죽을 수 있었다. `bmb lint`는 변이체마다 같은 일을 겪어 끝나지 않았다.
- `rlimit`(ADR-0017)는 해법기의 일을 세지만 메모리는 세지 않는다.

## 결정

1. **해법기 프로세스에 메모리 한도를 건다.** 값은 `scripts/toolchain.env`의 `Z3_MEMORY_MB`(1,024)이고 Z3의 `-memory`로 넘긴다. `BMB_Z3_MEMORY_MB`는 낮추기만 한다(`Z3_RLIMIT`과 같은 규칙).
2. **한도에 닿은 질의는 미결정이다.** E0811에 사유 `memory limit reached, 1024 MB`를 적는다. `rlimit` 도달과 같은 등급의 실패다.
3. **그 질의만 미결정이다.** 한도에 닿으면 프로세스가 끝나므로 다음 의무는 새 프로세스로 푼다. 의무마다 기반 전체를 다시 보내므로(ADR-0018) 답은 한 프로세스가 이어 푼 것과 같다.

## 근거

| 안 | 판정 |
| --- | --- |
| **고정된 메모리 한도, 닿으면 미결정(채택)** | 자원 한도의 정석이고 실패가 닫힌 쪽이다(DESIGN §6). Z3의 메모리 계수는 같은 판·같은 질의에서 같으므로 판정이 머신의 남은 메모리에 달리지 않는다 |
| 지금대로(시스템이 죽인다) | 판정이 머신에 달리고, 죽은 뒤의 의무가 풀리지 않은 채 실패로 세어진다 |
| 프로세스의 주소 공간 한도(`ulimit -v`) | 닿았을 때 Z3가 어떻게 끝나는지가 정해져 있지 않고(실험에서도 죽었다) 사유를 가를 수 없다 |

값의 근거: 표준 라이브러리 11단위(정의 218개)가 256MB 한도에서도 모두 같은 `rlimit` 합(20,192,306)으로 증명된다. 1,024MB는 그 네 배이고, 재현 질의는 이 한도에서 약 4초 만에 끝난다(4,096MB에서는 18초).

## 결과

- 재현 질의: 실패 의무 20 → 1(E0811, 사유 메모리), 56초 → 16초. `bmb lint`는 같은 파일에서 끝난다(328초, 전에는 끝나지 않음). 시험 `compiler/tests/gate.rs` `a_query_at_the_memory_limit_is_undecided_and_the_rest_go_on`.
- `lint`가 340줄에 328초인 것은 남는다: 변이체마다 한도까지 가는 질의가 있다. 변이 질의의 예산은 `T2-16`의 남은 일이다.
- 한도에 닿는 정상 증명이 생기면 게이트가 E0811로 보인다. 그때는 질의를 고치고 한도는 올리지 않는다(`Z3_RLIMIT`과 같다).
