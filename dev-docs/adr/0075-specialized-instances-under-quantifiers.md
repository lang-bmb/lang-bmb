# ADR-0075: 기저 인스턴스 재시도는 한정 기호 아래 적용에 특수화 인스턴스를 더하고, 완전성은 적용 단위로 판단한다

- 상태: 채택 (자율 채택, AUTONOMY.md §4). ADR-0023(기저 인스턴스 재시도)을 보완한다. 재시도는 그대로 첫 질의가 `unknown`일 때만 돈다
- 날짜: 2026-11-01
- 관련: ADR-0023, ADR-0064(배열을 묶는 정의와 MBQI), 백로그 T0-19, T0-24

## 맥락

- T0-10 BVB의 숨은 명세 강도 검사에서 증명되고 서명도 맞는 여섯 세션이 `undecided`로 실패했다. T0-19가 같은 판정기를 그대로 돌려 원인을 둘로 나눴다(`dev-docs/experiments/T0-19/results.md` §1·§2).
- **같은 뜻인 명세가 미결정(꼴 (나)):** 에이전트가 색인 술어 적용을 트리거로 쓴 존재 꼴(`r == !(forall|j| !#[trigger] hit_at(arr, k, j))`)을 쓰면, 판정기의 질의에는 그 트리거에 맞는 항이 없다. Z3의 모형 기반 인스턴스화가 메워야 하지만 `hit_at`의 정의 공리가 배열 정렬 변수를 묶어 `incomplete (theory array)`로 끝난다. 재시도는 한정 기호 밖의 적용만 인스턴스화해서(`collect_apps`가 `forall` 안으로 내려가지 않음) `hit_at(arr, k, j)`에는 인스턴스가 없다. 같은 꼴이 에이전트 자신의 증명도 막았다(809·max_of_list).
- **약한 명세도 미결정:** 과제의 약한 기준 해법 넷(454·804·808·809)은 해법기가 실제 반례(454: `text = [122]`)를 내는데도, 재시도가 "정의의 몸에 `forall`이 있으면 불완전"으로 보아 모형을 버렸다. 그래서 `undecided`는 약함과 같은 뜻을 가르지 못했다.
- 시제품(`specialize.py`)이 여섯 사례를 모두 `unsat`(rlimit 7~14K)으로 풀었고, 재귀·약한 사례에는 아무것도 더하지 않았다.

## 결정

1. 재시도의 인스턴스는 질의(와 이미 넣은 인스턴스의 몸)의 모든 적용에서 만든다. 적용이 놓인 자리에서 `forall`·`exists`·`let`이 묶은 변수를 함께 센다(`verify::collect_apps`).
2. 묶인 변수를 언급하는 인자가 없는 적용은 지금처럼 기저 인스턴스 `(=> guard (= f(args) body[args]))`를 받는다.
3. 묶인 변수를 언급하는 인자가 있는 **비재귀** 정의의 적용은 **특수화 인스턴스**를 받는다: 묶인 변수를 언급하지 않는 인자는 대입하고, 나머지 매개변수는 정의의 정렬 그대로 양화하며, 그 적용을 패턴으로 쓴다. `(forall (rest) (! (=> guard (= f(..) body[..])) :pattern (f(..))))`. 다음 깊이에서는 그 몸을 같은 한정 기호 아래에 두고 다시 적용을 찾는다(`verify::instance`).
4. 재귀 정의(재귀 `spec fn`, 재귀 데이터 타입의 유효성 함수)는 한정 기호 아래 적용에 인스턴스를 받지 않는다.
5. 재시도의 `sat`을 반례로 쓰는 완전성은 "모든 적용(한정 기호 아래 포함)이 인스턴스를 받았고, 깊이(3)에서 잘린 것이 없다"이다. 정의의 몸에 남은 `forall`은 그 자체로 불완전이 아니다. 그렇지 않으면 ADR-0023대로 "확인되지 않은 반례"의 E0811이다.
6. 충족 가능성 검사(ADR-0069)도 같은 재시도를 같은 뜻으로 쓴다. 사전조건 충족 검사(W0901)는 이미 있던 재시도에서 완전한 `sat`을 충족으로 받는다(전에는 `unsat`만). 공허 검사(W0905)의 도달 지점은 탐침과 전체 질의가 `unknown`이면 재시도를 탐침의 몫(`probe_limit`, rlimit 5만)으로 한 번 더 푼다: `unsat`은 반박, 완전한 `sat`은 도달.

## 근거

- **원인과 귀속 층:** 증명기 인코딩(컴파일러 층). 판정기(동결 하네스)와 프롬프트는 바꾸지 않는다(T0-19 §5의 후보 (B)·(D) 기각).
- **건전성(증명):** 특수화 인스턴스는 양화 정의에 인자를 대입한 것이라 그 귀결이다. 이것으로 얻은 `unsat`은 정의 아래의 `unsat`이다.
- **건전성(반례):** 완전할 때 재시도 질의는 정의된 기호를 인스턴스가 덮는 점(기저 점과 특수화 인스턴스의 조각)에서만 평가한다. 모형에서 정의된 기호를 덮이지 않은 점에서 몸의 값으로 바꾸면(비재귀는 의존 순서대로, 재귀는 기저 점이 호출에 닫혀 있어 감소 측도에 대한 귀납으로 같은 값) 질의의 참은 그대로이고 정의 전체가 성립한다. 그래서 그 모형은 원래 질의의 모형이다. 남은 한정 기호(몸의 `forall`, 질의의 가정, 특수화 인스턴스)는 Z3가 `sat`을 내기 전에 모형 검사를 거친다(ADR-0023 때부터 질의 자신의 `forall`은 그렇게 믿었다).
- **정석:** 지상 항에 대한 한정 기호 인스턴스화로 결정 가능한 조각에 넣는 것(Ge·de Moura, CAV 2009 "Complete instantiation for quantified formulas in SMT"). 특수화 뒤에는 배열 정렬 변수가 양화되지 않아 본질적으로 해석되지 않는 조각에 든다. 배열 성질 조각의 결정 절차(Bradley·Manna·Sipma, VMCAI 2006)가 색인 집합으로 인스턴스화하는 것과 같은 방향이다.
- **재귀를 빼는 이유:** 재귀 정의의 조각을 양화로 넣으면 그 몸의 재귀 적용이 다시 한정 기호 아래 적용이 되어 깊이마다 조각이 늘고, 시제품의 첫 판(배열마다 정의 전체 특수화)은 재귀 B에서 rlimit 5,000,000까지 돌았다. 재귀는 귀납이 필요한 문제라(T1-24·T1-25) 인스턴스로 풀리지 않는다.
- **공허 검사 재시도의 몫(측정):** 도달 지점의 한도(rlimit 100만)로 재시도하면 V12 292 → 261이지만 V11이 263,981,532 → 354,329,360(+34%, 예산 +10% 초과)이었다. 미결정 지점마다 한도까지 돌기 때문이다. 탐침의 몫(5만)으로는 V12 → 265(같은 30개 중 26개 결정), V11 → 270,327,604(+2.4%)라 이것을 택했다.
- **측정(같은 작업 트리에서 이전 → 이 결정, 새 코퍼스 파일 포함):**
  - T0-19 판정 표(`dev-docs/experiments/T0-19/results-t0-24.jsonl`, 동결 판정기 그대로): 65판정 중 받음 40 → 47, `undecided` 18 → 9. 같은 뜻 꼴 (나)의 여섯(454·804·808 H, 809 D, choose_odd D·Q2)이 받아지고, 809 D·max_of_list D의 에이전트 증명이 통과하며, 약한 기준 넷이 `refuted`(반례 확정)가 된다. 남은 아홉은 모두 재귀 술어다.
  - 실패 코퍼스: 기존 파일의 기대 출력은 바이트 그대로(E0811 → E0802 변화 없음).
  - V4 7,309,829 → 7,315,846(차이는 새 코퍼스 파일의 두 정의가 이제 증명되는 비용뿐), V3 2 → 0(같은 파일), V5·V7·V8·V9·V10 그대로(V7 0.0, V8 24,316,281, V10 11,946,407). 재시도는 첫 질의가 `unknown`일 때만 돌아 기존 증명에는 닿지 않는다.
  - V11 263,981,532 → 270,327,604(W0905 243,327,287 → 249,666,361, W0901 20,654,245 → 20,661,243), V12 292 → 265(W0905 287 → 261, W0901 5 → 4). 기준선(285)은 새 코퍼스 파일 전의 값이고, 그 파일의 미결정 일곱도 0이 되었다.

## 결과

- 결정된 의무의 판정은 바뀌지 않는다(재시도는 첫 질의가 `unknown`일 때만). 바뀌는 것은 미결정 → 증명(같은 뜻)과 미결정 → 확인된 반례(E0811 → E0802)뿐이다.
- 증명 캐시의 키는 첫 질의 텍스트라 그대로이고, 캐시에서 재생하는 재시도 텍스트는 새 인스턴스를 담는다.
- 측정 조건(ADR-0070): 컴파일러 트리가 바뀌므로 새 조건이다. 기록된 결과는 그대로 두고, 동결 하네스의 숨은 검사가 `bmb verify`를 부르므로 이후 실행은 새 판정을 쓴다.
- 시험: `verify::tests::applications_under_quantifiers_get_specialized_instances`, `recursive_definitions_under_quantifiers_leave_the_instances_incomplete`, `a_quantifier_in_a_body_keeps_the_instances_complete`, `ground_instances_take_datatype_arguments`, 코퍼스 `tests/verify/pass/index_preds.bmb`(이전 컴파일러에서 E0811 둘), `tests/verify/fail/weak_witness.bmb`(E0811 → E0802 반례 `text = [122]`).
- 되돌리기: `collect_apps`가 한정 기호 안으로 내려가지 않고 `ground_instances`가 몸의 `forall`을 불완전으로 보면 ADR-0023 그대로다. 충족 가능성 검사는 재시도의 `sat`을 버리고 공허 검사의 재시도를 빼면 ADR-0069 그대로다.
