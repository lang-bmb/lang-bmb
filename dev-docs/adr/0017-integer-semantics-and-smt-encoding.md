# ADR-0017: 정수 의미론과 SMT 인코딩

- 상태: 채택 (자율 채택, AUTONOMY.md §4) · §3·§5는 ADR-0018로 보완
- 날짜: 2026-10-24
- 관련: DESIGN.md §4.1(산술)·원칙 4·9, ADR-0016, 백로그 1B-01

## 맥락
1B(증명 게이트)를 구현하려면 실행 산술과 명세 산술의 의미, 그리고 그것을 SMT로 옮기는 방법이 정해져야 한다.

v0 `verify-vc`는 처음에 정수를 무한 정수로 모델링했다가 `i64` 래핑과 어긋나 건전하지 않았고, 64비트 bitvector로 옮겨 건전성을 회복했다(`legacy/v0:tests/verify-vc/EXPECTED.md`, T-BV). 원인은 v0의 실행 의미론이 **조용한 래핑**이었다는 데 있다. 또 v0는 `pos + 1` 같은 인덱스 연산이 극단값에서 넘칠 수 있다는 반례를 없애려고 `len < 2^62` 공리를 따로 넣었다.

## 결정

### 1. 실행 산술
- `i64`·`u64`·`usize`는 64비트 기계 정수다.
- `+ - * / %`의 값은 **수학적 결과**다. 그 결과가 타입의 범위 안에 있다는 것이 증명 의무다(무오버플로).
- `/`·`%`는 Rust와 같이 0 쪽으로 자른다. 제수가 0이 아님과 `i64::MIN / -1`, `i64::MIN % -1`이 아님이 증명 의무다.
- `wrapping_add/sub/mul`은 2^64 모듈러 연산이다. 의무가 없다.
- 그 외 변환·비트 연산은 M1에 없다.

### 2. 명세 산술
- 명세 문맥(계약, 불변식, `decreases`, `assert`, `spec fn` 본문)의 산술은 **무한 정수**다. 넘침도 의무도 없다. Verus의 `int` 승격과 같다.
- 실행 값이 명세로 들어올 때는 그 타입의 범위 사실을 갖는다.
- `spec fn`의 결과에는 범위 사실이 붙지 않는다. 반환 타입은 타입 검사에만 쓴다.

### 3. 인코딩
- 정수는 SMT `Int`로, `bool`은 `Bool`로 인코딩한다. bitvector는 쓰지 않는다.
- 범위 사실은 매개변수, 배열 원소를 읽은 값, 호출 결과에 대해 사용 지점에서 단언한다. 범위를 수량자로 일괄 단언하지 않는다.
- 0 쪽 자름 나눗셈은 SMT의 유클리드 `div`·`mod`로 정의한다: `tdiv(a,b) = sign(a)·sign(b)·div(|a|,|b|)`, `trem(a,b) = a − b·tdiv(a,b)`. 부호 없는 타입은 `div`·`mod` 그대로다.
- 래핑 연산은 `mod 2^64`로, `i64`는 그 뒤 부호 범위로 옮긴다.
- 슬라이스·배열은 `(Array Int Int)`(원소) + `Int`(길이)의 쌍이다. 쓰기는 `store`다.
- **길이 상한:** 슬라이스 길이는 `isize::MAX / size_of(T)` 이하라고 가정한다(`i64`·`u64`·`usize` 원소는 2^60 − 1, `bool`은 2^63 − 1). Rust 메모리 모델에서 할당 크기는 `isize::MAX` 바이트를 넘지 않으므로 건전한 사실이다. v0의 `len < 2^62` 공리를 근거 있는 사실로 대체한다.

### 4. `spec fn`
- 각 `spec fn`은 SMT 비해석 함수다. 정의 공리는 `∀ 인자. 범위(인자) ⇒ f(인자) = 본문`이고, 트리거는 `f(인자)`다.
- 정의 공리는 그 증명의 `#[uses(..)]`에 이름이 있을 때만 넣는다. 펼침은 전이되지 않는다. A의 본문이 B를 부르면, B를 펼치려면 B도 나열해야 한다.
- 재귀 `spec fn`은 범위 가정 아래 재귀 호출마다 `decreases` 값이 감소하고 0 이상임을 증명해야 정의 공리를 얻는다. 증명되지 않은 `spec fn`의 공리는 어디에도 넣지 않는다.

### 5. 질의 형태와 결정론
- 실행 함수 하나가 SMT-LIB 파일 하나다. 증명 의무마다 `(push)` `(assert (not 의무))` `(check-sat)` `(pop)`이다.
- 이름은 소스 경로·의무 위치에서 결정론적으로 만든다. 같은 입력이면 같은 바이트다.
- 옵션: `(set-option :smt.random_seed 0)`, 의무마다 고정 `rlimit`. 값은 `scripts/toolchain.env`의 `Z3_RLIMIT`이다(초기값 5,000,000, 측정 후 조정).
- `unsat`만 증명 성공이다. `sat`은 반례와 함께 실패, `unknown`·자원 초과·솔버 오류는 원인과 함께 실패다.

## 근거
- **v2에서는 Int가 건전하다.** 모든 실행 연산의 결과가 범위 안이라는 것이 증명 의무이므로, 증명이 통과한 프로그램에서 기계 값과 수학 값이 같다. v0가 bitvector를 쓴 이유(래핑과 무한 정수의 불일치)가 v2에는 없다.
- **Int가 더 잘 풀린다.** 범위 의무는 선형 부등식이고, 배열 인덱스를 다루는 수량자와 Z3의 정수 산술이 잘 맞는다. bitvector와 수량자의 조합은 불안정성의 주원인이다(genesis §4, 증명 취약성).
- 곱셈처럼 비선형인 의무는 `unknown`이 될 수 있다. 이것은 실패로 처리되고(fail-closed), 미증명 면적으로 드러난다.
- 비트 연산이 언어에 들어오면(M2 이후) 이 결정을 다시 검토한다.

## 결과
- 1B-02 이후 구현은 이 의미론을 따른다. `scripts/toolchain.env`에 `Z3_RLIMIT`을 추가한다.
- `#[uses]`가 전이되지 않으므로 증명 문맥 선언이 길어질 수 있다. 자동 채움 도구(DESIGN.md §8.2)의 후보다.
- 기존 예제 `tests/check/ok/search.bmb`는 증명 단계에서 `#[uses]`를 보강해야 한다.
