# ADR-0021: M1 측정 절차

- 상태: 채택 (자율 채택, AUTONOMY.md §4)
- 날짜: 2026-10-24
- 관련: DESIGN.md §9 R4, genesis §3.5·§5, ADR-0016, 백로그 1E-01

## 맥락
M1의 가설은 "에이전트가 파일 없이, 테스트 없이, 증명된 코드를 쓴다"이다(genesis §5). v0는 문제 지문을 고치는 동안 AI 벤치 점수를 올렸고, 재시도를 섞어 보고했다(genesis §3.5). 측정 절차를 과제보다 먼저 고정한다.

## 결정

### 1. 과제와 동결
- 과제는 `bench/m1/tasks/<id>.json`에 둔다. 각 과제는 지시문, 시작 작업 공간, 판정 방법을 담는다.
- 과제 유형은 둘이다.
  - **작성(write):** 정해진 시그니처의 정의를 구현하고 증명한다.
  - **탐색(navigate):** 시작 작업 공간에 대한 질문에 정의 경로 집합으로 답한다. 예: 영향받는 정의, 특정 술어를 보장하는 정의.
- 시작 작업 공간은 `bench/m1/seed/`의 BMB 프로그램이다.
- 지시문 틀(시스템 프롬프트)은 `bench/m1/prompt.md` 하나다.
- `bench/m1/MANIFEST`가 과제·시드·프롬프트 파일의 SHA-256 목록이다. 하네스는 MANIFEST와 실제 파일이 다르면 실행을 거부한다.
- 동결 뒤에 과제·프롬프트를 바꾸려면 새 과제 집합 이름(`m1b` 등)으로 만들고, 이전 결과와 섞어 보고하지 않는다.

### 2. 판정
- **작성 과제:** 아래 셋을 모두 만족해야 성공이다.
  1. 세션 종료 시 작업 공간 전체가 `verify`를 통과한다.
  2. 대상 정의가 요구한 시그니처를 갖는다.
  3. **명세 강도 검사:** 과제에 숨긴 기준 계약 `ref_pre`·`ref_post`에 대해, 하네스가 판정용 정의를 추가해 증명한다. 그 정의는 `requires ref_pre`, `ensures ref_post`를 갖고 본문에서 대상 정의를 부르기만 한다. 증명되면 에이전트의 `requires`는 기준보다 약하고(호출 가능), `ensures`는 기준보다 강하다(기준을 함의).
  - 그래서 "증명은 되지만 아무것도 말하지 않는 명세"는 실패다.
- **탐색 과제:** 답한 정의 집합과 정답 집합(맵에서 결정론적으로 계산)의 정밀도·재현율. 둘 다 1이면 성공이다.

### 3. 세션 규칙
- 과제당 세션은 한 번이다. 세션이 실패해도 다시 돌리지 않는다(1회 성공률).
- 세션 안에서 에이전트는 MCP 도구만 쓴다(`bmb mcp`). 파일 시스템·셸 도구는 주지 않는다.
- 세션 한도: 도구 호출 40회, 모델 출력 토큰은 과제당 고정값(하네스 설정에 기록). 한도에 닿으면 그 시점 상태로 판정한다.
- 모델 ID, 온도 등 설정은 결과 파일에 기록한다. 모델 간 비교는 같은 과제 집합·프롬프트에서만 한다.

### 4. 지표
| 지표 | 정의 |
| --- | --- |
| 1회 성공률 | 성공 과제 수 / 과제 수, 유형별로 따로 |
| 탐색 정확도 | 탐색 과제의 평균 정밀도·재현율 |
| 질의당 토큰 | 읽기 도구(`query`·`map`) 결과의 `ceil(bytes / 4)` 평균. 모델이 보고한 입력 토큰도 함께 기록 |
| Rust 습관 오류율 | 세션 중 반환된 진단 가운데 E02xx 개수 / `tx_commit` 호출 수 |
| 미증명 면적 | 세션 종료 시 실패한 의무 수와 `io` 정의 수 |

토큰 단위는 바이트 기반 근사(`ceil(bytes/4)`)로 고정한다. 모델별 토크나이저 값은 참고로만 기록한다.

### 5. 보고
- 원자료는 `bench/m1/results/<날짜>-<모델>.jsonl`(과제마다 한 줄)에, 요약은 `dev-docs/measurements/`에 커밋한다.
- 요약에는 과제 편향(정수·배열 한정, ADR-0016), 과제 수, 한도, 실패 사례를 함께 적는다.
- 하네스는 실제 모델 없이 대본 에이전트(replay)로 끝까지 돌 수 있어야 하고, 그 경로는 CI에서 테스트한다.

## 근거
- 명세 강도 검사가 없으면 `ensures true`에 가까운 명세로 "증명 성공"을 만들 수 있다. 기준 계약 함의를 증명으로 판정하면 테스트 없이도 명세의 충분성을 잴 수 있다.
- 동결 해시와 재시도 금지는 v0의 측정 실패를 직접 막는다.

## 결과
- 과제 작성 비용이 든다. 과제마다 기준 해법이 판정을 통과하는지를 CI가 확인한다(풀 수 있는 과제임을 보장).
- 실제 모델 실행은 유료 API를 쓰므로 사람의 승인이 필요하다(AUTONOMY.md §4).
