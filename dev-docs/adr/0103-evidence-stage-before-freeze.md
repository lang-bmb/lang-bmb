# ADR-0103: 동결 전 증거 단계(2H-01)와 측정의 검정력

- 상태: 채택(사람 승인 2026-11-09 "Ok 제안 및 권장안 채택", 종합 평가의 결정 D2·D5와 제안 P1·P2·P7·P8)
- 날짜: 2026-11-09
- 관련: ADR-0100 §5(동결 선언의 전제), ADR-0066(측정 모델), ADR-0077(반복 측정, 최소 차이 D), ADR-0078(보조 가설), ADR-0102(G5-L, E3 판정), ADR-0104(대규모 과업 축), `dev-docs/reports/utility.md` §5

## 맥락

- 가설 26개 가운데 확정 0, 반증 2(H-EFFECT, H-REPAIR), 결정론 근거 7이다. 결정론 근거는 모두 도구 사슬의 성질(안정성, 국소성, 정체성, 병합)이다. E3의 이득 쪽 가설(H-ORACLE, H-AMORT, H-SCALE, H-ENCAP, H-GAME)은 판정 불가이거나 아직 돌지 않았다. 그 측정 도구는 대부분 동결돼 있다: `bench/brb-encap`, `bench/impossible`, `bench/{m1b,bvb}-{diff,ast}`, BCB `suite`, BNB 과제 27개.
- 동결(ADR-0100) 뒤에는 측정이 요구하는 언어 변경이 포팅한 쪽에도 들어가야 하므로 비용이 두 배다.
- 1회 실행의 최소 차이 D는 30%p다(ADR-0077). 과제 25개짜리 집합에서 30%p 안의 차이는 방향을 주장하지 못한다. 그래서 "방향 일치"가 "확정"으로 가는 길이 거의 없다.
- H-ORACLE은 숨은 결함이 두 팔 모두 0이라 변별되지 않았다. 과제가 쉬운 탓이다(T0-07).
- 과제·하네스·컴파일러를 같은 작성자가 만들었다(utility §4.3).
- H-REPAIR(반례·수리 제안이 수리 반복을 줄인다)가 qwen 1회로 반증됐는데, 게이트의 P3(고칠 길이 붙은 오류 비율) 래칫은 산문 수리 제안을 계속 늘리는 쪽으로 작업을 끌었다.

## 결정

1. **2H-01은 증거 단계다.** 동결 선언(4D-01) 전에 측정 머신에서 차례로 돈다. 순서는 대기 중인 판정의 크기순이다.
   1. 2R-05: ADR-0095 앞뒤 문법 A/B(`bench/m1b`, 등록대로). 이어서 쓰기 판(`bench/m1b-write`) A/B.
   2. T0-21 H-ENCAP, T0-18 H-GAME: 동결된 집합, 반증 조건이 등록돼 있다.
   3. T0-08 H-ORACLE 변별 과제: 새로 만들어 동결한 뒤 돈다(결정 4).
   4. T1-41 H-EDIT: 남은 칸.
   5. BNB 모델 실행(3A-06의 모델 팔, ADR-0104 결정 5): 규모 축의 첫 모델 근거.
   6. 2A-14e H-AMORT: 모델이 필요 없는 CPU 측정이다. INF-19로 겹침 오염이 없음을 보이면 모델 측정과 병행한다.
2. **검정력은 순차 설계로 얻는다.** 위의 비교마다 qwen으로 한 번 돌리고, 차이가 D 안이면 같은 커밋·조건에서 반복을 3회까지 늘려 ADR-0077 §3의 구간으로 판정한다. 반복의 범위(ADR-0077 §2)는 이 비교들까지 넓힌다. 늘릴지는 첫 실행의 차이만으로 정하고 결과의 방향으로 정하지 않는다(이 문장이 사전 등록이다). sonnet은 ADR-0066 §3대로 같은 커밋에서 한 번이다.
3. **주장의 기준 모델.** 언어·도구의 효용 주장은 프런티어 교차 모델(sonnet)의 결과로 판정한다. qwen 결과는 같은 표에 나란히 보고하고 격차를 H-SMALL로 추적한다. 측정의 기본 실행 모델은 ADR-0066 그대로 qwen이다(반복, 디버깅, 첫 실행). 작은 모델을 1급 대상으로 삼을지는 H-SMALL 측정 뒤 다시 정한다.
4. **외부 과제를 섞는다.** T0-08의 과제는 가능한 한 제3자 출처(검증된 공개 벤치, 공개 버그 데이터)에서 옮기고, 출처와 라이선스를 과제마다 적는다. 출처를 가져올 수 없으면(네트워크 정책) 작성자 과제임을 표시한다.
5. **산문 수리 제안에는 새 투자를 멈춘다.** P3 래칫은 회귀 방지로 남긴다. P3를 올리는 것만이 목적인 태스크는 H-REPAIR를 반복 측정(결정 2)으로 다시 판정할 때까지 만들지 않는다. 기계가 적용하는 `bmb fix`는 이 결정 밖이다(정규형·결정론 효용).

## 근거

| 안 | 판정 |
| --- | --- |
| **동결 전 증거 단계, 순차 반복(채택)** | 동결 전이 언어 변경 비용이 가장 낮은 마지막 시점. 측정 도구가 이미 동결돼 있어 추가 구축이 작다. 반복은 필요할 때만 해 측정 머신 시간을 아낀다 |
| 동결 뒤 측정 | 결과가 언어 변경을 요구하면 두 컴파일러를 고쳐야 한다 |
| 모든 비교를 처음부터 5회 | 검정력은 가장 크지만 측정 머신 직렬 시간이 다섯 배(qwen 세션당 약 5분) |
| qwen을 주장 기준으로 | 사람 지침은 "가급적 qwen"이고 그것은 실행에 대한 지침이다. 효용 주장은 대상 사용자(프런티어 에이전트)에서 판정하는 것이 E1~E3의 대상과 맞다 |

## 결과

- 백로그 2H-01의 완료 기준이 위 목록이 된다. 4D-01은 2H-01과 2H-02 뒤다(ADR-0100 §5 그대로).
- `bench/run_models.py`의 `REPEAT_SETS`는 반복이 필요해진 집합만큼 넓힌다(그때 이 ADR을 근거로 적는다).
- 효용 보고서(utility)는 결과가 나올 때마다 §0~§5 서술까지 다시 쓴다.
