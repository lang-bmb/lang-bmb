# ADR-0029: 탈출구(`assume`·`external_body`)와 구조화 근거

- 상태: 제안 (언어 범위 확대. 채택은 사람 승인, AUTONOMY.md §4)
- 날짜: 2026-10-24
- 관련: DESIGN.md §4.1(탈출구·주석)·원칙 3·4·9·§7.2(미증명 면적), ADR-0003, ADR-0006, ADR-0016, ADR-0019 §2, ADR-0020, ADR-0030(제안), ROADMAP 2E, 백로그 2E-01

## 맥락
M1에는 탈출구가 없다. 증명되지 않으면 빌드되지 않고, 미증명 면적은 `io` 경계(`print_i64`)뿐이다(ADR-0016). 이 엄격함 때문에 다음이 막힌다.

- **비선형 산술.** `pow`(밑 ≤ 10, 지수 ≤ 15)의 의무 하나가 `rlimit` 500만 중 410만을 썼고 코퍼스에서 뺐다(`dev-docs/measurements/m1.md` §6). 수학적으로 참인 사실을 해법기가 못 푸는 경우 우회로가 없다.
- **해법기 한계.** 양화사가 남는 술어는 `unknown`(E0811)으로 끝날 수 있다(ADR-0023 결과). 판정은 옳게 실패지만 에이전트는 진행할 수 없다.
- **경계.** 앞으로 들어올 외부 경계(입력, 시간, FFI)는 본문을 증명할 수 없다.

DESIGN.md §4.1은 탈출구를 "근거 선언 필수, 맵에 미증명 면적으로 집계"로 정했고, ADR-0006은 근거를 노드 해시에 묶어 바뀌면 "미확인"으로 표시한다고 정했다. 문법·형식·코드 생성 규칙은 정해지지 않았다. 원칙 9는 "검증되지 않은 계약은 최적화에 쓰지 않는다"이다.

## 결정(제안)

### 1. 표면
- `assume(p(args));`: 실행 함수 본문의 문장. 인자는 계약 절과 같이 이름 붙은 술어 호출 하나(E0501과 같은 규칙, 위치가 달라 새 코드). 그 지점 이후의 증명에 `p(args)`를 가정한다. Verus의 `assume`과 같은 이름이다.
- `#[external_body]`: 실행 함수 속성. 본문은 검사(이름·타입·효과·소유권)만 하고 증명 의무를 만들지 않는다. 호출자는 평소처럼 `requires`를 증명하고 `ensures`를 가정한다. `spec fn`·`main`에는 쓸 수 없다.
- **근거 필수:** 두 탈출구 모두 바로 앞에 `#[rationale(kind = K, hash = "..", "설명")]`이 있어야 한다. 없으면 E1001.
  - `kind`는 닫힌 목록: `nonlinear`(비선형 산술), `solver_limit`(E0811 등 해법기 한계), `boundary`(외부 경계), `performance`(증명 비용 대비 이득). 맵이 신뢰 기반을 이유별로 집계하는 데 쓴다.
  - `hash`는 근거가 묶인 노드의 해시다(§3). **도구가 채운다**(원칙 6): 근거를 처음 쓰거나 확인할 때 `bmb fix`/트랜잭션 연산이 현재 해시를 써 넣는다. 에이전트는 설명과 `kind`만 쓴다.
- 구조화 근거는 탈출구 밖(`fn`, `spec fn`, `mod`)에도 붙일 수 있다(선택). `//` 주석은 M2에서도 유지한다(열린 질문 4).

### 2. 증명 게이트: 신뢰 사실의 분리
신뢰 사실 집합 `T` = 정의 안의 `assume` 사실 ∪ `external_body` 함수의 `ensures` ∪ 신뢰 등급이 `proved`가 아닌 callee의 `ensures`.

1. 정의의 의무를 먼저 `T` 없이 푼다(1차). 모두 증명되면 신뢰 등급 `proved`. 이때 정의의 `assume`은 필요 없는 것이므로 `bmb lint`가 경고한다(W1002).
2. 1차에서 실패한 의무가 있으면 `T`를 넣고 그 의무만 다시 푼다(2차). 모두 증명되면 신뢰 등급 `assumed`, 아니면 지금처럼 실패(`failed`, 빌드 거부).
3. `external_body` 정의는 의무가 없고 신뢰 등급 `external`이다.
4. 신뢰 등급은 호출 그래프를 따라 고정점으로 계산한다. callee가 `proved`가 아니면 그 `ensures`가 호출자의 `T`에 들어가므로, 그것에 기대는 호출자도 `assumed`가 된다(SCC 단위, 단조라 종료한다).
- 1차 결과는 `T`와 무관하다. 그래서 탈출구를 추가·삭제해도 `proved` 정의의 판정은 바뀌지 않는다(퍼저 성질 2).
- 증명 캐시 키(ADR-0019 §2의 출발점)에 callee의 신뢰 등급을 더한다. 계약이 같아도 등급이 바뀌면 다시 푼다.

### 3. 근거의 노드 해시와 "미확인"
- 근거 해시 = SHA-256(묶인 노드의 한정 정규형 ‖ 그 노드가 이름으로 부르는 술어들의 본문 해시). 묶인 노드는 `assume`이면 **둘러싼 정의의 본문**, `external_body`면 **그 정의 전체**다. 가정하는 술어의 정의가 바뀌어도 근거가 다른 것을 말하게 되므로 술어 해시를 함께 넣는다.
- 모든 해시(ADR-0019의 `body`·`iface`, 근거 해시)의 입력에서 `#[rationale(..)]` 속성은 뺀다. 근거 문구를 고쳐도 증명 캐시·중복 탐지가 흔들리지 않고, 해시가 자기 자신을 담는 순환이 없다. ADR-0019 §2("속성 … 전체")의 보완이다.
- 저장된 `hash`와 현재 값이 다르면 그 근거는 **미확인**이다. 미확인은 빌드를 막지 않는다(열린 질문 2). `status`·L1에 표시되고 `bmb lint`가 W1001로 알린다.
- 트랜잭션 `tx.put`은 근거 해시를 고쳐 쓰지 않는다. 자동으로 고치면 미확인이 드러나지 않기 때문이다. 확인은 명시적 연산(`tx.confirm_rationale(def)`, CLI `bmb fix --confirm`)이다. 확인은 판단이므로 에이전트의 몫이다.

### 4. 코드 생성: 신뢰 사실은 최적화 근거가 아니다
- `proved` 정의만 증명된 의무로 검사를 지운다(현재와 같음).
- `assumed`·`external` 정의는 **전체 검사 모드**로 컴파일한다. 즉 넘침·0 나눗셈·인덱스·변환 검사가 모두 `llvm.trap`으로 남는다. 현재 코드 생성기가 증명된 의무 집합(`codegen::emit`의 `proven`)에서 그 정의의 의무를 빼는 것으로 구현된다. 퍼저가 이미 쓰는 "전체 검사 빌드"와 같은 경로다.
- **하향 전파:** 전체 검사 모드 정의가 부르는 callee도 전체 검사 모드로 컴파일한다. 그 호출의 `requires`는 거짓일 수 있는 가설 위에서 증명되었기 때문이다(callee의 검사 제거가 전제에 기댄다). 처음에는 정의당 한 벌만 만들고, 측정에서 비용이 크면 검사 모드 복제본을 따로 두는 최적화를 검토한다.
- `assume` 자체는 코드를 만들지 않는다(술어는 일반적으로 실행할 수 없다). 안전은 남은 검사가 맡는다. 거짓 `assume`의 결과는 미정의 동작이 아니라 trap이다.
- 남은 검사가 있는 정의는 `panic` 효과를 갖는다(ADR-0030 제안). 그래서 탈출구의 영향이 효과로 호출자에게 드러난다.
- `noalias`·`readonly`는 타입 규칙(ADR-0015)에서 나오므로 신뢰 등급과 무관하게 유지한다.

### 5. 맵·`status`(ADR-0020 하위 호환: 키 추가만)
- L1 행·`status` 행에 키 추가: `trust`(`"proved"|"assumed"|"external"|"failed"`), `escapes`(정의 안 `assume` 수 + `external_body` 여부), `assumed_obligations`(2차에서만 증명된 의무 수), `checked`(전체 검사 모드 여부), `rationale`(`"none"|"confirmed"|"unconfirmed"`), `rationale_kinds`.
- `status` 요약 행에 `proved`, `assumed`, `external`, `escapes`, `unconfirmed` 추가. 기존 `status` 키의 값과 뜻은 그대로다(`verified` = 빌드 게이트 통과). 측정 하네스는 `trust`로 성공을 판정한다(§6).
- 미증명 면적 뷰(DESIGN.md §7.2)는 `trust != "proved"`인 정의와 그 근거, 그리고 `T`를 통해 등급이 떨어진 정의의 원인 간선(어느 callee의 `ensures` 때문인지)을 낸다.

### 6. 측정과의 관계
- 탈출구가 있으면 에이전트가 `assume`으로 과제를 "통과"할 수 있다. `m1b`/`m2` 하네스는 작성 과제의 성공 조건에 **새로 쓴 정의가 모두 `trust = "proved"`**를 더한다. 탈출구를 허용하는 과제는 따로 표시한다. 1E 동결 과제·프롬프트는 바꾸지 않는다.
- 미증명 면적(정의 수, `assumed_obligations` 합, `kind`별 분포)은 DESIGN.md §9 R4의 측정 축이다.

### 7. 거부할 Rust·Verus 습관과 진단(번호는 제안)

| 습관 | 처리 | 코드 |
| --- | --- | --- |
| `unsafe { .. }`, `unsafe fn` | 거부. 증명할 수 없는 본문은 `#[external_body]`로 | E0215 |
| `#[verifier::external_body]`, `#[verifier(external_body)]`(Verus) | `#[external_body]`로 기계 교체 | E0216 |
| `admit()`(Verus), `assume!`/`debug_assert!` | `assume(p(..))` + 근거로 안내(매크로는 기존 E0202) | E0217 |
| `// SAFETY: ..` 주석 뒤의 탈출구 | 주석 문구를 `#[rationale(..)]`의 설명으로 옮기는 수정 제안 | E1001의 `fix` |
| 근거 없는 탈출구 | 오류 | E1001 |
| 근거 형식 오류(`kind` 밖 값, 빈 설명, 탈출구 아닌 문장 앞) | 오류 | E1002 |
| `assume`의 인자가 술어 호출이 아님, `spec fn`·명세 문맥의 `assume` | 오류 | E1003 |
| `#[external_body]`를 `spec fn`·`main`에 붙임 | 오류 | E1004 |
| 근거 미확인 | 경고(`bmb lint`) | W1001 |
| 1차에서 이미 증명되어 필요 없는 `assume` | 경고(`bmb lint`) | W1002 |

E10xx·W10xx는 새 범주 "탈출구와 근거"다. W09xx(계약 조정 린트)와 섞지 않는다.

### 8. 테스트·퍼저
- 코퍼스: `tests/check/err`(E1001~E1004, E0215~E0217), `tests/verify`(`proved`/`assumed`/`external`/등급 전파 사례), `tests/run`(거짓 `assume`이 trap으로 끝나는 사례).
- IR 검사: `assumed`·`external`과 그 하향 전파 정의에는 `; proved` 주석과 검사 없는 연산이 없다.
- 건전성 퍼저(새 `soundness_escape.rs`, 기존 생성기 재사용): 무작위로 참·거짓 `assume`과 거짓일 수 있는 `external_body` 계약을 섞는다. 성질:
  1. `proved` 정의는 `T`가 거짓이어도, 전제를 만족하는 입력에서 오류가 없고 사후 조건을 만족한다(해석기는 `assume`을 무시하고 실행).
  2. 모든 `assume`을 지운 프로그램과 `proved` 집합이 같다.
  3. 실행 파일의 출력과 종료 상태가 "남은 검사에서 trap" 의미의 해석기와 같다. 즉 거짓 신뢰 사실이 조용한 오동작(trap 없는 틀린 출력, 범위 밖 접근)을 만들지 않는다.
- 근거 해시: 묶인 노드·가정 술어를 바꾸면 미확인, 근거 문구·`#[rationale]`만 바꾸면 확인 상태와 정의 해시가 그대로임을 테스트한다. 결정론(두 번 실행 같은 바이트)과 배치 독립(ADR-0020)도 같은 테스트에 둔다.

## 근거(검토한 대안)

| 안 | 판정 |
| --- | --- |
| **신뢰 사실 분리 + 전체 검사 모드(채택 제안)** | 원칙 9를 그대로 지킨다. 거짓 탈출구의 최악은 trap이다. 구현은 기존 "전체 검사 빌드" 경로의 정의 단위 적용이다 |
| Verus처럼 신뢰 사실을 증명 사실과 똑같이 사용 | 거짓 `assume` 하나가 `inbounds`·`nsw`를 통해 미정의 동작이 된다. v0의 "검증 여부와 무관하게 모든 계약에서 `llvm.assume` 방출" 결함(genesis §3.2 원칙 9 행)과 같은 종류다. 기각 |
| 의무 단위로만 검사 유지(2차에서 증명된 의무만 검사) | 불충분. 1차에서 증명된 의무도 2차로만 증명된 불변식·`assert`·callee 전제를 가설로 쓸 수 있어, 그 가설이 거짓이면 지운 검사가 틀린다. 정의의 사양 수준 의무가 모두 1차에서 증명된 경우에 한한 세분화는 측정 후 최적화로 둔다 |
| `assume(P)`를 실행 시 검사(`assert!`처럼)로 컴파일 | 술어가 `spec fn`·`forall`·무한 정수라 일반적으로 실행할 수 없다. 실행 가능한 부분집합만 검사하면 탈출구의 의미가 술어 모양에 따라 달라진다. 기각(전체 검사 모드가 같은 안전을 준다) |
| 증명 힌트(`assert .. by(nonlinear_arith)` 등)만 두고 탈출구 없음 | 힌트가 더 나은 방향이지만 범위가 크고 모든 한계를 풀지 못한다. 탈출구는 마지막 수단으로 두고, 힌트는 `kind = nonlinear` 집계를 근거로 따로 제안한다 |
| 근거를 정의 단위가 아니라 `assume` 문장 노드에만 묶음 | 주변 코드가 바뀌어 가정의 이유가 사라져도 감지되지 않는다. 기본은 둘러싼 정의(열린 질문 3) |
| 미확인 근거로 빌드 실패 | 정확성(이미 신뢰한 사실)과 무관하고, 확인 연산 하나로 넘길 수 있어 실효가 낮다. 경고 + 집계로 시작 |

## 결과
- 증명 게이트가 의무를 최대 두 번 푼다(1차 실패분만). 비용은 탈출구 수에 비례한다.
- 신뢰 등급 전파 때문에 탈출구 하나가 여러 호출자의 등급과 성능(전체 검사 모드)을 떨어뜨릴 수 있다. 이것은 의도한 정직한 집계이고, 영향은 `impact`/미증명 면적 뷰로 보인다.
- 해시 입력에서 `#[rationale]`을 빼는 것은 ADR-0019 §2의 보완이다. 채택 시 DESIGN.md §4.1 탈출구 행에 "신뢰 사실은 최적화에 쓰지 않는다"를 더한다.

## 열린 질문(측정 1E-07 또는 사람이 정함)
1. **2E의 시점:** 탈출구가 없어서 실제로 막힌 빈도(1E-10의 E0811·비선형 실패)가 있어야 우선순위가 선다. 현재 증거는 작성자 코퍼스의 `pow` 하나다.
2. **미확인의 강제력:** 경고(제안) 대 `build` 거부. 사람이 정한다.
3. **근거 해시의 범위:** 둘러싼 정의 전체(제안)는 무관한 편집에도 미확인을 만든다. `m2`에서 미확인 발생 수 대비 실제로 근거가 낡은 비율을 재서 정한다.
4. **`//` 주석의 처리:** DESIGN.md §4.1은 자유 주석을 구조화 근거로 대체한다고 했다. M2에서 `//`를 없앨지(Rust 습관 오류 증가 예상) 사람이 정한다.
5. **`kind` 목록:** 네 값으로 충분한지. `todo`(임시)를 둘지 — 두면 남용 위험, 없으면 작업 중 상태 표현이 없다.
6. **`external_body`의 효과:** 본문 검사로 효과를 확인하므로 효과는 신뢰하지 않는다(제안). 외부 경계(FFI)가 들어올 때 다시 정한다(4단계 생태계 이후).
