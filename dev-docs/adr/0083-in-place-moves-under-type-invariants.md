# ADR-0083: 반복 사이에 깨지는 타입 불변식: 루프 규칙은 그대로, 제자리 이동은 `copy_within`으로

- 상태: 채택 (사람 승인 2026-11-02 "결정사항 권장안 채택": 권장 (D). ADR-0060 열린 질문 3, 백로그 T1-26. 구현 T1-26a)
- 날짜: 2026-11-02
- 관련: ADR-0060 §2(유효성의 가정·의무), ADR-0031(`Vec`·슬라이스 연산), ADR-0016(언어 범위), JUDGMENT §10

## 1. 문제

엄격한 정렬 집합(`tests/run/sorted_set`)의 `insert`를 `self.items` 위에서 제자리로 옮기면(`self.items[j] = self.items[j - 1]`을 `j`를 줄이며), 반복 사이에 같은 값이 둘 있어 루프 머리의 유효성 의무(E0823)가 실패한다. 지금은 사본(`let mut a = self.items`) 위에서 옮기고 끝에 한 번 대입한다. 엄격하지 않은 순서(`<=`)라면 제자리 이동도 반복마다 불변식을 지킨다. 고리 버퍼, `generic_stack`, BRB-ENCAP의 넷(`bench/brb-encap`)의 루프는 막히지 않았다.

## 2. 원인과 귀속 층

ADR-0060 §2는 루프가 havoc하는 지역(불변식이 있는 타입)의 유효성을 머리에서 가정하고, 진입과 반복 끝에서 의무로 낸다. 그래서 반복 사이에 깨 두는 이동은 표현할 수 없다. 층은 언어(유효성 규칙)이거나, 이 이동을 한 연산으로 쓰게 하는 표준 연산의 부재(라이브러리)다.

## 3. 정석 해와 출처

- Rust: 겹치는 제자리 이동은 `slice::copy_within(src, dest)`(표준 라이브러리)로 쓴다. 손으로 쓰는 원소별 루프는 정석이 아니다.
- Verus·Dafny: 루프 머리에 타입 불변식을 자동으로 두지 않고, 루프 불변식으로 쓴다(Dafny의 `Valid()`는 명시적 술어). 자동 머리 유효성은 BMB가 편의로 더한 것이다(ADR-0060, `generic_stack` 이주에서 루프 불변식 절이 하나 줄었다).

## 5. 권장과 결정적 기준

(D). 갈린 기준은 S1과 S4다. 막힌 코드의 Rust 정석은 루프가 아니라 `copy_within` 한 호출이고, 그 호출은 불변식을 반복 사이가 아니라 한 연산 안에서만 깨므로 루프 규칙을 바꿀 필요가 없다. (C)는 정석과 같지만 지금 자동으로 얻는 머리 가정을 모든 루프에서 잃는다(S4). (B)는 선례 없는 표기다.

- 표면: `a.copy_within(lo..hi, dest)`(배열·`&mut [T]`·`Vec<T>`, `T: Copy`). 의무: `lo <= hi <= len`, `dest + (hi - lo) <= len`(E0805와 같은 경계). 결과: 새 배열의 `dest + k` 위치(`k < hi - lo`)는 옛 배열의 `lo + k`, 나머지는 그대로. 코드 생성: `llvm.memmove`(이미 있음).
- 그대로인 것: ADR-0060 §2의 머리 유효성. `sorted_set`의 `insert`는 `copy_within` 한 줄과 대입 둘이 된다.

## 6. 영향(정보)

- 검사기(메서드 하나), 인코더(배열 갱신 항: 범위 양화 하나), 코드 생성(`memmove`), 퍼저(`soundness_vec`에 이동 하나). 코퍼스: `tests/run/sorted_set`, BRB-ENCAP 기준 해법은 동결이라 그대로.
- 측정 조건: 컴파일러 트리가 바뀌므로 새 조건이다(ADR-0070 (a)). 동결 프롬프트의 언어 규칙 절에는 없는 연산이라, 에이전트가 쓰면(Rust 습관) 이제 받아진다.

## 구현 (2026-11-02, 백로그 T1-26a)

- 표면: 인자 자리의 `lo..hi`는 구문 트리 `ExprKind::Range`이고 `copy_within`의 첫 인자에서만 받는다(다른 곳 E0435, 새 진단). 인자 모양 E0405, 공유·불변 수신자 E0408, 이동 원소 E0404, 명세 안 E0503.
- 인코딩: §5의 의무 둘(E0805). 범위가 상수이고 16개 이하이면 새 원소 배열은 옛 값들의 `store` 사슬이고, 아니면 원소 잎 배열마다 새 상수 하나와 정량 사실 하나(트리거는 새 배열 읽기)다. 정량 사실만 쓰면 상수 범위의 두 시험 함수에서 도달 가능성 검사(W0905)가 미결정 2개, rlimit 2,000,000이었고 `store` 사슬로 0개, 4,454였다(health V12). 길이는 그대로이고 루프 쓰기 집합에 수신자가 든다.
- 코드 생성: 증명되지 않은 범위만 검사하고 `llvm.memmove` 한 번.
- 시험: `tests/verify/pass/copy_within.bmb`(배열·슬라이스·`Vec`·구조체 원소, 일반 계약), `tests/verify/fail/copy_within.bmb`, `tests/check/err/copy_within.bmb`, `soundness_vec`의 `CopyWithin`(경계 밖 포함, 해석기 대조), 게이트 검출력 변이체 `v-copy-within-dest-bound`·`v-copy-within-unshifted`.
- `tests/run/sorted_set`의 `insert`는 사본 우회 대신 `self.items.copy_within(p..n, p + 1)`로 옮기고 `shifted` 술어가 사라졌다. 출력은 그대로다.
