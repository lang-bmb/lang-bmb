# ADR-0138: 안정성과 버전 정책

- 상태: 채택(사람 승인 2026-11-14 "1/2 승인", 백로그 `5B-01`)
- 날짜: 2026-11-14
- 관련: ADR-0019(정규형), ADR-0037(부트스트랩), ADR-0059(정체성 해시), ADR-0095(입력 별칭), ADR-0100(stage0 기능 동결), ADR-0113(포팅된 구성 요소의 고정), `docs/ROADMAP.md` 5B, `docs/reference/`

## 맥락

- 컴파일러의 버전은 `0.0.1`에서 바뀐 적이 없다(`compiler/Cargo.toml`). 무엇이 바뀌면 버전이 바뀌는지 정한 적이 없다.
- 호환을 판정할 결정론 도구는 이미 있다. 받아들이는 언어는 지문(`scripts/surface.py`, 프로그램 248개와 진단 코드 191)과 적합성 사례 402개(`scripts/conformance.py`)가, 계약의 호환은 `bmb weaken`(H-COMPAT)이, 정의의 정체성은 해시(ADR-0059)가 본다. 진단 코드는 은퇴시키되 다시 쓰지 않는다(`diag::RETIRED`).
- 깨는 변경을 기계로 옮긴 선례가 있다: ADR-0095의 문법 변경은 옛 꼴을 입력 별칭으로 받아 `bmb fix`와 정규형이 새 꼴로 옮겼다(코퍼스 128/128).
- 동결(ADR-0100)은 포팅 동안 받아들이는 언어를 묶는다. 그 뒤(stage0 은퇴 뒤)의 규칙은 없다.
- 0.x 동안 리팩터링은 언제나 허용이다(JUDGMENT §6). 이 ADR은 그것을 바꾸지 않는다: 정하는 것은 무엇을 알리고 어떻게 옮기는가다.

## 결정

1. **호환의 대상은 넷이고, 각각을 지금 있는 도구가 판정한다.**

   | 대상 | 깨졌다는 것 | 판정 |
   | --- | --- | --- |
   | 받아들이는 언어 | 받던 프로그램을 거부하거나, 같은 프로그램의 뜻(출력, 증명 결과)이 바뀜 | 지문과 적합성 사례 |
   | 진단 코드 | 코드의 뜻이 바뀌거나 번호가 다시 쓰임 | `docs/diagnostics.md`, `RETIRED` |
   | 표준 라이브러리의 계약 | `pub` 함수의 계약이 호환되지 않게 바뀜 | `bmb weaken`의 판정 |
   | 도구의 출력 꼴 | CLI의 JSONL 필드나 MCP 도구의 인자·응답 필드가 없어지거나 뜻이 바뀜 | 차등 시험 사례(`tests/port`)와 CLI 시험 |

   정체성 해시의 계산이 바뀌는 것은 깨는 변경으로 센다(캐시와 `expect` 값이 무효가 된다).
2. **1.0 전의 버전은 `0.MINOR.PATCH`다.** 위 넷 가운데 하나가 깨지면 MINOR를, 아니면 PATCH를 올린다. 지문의 `history`에 항목이 생긴 커밋은 MINOR가 올라야 한다(게이트가 본다, 승인 뒤 태스크).
3. **이정표의 버전.** 동결 선언(`4D-01`)이 `0.1.0`, 전체 고정점(관문 D, 자립 사다리 L3)이 `0.2.0`이다. `1.0.0`의 조건은 stage0 은퇴(`4G-01`), 관문 B·D의 판정이 커밋돼 있을 것, 레퍼런스의 모든 절이 적합성 사례에 대응할 것(5A)이다.
4. **에디션은 두지 않는다.** 한 컴파일러가 두 방언을 받지 않는다. 깨는 표면 변경은 다음 순서로만 한다.
   1. 새 꼴을 정본으로 받고, 옛 꼴은 입력 별칭으로 받아 경고(W 코드)와 기계 수정(`bmb fix`)을 붙인다. 정규형은 새 꼴만 낸다.
   2. 다음 MINOR에서 옛 꼴을 거부한다(E 코드, 수정은 그대로 붙는다).
   - 기계 수정이 없는 깨는 변경은 1.0 전에는 ADR에 이주 절차를 적고, 1.0 뒤에는 MAJOR다.
5. **이주의 통과 기준.** MINOR를 올리는 커밋은 직전 MINOR의 코퍼스(태그의 `tests/`, `lib/std`, 벤치 시드)가 `bmb fix --write` 뒤 게이트를 통과함을 보인다.
6. **1.0 뒤는 유의적 버전이다.** MAJOR는 기계 이주가 없는 깨는 변경, MINOR는 더하는 변경과 기계 이주가 있는 깨는 변경, PATCH는 나머지다.
7. **동결 기간의 규칙은 ADR-0100이 우선한다.** 동결부터 stage0 은퇴까지 받아들이는 언어의 변경은 그 ADR의 예외뿐이고, 예외마다 MINOR가 오른다.

## 근거

| 안 | 판정 |
| --- | --- |
| **대상 넷, 에디션 없음, 별칭을 거치는 이주(제안)** | 호환의 판정이 이미 있는 결정론 도구에 놓인다(주장은 코드 경로로). 한 컴파일러·한 정규형(ADR-0019)과 맞고, ADR-0095가 이 절차로 한 번 돌았다 |
| Rust식 에디션 | 옛 방언을 영구히 받는 것은 컴파일러와 그 포트에 두 표면을 남긴다(포팅할 양, 증명할 양). 에이전트가 쓰는 언어에서는 기계 이주의 비용이 사람보다 훨씬 낮아 에디션이 사는 것이 적다 |
| 1.0까지 정책 없음 | 지금까지의 방식. 동결 선언이 첫 버전 사건인데 버전이 그것을 말하지 못한다. 측정 결과의 조건 표기(ADR-0070)도 커밋 해시에만 기댄다 |
| 달력 버전 | 호환을 말하지 않는다 |

## 결과

- 동결 선언 커밋에서 버전을 `0.1.0`으로 올렸다(`compiler/Cargo.toml`). 버전은 MCP의 `serverInfo`와 증분 캐시의 컴파일러 정체성에 든다.
- 후속: 게이트가 지문의 `history`와 버전을 견준다(백로그 `5B-02`). `5C-04`(릴리스 절차)는 이 버전을 태그와 변경 기록에 쓴다.
- 열린 질문: 표준 라이브러리의 `pub` 표면을 지문에 넣을지(지금은 프로그램의 결과만 본다). `bmb weaken`을 직전 MINOR의 `lib/std`와 견주는 게이트 작업으로 풀 수 있다(`5B-02`에서 함께 본다).
