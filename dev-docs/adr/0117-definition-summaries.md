# ADR-0117: 정의의 요약 `#[summary("..")]`와 입력 꼴 `///`

- 상태: 채택(사람 승인 2026-11-11 "A1~A7 권장안 채택", 안건 A3. 백로그 3P-08, ADR-0106 결정 5가 사람에게 넘긴 표면 결정)
- 날짜: 2026-11-11
- 관련: DESIGN §4.1 "주석"·§7.1(L1), ADR-0006(근거는 노드 해시에), ADR-0019(정규형), ADR-0008·0020(맵 L1, 추가는 하위 호환), ADR-0095(입력 별칭), ADR-0106(쌍둥이의 문서 조건), ADR-0100(동결)

## 맥락

- 단위에는 한 줄 요약 `#[summary("..")]`가 있고 맵 L0에 실린다. 정의(함수, 타입, trait, 상수)에는 문서를 실을 곳이 없다. 정규형은 주석을 지운다(DESIGN §4.1: 자유 주석 대신 구조화된 근거).
- 포팅 쌍둥이 측정(ADR-0104)에서 Rust 팔은 `///` 문서를 가질 수 있는데 BMB 팔은 가질 수 없다. ADR-0106은 Rust 팔의 주석을 지우는 조건을 주 조건으로 두고, BMB 쪽 통로는 표면 결정이라 사람에게 넘겼다.
- 저장소의 BMB 원문에는 이미 정의 앞 `///`가 열여섯 줄 있다(`tests/tools`, `bench/twin/fixtures`). 지금까지는 주석으로 버려졌다.
- 동결(ADR-0100) 뒤에 넣으면 두 컴파일러를 고친다.

## 결정

1. **정의는 `#[summary("..")]`를 하나 가질 수 있다.** 함수(trait 메서드 선언 포함), `struct`·`enum`, `trait`, `const`에 붙는다. 인자는 문자열 하나다(E0704). 둘 이상이면 E0605다. 단위의 `#[summary]`와 같은 속성이다.
2. **`///`는 그 입력 꼴이다.** 이어진 `///` 줄은 공백 하나로 이어 한 문자열이 된다. 정규형(`bmb fmt`)은 정의의 첫 속성으로 `#[summary("..")]`를 쓴다. `//`와 `////`는 주석 그대로다. 정의 앞이 아닌 자리의 `///`는 속성이 설 수 없는 자리의 속성으로 거부된다(E1002 등).
3. **어떤 해시도 요약을 읽지 않는다.** 정체성, 본문·계약 해시, 증분 증명 키는 요약 없는 텍스트로 계산한다. 요약을 고쳐도 다른 정의나 증명 캐시가 무효화되지 않는다(근거 `#[rationale]`와 같은 규칙, ADR-0029 §3).
4. **맵 L1 행에 `summary` 키로 실린다.** 요약이 있는 정의에만 생긴다(ADR-0020 §1: 추가는 하위 호환). 타입과 trait의 `signature`에는 들어가지 않는다. JSON AST(`edit_ast`)는 함수와 상수의 `summary` 키로, 타입과 trait는 `attrs`로 주고받는다.
5. **증명과 검사는 요약을 읽지 않는다.** 요약은 산문이고 계약이 아니다. 의도를 강제하는 것은 계약과 근거다(원칙 3).

## 근거

| 안 | 판정 |
| --- | --- |
| **정의 수준 `#[summary]`, `///`는 입력 꼴(채택)** | 단위에 이미 있는 장치 하나로 맞는다(JUDGMENT S3). 자유 주석 금지(원장)는 그대로다: 요약은 정의에 묶인 한 줄이고 맵의 일부다. `///`는 Rust의 정석 표기라 습관 그대로 받아 정본으로 옮긴다(ADR-0095의 입력 별칭과 같은 방식) |
| 정규형이 `///` 주석을 그대로 지킴 | 주석이 정규형의 일부가 되면 "표현 하나"가 깨지고, 맵에 싣는 통로가 따로 필요하다 |
| 맵 L1에만 싣고 소스에는 없음 | 맵은 코드의 파생물이다(원칙 2). 코드에 없는 것을 맵이 가질 수 없다 |
| 두지 않음 | 쌍둥이 측정에서 BMB 팔만 정의 문서가 없다. 효과가 있는지조차 잴 수 없다 |

## 결과

- 받아들이는 언어가 넓어진다: 정의 앞의 `#[summary]`와 `///`. 지금까지 주석이던 정의 앞 `///`는 요약이 되고, 몸 안의 `///`는 오류가 된다.
- 쌍둥이의 세 번째 문서 조건(ADR-0106 결정 5)을 건다: BMB 팔이 정의 요약을 갖고 Rust 팔이 `///`를 갖는 조건. 주 조건을 무엇으로 할지는 그 조건의 오라클 확인 뒤에 정한다(백로그 3P-09).
- 효과(H-COMPREHEND에서의 토큰·정답률 차이)는 3P-05에서 조건별로 잰다. 요약을 쓰라고 요구하는 린트는 그 결과 전에는 두지 않는다.
- 코퍼스 `tests/verify/pass/summaries.bmb`, `tests/check/err/summaries.bmb`, 시험 `compiler/tests/fmt.rs`의 `summaries_are_kept_by_the_normal_form_and_read_by_no_hash`.
