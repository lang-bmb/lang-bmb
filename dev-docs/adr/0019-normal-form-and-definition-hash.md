# ADR-0019: 정규형과 정의 해시

- 상태: 채택 (자율 채택, AUTONOMY.md §4). §2의 "계약 해시가 증분 빌드의 키"는 대체됨(ADR-0043: 키는 `#[uses]`를 뺀 호출자 해시, 계약 해시 자체는 그대로). §1 리터럴 행의 "10진수"는 대체됨(ADR-0048 §3: 정규형은 쓴 진법을 유지한다, 백로그 2N-02). §2 정의 해시의 이름 의존(참조를 경로로 적는 것)은 대체됨(ADR-0059: 정체성은 이름 없는 정규형의 해시, 이름은 색인)
- 날짜: 2026-10-24
- 관련: DESIGN.md 원칙 1·2·8, ADR-0008·0011, 백로그 1D-01

## 맥락
맵(L0~L2)과 증명 캐시는 정의 단위 해시를 키로 한다(DESIGN.md §6). 파일 배치는 도구가 결정론적으로 정한다(ADR-0011). 둘 다 "같은 프로그램이면 같은 텍스트"인 정규형이 있어야 정의할 수 있다.

## 결정

### 1. 정규형
`bmb fmt`가 내는 텍스트가 정규형이다. 정규형은 구문 트리에서만 결정되고, 원래 텍스트의 공백·줄바꿈·주석·항목 순서와 무관하다.

| 요소 | 규칙 |
| --- | --- |
| 들여쓰기 | 공백 4칸. 줄 길이 제한 없음(줄을 접지 않는다) |
| 단위 | `#[summary("..")]` 다음 줄에 `mod 이름 {`. 하위 단위가 먼저(이름순), 그다음 정의(이름순). 항목 사이 빈 줄 하나 |
| 속성 | `#[effects(..)]`, `#[uses(..)]` 순서. `uses` 목록은 정렬하고 중복을 없앤다 |
| 시그니처 | `fn 이름(a: T, b: U) -> R`. 계약이 없으면 같은 줄에 `{` |
| 계약 | `requires`·`ensures`·`decreases`를 각각 한 줄에 4칸 들여 쓰고, 항목은 쉼표로 잇고 끝에 쉼표. 그다음 줄에 `{` |
| 루프 | `while 조건` 다음 줄부터 `invariant ..,` `decreases ..,` 그다음 줄에 `{` |
| 블록 | 비어 있으면 `{}`. 아니면 문장마다 한 줄, 마지막에 꼬리 식. 블록 형태의 문장(`if`, 블록) 뒤에는 `;`를 붙이지 않는다 |
| 식 | 우선순위상 필요한 괄호만. 단, `if`·블록·`forall`이 연산자나 후위 연산의 피연산자이면 항상 괄호. 이항 연산자 양옆에 공백 하나 |
| 리터럴 | 10진수, 접미사 없음 |
| 주석 | 정규형에 없다. `//` 주석은 프로그램의 일부가 아니다(ADR-0016). 근거는 구조화 근거 문법(ADR-0006)이 맡는다 |

정규형의 성질(테스트로 보장): 포맷을 두 번 해도 한 번과 같다. 정규형을 다시 파싱하면 같은 검사·증명 결과가 나온다.

### 2. 정의 해시
- 해시 함수는 SHA-256이다. 표기는 `sha256:` + 16진수 64자. 맵에서는 앞 12자를 줄여 써도 된다.
- 해시 입력은 **한정 정규형**이다. 정규형과 같되, 모든 이름 참조를 전체 경로로 쓴다(`f(x)` → `unit::f(x)`, `#[uses(p)]` → `#[uses(unit::p)]`). 그래서 같은 텍스트라도 다른 단위에서 다른 것을 가리키면 해시가 다르다.
- 정의마다 해시가 둘이다.
  - **본문 해시(`body`)**: 속성, 시그니처, 계약, 본문 전체. 정의 자신의 이름은 `_`로 바꿔 넣는다. 그래서 같은 정의가 다른 이름이나 단위에 있어도 같은 해시가 나와 중복을 찾을 수 있다(DESIGN.md §7.2). 단, 자기 재귀 호출은 전체 경로로 남는다.
  - **계약 해시(`iface`)**: 속성, 시그니처, 계약만. 계약 방화벽 증분 빌드(DESIGN.md §8.1)의 키다. `spec fn`은 호출자가 `#[uses]`로 본문을 펼칠 수 있으므로 계약 해시가 본문 해시와 같다.
- 증명 캐시 키는 2단계에서 정한다. 본문 해시, 호출하는 정의들의 계약 해시, 펼치는 `spec fn`들의 본문 해시의 조합이 출발점이다.

### 3. 파일 배치
- 최상위 단위 하나가 파일 하나다: `src/<단위 이름>.bmb`. 하위 단위는 같은 파일 안에 중첩된다.
- 파일 내용은 그 단위의 정규형이다. 그래서 같은 프로그램이면 같은 파일 집합이 나온다.
- 파일 이름과 위치는 의미가 없다. 어떤 파일 배치로 읽어도 같은 프로그램이다(원칙 7).

## 근거
- 정렬된 항목 순서와 줄을 접지 않는 규칙은 정규형을 단순하고 결정론적으로 만든다. 사람이 읽기 좋은 줄 길이는 비목표다(DESIGN.md §3).
- 본문 해시에서 자기 이름을 빼면, 이동·이름 변경 뒤에도 동일 정의를 찾을 수 있다.
- SHA-256은 외부 의존 없이 표준 라이브러리만으로 구현해 검증 벡터로 테스트한다.

## 결과
- `bmb fmt`는 주석을 지운다. 사람이 손으로 쓴 주석은 보존되지 않는다.
- 항목 순서는 의미가 없어진다. 소스에서 정의 순서에 의존하는 기능을 언어에 넣지 않는다.
