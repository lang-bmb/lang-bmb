# ADR-0038: BVB(공개 Verus 과제 이식) 규칙

- 상태: 채택 (자율 채택, AUTONOMY.md §4: 측정 절차의 구현 수준 결정)
- 날짜: 2026-10-25
- 관련: ADR-0021, ADR-0025, ADR-0034(BVB), 백로그 2A-08·2A-09

## 맥락
ADR-0034는 공개 Verus 과제를 BMB로 옮겨 같은 모델로 원본 Verus와 비교하기로 했다. 이식은 선택 편향과 변환 오류의 위험이 크므로 규칙을 고정한다.

## 결정
1. **출처:** Verus-Bench(MIT, 커밋 고정)와 Vericoding의 Verus 부분(MIT, 커밋 고정). 문제문은 새로 쓰고 명세·참조 코드는 라이선스 사본과 함께 둔다(`bench/bvb/SOURCES.md`, `licenses/`). VeriContest는 공개 데이터가 없어 제외.
2. **선택:** M1 표현 범위(정수·슬라이스·루프·재귀·이름 붙은 술어)에 드는 과제만. Verus-Bench는 150개 전부 검토, Vericoding은 모양 필터 뒤 sha256 순서로 고정 표본. 제외 사유는 과제마다 표로 남긴다. BMB에 유리한 제외(M1에 보조정리·`assert forall`이 없어 BMB 해법을 못 찾은 2개)를 명시한다.
3. **변환 규칙 T1~T7:** 슬라이스 대응, 범위 전제를 붙인 정수 확장, `exists` → `!forall !`, `Seq` 재귀 → 접두 길이 재귀, 유클리드 나눗셈, 공허 절 제거 등. 규칙은 `bench/bvb/README.md`, 변환은 `port.py`로 재현.
4. **G1(주어진 정의):** 원본 명세가 재귀 명세 함수나 트리거용 이름 붙은 술어를 쓰면, 그 함수를 양쪽(BMB 시드 단위 `given`, Verus 시작 파일)에 똑같이 준다. 에이전트가 바꾸면 판정이 거부한다.
5. **판정:** 양쪽 모두 검증 성공 + 숨은 원본 명세 함의(명세 강도 검사). 같은 모델·같은 상한·1회.
6. **CI:** BMB 쪽 기준 해법 45/45·약한 대조군 0/45는 게이트, 원본 Verus 쪽은 고정 버전 Verus를 설치하는 별도 CI 작업.

## 결과
- 45개 과제(Verus-Bench 30, Vericoding 15). 원본 Verus에서도 기준 해법 45/45, 약한 대조군 0/45.
- 한계: 두 언어 모두 명세 강도 검사가 트리거에 민감하다. 숨은 계약은 원소 항에 트리거를 둬서 완화한다.
