# ADR-0128: H-REVIEW 변경 집합의 동결과 그 한계

- 상태: 채택(자율 채택, AUTONOMY §4 "결정 기록": ADR-0078이 정한 가설의 과제 집합 동결. 판정 기준은 바꾸지 않는다)
- 날짜: 2026-11-12
- 관련: ADR-0078(H-REVIEW·H-INTENT), ADR-0021(동결), ADR-0066(측정 모델), ADR-0077(판정 규칙), `bench/review`, 백로그 T1-44·T1-44d·T1-44f

## 맥락

- ADR-0078은 H-REVIEW를 "결함을 심은 변경 집합을 명세 diff(계약 차이와 `bmb weaken` 판정)와 코드 diff로 나눠 리뷰 모델이 검토"로 재고, 확정 기준을 "탐지율이 같거나 높고 읽은 토큰이 1/5 이하"로 동결했다. 집합과 리뷰 프롬프트·판정의 동결은 과제 집합의 ADR에 맡겼다.
- 증명 게이트를 통과하는 결함은 명세의 결함이다(DESIGN 전제 E1). 그래서 변경의 앞뒤 프로그램은 모두 증명되는 것이어야 한다.

## 결정

1. **집합.** `bench/review`: 동결된 BVB 과제 45개에서 도출한 변경 143개(결함 71, 무결 72). 손으로 쓴 프로그램은 없다.

   | 종류 | 앞 → 뒤 | 라벨 | 수 |
   | --- | --- | --- | --- |
   | `contract-weakened` | 기준 해법 → 약한 계약 | 결함 | 45 |
   | `contract-restored` | 약한 계약 → 기준 해법 | 무결 | 45 |
   | `contract-weakened+body` | 기준 해법 → 약한 계약 + 그 아래에서 증명되는 몸 변이체(숨은 계약이 거부하는 출력의 증인 입력 있음) | 결함 | 26 |
   | `body-only` | 기준 해법 → 같은 계약 아래 증명되는 몸 변이체 | 무결 | 27 |

   몸 변이체는 `bmb mutate`의 한 자리 변이이고 과제·종류마다 앞에서 둘까지다(규칙을 먼저 정하고 쟀다). 커밋된 `changes/`가 동결물이고, 생성에 쓴 컴파일러 커밋은 `set.json`에 있다.
2. **두 판.** 명세 판은 계약 텍스트의 diff(서명, `requires`·`ensures`, 그것이 부르는 spec fn)와 `bmb weaken`의 출력, 코드 판은 프로그램 전체의 diff다. 둘 다 의도 문장과 같은 동결 프롬프트를 받는다.
3. **판정.** 답은 `{"verdict": "defect" | "ok", "reason": ..}` 하나다. 탐지는 결함 변경에 `defect`, 오경보는 무결 변경에 `defect`, 꼴이 틀린 답은 따로 세고 탐지가 아니다. 확정·반증 규칙은 ADR-0078 그대로이고 D는 ADR-0077의 30%p다. 오경보율은 보고만 한다.
4. **평가자는 모델 리뷰어뿐이다.** 사람 표본 교정은 하지 않는다(사람 결정 2026-11-11, `2H-05` 취소). 이 집합의 판정은 모델 리뷰어에 한한 판정이다.
5. **게이트.** `gen.py --check`(구조)와 `test_review.py`(프로그램 143개 증명, 라벨, 판의 결정성, 대본 리뷰어 둘, 판정). 재생성(`--regen`)은 컴파일러의 증명력에 달려 있어 푸시 게이트에 넣지 않는다.

## 근거

- 무결 변경이 있어야 "언제나 결함"이라고 답하는 리뷰어를 가른다. 몸이 바뀌는 변경이 있어야 명세 판이 몸을 보지 않고도 되는지를 잰다.
- `weak → weak + 변이체`(계약이 그대로인 몸 결함)는 넣지 않았다. 계약 diff가 비어 명세 판이 원리상 잡을 수 없고, 그 빈자리는 가설에 유리하다. README에 적었다.

## 결과

- **이 집합에서 토큰 기준(1/5)은 닿을 수 없다(모델 실행 전에 결정론으로 잰 값).** 토큰 비 명세/코드는 전체 1.752, 몸이 바뀌는 53개에서 약 1.58이다. 과제가 함수 하나라 코드 diff가 87~228토큰이고, `bmb weaken`의 출력만 85~210토큰이다. 그래서 이 집합이 낼 수 있는 판정은 "반증"(탐지율이 D를 넘게 낮음)이거나 "확정 아님"이다. 기준은 바꾸지 않는다.
- 토큰 축을 재려면 여러 줄의 몸 변경이 있는 집합이 필요하다: `T1-44f`(실제 크기의 변경, 예: `lib/std`의 이력이나 포트).
- `bmb weaken`의 판정이 라벨을 143개 중 122개에서 가른다(미결정 21). 명세 판의 탐지율은 도구 판정을 읽은 결과일 수 있고, 표는 종류별로도 낸다.
- H-INTENT 집합(`T1-44e`)은 같은 하네스에 자료로 더한다(판의 부품 목록과 `compare.token_ratio`).
- 실제 모델 실행은 측정 머신에서 한다.
