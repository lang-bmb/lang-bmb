# ADR-0132: H-REVIEW·H-INTENT 토큰 기준의 처리

- 상태: 채택(사람 승인 2026-11-13, 백로그 `T1-44h`의 권장안 (A))
- 날짜: 2026-11-13
- 관련: ADR-0078(가설 등록), ADR-0128(`bench/review`), ADR-0130(`bench/intent`), `dev-docs/measurements/t1-44f.md`, 백로그 T1-44f·T1-44h

## 맥락

- ADR-0078은 두 가설의 확정 기준에 토큰 조건을 넣었다: H-REVIEW는 명세 쪽이 읽은 분량이 코드 쪽의 1/5 이하, H-INTENT는 명세+예시 쪽이 코드+명세 쪽의 1/2 이하.
- 동결한 두 집합에서 실행 전에 잰 비는 1.752와 1.571이다(ADR-0128, ADR-0130).
- `T1-44f`의 측정: 저장소의 이력은 변경 넷뿐이고, `lib/std`의 계약 있는 실행 함수 94개에서 계약 텍스트가 몸보다 큰 것이 77개다. 몸 전체를 다시 쓰는 변경을 가정해도 1/5에 닿는 함수는 1~12개이고, 예시를 0토큰으로 쳐도 1/2에 닿는 함수는 17개다. 함수 단위의 재료로는 두 기준에 닿는 집합을 만들 수 없다.
- 원인은 가설 등록에 있다: 기준을 정할 때 증명된 코드에서 계약 텍스트와 몸의 크기 비를 재지 않았다.

## 결정

1. **기준은 바꾸지 않는다.** ADR-0078의 확정·반증 규칙은 그대로다.
2. **두 집합은 탐지율만 판정한다.** `bench/review`와 `bench/intent`가 낼 수 있는 판정은 "반증"과 "확정 아님"이다. 측정 머신의 실행은 미루지 않는다.
3. **H-REVIEW의 토큰 축은 포트의 이력으로 잰다.** 계약이 그대로인 채 여러 함수의 몸이 바뀌는 변경은 포팅(`4D-02`) 뒤에 생긴다. `T1-44f`는 그때 연다.
4. **H-INTENT의 토큰 조건은 함수 단위 항목에서 충족 불가로 등록부에 적는다.** 계약 텍스트가 몸보다 크다는 것은 예시의 표현과 무관한 코드의 성질이다. 함수보다 큰 단위(모듈의 공개 계약 대 구현 전체)의 항목 집합은 재료가 생기면 따로 등록한다.

## 택하지 않은 것

- **기준을 다시 등록(B).** 모델 실행 전이지만 값을 본 뒤의 변경이다(운영 규칙: 기준은 측정 전에 고정).
- **두 가설을 포팅 뒤로 미룸(C).** 탐지율 축은 지금 집합으로 잴 수 있다.

## 결과

- 두 가설은 포팅 전에는 "확정"이 될 수 없다. 관문 D의 전제 E1은 그때까지 탐지율의 판정과 "토큰 축 미측정"으로 적는다.
- `docs/ROADMAP.md`의 가설 표 두 행에 이 처리를 적었다.
