# ADR-0049: 조기 탈출(`return`·`break`·`continue`·`?`)과 `for`·`loop`

- 상태: 채택 (2026-10-26, 사람 승인 "1/2 채택, 승인", 백로그 2V-12)
- 날짜: 2026-10-26
- 관련: ADR-0045, DESIGN.md §4.1("실패", "표현"), ADR-0031 §2(해제 지점), 2R-04f(`for` 오프라인 비교), 점검 R9, 백로그 2V-09


## 채택 시 확인 (2026-10-26)
- 진단 번호: E0241 오류 타입이 다른 `?`(비어 있음 확인). E0203(`return` 금지)·E0204(`for`·`loop` 금지)·E0206(`?` 금지)은 구현과 함께 은퇴한다(`diag::RETIRED`, 재사용 금지). E0206을 다른 뜻으로 쓰지 않는다.
- 열린 질문 1(`if let`·`while let`)은 원장 "표현"(정규형 하나, `match`)이 근거라 그대로 둔다.
- 원장 "표현" 행에 셀 수 있는 루프의 정규형(범위 `for`)을 이 채택과 함께 적는다.
- 구현 페이즈: ROADMAP 2K(제어 흐름).

## 맥락
BMB에는 `return`·`break`·`continue`·`?`·`for`·`loop`가 없다(E0206, E0207 "`return` is not supported in milestone 1" 등). 그래서 조건별 조기 반환을 중첩 `if`와 플래그로, 셀 수 있는 루프를 `while` + `decreases`로 쓴다. 셀프호스팅 분석에서 `?`·`return`·`break` 518곳이 비용 "상"이다. 원장이 금지하는 것은 `?`의 암묵적 `From` 변환(실패 경로를 숨김)뿐이고 조기 탈출 자체는 아니다. Verus·Dafny는 조기 반환과 `break`를 지원하고 VC 생성은 표준 기법이다.

## 결정

### 1. 조기 탈출
- `return e;`·`return;`(단위), 루프 안의 `break;`·`continue;`, 레이블 `'outer: while ..`과 `break 'outer;`·`continue 'outer;`(Rust와 같음).
- `e?`: `e: Option<T>`이고 함수 결과가 `Option<U>`이면 `None`을, `e: Result<T, E>`이고 결과가 `Result<U, E>`(같은 `E`)이면 `Err(e)`를 반환한다. 오류 타입이 다르면 거부(원장 "실패": 암묵적 `From` 없음)하고, 안내는 `match`나 명시 변환 함수.
- `loop { .. }`와 값 있는 `break e;`(`loop`에서만, Rust와 같음). `loop`도 `invariant`·`decreases`를 받는다.

### 2. `for`
- 셀 수 있는 루프의 정규형은 `for i in lo..hi { .. }`와 `for i in lo..=hi { .. }`다(`i`의 타입은 `lo`·`hi`의 정수 타입). `invariant` 절을 받는다. `lo <= i < hi`는 몸 안에서 자동 사실이고 `decreases`는 자동이다(`hi - i`, 원칙 6).
- `while`은 그 밖의 루프에 남는다. 같은 일을 하는 `while` 셀 루프는 정규형에서 `for`로 바꾸는 기계 수정을 둔다(원칙 8: 한 가지 일에 한 형태).
- 반복자 `for x in v.iter()`·`for x in &v`는 두지 않는다(반복자는 참조를 담는 구조: ADR-0015의 대가. 원장 "표현"의 정규형 하나). 안내는 `for i in 0..v.len()`.

### 3. 증명 인코딩
- `return`: 그 지점의 경로 조건 아래에서 `ensures`(반환값 대입)가 의무이고 경로가 끝난다. 함수 끝의 결과는 남은 경로의 합류다.
- `break`: 루프 출구 상태는 정상 출구(불변식 ∧ ¬조건)와 각 `break` 지점의 상태(그 반복의 기호 상태)의 합류다. `continue`는 그 지점에서 불변식 유지 의무를 진다.
- `?`: `match`로 펼친 것과 같다(`None`/`Err` 갈래가 `return`).
- `for`: `while` 인코딩에 범위 사실과 자동 `decreases`를 더한 것과 같다. 2R-04f의 펼친 SMT 질의 동일성 측정을 완료 기준에 넣는다.

### 4. 소유와 해제
- 조기 탈출이 지나는 블록의 소유 지역은 그 탈출 간선에서 해제된다. 해제 지점은 여전히 텍스트로 정해진다(ADR-0031 §2). 탈출 간선도 합류점이다(E0414 규칙이 간선마다 적용).

### 5. 코드 생성
- 탈출 블록으로의 분기와 간선별 해제. `?`는 태그 비교와 분기.

### 6. 진단
- E0206(`?` 금지)과 "`return`·`for`·`loop`·`break` is not supported" 메시지는 채택과 함께 없어진다. 코드 E0206은 재사용하지 않고 "다른 오류 타입의 `?`"에 쓸지 새 번호를 쓸지 채택 때 정한다(기존 코드의 의미 변경은 승인 사항).

## 근거(검토한 대안)
| 안 | 판정 |
| --- | --- |
| **Rust의 조기 탈출 전부 + 범위 `for` 정규형(채택 제안)** | Rust 표면 그대로(S1), 검증 선례 있음. `?`의 `From`만 원장대로 뺀다 |
| 지금처럼 중첩 `if`·플래그 | 우회. 줄 수와 토큰이 늘고 Rust 습관 오류가 난다(E0206 빈도는 2B-10·1E에서 잴 대상) |
| 반복자 `for` | 참조를 담는 반복자가 2차 참조(ADR-0015)와 충돌. 범위 `for`로 같은 일을 한다 |

## 결과
- DESIGN §4.1 원장 "표현" 행에 정규형을 적는다: 셀 수 있는 루프는 범위 `for`, 그 밖은 `while`/`loop`.
- 2R-04f(`for` 오프라인 비교)는 이 ADR의 측정 입력이 된다.
- 퍼저: 루프 퍼저에 `break`·`continue`·`return`·`?`를 넣는다.

## 열린 질문
1. `while let`·`if let`(ADR-0026이 뺌): `?`와 `match`로 충분한지 2B-10 측정 뒤 정한다.
