# ADR-0028: 정수 변환과 검사·포화 산술

- 상태: 제안 (언어 범위 확대. 채택은 사람 승인, AUTONOMY.md §4)
- 날짜: 2026-10-24
- 관련: DESIGN.md §4.1(산술)·원칙 4·8·9, ADR-0013, ADR-0017, ADR-0018, ADR-0022, ROADMAP 2C, 백로그 2C-01

## 맥락
M1에는 실행 코드의 정수 변환이 없다. `as`는 E0205로 거부되고(`compiler/src/parser.rs`, 수정 안내는 "checked conversions come after milestone 1"), 타입이 다른 정수의 혼합은 E0401이다. 명세 쪽은 ADR-0022로 풀었지만 실행 코드는 그대로다.

드러난 마찰(증거):
- **출력.** 내장 출력은 `print_i64`뿐이라 `u64`·`usize` 값을 찍으려면 세는 루프를 손으로 써야 했다. `tests/run/search.bmb`의 `show`(`u64`)와 `show_size`(`usize`)는 `c = c + 1; i = i + 1`을 `n`번 돌리고, 루프 비용 때문에 `printable_size(n) = n <= 1000000`이라는 근거 없는 상한까지 붙였다(측정 보고서 `dev-docs/measurements/m1.md` §6, ROADMAP 1C 관찰).
- **혼합.** `usize` 인덱스와 `i64` 누적값을 실행 코드에서 함께 계산할 방법이 없다. ADR-0022는 명세만 풀었다.
- **Rust 습관.** `as`는 E02xx(Rust 습관)로 집계된다. 실제 모델 측정(1E-10)이 끝나면 E0205 빈도가 나온다. 지금은 숫자가 없다.

정해야 할 것: 변환 실패를 증명 의무로 볼지 `Option`/`Result`로 볼지(2B 의존), 표면 형태, `checked_*`·`saturating_*`의 범위.

## 결정(제안)

### 1. 변환: 의무가 붙는 `T::try_from(x).unwrap()`
- 정수 타입 사이의 변환은 **`T::try_from(x).unwrap()` 한 형태**다(`T`는 `i64`·`u64`·`usize`). 값은 `x`와 같고, **`x`가 `T`의 범위 안이라는 것이 증명 의무**다(새 코드 E0815). Rust에서 `unwrap`이 panic할 자리가 BMB에서는 증명 의무가 된다. 인덱싱 `a[i]`(Rust: panic, BMB: 범위 의무)와 같은 변환이다.
- 원본 범위가 대상 범위에 포함되면(`u64`↔`usize`, BMB에서 둘 다 64비트) 의무를 만들지 않는다. 의무가 생기는 쌍은 `i64→u64`, `i64→usize`(`x ≥ 0`), `u64→i64`, `usize→i64`(`x ≤ i64::MAX`) 넷이다.
- **2B 이전:** `try_from` 뒤에 `.unwrap()`이 바로 붙은 융합형만 허용한다. 단독 `T::try_from(x)`는 E0412.
- **2B 이후:** 단독 `T::try_from(x)`는 2B가 정하는 `Result` 값이다(실패를 값으로 다루는 경로). 융합형의 의미는 바뀌지 않는다. `unwrap`을 일반적인 의무 연산(`is_some`/`is_ok` 증명)으로 넓힐지는 2B-01이 정한다. 이 ADR은 그 방향을 권고한다.
- 명세 문맥에서는 변환을 쓰지 않는다. 명세는 이미 무한 정수이고 타입을 섞을 수 있다(ADR-0022). 명세의 변환은 E0513.

### 2. 비트 재해석(선택 범위)
- `x.cast_unsigned()`(`i64→u64`), `x.cast_signed()`(`u64→i64`)는 2의 보수 재해석이고 의무가 없다(Rust 1.87의 같은 이름 메서드). 해시·난수 같은 래핑 계산용이다. 수요가 측정되면 넣는다(열린 질문 3).

### 3. 검사·포화 산술
- `saturating_add/sub/mul`: 의무 없음. 값은 수학적 결과를 타입 범위로 자른 것.
- `checked_add/sub/mul/div/rem`: `Option<T>`를 돌려주므로 **2B 이후**(백로그 2C-03이 2B에 의존).
- `overflowing_*`(튜플 반환)·`pow`·`abs`는 이 ADR 범위 밖이다. `i64::abs`는 `MIN`에서 넘치므로 넣는다면 의무가 붙는 연산으로 따로 정한다.

### 4. 출력
- 내장 `print_u64(x: u64)`(효과 `io`)를 추가한다. `usize`는 `print_u64(u64::try_from(n).unwrap())`(의무 없음). 위 `show_size` 루프는 `print_i64(i64::try_from(n).unwrap())` 한 줄이 되고, 슬라이스 길이에서 나온 값이면 길이 상한 사실(ADR-0017 §3, 2^60 − 1)로 의무가 바로 증명된다.

### 5. 증명 게이트
- 인코딩은 ADR-0017 그대로 `Int`다. 변환은 항등이고, 의무는 대상 범위 술어 `range_T(x)` 하나다. 결과에는 대상 범위 사실이 붙는다.
- 포화: `sat_T(v) = ite(v > MAX, MAX, ite(v < MIN, MIN, v))`, `v = a op b`(수학적 값). `add`·`sub`는 선형, `mul`은 비선형이라 `unknown`이 날 수 있다(fail-closed, 미증명 면적).
- `checked_*`: `ite(range_T(v), Some(v), None)`. `Option` 인코딩은 2B-02 결정을 따른다.
- 새 보조 사실을 넣으면 ADR-0018 §2 규칙대로 `compiler/tests/lemmas.rs`에 기계 증명을 함께 둔다. 위 정의만으로는 보조 사실이 필요 없다.

### 6. 코드 생성
- 증명된 변환은 **명령이 없다**(세 타입 모두 LLVM `i64`). 줄 주석 `; proved E0815`. 증명되지 않으면 범위 비교 + `llvm.trap`(`emit-llvm`)이고 `bmb build`는 거부한다.
- 포화: `llvm.{s,u}{add,sub}.sat.i64`, `mul`은 `llvm.{s,u}mul.with.overflow.i64` + `select`. 검사: `*.with.overflow`.
- `cast_*`: 명령 없음.

### 7. 맵·해시
- 변환·포화는 `wrapping_*`처럼 내장 메서드라 호출 간선을 만들지 않는다. `print_u64`는 `print_i64`처럼 `io` 경계 간선을 만든다(`status`의 `io_defs` 계산에 포함).
- 정규형은 `T::try_from(x).unwrap()` 그대로다. 해시 정의(ADR-0019)는 바뀌지 않는다.

### 8. 거부할 Rust 습관과 진단(번호는 제안, 구현 시점의 빈 번호로 확정)

| 습관 | 처리 | 코드 |
| --- | --- | --- |
| `x as T` | 기존 E0205 유지. `fix.replacement`를 `T::try_from(x).unwrap()`로 바꿔 `bmb fix`가 기계적으로 고친다. 절단을 의도했다면 증명이 반례로 실패한다(fail-closed) | E0205(기존) |
| `T::from(x)`, `x.into()`, `x.try_into().unwrap()` | 대상 타입을 알면 `T::try_from(x).unwrap()`로 교체 제안 | E0212(신규) |
| `T::try_from(x).expect("..")` | `.unwrap()`로 교체(정규형 하나) | E0213(신규) |
| `T::try_from(x)?` | 기존 E0206 | E0206(기존) |
| 2B 이전의 단독 `T::try_from(x)`, `bool`↔정수 변환 | 타입 오류 | E0412(신규) |
| 명세의 변환 | "명세는 타입을 섞을 수 있다(ADR-0022)" 안내, 변환 제거 교체 | E0513(신규) |
| 범위를 벗어날 수 있는 변환 | 증명 실패 + 반례 | E0815(신규) |

`checked_add` 등에 대한 E0404 수정 안내 문구는 단계에 맞게 갱신한다(의미 변경 아님).

### 9. 테스트·퍼저
- 코퍼스: `tests/check/err`(위 표의 각 코드), `tests/verify/pass|fail`(쌍마다 증명·반례), `tests/run`(`show_size` 루프 제거판, 포화 경계값).
- 코드 생성: 증명된 변환이 IR에 명령을 남기지 않음, 증명을 빼면 `icmp`+trap이 남음(1C 기준 2와 같은 형태).
- 건전성 퍼저: 부호 없는 산술 퍼저(1B-33, `compiler/tests/soundness_unsigned.rs`)의 생성기에 세 타입 사이 변환·포화 연산을 넣는다. 해석기는 범위 밖 변환을 오류로, 포화를 `i128` 자르기로 계산한다. 성질은 기존과 같다: 증명된 함수는 허용 입력에서 오류가 없다, 확정 반례는 실제로 깨뜨린다, 두 빌드의 출력이 해석기와 같다. 60배치 위반 0이 2C 통과 기준 2다.

## 근거(검토한 대안)

| 안 | 판정 |
| --- | --- |
| **`T::try_from(x).unwrap()` + 의무(채택 제안)** | 유효한 Rust이고, 증명된 BMB 프로그램은 같은 Rust 프로그램과 모든 실행에서 같은 동작이다. "panic 자리 = 증명 의무"라는 기존 규칙(인덱싱)의 재사용이라 새 개념이 없다. 2B를 기다리지 않는다 |
| `x as T`에 의무를 붙임 | 가장 강한 대안. Rust 습관 오류가 사라지고, 범위 안에서는 Rust의 절단과 값이 같다. 하지만 같은 토큰이 Rust에서는 "조용히 자름", BMB에서는 "범위 증명"을 뜻해 표면에서 의도가 보이지 않는다. 나중에 부동소수·문자 변환이 들어오면 `as` 하나가 여러 의미를 갖는다(원칙 8). 습관 비용은 `bmb fix` 자동 교체로 흡수한다. **E0205 빈도와 자동 교체 흡수율이 측정되면 다시 판단한다**(열린 질문 1) |
| `Option`/`Result` 반환만 | 증명으로 실패가 없음을 알 때도 분기를 강제해 장황하고, 2B가 먼저 있어야 한다. 실패를 값으로 다루는 경로는 2B 이후 단독 `try_from`으로 함께 둔다 |
| `as`를 래핑(절단) 의미로 허용 | DESIGN.md §4.1 산술 행이 포기한 "`as` 절단 변환" 그 자체다. 기각 |
| `u64`·`usize`를 하나로 합침 | Rust 표면과 어긋나 인덱스·길이 타입 습관이 깨진다. 기각 |
| 범용 `print`/서식 | 문자열·서식이 필요해 범위가 크다. `print_u64` 하나로 M1 마찰이 풀린다 |

## 결과
- 신뢰 기반 변화 없음: 변환 의무는 기존 범위 술어로 표현되고, 증명되지 않으면 빌드되지 않는다.
- 내장이 하나(`print_u64`) 늘고, 테스트 필요 면적의 `io` 경계가 하나 는다.
- `T::try_from(x).unwrap()`은 `as`보다 길다. 손실은 Rust 습관 오류율로 잰다(DESIGN.md §4.1 긴장과 대응 3).

## 열린 질문(측정 1E-07 또는 사람이 정함)
1. **표면:** `T::try_from(x).unwrap()` 대 의무가 붙는 `as`. 1E-10 결과의 E0205 빈도와, `bmb fix` 자동 교체 뒤 성공률로 정한다.
2. **2B 순서:** `checked_*`와 단독 `try_from`은 2B 뒤다. `unwrap`을 일반 의무 연산으로 둘지는 2B-01이 정한다(이 ADR은 권고).
3. **`cast_signed`/`cast_unsigned`:** `m1b`/`m2` 과제에 래핑 변환 수요가 있을 때만 넣는다.
4. **`bool`↔정수, `abs`·`abs_diff`·`min`·`max`:** 이번 범위 밖으로 둘지 사람이 정한다.
5. **2C의 우선순위:** 1E-07이 정한다. 마찰 증거는 현재 작성자 경험 하나(`show_size`)뿐이고, 실제 모델이 같은 곳에서 막히는지는 1E-10 결과로 확인한다.
