# ADR-0090: 명세에서 비트 연산의 피연산자는 그 타입 폭의 2의 보수 상이다

- 상태: 채택 (자율 채택, AUTONOMY.md §4: 정수 인코딩의 구현 수준 결정). ADR-0048 §4(인코딩 꼴)를 보완한다. 실행 코드의 뜻과 타입 안 피연산자의 질의 텍스트는 그대로다
- 날짜: 2026-11-05
- 관련: ADR-0022(명세 산술은 타입을 벗어날 수 있다), ADR-0048 §2·§4, 백로그 2N-10

## 맥락

- 명세 산술은 타입 밖으로 나갈 수 있다(ADR-0022: `x + y`는 `u8` 두 값의 합 그대로). 그런 값이 비트 연산의 피연산자가 되면 뜻이 인코더가 고른 꼴에 따라 달랐다(2N-03 발견). bitvector 꼴(`&`·`|`·`^`, 변수 양 시프트, 비트 메서드)은 `int2bv`로 하위 `w`비트를 읽고, 선형 꼴은 정수 값을 그대로 읽었다: 상수 양 `>>`는 `div`, `!`는 `-a - 1`·`MAX - a`, 상수 회전·`wrapping_shr`도 `div`.
- 그래서 같은 식이 두 값이었다. `u8`의 `x = 66, y = 255, k = 1`에서 `(x + y) >> k`(bitvector, 하위 8비트 65의 절반 32)와 `(x + y) >> 1`(`div 321 2` = 160)이 다르고, `!(x + y)`와 `!((x + y) & 255)`도 다르다. 이전 인코더는 두 등식을 반례와 함께 거부했다. 실행 코드의 값은 늘 타입 안이라 거짓 증명은 아니지만, 명세의 뜻이 하나가 아니다.

## 결정

1. **뜻.** 명세에서 비트 연산(`&`·`|`·`^`·`<<`·`>>`·`!`)과 비트 메서드의 정수 피연산자는 그 타입 폭 `w`의 2의 보수 상(`w`비트로 줄인 값을 타입의 부호로 읽은 값)으로 읽는다. 결과는 늘 타입의 값이다. 시프트 양은 지금처럼 그 값 그대로다.
2. **인코딩.** bitvector 꼴은 이미 이 뜻이다(`int2bv`). 선형 꼴 중 값을 그대로 읽던 것(상수 양 `>>`·`wrapping_shr`·회전, `!`, 바이트 폭의 `swap_bytes`)은 피연산자를 `wrap_int`로 감싼다(`verify::image`). 피연산자가 구문으로 타입의 값이면(리터럴, 변수, 자리, 메서드 결과, 비트 연산 결과, `old`, `verify::in_type`) 감싸지 않는다: 그 질의 텍스트는 바뀌지 않는다. `<<`의 선형 꼴(이미 `wrap_int`)과 `&` 마스크의 `mod`(낮은 `k ≤ w`비트는 상에서도 같다)는 그대로다.
3. **하위 증명.** `by (bit_vector)`는 인코더의 항을 옮기므로(ADR-0048 §4) 같은 뜻을 따른다.

## 근거

- **원인과 귀속 층:** 뜻을 정하지 않은 채 꼴마다 다른 읽기를 썼다. 층은 인코더다(언어의 뜻을 정하는 결정이지만 실행 코드의 뜻은 바뀌지 않는다).
- **정석:** 고정 폭 비트 연산은 피연산자를 그 폭의 비트열로 읽는다(SMT-LIB `int2bv`, Rust의 `as` 변환·`wrapping_*`가 같은 상을 쓴다). 타입 안의 값에서는 Rust의 결과와 같다.
- **후보.** (a) 정수 그대로(무한 정밀도 2의 보수): `&`·`|`·`^`는 정의되지만 변수 양 시프트가 `2^k`의 비선형 정의를 요구하고, 비트 메서드(`count_ones`·회전)는 폭 없이 뜻이 없다. (b) 2의 보수 상(이 결정): 모든 연산에 뜻이 있고 bitvector 꼴은 그대로다. (c) 타입 밖 피연산자를 금지(검사기 오류): 명세 산술의 이점(ADR-0022)을 비트 연산에서만 잃고, 어느 피연산자가 타입 밖인지는 증명해야 아는 일이라 검사기가 결정할 수 없다. 결정적 기준은 C1(뜻이 하나)과 S1(정석): (b)만 모든 꼴에 같은 뜻을 주면서 정석이다.
- **확인:** `tests/verify/pass/bit_vector.bmb`의 `shift_image`(상수와 변수 양 `>>`)·`not_image`(`!`와 상수 회전이 마스크한 피연산자의 것과 같음)는 이 결정 뒤 증명되고 이전 인코더에서는 반례가 나온다(`x = 66, y = 255, k = 1`; `x = 1, y = 255`). `soundness_bitvector`의 해석기도 모든 비트 연산에서 상을 읽는다.

## 결과

- 타입 밖 피연산자를 쓰던 명세의 뜻이 바뀐다. 실행 코드와 타입 안 피연산자의 질의는 텍스트까지 그대로다.
- 감싼 피연산자는 `mod`가 하나 더 붙는다(그런 질의만).
- 되돌리기: `verify::image`가 피연산자를 그대로 돌려주면 이전 꼴이다.
