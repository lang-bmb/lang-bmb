# ADR-0059: 해시 참조와 메타데이터로서의 이름

- 상태: 채택 (사람 승인 2026-10-28 "ADR-0059 to 0062 채택"). ADR-0019 §2의 정의 해시와 ADR-0032·0043의 키 행 가운데 이름이 들어가는 부분을 대체한다
- 날짜: 2026-10-28
- 관련: ADR-0019 §2(정의 해시), ADR-0032·0043(증분 키), ADR-0011(저장은 텍스트), ADR-0009(트랜잭션), ADR-0006(근거를 노드 해시에), ADR-0020(맵 스키마), DESIGN.md §3 원칙 1·7·8, `dev-docs/reviews/direction-2026-10-28.md` §5·§6(H-ID, H-PAR)

## 채택 시 확인 (2026-10-28)
- 구현 국면: ROADMAP M2-c(정체성과 협업), 백로그 T1-10. 결과 표의 T1-ID-01~05가 그 하위 태스크다.
- 반증 조건(결과 절)은 구현 중에 확인한다. 하나라도 성립하면 이 ADR을 폐기하고 되돌린다(자료 이주 없음).
- §5의 `rename`·`expect`를 MCP에 노출하는 것은 측정 조건 보존 규칙(ADR-0021, 2D)을 따른다. 동결된 과제 집합의 도구 목록은 바꾸지 않고, 노출은 새 판과 함께 한다.

## 맥락

지금 이름은 정의의 **정체성**에 들어 있다. 이름이 들어가는 곳은 넷이다.

| 자리 | 코드 경로 | 이름이 들어가는 방식 |
| --- | --- | --- |
| 정의 해시 | `fmt::qualified_text`(`compiler/src/fmt.rs:799`), `fmt::def_hash`(`fmt.rs:936`) | 다른 정의의 참조를 전체 경로로 적는다(`Printer::path`, `fmt.rs:92`). 자기 이름만 `_`로 바꾼다. 자기 재귀 호출, 매개변수, 지역, 필드 이름은 그대로 남는다 |
| 증분 키 | `incremental.rs:505~620` | 정의의 원문 조각(의무 위치가 바이트 오프셋이라서), 한정 정규형, 피호출자의 `caller_text` 해시(ADR-0032·0043) |
| 증명 캐시 키 | `cache.rs:30`(`ProofCache::key` = 해법기 버전 + 질의 텍스트) | 질의 안의 정의 기호가 경로 이름이다(`verify::sym`, `verify.rs:1879`: `\|unit::f\|`) |
| 맵·작업 공간 | `map.rs:824·909`(L1 `body`·`iface`, `duplicates`), `workspace.rs:157·308`(커밋의 `changed`) | 위의 정의 해시를 그대로 쓴다 |

측정(`dev-docs/experiments/rename-ripple/`):

- 실행 프로그램과 `lib/bytes.bmb`에서 정의 412개의 이름을 하나씩 바꿨다.
- 356번(86%)에서 다른 정의의 해시가 바뀌었다.
- 해시가 바뀐 참조자는 본문 611개, 계약 377개다. 계약 해시가 바뀌면 그 참조자의 호출자들도 증분 키가 바뀐다.
- 매개변수 이름은 계약 해시에 들어가므로 매개변수 이름 바꾸기도 같은 식으로 번진다(재지 않았다).
- `duplicates`(2D-06)는 본문 해시로 묶는다. 그래서 지역 이름만 다른 알파 동치 정의를 찾지 못한다.

이 상태는 두 가지를 막는다.

- **보존형 리팩터링(3C).** 이름 바꾸기·이동이 무관한 증명 캐시를 깬다.
- **동시 편집(H-PAR).** 이름 하나를 바꾸면 그 이름을 쓰는 모든 정의가 충돌 후보가 된다.

## 결정

1. **정체성 해시.** 정의의 정체성(`id`)은 이름 없는 정규형의 SHA-256이다.
   - 다른 정의(함수, `spec fn`, 타입, trait)에 대한 참조는 대상의 `id`(`#<hex>`)로 적는다.
   - 같은 재귀 성분 안의 참조는 `#self.k`로 적는다. 성분은 지금 쓰는 Tarjan SCC(`check.rs:7541`, `Checker::recursive`)이고 타입 순환도 같다.
     - 성분의 해시는 구성원 텍스트를 정해진 순서로 이은 것의 해시다.
     - 구성원의 `id`는 `#<성분 해시>.k`다.
     - 순서는 성분 안의 참조를 지운 해시로 정렬해 정한다(Unison과 같은 규칙).
     - 해시가 같은 구성원은 서로 알파 동치다. 이 경우에만 경로로 순서를 정하고, 그 사실을 문서에 적는다.
   - 묶는 이름은 묶인 순서대로 위치 이름(`_0`, `_1`, ..)으로 바꾼다. 대상은 매개변수, 결과 이름, 지역, 레이블, 타입 매개변수, `forall` 변수다(알파 정규화).
   - 필드와 변형은 타입 안의 선언 순서 위치로 적는다. 선언 순서는 레이아웃과 판별값을 정하므로 의미의 일부다.
   - 속성·효과·계약·`decreases`·트리거는 그대로 들어간다. `#[uses]`의 항목도 `id`로 적는다.
   - 들어가지 않는 것: 단위의 `#[summary]`, 근거 산문. 둘 다 메타데이터다.
   - 언어 내장(`Vec`, `Option`, `std::mem::replace`, 정수 타입)은 정의가 아니므로 이름 그대로 둔다.
2. **이름은 색인이다.** 작업 공간은 텍스트에서 `경로 → id` 색인을 도출한다.
   - 이름 하나에 정의 하나(DESIGN §4.1 "이름", 원칙 8)는 그대로다. 같은 경로의 두 정의는 지금처럼 거부한다(E0302).
   - Unison은 병합 뒤 한 이름에 두 정의를 해시 한정 이름으로 둔다. BMB는 모호성 0을 위해 이 방식을 따르지 않는다.
3. **저장은 텍스트 그대로다(ADR-0011).** 파일에는 이름으로 쓴 정규형이 남고, `id`는 적재할 때 결정론적으로 계산한다. 별도 코드베이스 저장소는 두지 않는다.
4. **키를 이름 없이 만든다.**
   - **`bmb hash`와 맵 L1:** `body`·`iface`를 정체성 해시로 바꿔 정의한다(`iface` = 본문을 뺀 정체성). 그래서 이름 바꾸기에 불변이다. `id` 필드를 더한다.
   - **증분 키(ADR-0032·0043):**
     - 피호출자 행은 이름 없는 호출자 해시를 쓴다.
     - "원문" 행은 이름 없는 정규형으로 바꾼다.
     - 저장하는 의무 위치는 바이트 오프셋 대신 AST 노드 경로로 둔다. 진단을 낼 때만 현재 원문의 위치로 옮긴다.
   - **증명 질의:**
     - 정의 기호를 `id` 접두사로 짓는다(`|#5568cad7c114|`). 지역 기호는 위치 이름으로 짓는다.
     - `--emit-smt`는 이름 범례를 질의 텍스트 밖의 별도 파일에 쓴다.
     - 그러면 증명 캐시 키(질의 텍스트)가 이름에 불변이다. 기호 이름을 바꾸는 것은 판정을 바꾸지 않았다(1B-40: 의무 718개마다 기호 이름 바꾸기 변형 4개를 포함한 16개 변형에서 판정이 바뀐 것 0%).
5. **쓰기는 이름으로 한다.**
   - 에이전트는 지금처럼 이름으로 쓴다(`put`의 Rust 꼴 코드, `remove`의 경로). 도구가 커밋할 때 `id`로 해석한다(direction §4 "구조적 주소, 친숙한 내용").
   - 트랜잭션에 두 연산을 더한다.
     - `rename`(경로 → 새 이름): 색인과 참조자 텍스트를 도구가 고친다. 어느 정의의 `id`도 바꾸지 않는다.
     - `expect`(경로 → `id`) 전제조건: 현재 `id`가 다르면 커밋을 거부한다. 낙관적 동시성이다(H-PAR).
   - 따라서 서로 다른 정의의 이름 바꾸기와 본문 편집은 충돌하지 않는다.
6. **보여 주는 쪽은 이름이다.**
   - 맵·진단·반례·`impact`는 지금처럼 이름으로 출력하고 `id`를 덧붙인다. 에이전트가 해시를 읽을 일은 없다.
   - `duplicates`는 정체성 해시로 묶는다. 그러면 알파 동치 정의를 찾고, DESIGN §8.1의 동형 함수 병합에 정확한 키가 생긴다.
   - 근거(ADR-0006, 2E)는 `id`에 묶는다.

## 근거

1. **문제.** 이름 바꾸기 412번 중 86%가 다른 정의의 해시를 바꿨다. 정체성과 이름이 한 값에 섞여 있어서, 이름만 바꾸는 편집이 의미를 바꾸는 편집과 같은 비용을 낸다.
2. **원인과 귀속 층.** 컴파일러와 도구 층이다(해시의 정의, 키의 구성). 원인은 ADR-0019 §2가 "한정 정규형"을 해시 입력으로 정한 데 있다. 표면 문법은 바뀌지 않으므로 언어 층이 아니다. ADR-0019는 같은 문제를 자기 이름에 대해서만 풀었다("본문 해시에서 자기 이름을 빼면 이동·이름 변경 뒤에도 동일 정의를 찾을 수 있다").
3. **정석 해와 출처.**
   - 내용 주소 코드(content-addressed code): Unison은 정의를 구문 트리의 해시로 식별하고, 이름을 해시에 붙은 메타데이터로 두며, 의존을 해시로 참조한다. 상호 재귀 정의의 순환은 해시 하나를 받고, 구성원은 `#x.n`(순환 해시와 위치)이다. 순서는 순환을 지운 개별 해시로 정렬한다([hashes](https://www.unison-lang.org/docs/language-reference/hashes), [tour](https://unison-lang.org/docs/tour), [unisonweb/unison](https://github.com/unisonweb/unison). 이 환경에서 사이트가 열리지 않아 검색 요약으로 확인, 원문 미확인).
   - 묶는 이름의 알파 동치 판정: 위치 이름(de Bruijn 색인)은 PL의 표준 기법이다(S1 (d)).
   - 빌드 키를 이름이 아니라 입력 내용의 해시로 만드는 것은 내용 주소 빌드의 표준이다(S1 (c)).
4. **후보 비교.**

   | (a) 현행: 경로 해시 | 통과 | 통과 | 통과 | 부분 | 이름 바꾸기 86%가 번짐 | 자기 이름만 예외 | 리팩터링·동시 편집에 불리 |
   | **(b) 텍스트 저장 + 적재 시 해시 참조, 이름은 색인** | 통과(키가 인코딩이 읽는 것 전부를 담는지 `with_audit`로 확인) | 통과(성분 순서 규칙, 동률은 경로) | 통과(저장은 텍스트, 원칙 1) | 통과(Unison·알파 정규화) | 이름이 정체성에 들어가는 부류 전체를 없앤다 | `id` 하나가 맵·키·근거·중복을 묶는다 | 이름 바꾸기·이동의 무효화 0, 정의 단위 동시성 |

5. **권장과 결정적 기준.** (b)를 권장한다.
   - (a)·(d)는 S2에서 떨어진다. 원인(정체성에 든 이름)이 그대로 남는다.
   - (c)는 C4에서 떨어진다. 정의 개정이 필요하고, (b)보다 얻는 것이 없다. 텍스트를 보존하는 비용은 적재 때 해시를 계산하는 것뿐이다.
6. **영향(정보).**
   - `fmt.rs`: 정체성 출력기 추가. 한정 출력기는 표시용으로 남긴다.
   - `check.rs`: SCC 재사용.
   - `incremental.rs`: 키 행 교체, 의무 위치를 노드 경로로.
   - `verify.rs`: 기호 이름 짓기.
   - `cache.rs`: 형식 버전 증가. 기존 캐시는 한 번 무효가 된다.
   - `map.rs`: `id` 필드 추가, `body`·`iface` 의미 변경(ADR-0020 개정).
   - `workspace.rs`·`mcp.rs`: `rename`·`expect`.
   - 시험: `tests/incremental.rs`(감사), `fmt_fuzz`(불변식 추가), `mcp_fuzz`.
   - `--emit-smt`는 기호가 해시라서 사람이 읽기 어려워진다. 범례 파일로 메운다.
   - 해법기 안정성(V7)을 다시 재야 한다.
7. **필요한 승인.**
   - 채택된 ADR-0019 §2와 ADR-0032·0043의 키 행 대체(AUTONOMY §4).
   - 맵의 `body`·`iface` 의미 변경(ADR-0020). 0.x라 하위 호환 의무는 없다(JUDGMENT §6).
8. **우회.** 없다.

**H-ID를 닫는 측정**

- **비용 쪽:** rename-ripple의 참조자 수(본문·계약)가 0이 되어야 한다. 이름 바꾸기 편집에서 증분 빌드가 다시 인코딩한 정의 집합(`build --stats`)과 증명 캐시 놓침도 0이어야 한다. 자기 정의는 텍스트가 바뀌어도 `id`가 같으므로 다시 인코딩하지 않는다.
- **이득 쪽:**
  - BCB 이력에 이름 바꾸기·이동 편집을 섞은 판에서, 커밋당 재인코딩 수와 CPU를 이 ADR 전후로 비교한다.
  - H-PAR 재생에서 정의 단위 충돌률을 같은 방식으로 비교한다.
- **가독성 쪽:** 맵·진단 출력이 `id` 필드를 빼면 바이트 단위로 이전과 같아야 한다(이름은 그대로 보인다).

**반증과 되돌림**

- 반증 조건 중 하나라도 성립하면 이 ADR을 폐기한다.
  - T1-ID-02 뒤에도 이름 바꾸기가 다른 정의의 `id`나 키를 바꾼다.
  - 이름 없는 키가 인코딩 입력을 다 담지 못해 감사가 불일치를 내고, 그 불일치를 이름 없이 고칠 수 없다.
  - 해시 기호 때문에 V7이 기준선보다 나빠진다.
- 되돌리기는 쉽다. `id`는 텍스트에서 도출한 값이고 저장 파일은 바뀌지 않으므로 자료 이주가 없다. 출력기를 한정 경로로 되돌리고 캐시 형식 버전을 올리면 된다.
