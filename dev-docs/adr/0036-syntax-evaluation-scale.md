# ADR-0036: 문법 평가 저울

- 상태: 채택 (자율 채택, AUTONOMY.md §4: 평가 방법만 정한다. 언어·DESIGN.md는 바꾸지 않는다)
- 날짜: 2026-10-25
- 관련: DESIGN.md §2·§3(원칙 3·5·6·7·8·9)·§4·§4.1·§9 R2·R4, ADR-0013·0019·0021·0034, 백로그 2R-01

## 맥락
DESIGN.md §4는 "표면은 Rust·Verus를 승계한다"고 정했다(ADR-0013). 승계의 목적은 학습하지 않은 언어의 비용을 줄이는 것이었다. 승계 자체가 목표는 아니다(사람 지시 2026-10-25). BMB의 목표와 조건은 Rust·Verus와 다르다. 사용자는 에이전트이고, 에이전트는 도구로만 코드에 닿는다. 정본은 정규형이고, 읽기 비용은 슬라이스 크기로 잰다. 그래서 문법 요소마다 사전 지식의 이득과 더 효과적인 새 형태를 같은 저울로 비교해야 한다.

지금은 그런 저울이 없다. §4.1 "긴장과 대응"은 "Rust 습관 오류율을 재서 손실이 크면 되돌린다"고만 한다. 기준·측정·판정 규칙은 정해지지 않았다. 측정도 부분적이다. ADR-0021의 습관 지표는 E02xx만 센다. 그런데 Rust·Verus 습관 상당수는 다른 코드로 나온다. 예를 들어 `y += 1`, `0 <= i < n`, `int`, `exists`는 E0103·E0211·E0402로 거부된다(2R-02 측정).

## 결정

### 1. 평가 단위와 두 표면
- 평가 단위는 **구성**이다. 구성은 한 가지 일을 하는 문법 요소 하나를 말한다(예: 계약 절, 루프 머리, 정수 변환). 목록은 2R-02가 만든다.
- 구성마다 두 표면을 따로 본다.
  - **쓰기 표면**은 에이전트가 내는 텍스트다(`tx_put` 입력).
  - **정본 표면**은 정규형이다(ADR-0019). 저장·해시·슬라이스·맵이 모두 정규형을 쓴다.
- 판정은 정본 형태에 대해 내린다. 쓰기 표면에서 다른 형태를 받아 정본으로 옮기는 것은 **입력 별칭**이라는 부가 표지로 기록한다. 입력 별칭은 세 조건을 모두 갖출 때만 성립한다.
  1. 결정론적이다.
  2. 의미를 보존한다.
  3. 전역 함수다. 별칭 형태 하나는 정본 하나로만 옮겨진다.

  입력 별칭은 정본의 모호성(원칙 8)을 늘리지 않는다. 대신 쓰기 도구가 별칭을 처리하는 노동을 맡는다(원칙 6).

- 오프라인 측정 도구는 `bench/syntax/measure.py`(2R-02)와 기존 CLI(`fmt`, `fix`, `uses`, `stability`, `query slice`, `query duplicates`)다. 2R-04가 변환기를 더한다.
- C1의 오프라인 값은 **예측**이다. 실제 모델 측정(2R-03, 2R-05)이 나오면 그 값으로 바꾼다. 문서에는 예측과 측정을 구분해서 적는다.

### 3. 제약과 목적 (DESIGN.md §2에서 유도)
기준을 가중합하지 않는다. **제약을 먼저 거르고, 남은 후보를 목적 순서로 비교한다.** DESIGN.md §2가 정확성은 제약, 성능은 목적함수, 사용자는 에이전트라고 정했기 때문이다.

**제약 K1~K4.** 하나라도 어기면 그 형태는 정본이 될 수 없다.

| 제약 | 내용 | 근거 |
| --- | --- | --- |
| K1 검증 가능 | 구성의 의미가 증명 게이트로 건전하게 인코딩되고, 퍼저로 덮을 수 있다 | §2 정확성, CLAUDE.md "검증되지 않는 기능은 넣지 않는다" |
| K2 정본 유일 | 정본 표면에서 한 일에 형태가 하나다. 입력 별칭은 허용한다(§1) | 원칙 8 |
| K3 구문 확정 | 호출 대상·이름·효과의 맵 간선이 구문과 명시된 선언만으로 정해진다 | 원칙 6·7, §4.1 호출 해석 |
| K4 행동 보존 | Rust·Verus에서 빌린 형태는, BMB가 받아들이는 모든 프로그램에서 Rust·Verus와 같게 동작한다. 엄격화(받는 프로그램을 줄이는 것)는 허용한다. 같은 형태에 다른 의미를 붙이는 것은 거짓 친구이므로 금지한다 | §4 "더 장황한 Rust", ADR-0013 |

**목적 O1~O5.** 앞의 것이 우선이다.

| 순서 | 목적 | 주 기준 | 근거 |
| --- | --- | --- | --- |
| O1 | 에이전트의 1회 정확성과 명세 품질 | C1, C3(a)(c) | G2·G3(ADR-0034). 사용자는 에이전트다 |
| O2 | 읽기 토큰 | C5 읽기 | 원칙 5·7, G4. 슬라이스는 여러 번 읽힌다 |
| O3 | 도구가 흡수하지 못하는 쓰기 토큰 | C5 쓰기에서 C3(a)로 채워지는 몫을 뺀 것 | 전제 E3, G5. 도구가 채우는 표기의 쓰기 비용은 0으로 본다 |
| O4 | 증명 비용과 안정성 | C4 | G2(시간 안에 증명), §4.1 증명 안정성 |
| O5 | 성능 | C6 | §2 목적함수, G6. 표면은 성능에 거의 영향을 주지 않는다. 측정된 이득만 세고, ±5%를 넘는 측정된 퇴행은 거부한다 |

**가중치 0인 것.** 사람의 가독성·학습 용이성·미감(DESIGN.md 비목표)과 새로움 자체에는 가중치를 주지 않는다. "더 깔끔하다"는 근거가 되지 못한다.

**도출 가능한 표기의 처리.** 어떤 표기가 다른 코드에서 100% 결정론적으로 도출되면(C3(a)), 에이전트가 그 표기에 담는 정보는 없다. 그런 표기는 쓰기 표면에서 선택으로 만든다. 도구가 채운다. 정본에 남길지는 다음 기준으로 정한다.
- 도출에 슬라이스 밖의 정보(전역 고정점, 타입 검사기, 증명기)가 필요하면 정본에 남긴다. 슬라이스가 자급해야 하기 때문이다(원칙 5).
- 슬라이스 안의 구문만으로 도출되면 정본에서도 생략할 수 있다(O2).
- 표기가 인터페이스 역할을 하면 남긴다. 인터페이스 역할이란 피호출자 변경이 호출자에게 번지는 것을 막는 일이다(ADR-0030의 효과 선언).

### 4. 판정 범주와 규칙
| 판정 | 뜻 |
| --- | --- |
| **차용** | Rust·Verus 형태를 그대로 쓴다. Rust에서 선택인 표기를 필수로 만드는 것("선택을 필수로", §4)도 형태가 같으면 차용이다 |
| **확장** | Rust·Verus에 대응 형태가 없는 개념에 새 형태를 둔다 |
| **변형** | Rust·Verus 형태가 있지만 그대로는 안 되어 가까운 변형을 쓴다 |
| **기각** | 그 형태를 받지 않는다. 습관 진단과 안내를 둔다 |

판정 절차는 다음 순서를 따른다.
1. **개념이 BMB 범위 안인가?** 범위 밖이면 문법 판정이 아니다. 범위 진단(E0207 계열)만 둔다.
2. **Rust·Verus에 이 개념의 형태가 있는가?** 없으면 확장 규칙(5)으로 간다.
3. **그 형태가 K1~K4를 지키는가?**
   - 지키면 차용 후보다. O1~O5에서 §5의 증거 기준으로 이기는 대안이 있으면 변형, 없으면 차용이다.
   - 어기면 가까운 변형이 있는지 본다. 있으면 변형, 없으면 기각이다.
4. **가까운 변형**은 다음을 모두 만족하는 형태다.
   - (i) Rust·Verus 어휘 안에 있다. 유효한 Rust이면 더 좋다.
   - (ii) 같은 구문 노드 안의 국소 변경이다.
   - (iii) 습관 형태에서 이 형태로 가는 의미 보존 기계 수정이 있다.

   (iii)이 없는 변형은 C1 손실을 도구가 흡수하지 못한다. 그런 변형은 실제 모델 근거(§5 E2 이상)가 있어야 채택한다.
5. **확장 규칙.**
   - 새 키워드·기호보다 Rust의 확장 자리를 먼저 쓴다. 확장 자리는 속성 `#[..]`, 경로 호출 함수, Verus의 절 위치다.
   - 이름은 가장 가까운 학습된 유사물에서 고른다.
   - K1~K4를 지킨다.
   - 표기가 100% 도출되면 문법이 아니라 도구 채움이나 맵 사실로 둔다(§3).
6. **기각에는 진단이 따른다.** 기각된 습관 형태마다 진단 코드와 안내를 둔다. 의미 보존 수정이 있으면 `fix.replacement`도 둔다.
7. **되돌림.** §4.1 대응 3에 따라, 측정된 C1 손실이 회수한 이득보다 크면 변형·기각을 차용으로 되돌린다. 근거는 §5 E2 이상이다.

### 5. 증거 기준과 변경 절차
**증거 수준**

| 수준 | 내용 |
| --- | --- |
| E0 | 논증(설계 원칙·사례). 판정의 출발점일 뿐 변경 근거가 아니다 |
| E1 | 오프라인 결정론적 측정(토큰, 도출률, 수정 보유율, `rlimit`, 정규형 검사). 측정 코드와 결과를 커밋한다 |
| E2 | 실제 모델 실행 로그의 구성별 집계(1E-10·2A-06, 2R-03) |
| E3 | 문법만 바꾼 쌍둥이 과제 집합의 A/B(2R-05). 같은 모델, 1회, 재시도 없음(ADR-0021) |

**변경 문턱**

이미 구현된 M1 구성을 바꾸는 데는 아래 문턱이 있다. 제안 ADR(0026·0028~0031)의 구성은 아직 구현 전이므로 E1과 논증으로 판정할 수 있다. 다만 C1을 낮추는 쪽이면 아래 문턱을 똑같이 적용한다.

| 변경 방향 | 필요 근거 |
| --- | --- |
| Rust·Verus 쪽으로(완화, 입력 별칭, 기각을 차용으로) | E1(K1~K4 유지 확인) + 다음 중 하나: E2에서 그 구성의 습관 진단이 `tx_commit` 10회당 1회 이상, 또는 E1에서 O2·O3 이득이 5% 이상 |
| Rust·Verus에서 멀어지는 쪽으로(새 형태, 기각 추가) | E1에서 O1~O4 중 하나의 이득 + E3에서 열세 아님 |
| O1을 걸고 바꿀 때(1회 성공률 주장) | E3. 쌍둥이 집합에서 대안만 성공한 과제 수가 기존만 성공한 과제 수보다 3개 이상 많을 것. 과제 1개가 7~10%p라서(m1 §2) 이보다 작은 차이는 잡음으로 본다 |

**의미 있는 크기(E1).** 다음 중 하나를 넘으면 의미 있는 크기로 본다.
- 읽기·쓰기 코퍼스 어휘 토큰의 5%
- `rlimit` 합의 10%, 또는 정의 하나라도 `rlimit_max`가 고정 `rlimit`의 50%를 넘음
- 도출률 95% 이상(채움 가능 판정)

**변경 억제**
- 판정은 묶어서 바꾼다. 결정 ADR(2R-06)이나 단계 측정(2H·3E) 때만 바꾸고, 구성 하나씩 수시로 바꾸지 않는다.
- 같은 구성은 새 E2·E3 근거 없이 다시 열지 않는다.

**이행**
- 정본 형태가 바뀌면 옛 형태는 한 단계 동안 입력 별칭으로 남긴다. 옛 형태를 쓰면 `fix.replacement`가 있는 진단을 내고, `bmb fix`가 기계적으로 옮긴다.
- 동결된 과제 집합은 고치지 않는다(ADR-0021). 새 문법은 새 이름의 쌍둥이 집합으로 잰다.

**수정의 의미 보존**
- 기계 수정이 값을 바꾸면 C3(c) 위반이고 결함이다. 그런 수정은 입력 별칭이 될 수 없다.
- 예: E0104가 `0x10`을 `0`으로 바꾸는 수정(2R-02에서 발견).

### 6. 습관 오류의 측정 범위
- ADR-0021의 지표("E02xx 수 / `tx_commit`")는 측정의 연속성을 위해 그대로 둔다.
- 2R-03은 이와 별도로 **구성별 습관 지표**를 집계한다. 하네스 로그의 진단(코드 + 메시지의 문제 토큰)을 2R-02의 구성 목록에 대응시키는 표를 쓴다. 이 표는 E02xx 밖의 습관도 센다.

| 습관 | 진단 |
| --- | --- |
| 이름 재사용 | E0303 |
| 인라인 계약 | E0501 |
| Rust 표준 메서드·타입 | E0404·E0402 |
| `T::MAX` | E0301 |
| `+=`·비트 연산·`exists`·`open spec fn`·`@`·`#![auto]` | E0103 |
| 연쇄 비교 | E0211 |
| 속성·절 누락 | E0601·E0506·E0511 |

- 이 표가 R4의 "Rust 습관 오류율"을 구성 단위로 나눈 값이다.
- 에이전트 출력 형태(DESIGN.md §9 R2: 텍스트 대 구조화 편집 연산)는 이 저울의 대상이 아니다. 이 저울은 텍스트 표면을 비교한다.

## 근거
- **제약 우선, 목적 순서.** DESIGN.md §2는 정확성을 제약으로, 성능을 목적함수로, 에이전트를 사용자로 정했다. 가중합은 제약 위반을 다른 이득으로 상쇄할 여지를 남긴다. 표면 문법이 성능에 주는 영향은 측정상 작다(1E-08: 검사 제거의 속도 이득도 잡음 수준). 그래서 O5는 거부권과 동률 해소에만 쓴다.
- **두 표면.** 에이전트는 코드에 직접 닿지 않는다(원칙 6). 그러므로 쓰기 형태와 저장 형태가 같을 필요가 없다. "명시성은 산출물의 성질이고, 그 노동은 도구의 몫"(원칙 6)을 저울의 규칙으로 옮긴 것이다. 입력 별칭의 세 조건이 정본 모호성 0(원칙 8)을 지킨다.
- **K4 행동 보존.** 사전 지식이 이득이 되는 것은 같은 형태가 같은 의미일 때뿐이다. 엄격화는 받는 프로그램만 줄이므로 지식을 해치지 않는다. 의미를 바꾸면 지식이 오히려 오류를 만든다.
- **증거 문턱.** 과제 1개 차이가 7~10%p인 규모(m1 §2)라 작은 A/B 차이는 잡음이다. 문법 변경은 코퍼스·시드·프롬프트·진단 전체를 흔든다(변경 억제). 그래서 Rust 쪽 완화는 싸게, Rust에서 멀어지는 변경은 비싸게 둔다.

검토한 대안:
- (1) 가중합 점수표. 가중치 근거가 없고 제약 위반이 상쇄된다. 기각.
- (2) 모든 판정을 A/B로만. 비용이 크고 대부분의 구성은 E1으로 갈린다. 기각.
- (3) 쓰기 표면과 정본을 하나로 묶음(현행). 도구가 흡수할 수 있는 습관 오류까지 에이전트 실패로 남는다. 저울에서 분리하고, 실제 분리 여부는 2R-06이 정한다.

## 결과
- 2R-02(1차 평가)·2R-04(오프라인 비교)·2R-06(결정)이 이 저울을 쓴다. 판정 자체는 이 ADR이 내리지 않는다. 언어 변경은 2R-06에서 사람 승인을 받는다.
- 2R-03에 구성별 습관 대응표 작성이 더해진다(§6).
- 되돌리려면 이 ADR을 `폐기`로 바꾼다. 코드 변경은 없다.
