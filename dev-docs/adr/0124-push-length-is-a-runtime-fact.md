# ADR-0124: `push`의 길이는 증명 의무가 아니라 런타임이 지키는 사실이다

- 상태: 채택(사람 승인 2026-11-11 "권장안으로 실행": `dev-docs/measurements/4d-13.md`의 권장안). ADR-0031의 표에서 `v.push(x)` 행의 의무와 ADR-0050의 `String` `push`·`push_str` 길이 의무를 대체한다
- 날짜: 2026-11-11
- 관련: ADR-0031(Vec과 소유), ADR-0050(문자열), ADR-0017 §3(길이 상한 사실), ADR-0100(동결: 받아들이는 언어), `dev-docs/measurements/4d-13.md`, 백로그 4D-13

## 맥락

- `v.push(x)`와 `String`의 `push`·`push_str`에는 "길이가 최대 길이 안"이라는 증명 의무(E0816)가 붙어 있었다.
- 트리를 걸으며 버퍼에 쓰는 함수는 이 의무를 계약으로 풀 수 없다(`port-shape` 실험의 두 팔이 모두 `push` 앞에 런타임 가드를 두었다). 포트의 서식기·코드 생성이 같은 꼴이다.
- 런타임은 이미 이 조건을 지킨다: `Vec`의 성장(`bmb_vec_grow`)은 새 바이트 크기가 `isize`에 들지 않거나 할당이 실패하면 `abort`한다(ADR-0031 §4).

## 결정

1. **`v.push(x)`에는 길이 의무가 없다.** 증명은 `push` 뒤에 "넣기 전 길이 < `LEN_MAX(T)`"를 사실로 얻는다. 길이 상한 사실(ADR-0017 §3)은 그대로 성립한다.
2. **`String`의 `push`·`push_str`도 같다.** 증명은 새 길이 ≤ `isize::MAX`를 사실로 얻는다.
3. **넘는 경우는 프로그램이 끝난다.** 할당 실패와 같은 등급이다(`alloc` 효과, `abort`). `Vec`은 성장 경로의 기존 검사가 맡고, `String`은 `bmb_str_append`의 성장 경로에 "필요한 길이 > `isize::MAX`이면 `abort`"를 넣는다. 둘 다 성장할 때만 도는 검사다.
4. **`Vec::with_capacity(n)`의 의무(E0816)는 그대로다.** `n`은 프로그램이 주는 값이다.

## 근거

| 안 | 판정 |
| --- | --- |
| **의무를 없애고 사실로(채택)** | 원인의 층에서 고친다(JUDGMENT §3): 의무가 런타임이 이미 하는 검사와 겹친다. Rust의 `Vec::push`도 용량 초과를 호출자에게 묻지 않는다(S1). 건전성(C1): `push`가 돌아왔다면 `len + 1 <= cap`이고 `cap * size <= isize::MAX`다 |
| 크기의 명세 함수와 보조 정리 | 걷는 함수마다 크기 함수와 귀납 증명이 들고, 자식을 공유하는 구조에는 상한이 없다 |
| 가드를 가진 라이브러리 함수 | 바이트마다 비교가 남고, 닿을 수 없는 길이에서 조용히 잘린다 |

측정(`4d-13.md`, 임시 빌드): 표준 라이브러리 11단위는 218개 정의의 판정이 그대로이고 의무 1,750 → 1,697, `rlimit` −2.2%. 가드를 뺀 `port-shape/tree.bmb`가 전부 증명된다.

## 결과

- 받아들이는 프로그램이 늘어난다(가드 없는 `push`가 증명된다). 동결 선언 전의 변경이다.
- E0816은 `Vec::with_capacity`의 용량에만 남는다. 진단 표의 설명을 고친다.
- 증명 코퍼스에서 `push` 의무 6건이 사라지고 그 의무만으로 실패하던 정의 둘(`sf::unbounded`, `vf::unbounded`)이 증명된다. 다른 판정은 그대로다.
- 코드 생성: `push`의 길이 검사(증명되지 않았을 때 남던 것)가 없어진다. 전체 검사 모드에서도 성장 경로의 검사가 같은 일을 한다.
- 표준 라이브러리와 코퍼스에 남은 길이 가드·용량 논증은 지워도 되고 두어도 증명은 그대로다. 지우는 것은 그 파일을 고칠 때 한다.
