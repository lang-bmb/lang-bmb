# ADR-0018: 증명 의무 격리와 나눗셈 보조 사실

- 상태: 채택 (자율 채택, AUTONOMY.md §4)
- 날짜: 2026-10-24
- 관련: ADR-0017 §3·§5 보완, 백로그 1B-09·1B-13

## 맥락
1B 구현 중 두 가지가 드러났다.

1. **증분 상태에 따른 결과 변동.** 같은 질의 40개를 한 Z3 프로세스에서 `push`/`pop`으로 연달아 풀자, 36번째만 `unknown`이 나왔다(rlimit 200,000). `rlimit`은 질의마다 적용되지만, 앞선 질의가 남긴 내부 상태가 결과를 바꾼다. 실제로 `a / b + a % b` 예제는 다른 의무 뒤에서만 증명되었고, 단독으로는 실패했다. 결정론은 유지되지만, 의무 하나를 추가하면 무관한 다른 의무의 결과가 바뀔 수 있다. 증명 안정성(genesis §4)에 정면으로 반한다.
2. **나눗셈의 비선형성.** ADR-0017의 `trem(a,b) = a − b·tdiv(a,b)`는 변수 제수에서 곱셈이 되어, `a % b`의 범위 의무조차 증명되지 않았다.

## 결정

### 1. 의무 격리
- 의무마다 `(reset)` 후 그 정의의 기반(옵션, 정의, 공리, 선언)을 다시 보내고, 그 의무의 가정과 부정된 목표만 단언한다. 의무끼리는 상태를 공유하지 않는다.
- `--emit-smt`로 내보내는 스크립트는 실제로 실행한 순서(`(reset)` + 기반 + 의무)를 그대로 담는다.
- 해법기 명령이 `check-sat` 전에 자원 한도로 취소되어도 E0811(결정 불가)로 보고한다.
- 해법기는 `print-success`로 모든 명령의 응답을 확인한다. 오류는 그것을 일으킨 명령에서 잡힌다.

### 2. 나눗셈 보조 사실
`/`·`%`를 쓸 때마다 다음 선형 사실을 가정한다(`q`는 몫, `r`은 나머지).

| 부호 | 사실 |
| --- | --- |
| 부호 있음 | `b = 1 ⇒ q = a`, `b = −1 ⇒ q = −a`, `|b| > 1 ⇒ 2|q| ≤ |a|`, `b ≠ 0 ⇒ |r| < |b|`, `b ≠ 0 ⇒ r = 0 ∨ sign(r) = sign(a)` |
| 부호 없음 | `a ≥ 0 ∧ b > 0 ⇒ 0 ≤ q ≤ a`, `b > 0 ⇒ 0 ≤ r < b` |

- 이 사실들은 신뢰 기반에 들어간다. 그래서 각 사실이 ADR-0017의 SMT 정의에서 따라 나옴을 `compiler/tests/lemmas.rs`가 매 게이트마다 Z3로 증명한다. 증명이 깨지면 게이트가 실패한다.
- **규칙:** 앞으로 검증기가 가정하는 보조 사실은 모두 같은 방식으로 기계 증명 테스트를 함께 둔다. 예제를 통과시키기 위한 특수 목적 사실은 넣지 않는다.

### 3. 부수 결정
- `#[uses(..)]`는 다른 단위의 술어를 전체 경로(`unit::name`)로 받는다.
- `unknown`이어도 해법기가 후보 모델을 주면 "unconfirmed counterexample"로 붙인다. 판정은 여전히 실패다.
- 배열 리터럴은 명세 문맥에서 금지한다(E0503). 무한 정수 명세에서 배열 값의 의미가 정해지지 않았다.

## 근거
- 의무 격리의 비용은 의무마다 기반을 다시 파싱하는 것이다. 현재 코퍼스 전체가 약 3초다. 안정성과 바꿀 만하다.
- 나눗셈 사실은 모두 선형이고 증명되어 있어, 신뢰 기반을 넓히지 않으면서 해법기 부담을 줄인다.

## 결과
- 증명 결과는 의무 단위로 독립이다. 성능 측정 시 의무 수가 비용의 주 요인이 된다.
- 비선형 산술(예: `a / b + a % b`의 넘침)은 여전히 증명되지 않을 수 있다. 미증명 면적으로 드러난다.
