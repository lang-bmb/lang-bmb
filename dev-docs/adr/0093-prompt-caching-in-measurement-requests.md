# ADR-0093: 측정 요청의 프롬프트 캐싱

- 상태: 채택 (2026-11-06, 사람 지시: 게이트웨이 운영자 요청 전달. ADR-0066·ADR-0070 범위 안의 측정 운영 결정)
- 날짜: 2026-11-06
- 관련: ADR-0066(측정 모델과 환경), ADR-0070(측정 조건), ADR-0076(출력 한도와 이어 쓰기), ADR-0088(게이트웨이 용량 장애), 백로그 INF-27

## 맥락

- 게이트웨이 운영자의 확인: 2026-10-30~11-06 `claude-sonnet-5-5` 요청 약 4,900건, 입력 약 5천만 토큰에서 캐시 읽기가 0, 캐시 쓰기가 합쳐 약 1만 토큰이다. 게이트웨이는 `cache_control`을 그대로 전달하고, 운영 경로에서 쓰기와 읽기가 모두 동작했다. 결국 요청에 `cache_control`이 없었다.
- 그 트래픽은 측정 하네스다. 모든 하네스가 `bench/m1/anthropic_agent.py`(표준 라이브러리 HTTP 클라이언트 `model_api.HttpAnthropic`)로 보내는데, 여기에 캐시 표시가 없었다. Claude Code 세션은 이 게이트웨이를 거치지 않는다(`ANTHROPIC_BASE_URL`이 다른 호스트), `DISABLE_PROMPT_CACHING`은 설정돼 있지 않다.
- 커밋된 sonnet 세션 기록(2026-11-04~06, 세션 456개, 요청 2,894건)에서 요청당 입력은 평균 약 10,900토큰, 세션당 요청은 중앙값 4건, 요청당 출력은 중앙값 460·99분위 4,466·최대 14,063토큰이다. 한 세션의 요청은 앞 요청의 프롬프트에 덧붙기만 한다(ADR-0076의 이어 쓰기도 마지막 사용자 턴에 블록을 더할 뿐이다).
- 캐시는 요청 가격을 바꾸고, 모델이 보는 입력은 바꾸지 않는다. 다만 응답 `usage.input_tokens`는 캐시 밖 나머지만 세므로, 그대로 더하면 측정의 토큰 지표(ADR-0021의 총 토큰)가 캐시 적중에 따라 줄어든다.

## 결정

1. **Anthropic 요청은 캐시를 켠다.** 마지막 도구 정의에 명시 표시(도구는 맨 앞에 렌더되므로 같은 도구 목록을 쓰는 집합의 세션들이 한 항목을 나눈다), 그리고 요청 최상위의 자동 캐싱(`cache_control: {"type": "ephemeral"}`, 커지는 대화의 끝에 표시가 따라간다). 시스템 프롬프트는 문자열 그대로 둔다(블록으로 바꾸면 요청 본문이 바뀐다, 3번).
2. **TTL은 5분.** 같은 세션의 다음 요청은 앞 응답의 생성과 도구 실행 뒤에 시작하고, 생성은 대부분 수백 토큰이라 5분 안이다. 1시간 TTL은 쓰기가 2배라 이 간격에서 이득이 없다. 측정이 5분을 넘는 간격을 자주 보이면 다시 정한다.
3. **토큰 지표는 전체 프롬프트다.** `input_tokens` = 캐시 밖 + 캐시 쓰기 + 캐시 읽기. 캐시 쓰기·읽기는 `cache_creation_input_tokens`·`cache_read_input_tokens`로 따로 센다(사용량과 요청별 기록). 그래서 지난 결과와 같은 정의로 비교된다.
4. **캐시는 측정 조건이 아니다.** `condition.py same`은 요청 본문과 결과 행에서 `cache_control`과 캐시 토큰 수를 빼고 비교한다(`condition.without_cache`). 모델이 보는 것과 판정이 같으면 같은 조건이다.
5. **qwen(OpenAI 호환) 요청은 바꾸지 않는다.** 운영자의 요청은 Anthropic 경로이고, OpenAI 호환 API에는 요청 쪽 캐시 표시가 없다.

## 근거(검토한 대안)

| 안 | 판정 |
| --- | --- |
| **마지막 도구 표시 + 자동 캐싱, 5분(채택)** | 세션 안의 반복 접두사 전부와 집합 안의 도구 접두사를 읽는다. 요청 본문은 표시만 더해지고, 판정과 모델 입력은 그대로 |
| 자동 캐싱만 | 세션 안은 같지만 세션의 첫 요청(세션당 중앙값 4건 중 1건)이 늘 전액이다 |
| 시스템 블록에도 표시 | 시스템을 블록 목록으로 바꿔야 해 요청 본문이 달라진다. 도구 표시가 이미 앞쪽 공통 접두사를 덮는다 |
| 1시간 TTL | 쓰기 2배. 요청 간격이 5분 안이라 읽기가 늘지 않는다 |
| 켜지 않음 | 같은 입력을 매 요청 전액으로 다시 낸다. 측정량을 정하는 일일 지출 한도(ADR-0088)를 그만큼 먼저 쓴다 |

## 결과

- 앞으로의 sonnet 측정은 같은 지출 한도로 더 많은 세션을 돈다. 게이트웨이가 벤더 계정 다섯에 나눠 보내 처음에는 계정마다 쓰기가 한 번씩 난다(운영자 안내).
- 확인은 결과 행의 `cache_read_input_tokens`다. 첫 실측에서 읽기가 0이면 접두사를 바꾸는 것이 있다는 뜻이고 요청 본문을 비교한다.
- 이미 커밋된 결과는 그대로 유효하다(캐시 없이 잰 것이고, 토큰 정의가 같다).
