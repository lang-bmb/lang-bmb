# ADR-0054: 스칼라 참조 매개변수 `&T`·`&mut T`

- 상태: 채택 (2026-10-27, 자율 채택: AUTONOMY §4 "기존 ADR 범위 안의 구현 수준 결정", 백로그 2T-08)
- 날짜: 2026-10-27
- 관련: ADR-0015(2차 참조), ADR-0016(M1 범위), ADR-0026 §2, ADR-0046 §1·§2, 백로그 2T-07a·2T-08

## 맥락
ADR-0015는 참조를 인자 위치에만 두는 2차 참조를 정했고, M1(ADR-0016)은 그 가운데 `&[i64]`·`&mut [i64]`만 받았다. 2B(ADR-0026)가 `&Point`·`&mut Point`를 더했다. 정수·`bool`을 가리키는 참조 매개변수(`x: &mut i64`)는 E0402였다.

그런데 제네릭(ADR-0046)은 타입 인자로 모든 값 타입을 받으므로 `fn get<T: Copy>(x: &T)`의 인스턴스 `get::<i64>`는 이미 `&i64` 매개변수를 갖는다. 코드 생성은 이것을 처리하지 못해 패닉했다(2T-08, 2T-01부터). 또 trait의 수신자 `self: &Self`를 정수 타입에 impl하려면(ADR-0046 §2) impl 함수의 서명이 `self: &i64`여야 하는데, 이것이 E0402였다. 같은 타입이 제네릭으로는 되고 직접 쓰면 안 되는 두 규칙이다.

## 결정
- 매개변수 타입에 `&T`·`&mut T`(`T`는 정수 타입 또는 `bool`)를 받는다. 2차 참조 규칙(ADR-0015: 인자 위치에만, 저장·반환 불가)과 별칭 규칙(E0410)은 그대로다. spec fn은 `&mut`을 받지 않는다(기존 규칙).
- 의미는 Rust와 같다. 본문에서 `*x`로 읽고 `&mut`이면 `*x = v`로 쓴다. 계약의 이전 값은 `*old(x)`(Verus와 같음).
- 코드 생성: 매개변수는 호출자의 슬롯을 가리키는 포인터이고 본문은 그것을 지역 변수 슬롯처럼 읽고 쓴다. 인자가 지역 변수나 스칼라 참조 매개변수이면 그 슬롯을 넘기고, 필드·원소(메모리 표현, `u8`·`bool`은 1바이트)이면 값을 임시에 담아 넘긴 뒤 `&mut`이면 호출 뒤 되쓴다. 2차 참조라 호출 동안 그 자리를 보는 다른 경로가 없으므로 되쓰기와 직접 참조는 관찰상 같다.
- 증명 인코딩은 바꾸지 않는다. 기존 `&mut` 인자 처리(호출 뒤 그 자리를 새 상수로, callee의 `ensures`만 가정)가 스칼라 자리에도 그대로 맞다.

## 근거
| 안 | 판정 |
| --- | --- |
| **스칼라 참조 매개변수 허용(채택)** | Rust 표면 그대로(S1). 제네릭 인스턴스와 직접 쓴 코드가 같은 규칙(S3). trait의 `&self` 수신자를 정수 타입에 impl할 수 있다 |
| 제네릭 인스턴스만 코드 생성하고 직접 쓰기는 계속 거부 | 같은 타입에 두 규칙. 정수 타입의 trait impl이 막힌다 |
| 스칼라 타입에 `&T` 인스턴스화를 금지 | ADR-0046의 "타입 인자는 값 타입"을 좁힌다(승인 필요). 정렬 같은 제네릭 알고리즘이 정수에 못 쓰인다 |

## 결과
- 출력 매개변수(`fn parse(s: &[u8], out: &mut u64)`)를 쓸 수 있다. 결과가 여럿이면 지금까지는 구조체로 돌려주었다. 둘 다 유효하고 정규형은 각각이다.
- 2T-08의 회귀 시험: `tests/run/scalar_refs`(지역·필드·원소·제네릭 인스턴스·정수 타입 trait impl), `tests/verify/fail/scalar_refs`(호출 뒤 바뀐 자리의 반례).
