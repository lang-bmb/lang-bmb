# ADR-0098: 명세는 옮긴 값을 읽는다

- 상태: 제안 (백로그 2T-12)
- 날짜: 2026-11-09
- 관련: ADR-0031·0047(이동, E0413), ADR-0062(`proof` 코드는 값을 읽고 옮기지 않음), ADR-0017(명세의 값), ADR-0092(표준 라이브러리), `dev-docs/health/4B.md` 발견 3

## 맥락

- 이동 검사(`compiler/src/moves.rs`)는 `assert`·루프 불변식·`decreases`의 언급도 사용으로 센다. 옮긴 지역 변수를 거기서 말하면 E0413이다. `proof { .. }` 블록 안은 이미 예외다(ADR-0062: 유령 코드는 값을 읽고 옮기지 않는다).
- 사후 조건은 막히지 않는다. `ensures`의 매개변수는 들어온 값이기 때문이다. 그래서 같은 사실을 `ensures`로는 말하고 몸 안의 `assert`로는 말하지 못한다. 재현(2026-11-09): `fn put<T>(v: &mut Vec<T>, k: T)`에서 `ensures`의 `k`는 통과하고, `v.push(k);` 뒤 `assert(..k..)`는 E0413 "`k` is used after it was moved".
- 4B-04에서 이것 때문에 `std::collections`의 이동 키 밀기를 루프 대신 재귀로 썼다(불변식이 옮긴 키를 말해야 했다).
- 증명 쪽에서는 이미 뜻이 있다. 옮긴 값은 더 읽히거나 바뀔 수 없으므로 그 논리 값은 옮긴 때의 값 그대로다. 인코더는 이동 정보를 읽지 않는다(`moves::MoveInfo`는 코드 생성의 해제 지점에만 쓰인다).
- Verus는 명세용 유령 지역 변수(`let ghost`)로 스냅숏을 남기는 것이 정석이다.

## 결정(제안)

1. **명세 자리(`assert`·`assume`·루프 불변식·`decreases`, 그리고 지금처럼 `proof` 블록)는 옮긴 지역 변수를 읽을 수 있다.** 읽는 값은 마지막으로 옮긴 때의 값이다. 그 뒤에 다시 대입했으면 대입한 값이다(지금의 SSA 그대로).
2. 명세 자리의 언급은 이동이 아니다. 실행 위치의 사용은 그대로 E0413·E0414다.
3. 부분 이동(필드 경로)도 같다. 옮긴 필드의 값을 명세가 읽는다.
4. 새 표면은 없다. `let ghost`는 두지 않는다.

## 근거(검토한 대안)

| 안 | C1 건전성 | 판정 |
| --- | --- | --- |
| **명세가 옮긴 값을 읽음(권장)** | 바뀌지 않음: 옮긴 값은 접근할 수 없어 바뀌지 않고, 인코딩은 이미 그 값을 담는다. 실행 코드의 소유권 규칙은 그대로 | 새 표면이 없다. `ensures`와 몸 안의 `assert`가 같은 이름을 같은 뜻으로 읽는다 |
| 유령 지역 변수 `let ghost k0 = k;`(Verus) | 같음 | 키워드와 지움 규칙이 새로 생기고, 같은 사실을 쓰는 형태가 둘이 된다. Rust 사용자에게 없는 습관이다 |
| 그대로(재귀로 우회) | 같음 | 루프를 재귀로 바꾸게 하는 마찰이 포팅에서 반복된다(4B-04) |

결정적 기준은 S1(정석, 새 표면 없음)과 원칙 "정규형 하나"다.

## 결과

- 구현: `moves.rs`의 명세 위치(지금 `ghost`인 `proof` 블록처럼)에서 이동 상태를 검사하지 않음. 코퍼스 `tests/verify/pass`(옮긴 키를 말하는 불변식이 증명됨), `tests/check/err`(실행 위치의 E0413 그대로). 퍼저 `soundness_specs`에 옮긴 값을 말하는 `assert`.
- `std::collections`의 이동 키 밀기는 루프로 되돌릴 수 있다(비용·판정 비교 후).
- 코드 생성은 바뀌지 않는다(명세는 지워진다).
