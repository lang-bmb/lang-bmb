# ADR-0102: 효용의 판정 단위(수명 단위 G5-L)와 원칙 4의 범위

- 상태: 채택(사람 승인 2026-11-09 "Ok 제안 및 권장안 채택", 종합 평가의 제안 P4·P5)
- 날짜: 2026-11-09
- 관련: DESIGN.md §2(전제 E3, 원장)·§3 원칙 4, ADR-0034(G5), ADR-0041(원장, 결과 "쓰기 어렵다 대 AI 효율"), ADR-0003(테스트 필요 면적), ADR-0078(H-EFFECT), `dev-docs/measurements/t0-30.md`, `dev-docs/reports/utility.md` §2.7

## 맥락

- **G5(ADR-0034)는 BRB 과제 하나의 총 토큰으로 판정한다.** 2단계 기준은 "결함률 Rust+테스트의 1/2 이하, 총 토큰 2배 이내"다. 정식 측정에서 성공당 토큰은 sonnet이 Rust의 약 15~18배(원판·쓰기 판), qwen이 쓰기 판에서 1.3~2.4배다. 강한 모델의 Rust 기준선은 세션당 도구 호출 3번 정도다.
- **전제 E3는 수명의 거래다.** "쓰기 때 한 번 치르는 비용으로 변경마다 반복되는 검증 비용과 빠져나가는 결함을 줄인다." 과제 하나는 그 거래의 앞쪽 절반(쓰기)만 잰다. 이득 쪽(이후 변경, 재검증, 결함 수리)은 어떤 정식 측정에도 들어 있지 않다.
- **H-EFFECT가 반증됐다(T0-30, sonnet).** 효과로 I/O를 가른 과제 넷에서 남은 테스트 면적이 실행 정의의 0.667(기준 ≤ 0.2), 테스트가 필요한 코드가 Rust 테스트 줄의 4.1배였다. 면적은 분해에서 온다: `io` 껍데기 정의 자체가 면적이다. 원칙 4는 "대체 범위는 단위 수준의 기능 정확성"이라고 이미 적지만, 효과 껍데기가 남는다는 것은 적혀 있지 않다.

## 결정

1. **G5는 두 층으로 보고한다.**
   - **G5(과제 단위)**: ADR-0034 그대로(BRB, 2배 이내). 지금은 **미충족**으로 기록한다. ADR-0041의 결과(총 토큰이 크면 표면·도구를 고친다)는 그대로 유효하고, 효용 보고서가 비율의 궤적(측정마다)을 보고한다.
   - **G5-L(수명 단위)**: 같은 코드베이스에서 작성 1회 + 후속 변경 k회 + 숨은 판정이 찾은 결함의 수리까지의 총 토큰과 누적 검증 실행 비용. 비교군은 같은 이력을 따르는 Rust+테스트 팔이다. 목표는 ADR-0034의 3단계 기준 "총 토큰 Rust+테스트 이하"를 이 단위에 건다.
2. **E3의 판정은 G5-L과 결함률이 한다.** E3는 G5-L ≤ 1배이거나, G5-L이 2배 이내이면서 빠져나간 결함이 Rust+테스트의 1/2 이하일 때 성립으로 본다. 둘 다 아니면 반증이다. 이 기준은 측정 전에 등록한다(측정 장은 ADR-0103·0104).
3. **원칙 4의 범위를 적는다.** 증명이 대체하는 것은 순수 핵심(`pure` 정의)의 기능 정확성이다. `io` 효과 정의(껍데기)는 테스트 면적으로 남고, 컴파일러가 면적을 산출해 보고한다(ADR-0003). 껍데기를 줄이는 길(명세에서 생성한 시험, 기록·재생, 껍데기를 얇게 만드는 분해 진단)은 후보로만 두고, 채택 전에 잰다.
4. H-EFFECT의 판정은 "반증(sonnet)"으로 둔다. 같은 기준을 실제 코드(포팅 쌍둥이, ADR-0104)의 효과 분포에서 다시 잰다.

## 근거

| 안 | 판정 |
| --- | --- |
| **두 층, 결정적 판정은 수명 단위(채택)** | E3가 주장하는 거래의 단위와 측정 단위가 맞는다. 과제 단위 미충족을 지우지 않고 그대로 기록하므로 목표를 사후에 낮추지 않는다 |
| 과제 단위만 유지 | 강한 모델에서 원리상 충족할 수 없는 꼴(Rust 쪽 세 호출)이고, E3의 이득 쪽을 재지 않는다 |
| 과제 단위 목표를 낮춤(예: 5배) | 근거 없는 사후 완화 |
| 원칙 4 그대로 | 반증된 기대("테스트 0" 지향)가 껍데기에도 걸려 있는 것처럼 읽힌다 |
