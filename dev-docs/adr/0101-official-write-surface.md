# ADR-0101: 정식 측정의 쓰기 표면은 정의 단위 한 번 쓰기(`write`)

- 상태: 채택(사람 승인 2026-11-09 "Ok 제안 및 권장안 채택", 종합 평가의 결정 D1)
- 날짜: 2026-11-09
- 관련: ADR-0066(측정 모델 환경), ADR-0077 §4(최소 차이 D), ADR-0073(세 편집 표면 동결), ADR-0009(쓰기는 트랜잭션), `dev-docs/measurements/t0-13.md`(권장안), 백로그 T0-13

## 맥락

- 정식 측정(ADR-0066)은 트랜잭션 표면(`tx_begin`·`tx_unit`·`tx_put`·`tx_commit`)으로 돌았다. 원판 실패의 큰 몫은 도구 호출 한도였다: qwen BVB 20/45·BRB 9/24, sonnet BRB 4/24. 한 정의를 쓰는 데 최소 다섯 호출이 든다.
- T0-13(`e5247e8d`, 같은 커밋 두 모델)에서 정의 단위 한 번 쓰기(`bench/*-write`)는 원판보다 D(30%p)를 넘게 뒤진 칸이 없고, qwen BRB에서 +46%p로 D를 넘게 앞섰다(7/24 → 18/24). 한도 도달은 qwen 1, sonnet 0이다. 도구 호출은 BVB −80%(sonnet)다.
- sonnet `m1b-write`는 2026-11-05에 같은 커밋에서 다시 돌아 25/25였다(ADR-0088로 무효된 첫 실행을 대신). 쓰기 판은 세 집합 모두 원판과 같거나 높다(25/25·45/45·24/24).
- 2026-11-04에 이 결정은 T0-33(BVB·BRB 반복으로 집합별 D) 뒤로 미뤄졌다. T0-33은 반복 1의 `bvb-write`만 유효하고 나머지가 남았다.
- 사전에 제안했던 규칙("BVB와 BRB 모두 D를 넘으면 `write`")은 충족되지 않는다. sonnet은 두 집합 모두 천장 근처(45/45, 20~24/24)라 그 규칙은 거의 충족될 수 없었고, 등록 때 이 점을 고려하지 않았다.

## 결정

1. **정식 측정의 기본 표면은 정의 단위 한 번 쓰기다.** `bench/run_models.py`의 기본 집합은 `m1b-write`·`bvb-write`·`bvb-verus`·`brb-write`·`brb-rust`다. 비교군(Verus·Rust 팔)은 바뀌지 않는다.
2. **원판(`m1`·`m1b`·`bvb`·`brb-bmb`)은 동결된 비교 기준으로 남는다.** 이름을 주면 돈다. T0-10·T0-11·T0-13 원판 결과와의 비교, 그리고 원판에서 만든 변형 판(T0-14 H-NAME, 2A-07, T0-15, T0-17, T0-18)은 각자의 원판과 비교한다.
3. **새 변형 판은 쓰기 판에서 만든다.** 이미 진행 중인 측정은 등록한 집합 그대로 끝낸다(2R-05는 `bench/m1b`로 등록되어 그대로 돈다. 쓰기 판 A/B는 ADR-0103의 증거 단계에서 더한다).
4. **사후 변경임을 밝힌다.** 이 결정은 T0-13 결과를 본 뒤의 규칙 변경이다. 근거는 "D를 넘는 손해 없음"과 "실패 원인이 도구 층의 호출 비용"이고, 언어(검증·판정)는 두 표면에서 같다.
5. 언어의 쓰기 의미(트랜잭션, 증명은 빌드 게이트, ADR-0009)는 바뀌지 않는다. `write`는 한 정의의 트랜잭션을 한 호출로 여닫는 도구 표면이다.

## 근거

| 안 | 판정 |
| --- | --- |
| **`write`를 정식으로(채택)** | D를 넘는 손해 없음, 한 칸에서 D를 넘는 이득, 호출·토큰이 대부분 적음. 에이전트 편집 도구의 정석 꼴(한 번에 끝나는 쓰기, 여러 단계는 선택지) |
| 원판 유지 | 측정이 언어보다 도구 절차의 호출 한도를 잰다 |
| 사전 규칙 그대로 적용 | 천장 효과 때문에 사실상 원판 고정. 규칙의 등록 결함 |

## 결과

- `bench/run_models.py`의 `DEFAULT`와 `bench/test_run_models.py`.
- 11-04의 미룸은 이 승인으로 풀린다. T0-33은 계속 돌아 T0-13의 차이를 집합별 D로 다시 읽는다. 다시 읽은 결과가 쓰기 판이 D를 넘게 뒤진다고 보이면 이 결정을 다시 연다.
- 효용 보고서(`dev-docs/reports/utility.md`)의 비용 서술은 쓰기 판 결과를 기본으로 한다.
