# ADR-0099: 명세의 정수 넓힘: 갈래와 결과

- 상태: 제안 (백로그 2N-08, ADR-0022 확장)
- 날짜: 2026-11-09
- 관련: ADR-0022(명세에서 정수 타입 혼합), ADR-0017 §4(spec fn 정의 공리의 범위 가드), ADR-0028·0095 A4(`x as T`), ADR-0095(입력 별칭)

## 맥락

- ADR-0022로 명세 산술·비교·`spec fn` 인자는 정수 타입을 섞는다. 그러나 `if`·`match`의 갈래끼리, 그리고 `spec fn` 본문 대 선언한 결과 타입은 같아야 하고(E0401), 명세에는 변환이 없다(E0513).
- 그래서 `u8` 바이트를 `u64` 결과로 쓰려면 항등 함수에 넘겨야 했다: `lib/std/sha256.bmb`의 `spec fn wide(b: u64) -> u64 { b }`와 `pad_byte`의 `if i < msg.len() { wide(msg[i]) } else ..`(T4-01 발견). 그 항등 함수는 `#[uses]`에도 적혀야 했다.
- ADR-0095 A4로 실행 코드의 변환은 `x as T`가 정본이다. 같은 습관으로 명세에 `msg[i] as u64`를 쓰면 E0513이다.

## 결정(제안)

1. **명세에서 정수 갈래·결과는 넓힘으로 맞춘다.** 기대 타입(선언한 결과, 다른 갈래)의 범위가 값의 타입의 범위를 담으면(`u8` → `u16`·`u32`·`u64`·`usize`·`i16`·`i32`·`i64`, `i32` → `i64` 등) 같은 타입으로 본다. 담지 않으면(`u64` → `u8`, `i64` ↔ `u64`) E0401 그대로다.
2. **명세의 넓히는 `x as T`는 입력 별칭이다.** 뜻은 항등이고 `fmt`가 지우며 `bmb lint`가 알린다(새 W 코드). 좁히는 `as`는 E0513 그대로다(명세에는 실패 의무가 없다).
3. 실행 코드는 바뀌지 않는다.

## 근거(검토한 대안)

| 안 | C1 건전성 | 판정 |
| --- | --- | --- |
| **넓힘만(권장)** | 범위가 담기므로 결과 타입의 범위 사실이 그대로 참이다. 결과 범위를 가정하는 곳이 있는지 감사할 필요가 없다 | 측정된 마찰(`wide`)을 덮고, 표면은 늘지 않는다 |
| 명세의 모든 정수를 섞음(갈래·결과도 무한 정수) | `spec fn -> u8`의 결과가 범위 밖일 수 있어, 결과 범위를 가정하는 모든 곳의 감사가 먼저다 | 근거(측정된 사례)에 비해 넓다 |
| 명세의 `as`를 정본으로 | 좁히는 `as`의 뜻(잘림인가 실패인가)을 명세에 새로 정해야 한다. 실행의 `as`(검사된 변환, ADR-0095 A4)와 뜻이 갈린다 | 정규형이 둘(섞는 산술과 `as`) |
| 그대로(항등 `spec fn`) | 같음 | 항등 함수와 그 `#[uses]` 항목이 남는다 |

결정적 기준은 C1을 감사 없이 지키는 가장 좁은 규칙인가였다.

## 결과

- 구현: 검사기의 명세 모드 갈래·결과 비교에 넓힘 관계, 명세 `as` 별칭과 W 코드, 코퍼스(`tests/verify/pass`의 넓힘 갈래, `tests/check/err`의 좁힘 E0401·E0513), `lib/std/sha256.bmb`의 `wide` 제거(정의별 판정·비용 비교).
- 인코더는 바뀌지 않는다(명세 정수는 이미 `Int`).
