# ADR-0061: 부동소수 `f64`: IEEE 754 의미, 기본 불투명 인코딩과 `by (bit_vector)` 안의 비트 정밀 증명

- 상태: 제안 (2026-10-28, 사람 지시로 초안 작성. 채택은 언어 범위 확대라 사람 승인, AUTONOMY §4)
- 날짜: 2026-10-28
- 관련: ADR-0045(판단 기준), ADR-0017(정수 인코딩), ADR-0028(변환), ADR-0048 §2·§3(`by (bit_vector)`), ADR-0046(`Eq`·`Ord` 경계), ADR-0019(정규형), 방향성 논의 `dev-docs/reviews/direction-2026-10-28.md` §7.2 T3, §8 Q4

## 맥락

- BMB에는 부동소수가 없다. 파서는 `f32`·`f64`를 타입 이름으로 받지 않는다(`compiler/src/parser.rs`의 예약 원시 타입 목록). 리터럴은 10진 정수뿐이고(`lexer.rs`), 코드 생성은 모든 스칼라를 `i64` 레지스터에 둔다(ADR-0048 §1).
- 트랙 재설정(T3)은 자체 성능 벤치 7개를 공인 벤치로 바꾼다. Computer Language Benchmarks Game의 프로그램 가운데 n-body·spectral-norm·mandelbrot·fasta가 `f64`를 쓴다. 지금 언어로 쓸 수 있는 것은 binary-trees·fannkuch-redux뿐이다. 새 트랙 규칙("언어 페이즈는 T3·T4의 구체 수요가 열 때")에서 이 ADR의 수요가 바로 그것이다.
- 정석 Rust 프로그램 중 부동소수를 쓰는 것을 지금 BMB로 쓸 수 없다. 이것은 JUDGMENT §7로 보면 언어 결함이다. 원장(DESIGN §4.1)에 부동소수를 금지하는 행은 없다.

## 결정

### 1. 타입

- **`f64` 하나를 둔다.** `f32`는 수요가 생길 때 같은 규칙으로 더한다. T3의 대상 프로그램은 모두 `f64`다. 파서는 `f32`에 E0402를 그대로 내고 `f64`로 바꾸라고 안내한다.
- `f64`은 값으로 복사되는 스칼라다(`Copy`). 배열·슬라이스·`Vec`·구조체 필드·열거형 페이로드·제네릭 인자에 정수와 같은 규칙으로 들어간다.
- `f64`은 내장 경계 `Eq`·`Ord`(2T-02)를 갖지 않는다. Rust와 같다. 정렬·이진 탐색에는 쓸 수 없고, `total_cmp`는 수요가 생길 때 더한다.

### 2. 리터럴과 정규형

- 꼴: `숫자.숫자`에 선택적인 지수 `e[+-]숫자`를 붙인다(`1.0`, `0.5`, `6.02e23`, `1.0e-9`). 점 양쪽의 숫자는 필수다. `1.`과 `.5`는 받지 않는다. 그래서 `0..n`(범위)과 겹치지 않는다. 접미사는 없고, 기대 타입이 `f64`일 때만 부동소수 리터럴이 된다(정수 리터럴과 같은 규칙).
- 값은 10진 표기를 가장 가까운 binary64로 올바르게 반올림한 것이다(Rust `str::parse::<f64>`와 같다).
- **정규형**(ADR-0019)은 그 값의 가장 짧은 왕복 표기다(Rust `{:?}`와 같다. 컴파일러는 Rust 표준 라이브러리로 계산한다). `0.10`과 `1e-1`은 `0.1`이 된다. 같은 값이면 같은 텍스트이고 같은 해시다.
- `f64::INFINITY`·`f64::NEG_INFINITY`·`f64::NAN`·`f64::MAX`·`f64::MIN_POSITIVE`·`f64::EPSILON`은 연관 상수다(2N-06의 `T::MIN`·`T::MAX`와 같은 경로).

### 3. 연산

| 연산 | 의미 | 의무 |
| --- | --- | --- |
| `+`·`-`·`*`·`/`, 단항 `-` | IEEE RNE | 없음. Rust에서 panic하지 않는 전함수다 |
| `%` | Rust의 `%`(fmod, 절단). SMT `fp.rem`(IEEE remainder)과 다르다 | 첫 범위에서 뺀다. 수요가 생기면 불투명 함수로 더한다 |
| `==`·`!=`·`<`·`<=`·`>`·`>=` | IEEE 비교(NaN이 끼면 `!=`만 참) | 없음 |
| `x.sqrt()`·`x.abs()`·`x.min(y)`·`x.max(y)`·`x.is_nan()`·`x.is_finite()` | Rust 표준 의미. `sqrt`는 IEEE에서 올바르게 반올림된다 | 없음 |
| `sin`·`cos`·`exp`·`ln`·`powf` 등 | libm. 올바른 반올림이 보장되지 않아 비트 정밀 인코딩이 불가능하다 | 첫 범위에서 뺀다(열린 질문 2) |

- 숨은 실패 경로(원장의 "산술" 행)에 대한 판단: 정수 넘침은 Rust에서 panic(디버그)과 래핑(릴리스)이 갈리므로 의무로 만들었다. 부동소수 산술은 Rust 안에서 뜻이 하나이고 전함수다. 그래서 암묵 의무를 두지 않는다. 유한성이 필요하면 계약에 `is_finite()`를 쓰고 `by (bit_vector)`로 증명한다(§5).

### 4. 변환

- **정수 → `f64`:** `f64::from(x)`. Rust는 32비트 이하 정수에만 `From`을 둔다. BMB는 모든 정수 타입에 받는다.
  - 원본이 32비트 이하면 의무가 없다(정확하다).
  - 원본이 `i64`·`u64`·`isize`·`usize`면 정확성 의무 `|x| <= 2^53`(E0815, ADR-0028의 범위 의무와 같은 번호)를 낸다. 정수 사실이라 지금 증명기로 푼다(spectral-norm의 `i + j`, fasta의 정수 난수 등).
  - Rust와 다른 점(`From<i64>` 없음)은 원장에 한 행으로 적는다(§결과).
- **`f64` → 정수:** 첫 범위에서 뺀다. Rust의 유일한 안전 경로인 포화 `as`는 원장이 금지한 "조용히 잃는 변환"이다. 대상 프로그램 넷도 쓰지 않는다. 표면은 2R-06(`as`의 표면 결정) 뒤에 정한다(열린 질문 1).
- **비트 재해석(`to_bits`·`from_bits`):** 첫 범위에서 뺀다. NaN 페이로드는 Rust에서 보장되지 않고 SMT-LIB에서는 NaN이 하나뿐이다. 그래서 `to_bits(NaN)`에 대한 사실은 어느 쪽으로 정해도 건전하지 않을 수 있다.

### 5. 증명 인코딩

- **정렬(sort)은 비트 정밀하다:** `f64` 값은 SMT `(_ FloatingPoint 11 53)`이다.
- **연산과 비교는 기본적으로 해석하지 않는다:** 일반 의무 질의에서 `+`·`<`·`sqrt` 등은 해석하지 않는 함수·술어 기호(`f64.add` 등)다. 경로 조건(`if x < 4.0`)은 그 기호의 원자로 들어간다.
  - 결과: 부동소수가 섞인 함수의 정수·인덱스·이동 의무는 비트 블래스팅 없이 지금 비용으로 풀린다.
  - 해석하지 않는 함수는 모든 해석에서 참인 사실만 낳으므로 건전하다(C1). 같은 연산 같은 인자 → 같은 값(합동)은 IEEE RNE가 결정론적 함수라 성립한다. 성립하지 않는 것은 NaN 페이로드뿐이고, §4가 비트 재해석을 빼서 관찰할 수 없게 했다.
- **비트 정밀 증명은 `assert(e) by (bit_vector);` 안에서 한다:** ADR-0048 §3의 하위 증명을 그대로 쓴다. Verus PR #2229가 같은 구문으로 같은 일을 한다.
  - 그 질의에서만 기호를 `fp.add RNE` 등으로 해석한다.
  - 증명된 `e`는 바깥 질의에서 해석하지 않는 기호 위의 사실로 쓴다.
  - 건전성의 근거는 코드 생성이 IEEE RNE를 그대로 내보낸다는 것이다(§6). Verus처럼 "IEEE 가정"을 선택 모듈로 두지 않는 이유: BMB는 컴파일러가 하나이고, fast-math·축약을 끈 LLVM 출력이 IEEE임을 컴파일러 자신이 보장하기 때문이다.
- **실수(`Real`) 인코딩은 쓰지 않는다:** 반올림을 무시해 거짓 사실을 낳는다(C1 위반).

### 6. 코드 생성과 결정론

- **표현:** `f64`은 LLVM `double`이다. 레지스터 모델(`i64`)과 별도 슬롯 종류다. 메모리는 8바이트다.
- **연산:** `fadd`·`fsub`·`fmul`·`fdiv`·`fneg`·`fcmp`(순서 있는 비교 `olt`·`ole`·`ogt`·`oge`·`oeq`, `!=`는 `une`), `llvm.sqrt.f64`·`llvm.fabs.f64`, `min`·`max`는 Rust 의미에 맞는 `llvm.minnum`/`llvm.maxnum`.
- **결정론(C2):**
  - fast-math 플래그를 붙이지 않는다.
  - `contract`(FMA 축약)을 붙이지 않는다. IR 플래그가 없으면 clang `-O2`도 축약하지 않는다.
  - x86_64(SSE2)·aarch64에서 같은 IR이면 같은 비트를 낸다. 확인은 결정론 시험(V6)에 부동소수 실행 프로그램을 더해서 한다.
- **출력:** 내장 `print_f64(x: f64, decimals: u32)`. Rust `println!("{:.N}", x)`과 같은 고정 소수점 출력이다. 구현은 libc `printf("%.*f")`다(glibc는 정확한 값을 올바르게 반올림한다). 런타임 의존은 libc 그대로다(S3 = `[]`). `sqrt`가 LLVM 내장이라 libm이 필요 없다. 정확히 반만큼 떨어진 경우(ties)를 포함해 Rust 서식과 차등 시험한다.

### 7. 퍼저

- 독립 해석기(`tests/soundness*.rs`, Python 보조)는 binary64를 그대로 쓴다. CPython `float`는 C `double`이고 `+ - * /`·`math.sqrt`가 IEEE RNE다. 값 비교는 `struct.pack('<d')` 비트로 하되 NaN은 `isnan`으로 비교한다.
- 생성기는 유한값·부호 있는 0·무한대·NaN·준정규수를 섞는다. 두 빌드(검사 제거, 전체 검사)의 출력과 해석기의 출력을 대조한다.
- 변이체: `fadd`↔`fsub`, `olt`→`ole`, 단언 해석 누락(`by (bit_vector)` 밖에서 `fp.lt` 해석). 셋 다 게이트 검출력(`dev-docs/measurements/gate-power`)에 넣는다.

## 근거 (JUDGMENT §10)

1. **문제:** 정석 Rust의 부동소수 프로그램을 BMB로 쓸 수 없다. T3의 공인 성능 벤치 넷이 막힌다.
2. **원인과 귀속 층:** 언어(JUDGMENT §3 "정석 해법을 언어로 표현할 수 없다"). 원장에 금지 근거가 없으므로 결함이다(§7).
3. **정석 해:** Rust `f64` 의미(S1 a) + 검증 도구의 "기본 불투명, 국소 비트 정밀"(S1 b: Verus PR #2229, CopilotVerifier).

## 결과

- **쓸 수 있게 되는 공인 벤치(T3):**
  - 이 ADR만으로: n-body(구조체 배열, `sqrt`), spectral-norm(`Vec<f64>`, `f64::from`, `sqrt`)
  - 2N-02(비트 연산)와 함께: mandelbrot(PBM 비트 출력, `print_bytes`)
  - 2U·바이트 출력과 함께: fasta(정수 LCG + 누적 확률 비교, `f64::from(u32)`)
- **DESIGN §4.1 원장:**
  - "변환" 행에 "정수 → `f64`은 `f64::from` 하나. 64비트 원본은 정확성 의무(`|x| <= 2^53`). `f64` → 정수와 비트 재해석은 없음"을 더한다.
  - "산술" 행에 "부동소수는 IEEE 전함수라 의무 없음"을 더한다.

  3. `f32`.
  4. `total_cmp`와 정렬.
