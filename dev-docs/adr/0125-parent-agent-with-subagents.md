# ADR-0125: 모에이전트가 서브에이전트를 관리하는 진행 방식

- 상태: 채택(사람 지시·승인 2026-11-11 "서브에이전트를 지속 관리하는 모에이전트 방식으로", "권장안으로 실행"). AUTONOMY.md §2의 작업 루프를 보완한다
- 날짜: 2026-11-11
- 관련: AUTONOMY.md(작업 루프, 결정 권한, 보고), ADR-0111(판정 관문), ADR-0113(구성 요소 고정), ADR-0122(원장의 작성 비용), HEALTH.md(게이트), `scripts/ship.sh`

## 맥락

- 이 언어는 에이전트가 쓰는 언어다. 에이전트가 BMB로 일하는 과정이 곧 효용의 자료다(포팅 원장의 세션 토큰·게이트 실행, ADR-0122).
- 한 세션이 모든 것을 직접 쓰면 문맥이 태스크의 세부로 차고, 독립된 일을 나란히 하지 못한다.
- 같은 모델이 쓰고 같은 모델이 읽어서 통과시키면 검증이 아니다.

## 결정

1. **목표는 관문 단위다.** 한 번에 하나의 목표를 건다. 목표의 완료 조건은 출력으로 판정되는 것만 적는다(백로그 행의 상태, 게이트의 종료 코드, 브랜치와 원격의 일치). 사다리: 동결 전 자율 큐 → 포팅 P0~P2와 관문 B0 → P3와 관문 B → 고정점(ADR-0111의 관문).
2. **역할.** 모에이전트는 태스크 선택, 지시문, 검증, 통합, 커밋, 게이트, 기록을 맡는다. 서브에이전트는 태스크 하나와 파일 집합 하나를 맡고 커밋·푸시하지 않는다.
3. **검증은 실행이다.** 모에이전트는 서브에이전트가 보고한 수치를 옮겨 적지 않고 다시 잰다(시험, 측정 스크립트, 게이트). 읽어 보고 통과시키지 않는다.
4. **병렬은 파일이 겹치지 않는 둘까지다.** 컴파일러(`compiler/`)를 고치는 작성자는 한 번에 하나이고, 다른 서브에이전트가 도는 동안에는 별도 빌드 디렉터리나 작업 트리에서 한다(바이너리를 바꾸면 남의 실행이 흔들린다).
5. **지시문의 고정 항목.** 고칠 수 있는 파일, 금지(커밋, 범위 밖 파일), 완료 기준, 보고 형식: 사실, 문서와 구현의 어긋남, 마찰과 진단 코드, 게이트 실행 횟수와 미결정으로 끝난 실행(ADR-0122).
6. **승인 안건은 쌓고 멈추지 않는다.** AUTONOMY §4의 승인 필요 항목에 닿으면 권장안(JUDGMENT §10)을 내고 다음 태스크로 간다. 멈추고 보고하는 경우는 AUTONOMY §6에 더해: 건전성 결함 발견, 같은 원인으로 게이트 두 번 실패, 가설 판정이 나오는 측정 결과.
7. **기록.** 서브에이전트 세션의 토큰과 게이트 실행을 백로그 근거나 포팅 원장에 적는다.

## 근거

| 안 | 판정 |
| --- | --- |
| **모에이전트 + 서브에이전트, 실행으로 검증(채택)** | 독립된 일을 나란히 하고, 쓰는 쪽과 판정하는 쪽을 가른다. 게이트가 한 번에 하나이고 푸시가 한 브랜치라 통합은 한 곳에서 해야 한다 |
| 별도 클라우드 세션들 | 작업 트리가 달라 통합과 게이트가 세션마다 따로다. 독립된 긴 실행(게이트 검출력 변이체 등)에만 쓴다 |
| 한 세션이 직접 | 문맥이 세부로 차고 직렬이다 |

첫 사례: `port-shape` 실험(팔마다 한 세션, 모에이전트가 `measure.py`로 다시 잼), 적합성 시험 묶음(`5A-02`, 장을 둘로 나눔).

## 결과

- AUTONOMY.md에 "§8 모에이전트와 서브에이전트" 절을 둔다.
- 임계 경로는 여전히 사람 승인과 측정 머신에 묶인다. 이 방식은 그 사이의 일을 채운다.
