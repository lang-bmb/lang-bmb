# ADR-0146: 본문의 글 찾기 `query text`, 포팅 쌍둥이의 BMB 팔은 응답 창을 켠다

- 상태: 채택 (사람 승인 2026-11-22 "권장안 채택": 백로그 `3P-14`의 권장안. 채택하며 둘을 고쳤다: 긴 줄은 출현의 둘레만 보이고(결정 1), 설명문은 `--bounded`에서만 이 질의를 말한다(결정 3))
- 날짜: 2026-11-22
- 관련: ADR-0020(맵과 질의), ADR-0127(응답의 창), ADR-0142(본은 에이전트의 작동 방식), ADR-0144(첫 쌍둥이 측정의 조건: "BMB 팔에 본문의 글 찾기가 필요한지는 `3P-05a`의 갈래별 결과로 정한다"), DESIGN.md 원칙 6·7, `dev-docs/measurements/3p-05a.md`

## 맥락

- `3P-05a`(포팅 쌍둥이의 이해 과제 24개). 맵의 간선으로 답하는 질문(호출자, 영향)은 BMB 팔이 Rust 팔의 5~9%만 읽고 정답이 같거나 높다. 정의의 글을 읽어야 답하는 질문(어느 함수가 진단 코드를 내는가, 어느 함수가 상태의 필드를 바꾸는가)은 반대다: sonnet이 23배와 7배를 읽고 정답이 10/12 대 12/12다.
- 까닭은 도구에 있다. BMB 팔에는 글을 찾는 수단이 없어 정의를 통째로 읽으며 훑는다. Rust 팔은 `grep` 한 번이다.
- 작은 모델은 그 응답을 감당하지 못한다. qwen 3회에서 BMB 팔의 세션 41개가 문맥 초과(HTTP 400)로 끊겼고 Rust 팔은 0이다. 끊긴 세션이 읽은 도구 응답은 5만~20만 토큰이다.
- 응답의 창은 이미 있다(`bmb mcp --bounded`, ADR-0127: 32,768바이트, `offset`·`limit`, 잘림 행). 첫 측정의 조건(ADR-0144)은 `--write-tool --compact`였고 창은 꺼져 있었다.

## 결정

1. **`query text PATTERN [PATH..]`.** 작업 공간의 정규형 원문에서 `PATTERN`(글자 그대로, 대소문자 구분)을 담은 줄마다 한 행: `{"path","line","text"}`(`path`는 그 줄이 든 정의나 타입, `line`은 그 정의의 정규형 안의 줄 번호, `text`는 앞뒤 공백을 뗀 줄이고 200바이트를 넘는 줄은 첫 출현의 앞 60바이트부터 200바이트: 포트의 정규형에는 수천 바이트의 줄이 있어, 줄을 통째로 내면 행의 크기가 맞은 수에 비례하지 않는다). 끝에 요약 행 `{"summary":true,"pattern","matches","defs"}`. 범위 인자(`PATH..`)와 응답의 창은 다른 질의와 같다. 순서는 경로, 줄.
2. **정규식은 받지 않는다.** 찾는 꼴은 하나다(원칙 8). 정규식이 필요한 물음(이 필드에 쓰는 자리)은 구조의 질의가 답할 일이다(결정 4).
3. **포팅 쌍둥이의 BMB 팔은 `--write-tool --compact --bounded`다.** MCP `query`의 설명문은 `--bounded`에서만 `text`를 말한다: 플래그 없는 설명문은 동결 집합의 것 그대로다(ADR-0021, ADR-0127 결정 3). 같은 과제(`port/c*`)를 새 조건으로 다시 잰다(`3P-15`). 첫 측정의 결과는 그 조건의 값으로 그대로 둔다.
4. **이 결정에 넣지 않은 것.** (가) 필드의 읽기·쓰기 간선(`edges`의 종류로: "이 필드를 바꾸는 정의"를 글이 아니라 구조로 답한다)은 `3P-15`의 상태 갈래 결과를 본 뒤 정한다. (나) 리팩터링의 비용(H-REFACTOR: 토큰 3.5배)은 쓰기 표면의 일이다: 이름 바꾸기 연산(`apply`의 `rename`)은 측정한 표면(`--write-tool`)에서 숨겨져 있었다. 3C(보존형 리팩터링 연산)와 `T1-41`(H-EDIT)에서 다룬다.

## 근거

| 안 | 판정 |
| --- | --- |
| **글 찾기 + 창(권장)** | 두 원인이 다르다: 찾을 수단이 없는 것과 응답에 상한이 없는 것. 글 찾기는 응답이 맞은 줄 수에 비례한다(원칙 7). 에이전트가 실제로 하는 일(`grep`)을 도구가 결정론으로 해 준다(ADR-0142, 원칙 6). 창은 이미 있는 플래그다 |
| 창만 켠다 | 끊김은 줄지만 훑는 양은 그대로다: 창을 넘겨 가며 정의를 다 읽는다 |
| 구조의 질의만 더한다(리터럴을 내는 정의, 필드를 바꾸는 정의) | 정확하지만 물음마다 질의가 하나씩 는다. 미리 알지 못한 물음에는 수단이 없다. 글 찾기를 둔 뒤 잦은 물음을 구조의 질의로 올리는 순서가 맞다 |
| 그대로 두고 주장을 간선의 질문에 한정한다 | H-COMPREHEND의 문장(진단 경로, 불변식이 지켜지는 곳)을 줄여야 한다. 도구의 빈 곳을 가설의 범위로 덮는 일이다 |

- 정규형에는 주석이 없으므로 글 찾기가 죽은 글에 맞는 일이 없다. 요약(`#[summary]`)은 맞는다: 찾는 것이 뜻이면 쓸모가 있다.
- 동결 조건: 플래그 없는 서버의 도구 목록과 설명문은 그대로다(질의 `text`는 불러야만 답한다). 쌍둥이의 BMB 팔은 플래그가 하나 늘어 첫 측정과 같은 조건이 아니다. 그래서 다시 잰다.
- `edges`에는 이미 `writes` 종류가 있다. 결정 4 (가)는 그것이 상태 갈래의 물음에 답하는지부터 본다.
