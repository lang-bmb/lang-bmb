# ADR-0056: 구조체만으로 된 재귀의 증명 인코딩

- 상태: 채택 (2026-10-27, 자율 채택: AUTONOMY §4 "기존 ADR 범위 안의 구현 수준 결정", 백로그 2O-03d)
- 날짜: 2026-10-27
- 관련: ADR-0027 §1·§3(구조체의 잎 분해, 열거형 데이터타입), ADR-0047 §3(재귀 타입의 인코딩, "경계와 안정성은 구현 때 잰다"), 측정 `dev-docs/measurements/z3-nested-datatypes`, 백로그 2O-03d

## 맥락
`struct Node { v: i64, kids: Vec<Node> }`(Rust의 정석 장미 나무)는 구조체만으로 자기를 담는다. 구조체는 잎의 묶음(ADR-0027 §1)이라 잎이 끝없이 늘어나므로, 2O-03c까지는 E0421로 막고 열거형을 끼우게 했다. ADR-0047 §3은 재귀 타입을 SMT 데이터타입으로 둔다고 했지만, 구조체는 생성자가 하나라 그 생성자가 자기 배열을 담는 데이터타입은 Z3가 받지 않는다(well-founded가 아님).

측정(`z3-nested-datatypes` README 2O-03d 절, 증명기가 낸 질의 그대로, Z3 4.15.4):
- 자리 채움 생성자를 더한 데이터타입: 작은 만족 질의에서 답하지 않는다(20초 제한). 생성자 순서·모양을 바꿔도 질의마다 결과가 갈리고, 한 경우 Z3가 비정상 종료했다.
- 정해지지 않은 정렬과 선택자 함수: 증명은 바로 끝나지만, 한정자 spec fn이 있는 만족 질의에서 `unknown`(rlimit 5,000,314, 한도).
- 같은 질의에서 정렬을 `Int`로: `sat`(rlimit 93,293).

## 결정
1. **손잡이.** 구조체만으로 자기를 담는 구조체(필드·`Vec`·배열·`Box`를 거쳐, 열거형 없이: `check::struct_cycle`)의 값은 `Int` 손잡이다. 정렬 이름은 구조체의 것이고(`(define-sort |m::Node| () Int)`) 모든 데이터타입보다 먼저 선언한다. 필드 잎마다 선택자 함수(`|m::Node::Node.0|` 등, 열거형 페이로드와 같은 이름 규칙)를 데이터타입 뒤에 선언한다.
2. **값 만들기는 지상 사실.** 구조체 식과 필드 쓰기(`n.v = x`, `n.kids[i].v = x`, `n.kids.push(c)`)는 새 상수를 만들고 그 선택자의 값을 등식으로 단언한다(`Enc::mk_struct`). 생성자 함수와 한정자 공리가 없어 질의는 한정자 없이 남는다. 필드의 범위·길이 사실은 의무의 경로 조건과 목표에 나오는 선택자 적용마다 지상으로 더한다(`Prog::struct_facts`, 한정자 안의 항 제외). 경로의 항은 그 경로에 있는 값을 가리키고, 그 필드는 앞선 의무가 검사했다. 값 정의(새 상수의 선택자 등식)는 훑지 않는다: 뒤에서나 다른 경로에서 만든 값의 필드 사실은 그 필드를 검사하는 의무가 증명할 것을 가정한다(구현 중 소유 퍼저가 찾은 결함: `Node { v: 3 * x, .. }`의 넘침이 증명되었다).
3. **명세의 제한.** 명세에서 이 구조체의 값을 만드는 것은 E0432(정의의 공리에 쓸 항이 없다: 필드로 말한다). 재귀 타입이 `Vec`을 담으면 명세 `==`는 E0431(깊이가 정해지지 않은 값의 원소별 비교를 펼칠 수 없다: 2O-03c의 열거형 `==`가 인코더를 끝나지 않게 하던 결함도 함께 막는다).
4. **종료.** `decreases n`은 이 구조체도 받는다. 구조적 감소는 2O-03c의 선택자 사슬(원소 단계와 범위 조건) 그대로이고, 구조체 생성자에는 판별자가 없다. 사슬이 엄격한 부분인 근거는 SMT의 데이터타입이 아니라 프로그램 값이 유한하다는 것이다(값은 생성으로만 생기고 순환 참조가 없다, ADR-0047 §1).
5. **다른 데이터 타입은 그대로.** 재귀 없는 구조체는 잎 분해, 열거형(재귀 포함)은 데이터타입을 유지한다. ADR-0047 열린 질문 1(통일)은 열어 둔다: 이번 측정은 배열에 중첩된 재귀 데이터타입이 Z3 4.15.4에서 불안정하다는 것만 보였다.
6. **코드 생성은 바뀌지 않는다.** `Vec`이 배치를 끊으므로 재귀 구조체는 보통 구조체이고, drop glue가 서로 부른다(2O-02).

## 근거(검토한 대안)
| 대안 | 판단 |
| --- | --- |
| 데이터타입 + 자리 채움 생성자 | Z3 4.15.4에서 만족 질의가 끝나지 않는다(반례가 나올 자리에서 360초 대기) |
| 정해지지 않은 정렬 + 생성자 함수와 한정자 공리 | 만족 질의가 `unknown`, 반례 없음 |
| 정해지지 않은 정렬 + 지상 사실 | 한정자 spec fn이 있으면 모형 탐색이 자원 한도까지 간다(실패 하나에 5M) |
| **`Int` 손잡이 + 지상 사실(채택)** | 측정한 질의 모두 즉시 답한다. 손잡이에 산술이 없어 의미는 정렬의 원소 수 말고 같고, 인코딩은 원소 수에 기대지 않는다 |
| E0421 유지(열거형을 끼우게) | 정석 Rust 형태를 막는다. 마찰(`m1.md` §6) |

## 결과
- 코퍼스: `tests/verify/pass/rec_structs`(상호 재귀 구조체, 제네릭 `Rose<T>`, 두 단계 아래 쓰기, 재귀 spec fn), `tests/verify/fail/rec_structs`(반례 7), `tests/check/err/rec_structs`(E0431·E0432·E0401), `tests/run/rose`(valgrind 깨끗).
- 퍼저 `soundness_owned`가 장미 나무·`Vec` 트리 연산을 돌린다(80배치 불일치 0). 위 결정 2의 경로 제한은 그 퍼저가 찾은 결함의 수정이고, 게이트 변이 `v-struct-facts-from-definitions`가 되돌림을 잡는다.
- 반례는 재귀 구조체 입력을 한 단계 필드로 보여 준다(`n = Node { v: 0, kids: [Node { .. }] (len 1) }`).
- 명세에서 두 재귀 값의 같음은 말할 수 없다(E0431). 필요하면 재귀 spec fn으로 쓴다.
