# BMB 진행 리포트

> 한 파일을 제자리에서 갱신한다. 지난 판은 git 이력에 있다(`git log -p --follow dev-docs/reports/progress.md`). 2026-10-28 판은 이 파일의 이전 이름 `2026-10-28-progress.md`다.
>
> **갱신 방법.** `python3 scripts/progress.py --write dev-docs/reports/progress.md`가 §6 표를 다시 만들고, "지난 보고" 열을 이 파일의 직전 커밋 판에서 채운다. 표의 값은 모두 저장소 파일에서 읽는다(출처 열). §0~§5의 해설과 §7~§9는 표를 보고 손으로 쓴다. 표에 없는 값을 해설에 쓸 때는 출처를 같이 적는다.
>
> **주기.** 주 1회와 국면이 닫힐 때. 국면이 닫힐 때는 종료 감사(`dev-docs/health/<국면>.md`)를 함께 낸다.
>
> **health 값의 뜻.** health 지표는 마지막 `health.py accept` 때의 기준선 값이다. 게이트가 매 커밋 현재 값이 래칫 안에 있는지 확인하므로, 고정 규칙과 래칫 지표는 현재 값과 같거나 더 나쁘지 않다. 예산 지표(V4·V8·V10·V11·B1)는 현재 값이 기준선보다 최대 +10%(B1은 +5%)까지 높을 수 있다. 정확한 현재 값은 `python3 scripts/health.py table`로 본다.

## 1. 부트스트랩

- **현재.** 자립 사다리 L2(stage0 기능 동결, 2026-11-14). 닫힌 포트: `source`·`diag`·`sha256`(C0), 렉서(C1), 파서·구문 트리(C2), 정규형·정체성(C3: `fmt`·`identity`), 검사기(C4: 앞 단계, 선언 수집, 몸 검사, `moves`, `methodize`). 구성 요소마다 닫는 조건은 명령의 출력이 stage0과 바이트 동일한 것이다: `codes`, `check`, `fmt`·`fmt --check`, `hash`, 그리고 단계별 관측점 `dump tokens`·`parse`·`std`·`lower`·`decls`·`types`·`moves`·`texts`. 포트로 지은 stage1은 이 명령들을 가진 실행 파일이다(`bmb build selfhost/*.bmb`).
- **확인.** 2026-11-17에 전체 게이트가 `51cc9e4c`에서 통과했다: 차등 시험 34사례가 모두 같다(추적되는 `.bmb` 941개를 파일 하나씩, 그리고 가장자리 입력). 사례 밖에서 손으로 돌린 대조: 변형 입력 6,000개(검사를 통과하는 것은 213개), 검사를 통과하는 생성 프로그램 1,500개, 메서드 호출 2,120곳을 경로 호출로 바꾼 포트 전체. 모두 같다.
- **비용 실측(관문 B0).** P0~P2와 `fmt`의 일부 8,750줄이 stage0 8,715줄에 맞서 전체 배 1.00이고, 전체 포트의 추정은 6.6만~7.5만 줄이다(포팅 지도 §7.8). 앞의 추정 23만~37만 줄은 기능 명세까지 증명한 표준 라이브러리 두 쌍의 배율이었다. 포트의 정의는 전부 증명되지만(원장의 "증명된 정의" 열) 증명한 것은 안전성이고, stage0과의 같음은 차등 시험이 맡는다.
- **포팅이 찾은 것.** stage0의 코드 생성 결함 셋(`4D-21`, `4D-23`: `if` 조건의 임시값 해제, `4D-34`: `match`가 묶은 값의 부분 이동 뒤 이중 해제), 건전성 결함 하나(`4D-27`: 제네릭 `Vec<T>.clone()`의 이중 해제), 검사기와 증명 스크립트의 결함(`4D-29`·`4D-32`·`4D-33`), `std::json`의 결함 넷(`4D-15`), 표준 라이브러리의 채울 수 없는 길이 전제(`4D-20`·`4D-22`). 열려 있는 것: 디버그 빌드의 스택 넘침(`4D-35`), `&&` 안의 `&mut` 호출 뒤 불변식(`4D-24`).
- **가장 큰 위험.** 증명한 것은 안전성(색인, 넘침, 끝남)이고 stage0과의 같음은 차등 시험이 맡는데, 그 입력의 힘이 고르지 않다: 변형 입력은 대부분 검사에서 떨어져 뒤 단계(해시, 정규형)에 닿지 않았다. 검사를 통과하는 생성 프로그램의 내보내기(`BMB_FMT_FUZZ_EXPORT`)를 더했으나 차등 사례에는 아직 묶지 않았다. 포트 전체를 다시 증명하는 데 20분이 든다(바뀐 정의만 증명하는 캐시는 타입이 바뀌면 넓게 무효가 된다): 코드 생성이 들어오면 더 는다.
- **stage0의 크기.** S4는 56,001 → 57,412줄(+1,411)이다. 관측점(`dump std`·`lower`·`decls`), `clone`, 결함 수리가 늘렸다. 동결은 받아들이는 언어의 것이고 관측점은 포트의 차등 시험이 요구한다.

## 2. 언어 개발 수준

- **동결.** ADR-0100이 채택됐고 `dev-docs/health/surface.json`이 `frozen: true`, 버전은 `0.1.0`이다(ADR-0138). 관문 A의 증거 전제 셋은 관문 B로 옮겼다(ADR-0137).
- **동결 뒤의 예외.** 메모리를 가진 값의 `clone`(ADR-0141, 사람 승인). 근거는 포트가 손으로 만든 사본 함수 86개(약 890줄)였다. 와일드카드 갈래는 열지 않았다. 다음 후보 `4D-24`(`&&`·`||` 안의 `&mut` 호출 뒤 타입 불변식)는 우회 중이고, 우회 수가 쌓이면 안건으로 올린다.
- **설계의 본(ADR-0142·0143, 사람 지시 2026-11-16).** 형태는 에이전트의 작동 방식 가운데 맞춘 성질로 정당화하고, "쓰고 싶다"는 실측으로 판정한다. Rust·Verus 승계는 학습 부재를 메우는 수단으로 내려왔고, 벗어날 수단이 지금의 모델에서 실측으로 충분한 자리에서는 본에 맞는 꼴이 먼저다. 당장 바뀌는 문법은 없다. 따르는 태스크는 `T0-42`(비교 규약)와 `T1-50`(벗어날 수단의 목록)이다.
- **증명 게이트의 신뢰.** 미증명 정의 0(V3), 건전성 퍼저 17종(O2). 충족 검사 미결정은 86 → 88, 비용은 1.18억 → 1.21억이다(V11·V12, 포트와 함께 는 것).
- **목표까지.** 언어에 대한 다음 근거는 포팅 원장의 마찰에서 온다. 지금까지의 마찰은 원장에 구성 요소마다 적혀 있다(튜플 없음, `&'static str` 필드 없음, 글자 경계 의무의 실행 때 확인, 주석을 버리는 정규형).

## 3. 성능

- **현재.** 기준 벤치 7/7이 G6(±5%) 안이고(0.962~1.041, 2026-11-04 측정) 크기 합은 101,664바이트다(B1). 측정은 12일 전 것이다. 그 뒤 생성 코드에 닿은 변경이 있다(`4D-21`·`4D-23`, `clone` glue): B1은 같고 시간은 다시 재지 않았다.
- **목표까지.** 실규모의 첫 값은 관문 C(stage1 대 stage0의 컴파일 시간과 크기)이고 `4D-05`(코드 생성 포팅) 뒤다. 공식 Benchmarks Game 제출과의 비교(T3-01·T3-04)는 네트워크 정책으로 막혀 있다.

## 4. 생태계

- **닫혀 있다.** 5E는 원칙 4·6이 측정으로 입증된 뒤(관문 E)에 연다.
- **쌓인 것.** 증명된 표준 라이브러리 11단위 4,262줄, CLI 명령 24개, 5A 5/5. 안정성·버전 정책(ADR-0138)과 측정 도구의 Python 의존(ADR-0139)이 채택됐다.

## 5. 미션 효용

- **현재.** 확정 0, 반증 3(H-SCALE 경계, H-EFFECT, H-REPAIR), 결정론 근거 7. 등록부의 값은 지난 판과 같다. 이번 주기에 새 모델 실행 결과는 없다.
- **판정 전인 것.** E3의 이득 쪽: 숨은 결함(H-ORACLE), 누적 검증 비용(H-AMORT), 큰 코드에서의 과업(H-TASK·H-COMPREHEND·H-REFACTOR). 뒤의 셋은 판정 장이 포팅 쌍둥이(P3 크기)이고 `4D-03` 뒤에 과제 생성기(`3P-02`~`04`)가 열린다.
- **비교의 규칙이 바뀌었다(ADR-0142 결정 3, ADR-0143 결정 3).** 학습된 언어와의 차이는 설계의 비용과 학습 안 됨의 비용의 합이므로 가르지 않은 값과 가른 값을 따로 보고하고, 설계 판단의 1순위 근거는 두 팔이 똑같이 낯선 비교다. 평가는 지금의 모델과 수단으로 한다. 이미 있는 측정을 이 규칙으로 다시 읽는 일이 `T0-42`다.
- **포팅이 주는 근거.** 포트를 쓰는 세션이 "에이전트가 쓰고 싶은가"의 첫 실측 자리다. 원장의 세션 토큰 열은 아직 비어 있고(게이트 실행과 미결정 횟수만 C2·C4에 있다) 채워야 근거가 된다.
