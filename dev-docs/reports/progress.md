# BMB 진행 리포트

> 한 파일을 제자리에서 갱신한다. 지난 판은 git 이력에 있다(`git log -p --follow dev-docs/reports/progress.md`). 2026-10-28 판은 이 파일의 이전 이름 `2026-10-28-progress.md`다.
>
> **갱신 방법.** `python3 scripts/progress.py --write dev-docs/reports/progress.md`가 §6 표를 다시 만들고, "지난 보고" 열을 이 파일의 직전 커밋 판에서 채운다. 표의 값은 모두 저장소 파일에서 읽는다(출처 열). §0~§5의 해설과 §7~§9는 표를 보고 손으로 쓴다. 표에 없는 값을 해설에 쓸 때는 출처를 같이 적는다.
>
> **주기.** 주 1회와 국면이 닫힐 때. 국면이 닫힐 때는 종료 감사(`dev-docs/health/<국면>.md`)를 함께 낸다.
>
> **health 값의 뜻.** health 지표는 마지막 `health.py accept` 때의 기준선 값이다. 게이트가 매 커밋 현재 값이 래칫 안에 있는지 확인하므로, 고정 규칙과 래칫 지표는 현재 값과 같거나 더 나쁘지 않다. 예산 지표(V4·V8·V10·V11·B1)는 현재 값이 기준선보다 최대 +10%(B1은 +5%)까지 높을 수 있다. 정확한 현재 값은 `python3 scripts/health.py table`로 본다.

## 1. 부트스트랩

- **현재.** 자립 사다리 L1(통합 시험이 CLI로 돈다, S5 = 1). 런타임(4C)과 표준 라이브러리(4B)가 닫혔고, 포팅의 장치가 섰다: 포팅 지도 재기준(4D-07), 포팅 원장(4D-08), 구성 요소 고정(4D-10), 동결 감지(`scripts/surface.py`), 관찰 명령 `bmb dump tokens`·`dump parse`(4A-03).
- **목표까지.** 관문 A의 전제 14개 중 13개가 닫혔다(`dev-docs/health/freeze-readiness.md`). 남은 것은 증거 단계의 세 칸이다: `T0-08` qwen 반복, `T1-41` qwen, `2A-14e`. 측정 결과는 2026-11-10 뒤로 커밋되지 않았다.
- **가장 큰 위험.** 포팅할 양이다. stage0은 65,664줄이고(`scripts/components.py table`), 전체 포트의 추정은 표준 라이브러리 두 쌍의 배율 3.5~5.7을 곱한 23만~37만 줄뿐이다(배율은 포팅 지도 §7.3). 계약 없는 배율과 증명한 배율의 첫 실측은 렉서(P1)이고 보고는 관문 B0다. 이 값이 나오기 전의 계획은 추정 위에 서 있다.
- **이번 주기에 생긴 문제.** 기다리는 동안의 선행 투자가 stage0을 2026-11-11의 62,668줄에서 65,664줄로 늘렸다(+2,996줄, 도구와 증명 인코딩). 배율을 곱하면 포트 1만~1.7만 줄이다. 그래서 열여섯째 계획은 stage0을 늘리지 않는 작업을 앞에 둔다(ROADMAP "기다리는 동안의 규칙").

## 2. 언어 개발 수준

- **현재.** ① 언어 코어와 ② 남은 언어 기능이 닫혔고, ⑤의 문법 결정(ADR-0095·0096)과 동결 전 표면 결정(ADR-0052·0053·0097~0099·0124)이 채택·구현됐다. 레퍼런스 초안 여덟 장(`docs/reference/`)과 적합성 사례 402개(5A-02)가 표면을 고정한다.
- **증명 게이트의 신뢰.** 미증명 정의 0(V3), 건전성 퍼저 17종(O2), 게이트 검출력 99/99(1B-57)와 재실행 21/21(1B-59). 고친 건전성 결함의 원장은 `dev-docs/health/soundness-ledger.md`다.
- **증명기의 완전성.** 충족 검사의 미결정이 216 → 86, 그 비용이 2.72억 → 1.18억으로 줄었다(T2-13, ADR-0133: 재귀 정의를 재귀 함수 꼴로). 남은 86은 분류해 뒀다(T2-19). 권고 질의의 `rlimit`(ADR-0131)과 해법기 메모리 판정(ADR-0129)도 이번 주기다.
- **쓰기·읽기 도구.** `bmb examples`(ADR-0134), `bmb fix --induction`(ADR-0135), 질의 응답의 창(ADR-0127), 이름 바꾸기의 남은 대상과 `move`(T1-23), MCP의 `rename`·`expect`(T1-20). 모두 선택 기능이고 동결 판의 도구 목록은 그대로다.
- **목표까지.** 받아들이는 언어에 남은 일은 동결 선언뿐이다. 언어에 대한 다음 근거는 포팅 원장의 마찰(무엇이 쓰기 어렵고 무엇이 증명되지 않는가)에서 온다.

## 3. 성능

- **현재.** 기준 벤치 7/7이 G6(±5%) 안이고(0.962~1.041, 2026-11-04 측정) 크기 합은 101,664바이트다(B1). 이번 주기에 생성 코드에 닿는 변경은 없었다.

## 5. 미션 효용

- **현재.** 확정 0, 반증 3(H-SCALE 경계, H-EFFECT, H-REPAIR), 결정론 근거 7. 공학적 가설(판정 신뢰, 증명 안정성·국소성, 정체성, 병합, 성능, 크기)은 입증됐다. 과제 단위 총 토큰(G5)은 미충족이고 판정은 수명 단위(G5-L)로 옮겨져 있다(ADR-0102).
- **판정 전인 것.** E3의 이득 쪽이다: 숨은 결함(H-ORACLE, 네 번 변별 실패 뒤 변이 점수 판 T0-40으로), 누적 검증 비용(H-AMORT, `2A-14e`), 큰 코드에서의 과업(H-TASK·H-COMPREHEND·H-REFACTOR). 뒤의 셋은 판정 장이 포팅 쌍둥이(P3 크기)라 포팅이 시작돼야 잴 수 있다.
- **이번 주기.** 새 모델 실행 결과는 없다. 측정 집합은 늘었다: H-REVIEW(`bench/review` 143개), H-INTENT(`bench/intent` 90개, 2026-11-14 재동결), 절제 판 여섯(ADR-0136), 응답 창 판(2D-39a). 두 집합의 토큰 기준은 동결 집합에서 닿지 않음이 결정론으로 확인됐고 기준은 그대로 뒀다(ADR-0132).
- **구조적 문제.** 측정 머신의 대기열이 만드는 속도보다 느리게 빠진다. 임계 경로의 세 칸 뒤에 열 개가 넘는 실행이 있다. 대기열의 예상 토큰과 날 수를 계측하고(INF-39), 새 집합은 대기열이 줄 때까지 만들지 않는다.
