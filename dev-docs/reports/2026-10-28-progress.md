# BMB v2 진행 보고 (2026-10-28)

> 기준 커밋 `62751306`(main, 2N-01b). 기간은 v2 리셋(2026-10-24, `9bb88ea`)부터 이 커밋까지다.
> 수치는 모두 커밋된 자료에서 가져왔다: `dev-docs/health/baseline.json`(다섯 축 지표), `dev-docs/health/<페이즈>.md`(종료 감사), `bench/baseline/results/2026-10-24.md`(성능), `dev-docs/measurements/gate-power/`(게이트 검출력), `dev-docs/BACKLOG.md`(태스크 상태).
> 이 문서는 그 시점의 기록이다. 현재 상태는 `docs/ROADMAP.md`와 백로그를 본다.

## 1. 요약

- **증명된 코드만 바이너리가 되는 관통 경로가 동작한다.** 파싱 → 검사 → 증명 게이트(Z3) → LLVM IR → 바이너리, 그리고 파일 없이 쓰는 맵·MCP 도구까지 1단계(1A~1D, 1F)가 통과 기준을 충족했다.
- **언어는 정수·배열 장난감에서 실용 프로그램을 쓸 수 있는 수준으로 넓어졌다.** 2단계 페이즈 일곱(2B 데이터 타입, 2C 변환, 2G 메모리, 2S 바이트·문자열, 2T 제네릭·trait, 2O 소유 타입, 2K 제어 흐름)이 종료 감사를 마쳤고, 2N(정수와 비트 연산)이 진행 중이다.
- **"증명되었다"는 판정을 믿을 근거를 쌓았다.** 건전성 퍼저 10종, 게이트 검출력 53/53(심은 결함 전부 검출), 미증명 정의 0, 결정론적 검증을 매 커밋 래칫으로 지킨다.
- **아직 증명되지 않은 것: 미션의 핵심 가설.** 에이전트가 BMB로 더 결함 적은 코드를 1회에 쓴다는 주장(G2~G5, G8)은 벤치와 하네스만 준비되었고 실제 모델 측정은 없다. 이것이 가장 큰 남은 일이다.

## 4. 증명 판정의 신뢰

증명 게이트가 틀리면 나머지 주장이 모두 무너지므로, 판정 자체를 시험하는 데 가장 많은 공을 들였다.

- **건전성 퍼저 10종**(정수, 명세, 루프, 호출, 재귀, 부호 없는 산술, 데이터 타입, `Vec`, trait, 소유 타입). 증명된 함수를 독립 해석기로 실행하고, 반례를 재현하고, 검사 제거 빌드와 전체 검사 빌드의 출력을 대조한다. 게이트와 야간 실행에서 위반 0.
- **게이트 검출력 53/53.** 증명기·코드 생성기에 그럴듯한 결함(건전성 37, 완전성 2, 오컴파일 14)을 하나씩 심고 게이트 전체가 잡는지 쟀다. 첫 실행에서 놓친 다섯마다 시험을 더해 전부 잡게 했고, 코드가 바뀌어 변이체가 더는 적용되지 않는 것을 게이트가 스스로 알리게 했다(`power` 단계, 2T-05).
- **퍼저와 증명이 실제로 찾은 결함.** 루프 havoc이 `match` 갈래 안의 대입과 `&mut` 바인딩을 거친 쓰기를 놓치던 건전성 결함 둘(2K-01a), `Vec` 루프 길이 처리의 건전성 결함(2G), 레이블 렉서 결함(서식 퍼저), 실행 프로그램 `numlist`의 자기 결함 셋(빈 입력의 사후조건 위반, 자릿수 불변식이 약해 생기는 넘침, 길이 한도 초과)을 증명이 잡았다.
- **결정론.** 같은 입력이면 진단·맵·SMT 질의 텍스트가 바이트 단위로 같다(V6). 불안정 질의 비율 0(V7, 질의 2,206개).
